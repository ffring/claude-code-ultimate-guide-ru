## Высокий приоритет

### команды на основе gstack (отложено с аудита 26 марта 2026 г.)

Аудит [gstack](https://github.com/garrytan/gstack) (набор инструментов для спринта Claude Code Гарри Тана) выявил эти пробелы. Элементы ВЫСОКОГО приоритета уже реализованы (обновления `/investigate`, `/qa`, `/canary`, `/land-and-deploy`, `/review-pr`). Остальные предметы отложены здесь.

**`/autoplan`** — единая команда, которая автоматически объединяет генеральный директор → Дизайн → Инженерное обеспечение с закодированными принципами принятия решений. Классифицируйте решения как механические (автоматическое решение) и вкусовые (поверхностное для пользователя). Предварительное условие: наши команды `/plan-ceo-review` и `/plan-eng-review` должны быть сначала стабильными. Источник: `gstack/autoplan/SKILL.md`.

**`/office-hours`** — диагностика продукта в стиле YC с 6 навязчивыми вопросами перед планированием. Выше `/plan-ceo-review`. Пишет бриф на проектирование в `~/.claude/projects/`. Источник: `gstack/office-hours/SKILL.md`.

**`/design-review`** — визуальный аудит сайта в реальном времени + цикл исправлений. Делает снимки экрана URL-адреса, проверяет spacing/typography/color/contrast, обнаруживает шаблоны ошибок AI (фиолетовые градиенты, сетки из трех столбцов, все по центру). Сначала требуется стандартизация инструментов браузера. Источник: `gstack/design-review/SKILL.md` + `design-checklist.md`.

**`/benchmark`** — обнаружение регрессии Core Web Vitals (TTFB, FCP, LCP, загрузка DOM, размеры пакетов). Сравнение базового уровня с порогами регрессии (>50% ИЛИ >500 мс = регрессия). Источник: `gstack/benchmark/SKILL.md`.

**`/retro`** — еженедельная ретроспектива с анализом журналов git для каждого участника. Текущее и предыдущее окно. Источник: `gstack/retro/SKILL.md`.

**`/freeze` + `/unfreeze`** — блокировка редактирования каталога во время выполнения с помощью перехватчика PreToolUse (жесткий запрет, а не предупреждение). Файл состояния по адресу `~/.claude/freeze-dir.txt`. Комбинируется с `/careful` в команду `/guard`. Источник: `gstack/freeze/SKILL.md`.

**`/document-release`** — обновления документации после отправки. Считывает различия с момента последнего выпуска, обновляет README/ARCHITECTURE/CONTRIBUTING/CLAUDE.md, дорабатывает CHANGELOG, очищает TODOS. Источник: `gstack/document-release/SKILL.md`.

**Таблицы сжатия усилий** — добавьте в шаблоны навыков: время человека и время ИИ для каждого типа задачи. Архитектурное решение для формата навыков — обсудите, прежде чем реализовывать все навыки.

**Триггер для реализации**: запросы читателей или когда мы проводим спринт «полноты рабочего процесса».

### Навыки агента — пробелы в документации (из официальной документации Agentskills.io, 14 мая 2026 г.)

Шесть фактических элементов были признаны отсутствующими в главе о навыках руководства после перекрестных ссылок с официальной спецификацией Agentskills.io и руководством по реализации клиента.

**[HIGH] Соглашение о межклиентских каталогах `.agents/skills/`** — в руководстве документируется только `.claude/skills/` (специфично для Claude Code). Открытый стандарт определяет `.agents/skills/` (проект) и `~/.agents/skills/` (пользователь) как межклиентские пути. Размещенные там навыки работают на всех более чем 35 совместимых клиентах. Это различие напрямую влияет на требования о переносимости. Добавьте в раздел «Где живут навыки».

**[ВЫСОКИЙ] 4-уровневый приоритет загрузки навыков** — В руководстве не описана полная иерархия: Предприятие → Личное → Проект → Плагины. В настоящее время руководство подразумевает только «Личное» и «Проектное». Enterprise (управляемые настройки, наивысший приоритет) и плагины (самый низкий) отсутствуют. Добавьте в раздел иерархии приоритетов.

**[MEDIUM] Стоимость токенов прогрессивного раскрытия** — в спецификации указаны конкретные цифры: ~50-100 tokens/skill для каталога (только имя + описание), рекомендуется <5000 токенов для полного тела SKILL.md, ресурсы по запросу. Руководство объясняет концепцию, но никогда не приводит приблизительных цифр. Полезно для читателей, решающих, сколько навыков установить.

**[MEDIUM] Ограничение тела SKILL.md в 500 строк** — спецификация рекомендует сохранять SKILL.md менее 500 строк. Нигде в руководстве не описано. Добавьте практическое правило в раздел структуры.

**[MEDIUM] `name` должен соответствовать имени родительского каталога** — спецификация требует этого как структурное ограничение. В руководстве документированы правила character/format для `name`, но это требование опущено. Несоответствие приводит к сбою `skills-ref validate`.

**[LOW] Соглашение о хранении оценочных данных.** — спецификация определяет стандартную структуру файлов: `evals/evals.json` внутри папки навыков + `my-skill-workspace/iteration-N/with_skill|without_skill/` для оценочных запусков. Не описано в разделе оценки руководства. Имеет значение совместимость различных инструментов с метанавыком `skill-creator`.

**Источник**: `claudedocs/anthropic-cert/01-agent-skills/agentskills-io-docs.md` (разделы 2, 6, 8)

## Отброшенные идеи

| Идея | Причина отброшена |
|------|------------------|
| LLM Руководство по точной настройке | Вне области применения — пользователи не контролируют обучение модели. |
| Внутреннее устройство архитектуры модели | Слишком теоретически, не практично. |
| Оптимизация ценообразования токенов | Изменения слишком частые, используйте официальную документацию |
| Протокол A2A (между агентами) | Claude Code — это один агент с субагентами, а не настоящий мультиагент. |
| Панель управления AgentOps Enterprise | Инфраструктура для инструмента CLI не существует. |
| Оценка LLM в качестве судьи | Overkill для CLI, добавляет задержку без пропорционального значения. |
| Регистрация траектории принятия решений | Нет доступа к внутренним следам (черный ящик) |
| Формальная структура из 4 столпов | Слишком академично – руководство уже прагматично описывает симптомы. |
| Развертывания Canary/Blue-Green | Шаблоны инфраструктуры, не относящиеся к CLI |
| Защита от отравления памяти | Теоретический риск, требующий предварительного компрометации системы |
| Оперативное проектирование для генерации кода | Уже хорошо описано (xml_prompting, Prompt_formula). |
| Оптимизация контекстного окна | Уже хорошо описано (context_management, context_triage). |
| Шаблоны декомпозиции задач | Охватывается через plan_mode, Interaction_loop |
| Сравнение архитектуры агентов | За рамками — не многоагентная теория |
| Практические примеры | Непроверяемые показатели, подверженные маркетингу |
| Сравнение с другими инструментами | Вышло за рамки, быстрое устаревание |
