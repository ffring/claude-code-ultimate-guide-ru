# Критерии проверки качества кода

При проверке качества кода оцените следующие аспекты:

## Организация
- Является ли структура модуля логичной и последовательной?
- Файлы находятся в правильных каталогах?
- Согласовано ли соглашение об именах во всей кодовой базе?

## СУХИЕ нарушения
- Отмечайте любую дублированную логику (будьте агрессивны)
- Определите шаблоны копирования и вставки, которые следует абстрагировать
- Проверьте повторяющуюся конфигурацию или магические значения.

## Обработка ошибок
- Обрабатываются ли ошибки на должном уровне (не проглатываются и не перехватываются)?
- Обрабатываются ли крайние случаи явно или документируются как выходящие за рамки?
- Предоставляют ли сообщения об ошибках достаточный контекст для отладки?
- Имеются ли сбои без уведомления (пустые блоки catch, игнорируемые возвращаемые значения)?

## Технический долг
- В каких районах наибольшая нагрузка на содержание?
- Есть ли комментарии TODO/FIXME, на которые следует обратить внимание сейчас?
- Есть ли мертвый код, который следует удалить?

## Инженерный баланс
- Есть ли области, которые являются чрезмерно продуманными (преждевременная абстракция, ненужная сложность)?
- Есть ли области, которые недостаточно спроектированы (хрупкие, хакерские, отсутствуют проверки)?
- Соответствует ли сложность реальным требованиям?
