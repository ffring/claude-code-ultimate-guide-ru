# Ознакомьтесь с таблицей правил приема

Это предлагаемая таблица политик, а не установленный планировщик или проверенное улучшение пропускной способности. Примените его к одной услуге и сопоставимому классу изменений.

| Поле | Решение команды |
|---|---|
| Очередь и ответственный владелец | |
| Допустимый класс изменения и исключенная работа | |
| Результат, понятный пользователю, и свидетельство завершения | Назовите поведение или решенную проблему; регистрировать выпуск и принятие отдельно от принятия на рассмотрение |
| Известный дефект и более ранняя профилактическая проверка | Сохраните инцидент, случай, который проверка должна отклонить, и соседний допустимый случай, который она должна разрешить. |
| Окно наблюдения базовой линии | |
| Прибытие | Первое заявление о готовности при заявленной редакции |
| Событие приемки | Принятие требуемой политики в этой версии |
| Работа в очереди и зарезервированные места | Подсчитайте уникальные изменения; отслеживать авторов в полете отдельно |
| Возрастной показатель и ограничение, утвержденное владельцем | |
| Правило паузы | Приостанавливайте новую разработку, когда достигнута очередь или возрастной предел, емкость недоступна или данные телеметрии устарели. |
| Правило возобновления | Используйте более низкий порог очереди, приемлемый возраст, свежие данные телеметрии и доступные возможности проверки. |
| Работа разрешена во время паузы | Существующая проверка, согласованные исправления, реагирование на инциденты в рамках существующих полномочий |
| Срочное исключение | Именованный утверждающий, причина, ограниченная область действия, замененная работа, срок действия |
| Стоимость данного полиса | Усилия рецензента, повторные проверки, ложные блокировки, обходы и работы по техническому обслуживанию |

Начните с заявленной доступности и именованного верификатора. Первый пилотный проект может остаться ручным. Если прием автоматизирован, перед отправкой зарезервируйте слот проверки атомарно и сделайте выпуск или преобразование идемпотентным под стабильным идентификатором резервирования. Прежде чем повторить попытку, согласуйте неопределенное подтверждение. Отмененная задача не считается принятым изменением. Исправления остаются привязанными к своим первоначальным изменениям. Новая редакция делает недействительными соответствующие доказательства приемки.

Для каждой отложенной задачи фиксируется ее причина, владелец, условие возобновления и точка окончания срока действия или проверки. Повторные отсрочки требуют пересмотра, сокращения объема, переназначения или явной отмены в соответствии с согласованной политикой. Истечение срока действия резервации не дает права ее предыдущему владельцу продолжать действие. Не делайте вывод об усталости на основе телеметрии активности и не добавляйте планировщик только для реализации этой таблицы.

## Настольные учения

Следующие цифры являются синтетическими исходными данными политики, а не рекомендуемыми командными ограничениями. Предположим, что ограничение в очереди составляет три слота occupied/reserved, возобновление в одном или меньшем количестве, выбранный возрастной предел и свежие данные телеметрии.

| Состояние или событие | Ожидаемое решение |
|---|---|
| Два занятых слота; два автора вместе подают заявку на допуск | Зарезервируйте одно место, допустите одного автора, поставьте в очередь другого; никогда не бронируйте слишком много |
| Три занятых слота; существующий рецензент завершает проверку | Дайте обзору завершиться; не отменяйте его, поскольку авторская работа приостановлена |
| Два слота после принятия | Оставайтесь на паузе, пока не будет выполнено условие возобновления |
| Один слот, но его самое старое изменение превышает возрастной предел | Оставайтесь на паузе; решить проблему старения |
| Один слот, приемлемый возраст, свежие данные телеметрии, доступен рецензент | Возобновить прием по правилу бронирования |
| Данные очереди недоступны или рецензент недоступен. | Приостановить новую авторскую работу; сохранять записи и направлять блокировщик к владельцу |
| Срочный запрос без одобрения названного исключения | Держите в очереди |

Записывайте наблюдаемые решения при выполнении реализации. До тех пор это всего лишь ожидаемые результаты. Сравните эквивалентные классы изменений в сопоставимых окнах. Отслеживайте принятые изменения, устраненные дефекты, человеческие усилия и время до результата указанного пользователя, а также размер очереди, чтобы более быстрые утверждения не маскировались под улучшения. Если политика задерживает полный результат или блокирует допустимую работу, не предотвращая известный сбой, пересмотрите ее вместе с владельцем.

В ходе локального контрольного упражнения [](review-control-demo.py) проверяются устойчивые бюджеты и параллельные эффекты на моделируемую услугу. Он не реализует эту политику пропускной способности и не измеряет доступность людей.
