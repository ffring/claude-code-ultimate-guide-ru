## 1. Цель

Этот устав определяет, как сотрудники [Организации] могут использовать помощников по кодированию с использованием искусственного интеллекта, какие инструменты одобрены, какие данные с ними можно использовать и кто несет ответственность за соблюдение требований. Цель состоит в том, чтобы обеспечить продуктивную разработку с помощью искусственного интеллекта, одновременно управляя рисками безопасности, конфиденциальности и нормативного регулирования.

## 3. Правила классификации данных

Все данные в [Организация] классифицируются по четырем уровням. Использование вами инструментов искусственного интеллекта должно соответствовать этой классификации.

| Классификация | Примеры | Claude Code разрешено? | Примечания |
|----------------|----------|----------------------|-------|
| **PUBLIC** | Открытый исходный код, общедоступная документация | Да — без ограничений | |
| **ВНУТРЕННИЙ** | Внутренние инструменты, неконфиденциальный бизнес-код | Да — стандартная конфигурация | Используйте аккаунты компании |
| **КОНФИДЕНЦИАЛЬНО** | Данные о клиентах (не персональные данные), коммерческая тайна, собственные алгоритмы. | Да — только план Enterprise с утвержденной конфигурацией. | |
| **RESTRICTED** | Данные карты PCI, PHI, учетные данные, токены аутентификации, ключи шифрования. | **Никогда** | Никаких исключений |

### Жесткие правила

- ОГРАНИЧЕННЫЕ данные **никогда** не входят в контекстное окно AI — не в подсказках, не в файлах, которые читает Claude, не в качестве примеров.
- Личные учетные записи AI (персональные подписки Pro) можно использовать только с ПУБЛИЧНЫМИ или ВНУТРЕННИМИ данными.
- Учетные данные компании и ключи API ОГРАНИЧЕНЫ. Никогда не вставляйте их в подсказки.

### Техническое правоприменение

Проекты, обрабатывающие КОНФИДЕНЦИАЛЬНЫЕ или ОГРАНИЧЕННЫЕ данные, должны настроить `permissions.deny` в `.claude/settings.json`, чтобы заблокировать доступ ИИ к конфиденциальным файлам. Готовые к использованию конфигурации см. в конфигурации [Standard или Regulated level](../../guide/security/enterprise-governance.md#4-guardrail-tiers).

## 4. Одобренные варианты использования

Следующие виды использования ИИ-помощников по кодированию одобрены без дополнительной проверки:

- Завершение и создание кода для утвержденных классификаций данных
- Обзор кода и анализ качества
- Генерация тестов и мутационное тестирование
- Составление и обновление документации
- Отладка, анализ первопричин, анализ журналов
- Анализ архитектуры внутренних систем
- CLI сценарии, автоматизация, инструменты сборки
- Рефакторинг и очистка кода

## 5. Запрещенные случаи использования

Следующие **не разрешены** без явного письменного разрешения:

| Запрещенное использование | Причина | Процесс исключения |
|----------------|--------|------------------|
| Обработка необработанных данных держателей карт PCI | Нормативное регулирование (PCI DSS) | Нет — технически обеспечено |
| Генерация кода, обрабатывающего незашифрованную PHI без проверки безопасности | Нормативно-правовое регулирование (HIPAA) | Требуется проверка безопасности |
| Автономное внедрение в производство | Требование человеческого надзора | Одобрение технического директора |
| Использование личных учетных записей ИИ для КОНФИДЕНЦИАЛЬНЫХ данных | Данные residency/privacy | Перейти на корпоративный аккаунт |
| Обмен данными о клиентах в качестве примеров в подсказках | Конфиденциальность, обработка данных | Используйте синтетические данные |
| Обход средств управления (перехватчики, запретные правила) | Нарушение правил | Никто |

## 6. Управление сервером MCP

Серверы Model Context Protocol (MCP) расширяют возможности Claude Code и создают дополнительную поверхность риска. Все серверы MCP, используемые в проектах компании, должны быть:

1. Внесен в утвержденный реестр (`.claude/mcp-registry.yaml` в репозитории конфигурации платформы)
2. Привязано к точной версии (никогда не `@latest`)
3. Пересматривается каждые 6 месяцев или при обновлении основной версии.

**Процесс утверждения**: отправьте запрос с указанием имени сервера, URL-адреса источника, предполагаемого варианта использования и объема данных на адрес [platform-team@company.com] или [#claude-code-requests Slack канал].

Неутвержденные MCP, обнаруженные в конфигурациях проекта, будут помечены при запуске сеанса. У разработчиков есть 48 часов, чтобы удалить или получить одобрение.

## 7. Проверка кода и атрибуция

### Атрибуция ИИ

Все запросы на включение, в которых ИИ помогал в написании кода, должны включать раздел раскрытия информации об ИИ:

```markdown
## AI Assistance
- AI tool used: Claude Code
- Scope: [e.g., "Generated tests for auth module", "Refactored payment handler"]
- Human review: Reviewer checked logic, security implications, and edge cases
```

Стандартный трейлер фиксации `Co-Authored-By: Claude <noreply@anthropic.com>` (добавленный автоматически Claude Code) обеспечивает указание авторства для обычных изменений. Явное раскрытие информации о PR требуется для:
- Любое изменение аутентификации или авторизации
- Любые изменения в платежной или финансовой логике
- Любое изменение схемы базы данных
- Любая новая внешняя интеграция API

### Ожидания от проверки кода

Код, созданный ИИ, не освобождается от проверки кода. Рецензенты должны применять такую ​​же или более строгую проверку к разделам, созданным с помощью ИИ, особенно в отношении:
- Пути, чувствительные к безопасности (аутентификация, шифрование, контроль доступа)
- Обработка данных (PII, финансовые данные)
- Крайние случаи и ошибочные ситуации, которые инструменты ИИ часто упускают из виду

## 8. Подотчетность

### Обязанности разработчика

Используя Claude Code в системах компании, вы соглашаетесь:
- Следуйте этому уставу
- Сообщите о подозрении на утечку данных по адресу [security@company.com] в течение 24 часов.
- Участвовать в ежеквартальных проверках доступа
- Заполните контрольный список инструментов искусственного интеллекта при присоединении к команде или смене команды.
- Не обходить средства управления (перехватчики, запретные правила, реестр)

### Обязанности руководителя группы

- Убедитесь, что в проектах настроен соответствующий уровень ограждения.
- Проверяйте реестр MCP ежеквартально.
- Включите устав ИИ в процесс адаптации команды
- Эскалация нарушений устава согласно §9

### Обязанности команды платформы

- Поддерживать конфигурацию общего управления (шаблоны settings.json, перехватчики)
- Рассмотрите запросы на утверждение MCP в течение 1 недели.
- Обновляйте устав при изменении инструментов, уровней или рисков.
- Проводить полугодовой аудит корпоративного управления

## 9. Реагирование на инциденты

### Если вы подозреваете, что данные раскрыты

1. **Немедленно остановить** текущий сеанс ИИ.
2. **Document** какие данные могли быть включены в контекст (какие файлы, какие подсказки)
3. **Отправьте отчет** на адрес [security@company.com] с темой «Раскрытие данных AI» в течение 24 часов.
4. **Не пытайтесь** исследовать или исправить ситуацию без инструкций по безопасности.

### Нарушения устава

| Серьезность | Примеры | Ответ |
|----------|----------|---------|
| **Минор** | Забыл атрибуцию ИИ в PR, кратковременно использовал несанкционированный MCP | Коучинг, исправление |
| **Умеренный** | Использовали личный кабинет с КОНФИДЕНЦИАЛЬНЫМИ данными, обошли хук | Официальное предупреждение, переподготовка |
| **Тяжелая** | Обработка ОГРАНИЧЕННЫХ данных с помощью ИИ, постоянный обход средств контроля | Участие HR/legal |

## 10. Картирование соответствия

В настоящей Хартии рассматриваются следующие требования соответствия:

| Рамки | Соответствующие элементы управления | Настоящая Хартия адресована |
|-----------|------------------|----------------------|
| **SOC 2** | CC6.1 (Логический доступ), CC7.1 (Мониторинг), CC9.2 (риск поставщика) | Классификация данных, реестр MCP, ведение журнала аудита |
| **ISO 27001** | A.8.3 (Ограничение доступа), A.8.25 (Жизненный цикл безопасной разработки), A.5.23 (Облачные сервисы) | Утвержденные инструменты, уровни управления, обработка данных |
| **HIPAA** (если применимо) | Правило безопасности §164.312 (контроль доступа, контроль аудита) | ОГРАНИЧЕННЫЙ запрет данных, ведение журнала в режиме соответствия |
| **PCI DSS** (если применимо) | Требование 6.3 (Уязвимости безопасности), Требование 12 (Политика) | Запрет данных PCI, требования к проверке кода |
| **GDPR/CCPA** | Минимизация данных, ограничение цели | Классификация CONFIDENTIAL/RESTRICTED, правила области данных |
