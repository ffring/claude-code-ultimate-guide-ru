# Обсуждение, этап 3: Концепции

Создает исчерпывающий каталог всех идентифицируемых концепций в исходном материале. Каждая концепция пронумерована, классифицирована и оценена по ее потенциалу разговора.

## Когда использовать этот навык

- После этапа 1 (и этапа 2 в режиме REX)
- До этапа 4 (должность нуждается в концептуальном каталоге)
- Если вам нужен структурированный перечень того, что доступно, прежде чем выбирать ракурс

## Что дает этот навык

1. **Читает сводку**: загружает `{slug}-summary.md`
2. **Читает временную шкалу** (если доступно): дополняет оценку проверенными датами.
3. **Концепции экстрактов**: полное сканирование исходного материала
4. **Categorizes**: присваивает каждому понятию категорию предметной области.
5. **Scores**: ВЫСОКИЙ / СРЕДНИЙ / НИЗКИЙ для потенциала разговора
6. **Необязательное пополнение репозитория**: если указан repo_path, анализируются концепции конфигурации AI.
7. **Записывает выходные файлы**

## Вход

- `talks/{YYYY}-{slug}-summary.md` (обязательно)
- `talks/{YYYY}-{slug}-timeline.md` (необязательно, расширяет концепции REX)
- `repo_path` (опционально, для извлечения концепции config/infrastructure)

## Выход

- `talks/{YYYY}-{slug}-concepts.md` (основной каталог)
- `talks/{YYYY}-{slug}-concepts-enriched.md` (если указан путь_репо)

## Критерии оценки

### ВЫСОКИЙ: сильный потенциал
- Демонстрация вживую или со скриншотом
- Противоречиво или неожиданно (вызывает реакцию)
- Связано с проверяемыми номерами
- Конкретно и действенно (объясняется за 30 секунд)
- Отличие от других докладов на ту же тему

### СРЕДНИЙ: Умеренный потенциал
- Полезно, но ожидаемо (не удивительно)
- Отсутствуют конкретные доказательства или цифры
- Слишком специфично для одного конкретного контекста
- Требуется слишком много объяснений для 30-минутного разговора

### НИЗКИЙ: Слабый потенциал
- Слишком абстрактно или философски без конкретного обоснования.
- Уже широко освещено другими докладчиками
- Требуется определенный технический опыт
- Трудно проиллюстрировать на слайде.

**Оценочная дисциплина**: Макс. 30% ВЫСОКИЙ. Если все ВЫСОКОЕ, ничего нет.

## Стандартные категории

| Категория | Описание |
|----------|-------------|
| **Архитектура** | Технические решения, стек, структурные закономерности |
| **Инструмент** | Инструменты, рабочие процессы, автоматизация |
| **Философия** | Принципы, мышление, подходы |
| **Рабочий процесс** | Рабочие процессы, привычки |
| **Передача знаний** | Адаптация, команда, обмен знаниями |
| **Проблемы** | Встречающиеся препятствия, компромиссы |
| **Открытый исходный код** | Вклады, обмен, сообщество |
| **AI Конфигурация** | Конфигурация ИИ, профили, подача знаний |
| **AI Инфраструктура** | Агенты, навыки, хуки, команды |
| **AI Качество** | Обзор, тесты, антипаттерны |
| **AI Безопасность** | Защитные крюки, ограждения |
| **Оптимизация** | Производительность, снижение cost/token |

Адаптируйте или создайте категории, если в докладе есть темы, специфичные для конкретной предметной области.

## Выходной формат

### concepts.md

```markdown
# Key Concepts: {provisional title}

**Date**: {date}
**Source**: {source path} x Summary x Timeline (if available)

---

## Concept table

| # | Concept | Category | Short description | Talk potential |
|---|---------|----------|------------------|----------------|
| 1 | **{Concept name}** | {Category} | {1-2 concrete sentences} | HIGH / MEDIUM / LOW |
...

---

## Category breakdown

| Category | Count | HIGH concepts | Examples |
|----------|-------|---------------|---------|
| {category} | {n} | {n} | {examples} |
...
| **TOTAL** | **{N}** | **{N HIGH}** | |

---

## Recommendations for positioning

{3-5 sentences on concept clusters that could form the talk's acts.
Which HIGH concepts reinforce each other? What narrative arc is emerging?}
```

### concepts-enriched.md (если доступно репо)

Та же структура, но основное внимание уделяется тому, что показывает анализ репо:
- Специализированные агенты (количество, размер, роли)
- Вызываемые навыки (каталог, охваченные области)
- Системные перехватчики (события, логика)
- Модульная конфигурация (профили, модули, конвейер)
- Шаблоны кода для конкретного проекта

Для каждой расширенной концепции укажите:
- **Точный источник**: файл и приблизительная строка
- **Demo-able**: yes/no (можно ли это показать на слайде или вживую?)

## Anti-patterns

- Создание слишком детализированных концепций (одна функция = максимум одна концепция)
- Оценка ВЫСОКАЯ по умолчанию (будьте выборочными)
- Опускаем концепции LOW (их полезно позиционировать как «углы, которых следует избегать»).
- Дублирование очень похожих концепций (вместо этого объедините их)
- Анализ кода репо, если репо недоступно

## Контрольный список проверки

- [ ] Определено минимум 15 концепций (более 20 для REX с репо)
- [ ] Каждое понятие имеет конкретное описание в 1-2 предложениях.
- [ ] Оценки калибруются (не все ВЫСОКИЕ, не все НИЗКИЕ)
- [ ] Категории охватывают темы резюме.
- [ ] Имеются рекомендации по позиционированию
- [ ] Файлы сохранены по правильным путям

## <a name="tips"></a>Советы

- Каталог концепций — это то, из чего черпается Этап 4 (Позиция); чем он богаче, тем лучше выбор ракурсов
- Концепции LOW ценны: они определяют границы того, чего НЕ следует говорить в разговоре.
- Если две концепции кажутся вам очень похожими, объедините их (меньший и более четкий список лучше длинного разбавленного).
