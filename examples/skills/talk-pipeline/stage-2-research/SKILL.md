# Этап разговора 2: Исследование (только в режиме REX)

Создает git-доказательство для доклада REX. Перекрестные ссылки на историю git, CHANGELOG и сводку этапа 1 для получения проверенной временной шкалы и анализа скорости.

**Автоматически пропускается в режиме `--concept`.** Запускается только в том случае, если исходным материалом является REX с доступом к репозиторию git.

## Когда использовать этот навык

- После этапа 1 (отрывок) при построении разговора REX
- Когда у вас есть доступ к git-репозиторию проекта
- Чтобы сверить метрики, упомянутые в исходном материале, с фактическими данными git.

## Что дает этот навык

1. **Читает резюме**: понимает период и темы этапа 1.
2. **Gitarchaeology**: извлекает метрики скорости (только команды только для чтения)
3. **Анализ журнала изменений**: сканирование выпусков, функций, документированных показателей.
4. **Перекрестные ссылки**: выравнивает git, CHANGELOG и сводку.
5. **Строит график**: проверенные даты, а не приблизительные
6. **Записывает 3 выходных файла**

## Вход

- `talks/{YYYY}-{slug}-summary.md` (обязательно с этапа 1)
- `repo_path`: абсолютный путь к репозиторию git.
- Необязательно: путь CHANGELOG, если он отличается от `{repo_path}/CHANGELOG.md`.

## Выход

Три файла:
- `talks/{YYYY}-{slug}-git-archaeology.md`
- `talks/{YYYY}-{slug}-changelog-analysis.md`
- `talks/{YYYY}-{slug}-timeline.md`

## Команды Git (только для чтения)

```bash
# Commits by month
git -C {repo_path} log --pretty=format:"%Y-%m" | sort | uniq -c

# Commits by contributor
git -C {repo_path} shortlog -sn --no-merges

# First and last date
git -C {repo_path} log --pretty=format:"%ad" --date=short | tail -1
git -C {repo_path} log --pretty=format:"%ad" --date=short | head -1

# Merged PRs (if merge commit convention)
git -C {repo_path} log --merges --oneline | wc -l

# Tags (releases)
git -C {repo_path} tag --sort=version:refname

# Velocity peak (busiest months)
git -C {repo_path} log --pretty=format:"%Y-%m" | sort | uniq -c | sort -rn | head -5
```

## Ключевые правила

- **Только для чтения**: нет команд git, изменяющих состояние репозитория.
- **Проверьте перед утверждением**: дата не найдена в git = "unverified"
- **Перекрестная ссылка**: отмечайте несоответствия между источниками, не выбирайте один произвольно
- **Granularity**: минимум по месяцам; неделя за неделей, если менструация короткая (< 2 месяцев)

## Anti-patterns

- Запуск команд git, изменяющих репозиторий
- Оценка дат вместо их проверки в git
- Округление показателей без пометки
- Тихое объединение противоречивых данных из разных источников
- Исключение периодов затишья (плато тоже рассказывают историю)

## Контрольный список проверки

- [ ] Выполняются только команды git только для чтения
- [ ] Временная шкала охватывает весь период от сводки
- [ ] Все метрики имеют явный источник (git или CHANGELOG).
- [ ] Конфликты между источниками отмечены в специальном разделе.
- [ ] 3 файла созданы и сохранены

## <a name="tips"></a>Советы

- Временная шкала – это то, что используется на этапе 3 (Концепции) для повышения оценки концепций; хороший график делает концептуальный каталог сильнее
- Стоит отметить, что «периоды покоя» в скорости git часто соответствуют самым сложным инженерным задачам.
- Если в CHANGELOG нет тегов версии, вернитесь к привязке на основе даты.
