# Агент-оценщик

Обнаружьте каждый пользовательский агент в области действия, проверьте его на соответствие собственной схеме его хоста, оцените его, а затем просмотрите его вместе с пользователем по одному агенту за раз.

Агенты выбираются родительским агентом из их `description`. Расплывчатое или перекрывающееся описание делает делегирование непредсказуемым, поэтому перекрытие — это дефект корректности, а не проблема стиля. Цель состоит в том, чтобы сделать каждого агента загружаемым, отдельным, правильно смоделированным и безопасным для делегирования.

## <a name="when-to-use"></a>Когда использовать

- Аудит парка агентов перед подключением его к рабочему процессу делегирования или оркестрации.
- Родительский агент продолжает делегировать полномочия не тому агенту или никогда не делегирует полномочия
- После копирования агентов из другого проекта или установки плагина
- Добавлен новый агент, который может конфликтовать с существующими.
- Периодическая гигиена: все ли эти агенты по-прежнему делают что-то особенное?

Не для: навыков (`eval-skills`), перехватчиков (`eval-hooks`), правил Claude Code (`eval-rules`) или отчета о состоянии конфигурации между хостами (`eval-agent-config`).

## Ссылка на хост

### Claude Code: где загружаются агенты

Claude Code выбирает определение из местоположения с наивысшим приоритетом, когда несколько имеют общий `name`:

| Приоритет | Расположение | Область применения |
|---|---|---|
| 1 | Каталог управляемых настроек, `.claude/agents/` | Организация |
| 2 | Флаг `--agents` CLI (JSON или путь к файлу JSON с `-p`) | Текущая сессия |
| 3 | `.claude/agents/` | Проект |
| 4 | `~/.claude/agents/` | Пользователь |
| 5 | Каталог плагина `agents/` | Где плагин включен |

- `.claude/agents/` и `~/.claude/agents/` сканируются рекурсивно. Подпапки не меняют идентичность.
- Агенты проекта обнаруживаются при переходе из рабочего каталога; каждый `.claude/agents/` до корня репозитория сканируется, и побеждает определение, ближайшее к рабочему каталогу.
- Каталоги, добавленные с помощью `--add-dir` или `/add-dir`, также добавляют свой `.claude/agents/`.
- Подпапки плагина становятся частью идентификатора области действия: `agents/review/security.md` в плагине `my-plugin` регистрируется как `my-plugin:review:security`.

### Claude Code: файлы, которые среда выполнения пропускает автоматически.

- Нет `name`: рассматривается как документация, хранящаяся рядом с агентами.
- Открытие `---` не в первой строке: читается как отсутствие вступительной части.
- `name`, начинающийся с `-` или содержащий `:`: пропущен, ошибка в журнале отладки.
- `name` без `description`: пропускается.
- YAML, который не анализируется: пропущен. Агент плагина без `name` или с неразбираемым вступлением по-прежнему загружается под своим именем файла.

«Не анализирует» означает собственный синтаксический анализатор Claude Code, который принимает некоторые элементы, которые строгая библиотека YAML отклоняет, например, многострочный `description` без кавычек, строки которого содержат `: `. Принимайте решение с помощью `claude plugin validate <agents directory>` (v2.1.233 или новее) или списка агентов сеанса (`/agents`), а не только строгой библиотеки YAML. Файл, загрузку которого отклоняет только строгий анализатор: сообщите об этом как предупреждение о переносимости (другие инструменты могут его отклонить) и предложите блочный скаляр `>`.

Два файла в одном дереве агентов, которые объявляют один и тот же `name`: загружается только один, выбранный по порядку чтения файловой системы, а не по документированному приоритету. Об этом сообщает `/doctor`.

### Claude Code: поля заголовка

Требуются только `name` и `description`. Имена полей имеют верблюжий регистр и должны точно совпадать; неизвестное поле игнорируется без ошибки.

| Поле | Примечания |
|---|---|
| `name` | Необходимый. Уникальная идентичность; хуки получают его как `agent_type`. Имя файла не обязательно должно совпадать. |
| `description` | Необходимый. Когда родитель должен делегировать полномочия. |
| `tools` | Строка, разделенная запятыми, или список YAML. Опущено: наследует все инструменты, доступные субагентам. Нет разрешимой записи: агент обычно не запускается. |
| `disallowedTools` | Удален из унаследованного или объявленного списка. Спецификатор, такой как `Bash(git push *)`, удаляет весь инструмент. |
| `model` | `sonnet`, `opus`, `haiku`, `fable`, полный идентификатор модели или `inherit`. |
| `permissionMode` | `default` (псевдоним `manual`), `acceptEdits`, `auto`, `dontAsk`, `bypassPermissions`, `plan`. Игнорируется, когда основной разговор ведется в `bypassPermissions`, `acceptEdits` или автоматическом режиме. |
| `maxTurns` | Агентское ограничение поворота; вывод возвращается с пометкой «частичный». |
| `skills` | Навыки предварительно загружаются полностью при запуске. |
| `mcpServers` | Имена серверов или встроенные определения серверов. |
| `hooks` | Перехватчики активны во время работы этого агента; `Stop` становится `SubagentStop`. Перехватчики агента проекта запускаются только после принятия доверия к рабочей области. |
| `memory` | Область постоянной памяти: `user`, `project` или `local`. |
| `background` | `true` оставляет агента в фоновом режиме. |
| `omitClaudeMd` | `true` запускается без файлов пользователя, проекта и локальных файлов CLAUDE.md. |
| `effort` | `low`, `medium`, `high`, `xhigh`, `max`; доступные уровни зависят от модели. |
| `isolation` | `worktree` запускает агент во временном рабочем дереве git. |
| `color` | Цвет дисплея. |
| `initialPrompt` | Первая очередь пользователя, когда агент работает в качестве основного агента сеанса. |
| `experimental` | Карта; читается только `cacheTtl: 5m` или `1h` и только из файлов агента. |

Агенты плагинов игнорируют `hooks`, `mcpServers` и `permissionMode`; `initialPrompt` также игнорируется для агентов плагинов.

Пометить как нераспознанные (молча игнорируемые Claude Code): `allowed-tools`, `disallowed-tools`, `context`, `argument-hint` и любой другой ключ, которого нет в таблице. Это поля навыков, а не поля агента.

### Claude Code: разрешение модели

1. Параметр `model` для каждого вызова, передаваемый родительским элементом.
2. Заголовок агента `model` (`inherit` выбирает основную модель разговора)
3. `CLAUDE_CODE_SUBAGENT_MODEL`, если установлен псевдоним или идентификатор модели.
4. Модель основного разговора

`CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` заставляет каждого агента игнорировать свое поле `model`. Псевдоним семейства преобразуется в точную модель основного диалога, если эта модель принадлежит к тому же семейству. Заменяется значение, заблокированное `availableModels` организации.

### Claude Code: инструменты, которые субагент никогда не получает

Среда выполнения удаляет эти инструменты из каждого подагента, не являющегося разветвлением, даже если они перечислены в `tools`: `AskUserQuestion`, `EndConversation`, `EnterPlanMode`, `ExitPlanMode` (кроме `permissionMode: plan`), `ScheduleWakeup`, `WaitForMcpServers` и `Agent` на пределе глубины.

### Codex: специальные агенты

| Элемент | Правило |
|---|---|
| Расположение | Один файл TOML для каждого агента в `~/.codex/agents/` (личный) или `.codex/agents/` (проект). |
| Необходимые ключи | `name`, `description`, `developer_instructions` |
| Личность | `name` — источник истины; имя файла - это всего лишь соглашение |
| Дополнительные ключи | Любой поддерживаемый ключ `config.toml`, например `model`, `model_reasoning_effort`, `sandbox_mode`, `mcp_servers`, `skills.config`; пропущенные ключи наследуются от родительского сеанса |
| Встроенные агенты | `default`, `worker`, `explorer`; собственный агент с таким же именем имеет приоритет |
| Глобальные настройки | `[agents]` в `config.toml`: `enabled`, `max_concurrent_threads_per_session` (устаревший `max_threads`), `default_subagent_model`, `default_subagent_reasoning_effort`, `interrupt_message` |

Агент Markdown с фронтальной частью YAML или файл TOML, использующий `prompt` вместо `developer_instructions`, представляет собой определение в форме Claude и не удовлетворяет схеме Codex.

## Критерии оценки

### Агенты Claude Code (15 очков)

| # | Критерий | Макс | Что проверяется |
|---|---|---|---|
| 1 | **загружаемый** | 2 | Анализ Frontmatter для Claude Code (см. выше) и `name` действителен: присутствует, нет `:`, нет ведущего `-` (1); `description` присутствует (1). Значение 0 здесь означает, что среда выполнения пропускает файл: прекратите оценку и сообщите о нем как о блокирующем. Ошибка «только YAML» сохраняет суть и добавляет предупреждение о переносимости. |
| 2 | **описание** | 3 | Указывает, когда делегировать (1); отличим от любого другого агента в той же области действия (1); кратким, поскольку объединенные описания, превышающие 15 000 токенов, вызывают предупреждение при запуске (1) |
| 3 | **модель** | 2 | Заявлено или намеренно унаследовано (1); уровень соответствует задаче (1) |
| 4 | **инструменты** | 3 | `tools` явный (1); нет инструмента с возможностью записи (`Bash`, `Edit`, `Write`, `NotebookEdit`), если задача не изменяет файлы или не запускает команды (1); `disallowedTools` или `tools` исключает `Agent`, когда агент не должен дальше делегировать (1) |
| 5 | **Системная подсказка** | 5 | Роль и сфера применения в первом пункте (1); что он делает и чего не делает (1); договор поставки или возврата (1); нет заполнителя или TODO (1); нет инструкций, требующих инструмента, который удаляет среда выполнения, например, задания пользователю вопроса (1) |
| Бонус | **Полевая гигиена** | +1 | Нет нераспознанных полей, нет недопустимых значений полей и нет полей, которые игнорирует источник агента (например, `hooks` в подключаемом агенте). |

### Агенты Codex (12 очков)

| # | Критерий | Макс | Что проверяется |
|---|---|---|---|
| 1 | **загружаемый** | 3 | TOML анализирует (1); `name` и `description` присутствуют (1); `developer_instructions` присутствует и непустой (1) |
| 2 | **описание** | 3 | Те же проверки, что и Claude Code, в отношении других агентов Codex и встроенных модулей. |
| 3 | **модель и усилие** | 2 | `model` и `model_reasoning_effort` устанавливаются вместе, когда модель переопределена (1); уровень соответствует задаче (1) |
| 4 | **инструкции** | 4 | Роль и масштабы (1); границы (1); договор возврата (1); нет заполнителя (1) |

**Пороги:** Хорошо >= 80%, Требует доработки 60-79%, Исправление < 60%.

### Сигналы уровня модели

| Работа | Claude Code | Codex (согласно документации субагента Codex) |
|---|---|---|
| Механические: поиск, извлечение, двоичная проверка. | `haiku` | более легкая модель, такая как `gpt-6-luna` |
| Ограниченное суждение: обзор, отладка, тесты, документация | `sonnet` | `gpt-6-sol`, `medium` усилие |
| Сквозной синтез: архитектура, модель угроз, многосистемные компромиссы | `opus` | `gpt-6-sol`, `high` или выше |

Отметьте оба направления: модель с недостаточной мощностью для работы по суждению и модель с повышенной мощностью для механической работы, которая выполняется много раз. Государственная стоимость на основе опубликованных цен вместо фиксированного мультипликатора; например, в руководстве указаны Opus 5.5 по цене 4 доллара США/20 долларов США и Haiku 5.5 по цене 0,10 доллара США/0,50 доллара США за миллион токенов input/output (предлагается до 100 тысяч токенов). Haiku 5.5 поддерживает усилие и по умолчанию используется `medium`; только устаревшая версия Haiku 4.5 не имеет параметра усилий, поэтому поле `effort` на агенте, закрепленном за Haiku 4.5, не имеет никакого эффекта.

### Антипаттерн «человек в цикле»

Субагенты не получают `AskUserQuestion` или инструментов режима планирования и по умолчанию работают в фоновом режиме. Любые инструкции системы, такие как «спросить пользователя», «подтвердить перед удалением» или «дождитесь одобрения», не могут быть выполнены. Безопасная альтернатива: «Если контекста недостаточно, верните `{ "status": "needs_context", "missing": [...] }` и остановитесь».

## Инструкции по выполнению

### Шаг 1: Открытие

Определите область из аргумента или по умолчанию выберите проект плюс область пользователя каждого запрошенного хоста.

| Запрос | Бегать |
|---|---|
| По умолчанию | Шаги 1–6, с интерактивным обзором |
| `audit-only`, или пользователь просит не вносить изменения | Шаги 1–4 и 6: перечислите предлагаемые изменения вместо того, чтобы спрашивать или редактировать |
| В наличии более 20 агентов | Сортировка: запустите шаги 1–3 и структурные проверки шага 2 для каждого файла, полностью оцените только агентов с обнаружением плюс выборку остальных и сообщите об остальных в одной компактной таблице. |

```bash
# Claude Code: every .md file, recursively (-L follows symlinked directories)
find -L .claude/agents -name "*.md" 2>/dev/null
find -L ~/.claude/agents -name "*.md" 2>/dev/null   # user scope, when requested

# Codex: one TOML file per agent
find -L .codex/agents -name "*.toml" 2>/dev/null
find -L ~/.codex/agents -name "*.toml" 2>/dev/null  # user scope, when requested
```

Также перечислите вложенные каталоги `.claude/agents/` между рабочим каталогом и корнем репозитория.

Если отчет `ctxharness doctor --format json`, созданный во время выполнения этой задачи, доступен, отчеты каждого уровня агентов, обнаружившие его, должны появиться в аудите.

Выполняется, когда: каждый файл-кандидат указан с указанием его хоста и области действия или в отчете указано, что каталог агента не существует, и работа прекращается.

### Шаг 2. Разберите и проверьте загружаемость

Для каждого файла прочитайте его полностью и запишите: хост, область действия, длину `name`, `description`, `model`, `tools` или `(inherits)`, все остальные ключи, тело или количество строк `developer_instructions`.

Для Claude Code `claude plugin validate .claude/agents` (v2.1.233 или новее) сообщает о файлах, заголовок которых не анализируется; он не помечает анализируемый файл без `name`, поэтому проверьте это отдельно. Он только читает файлы, поэтому в режиме `audit-only` он безопасен.

Проверьте значения, а также имена полей:

- `permissionMode` — одно из документированных значений; все остальное, например `ask`, не является режимом.
- `model` — псевдоним из таблицы или полный идентификатор модели; `effort`, `memory`, `isolation` и `experimental.cacheTtl` используют свои документированные значения.
- Каждая запись `tools` и `disallowedTools` называет инструмент из справочника инструментов (https://code.claude.com/docs/en/tools-reference) или инструмент MCP (`mcp__server__tool`). Недокументированное имя, например `MultiEdit`, не разрешается: пометьте его и пометьте агент как риск запуска, если ни одна запись не разрешается.
- Каждая запись `skills` соответствует навыку, доступному в этой области.

Выполняется, когда: каждый файл классифицируется как загружаемый, пропущенный средой выполнения (с указанием причины из ссылки на хост выше) или нечитаемый, с указанием недопустимых значений.

### Шаг 3. Проверьте столкновения и перекрытие.

- Один и тот же `name` дважды в одном дереве агентов Claude Code или пользовательский агент Codex, который дублирует встроенный: сообщает, какой файл выигрывает или что выбор не определен.
- Тот же `name` в области пользователя и проекта: определение проекта побеждает внутри этого проекта, поэтому пользовательская копия там мертва. Перечислите эти пары и укажите, различаются ли эти два определения.
- Сравните описания попарно внутри каждого хоста и области. Пары флагов, которые требуют одного и того же типа запроса без установленной границы.

Выполняется, когда: каждая пара коллизий и перекрытий указана с обоими путями к файлам.

### Шаг 4: Оценка

Примените таблицу оценок хоста. Определите уровень модели из системного приглашения и отметьте несоответствия.

Выполняется, когда: каждый загружаемый агент имеет оценку, статус и не более трех приоритетных исправлений.

### Шаг 5: Интерактивный обзор

Обрабатывайте агентов один за другим. Покажите хост, область действия, `name`, модель, инструменты, оценку и отмеченные проблемы, а затем спросите:

1. Достаточно ли конкретное описание, чтобы отличить этого агента? (у/переписать)
2. Правильный ли уровень модели? (у / изменить)
3. Правильно ли определены инструменты? (y/добавить/удалить)
4. Что-нибудь нужно изменить в системном приглашении или инструкциях? (описать/пропустить)

Примените подтвержденные изменения с возможностью редактирования файлов и подтвердите каждое из них. Для агента, который пользователь помечает как устаревший, перед удалением файла попросите явно сказать «да, удалить его».

Выполняется, когда: у каждого агента есть записанный ответ (подтвержденный, отредактированный, помеченный как устаревший или пропущенный).

## Краевые случаи

- **`tools` опущен**: агент наследует пул инструментов подагента. Это не ошибка загрузки; пометьте его для проверки, если агенту не требуется доступ для записи или оболочки.
- **`model` опущен**: разрешение снижается до `CLAUDE_CODE_SUBAGENT_MODEL` или модели основного разговора. Сообщите об эффективном источнике.
- **`allowed-tools` присутствует вместо `tools`**: игнорируется Claude Code, поэтому агент наследует все инструменты. Пометить как исправление с высоким приоритетом.
- **`effort` на агенте Haiku**: нет эффекта; предложите удалить.
- **Агент плагина с `hooks`, `mcpServers` или `permissionMode`**: игнорируется; пользователь должен скопировать агент в `.claude/agents/` или `~/.claude/agents/`, чтобы использовать их.
- **Файл агента в каталоге, созданном после начала сеанса.**: Claude Code не просматривает его до перезапуска; сообщите об этом, когда новый агент «не появится».
- **Codex TOML, использующий `prompt`**: не поле Codex; Требуется `developer_instructions`.
- **Описание «использовать для всего»**: приемлемо только для намеренного обобщения; отмечайте других.
