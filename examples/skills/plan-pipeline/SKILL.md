# Оркестратор конвейера планирования

Организует весь конвейер от плана до выполнения. Может запускать весь конвейер или одну изолированную стадию.

## Этапы

| Этап | Навык | Цель |
|-------|-------|---------|
| 1 | `/plan-pipeline:ceo-review` | Бросьте вызов брифу, зафиксируйте направление продукта |
| 2 | `/plan-pipeline:eng-review` | Архитектура блокировки, диаграммы и тестовая матрица |
| 3 | `/plan-pipeline:start` | 5-этапное планирование: PRD, исследования, нежелательные реакции, список задач. |
| 4 | `/plan-pipeline:validate` | Двухуровневая проверка перед написанием кода |
| 5 | `/plan-pipeline:execute` | Изоляция рабочего дерева, параллельные агенты, контроль качества, PR |

## Использование

```
/plan-pipeline                     # full pipeline, asks for context
/plan-pipeline --from=start        # skip gates, start from planning phase
/plan-pipeline --from=validate     # validate an existing plan
/plan-pipeline --from=execute      # execute a validated plan
```

## Когда использовать каждый этап

**ceo-review**: используйте перед любой важной функцией, когда направление не заблокировано. Особенно ценно, когда запрос конкретен (специфичность сигнализирует о свернутом пространстве решения).

**eng-review**: использовать после блокировки направления. Требуется для функций с асинхронными компонентами, внешними зависимостями или многоэтапными потоками.

**start**: используйте для любой нетривиальной функции, затрагивающей более двух файлов или включающей архитектурные решения.

**validate**: всегда перед выполнением. Стоимость проверки незначительна по сравнению со стоимостью обнаружения проблем в середине выполнения.

**execute**: после проверки подтверждается, что все проблемы решены.

## <a name="workflow"></a>Рабочий процесс

1. **Собрать контекст**: что строим и с какого этапа начинаем?
2. **ceo-review**: ворота направления продукта (можно пропустить с помощью `--from=eng-review` или более поздней версии)
3. **eng-review**: шлюз архитектуры (можно пропустить с помощью `--from=start` или более поздней версии)
4. **CHECKPOINT**: перед планированием попросите пользователя подтвердить направление и архитектуру.
5. **start**: запустить 5-фазное планирование, создать `docs/plans/plan-{name}.md`
6. **CHECKPOINT**: представить план для проверки перед проверкой.
7. **validate**: двухуровневая проверка (структурные + специальные агенты)
8. **execute**: изоляция рабочего дерева -> параллельные агенты -> ворота качества -> PR

## Граф зависимостей

```
   ceo-review
        |
   eng-review
        |
      start
        |
    validate
        |
    execute
```

## Примечания

Каждый этап записывает свои выходные данные на диск перед началом следующего этапа. Если конвейер прерван, возобновите его с помощью `--from=<stage>`, используя правильное имя этапа. Все решения записываются в `docs/plans/plan-{name}.md`, а соответствующие АДР — в `docs/adr/`.
