# agent-rationale

Записывает краткое обоснование каждого фрагмента, который вы изменили, в примечание git к коммиту, чтобы рецензент читал ваши причины рядом с кодом, а не восстанавливал их. Заметка привязывается к фрагменту посредством хеша добавленных строк; если кусок изменится позже, `show` повторно привязывает заметку к тексту аннотированной строки, когда этот текст появляется ровно один раз в добавленных строках коммита для файла, и в противном случае сообщает, что заметка устарела, а не угадывает.

Это шаблон из [Claude Code Ultimate Guide](https://cc.bruniaux.com/guide/), продемонстрированный собственными тестами, а не измеренное улучшение качества обзора.

## <a name="workflow"></a>Рабочий процесс

1. **Сначала выполните коммит.** Примечания прикрепляются к коммиту. Зафиксируйте изменение, которое хотите объяснить. Готово, когда `git log -1` это покажет.

2. **Одно примечание для каждого фрагмента, который рецензент может задать вопрос.** Для каждого такого фрагмента выберите одну строку внутри него (номер строки в зафиксированной версии файла) и запишите:

   ```bash
   python3 -I ${CLAUDE_SKILL_DIR}/scripts/rationale.py add --file src/cart.py --line 42 \
     --intent "Sum prices, not item objects" \
     --rejected "Give Item an __add__ method" \
     --risk "Items without a price attribute now raise AttributeError" \
     --evidence "tests/test_cart.py::test_total_uses_price" \
     --open-question "unknown"
   ```

   - `--intent` является обязательным. Построчно пишите, для чего предназначены изменения, а не что они делают.
   - `--rejected`: альтернативу, которую вы рассматривали и почему вы ее не выбрали.
   - `--risk`: что это может сломать, для кого.
   - `--evidence`: тест, команда или вывод, поддерживающий изменение. Напишите `unknown`, а не изобретайте его.
   - `--open-question`: на что вы не смогли решить и хотите, чтобы рецензент ответил. `unknown` — правильный ответ для любого поля, кроме намерения.

   Готово, когда команда печатает `rationale recorded`. Строка вне изменений коммита отклонена; удаленные строки и двоичные файлы не могут быть аннотированы, поэтому выберите ближайшую добавленную строку. Пути могут быть заданы из любого каталога и хранятся в корне репозитория.

3. **Проверьте, что увидит рецензент.**

   ```bash
   python3 -I ${CLAUDE_SKILL_DIR}/scripts/rationale.py show
   ```

   Каждая заметка имеет вид `[anchored]`, `[reanchored]` (кусок изменился, но строка с аннотацией все еще присутствует) или `[stale]` (строка с аннотациями исчезла или ее текст больше не уникален; проверьте еще раз, прежде чем доверять заметке). Готово, когда каждая написанная вами заметка отображается как закрепленная.

## Ведите заметки, изменяя и перебазируя

Git перемещает заметки на `git commit --amend` и `git rebase` только по указанию. Один раз для каждого репозитория:

```bash
git config notes.rewriteRef refs/notes/rationale
```

Локальный `git merge --squash` создал коммит без примечания в тесте этого руководства; сквош, сделанный кнопкой слияния в кузнице, не тестировался. По умолчанию заметки не отправляются: `git push origin refs/notes/rationale`.

## Правила

- Напишите заметку о том, что вы на самом деле сделали и проверили. Обоснование — это утверждение, которое проверит рецензент, а не само по себе доказательство.
- Не помещайте в заметку секреты, учетные данные или данные клиента: заметки передаются вместе со ссылками на репозиторий.
- Храните человеческие записи под другими заметками, ссылка: `refs/notes/rationale` содержит один документ с обоснованием агента для каждого коммита, а `show` отклоняет заметку, которую он не писал.
