# Разблокировать сеанс, замедленный песочницей

Написать отчет о блокировке дешево, а действовать дорого. Этот навык загружается заранее
проверка, поэтому отчет, который доходит до сопровождающего, стоит его времени.

Приведенные ниже измерения получены на одной машине macOS на Claude Code.
С 2.1.220 (июль 2026 г.) по 2.1.302 (октябрь 2026 г.). Относитесь к числам как к
иллюстративен и метод как точка.

## Самодиагностика, все одиннадцать проверок, прежде чем жаловаться

Запустите их по порядку. На каждом шаге указано, что запускать, что читать и каков результат.
позволяет сделать вывод. Шаги 3, 3b, 5b и 5c окупаются быстрее всего.

**1. Не делайте никаких выводов из описания песочницы в системной подсказке.**

В нем перечислены шаблоны `permissions.deny Read(...)` под `read.denyOnly`, например
`**/*.pem` или `**/.env*`. Достигнуты ли эти шаблоны подпроцесса Bash.
менялся в разных версиях и по-прежнему зависит от местоположения: в версии 2.1.302 изолированная программная среда
`wc -c` считывает `.env` вне проекта, на который распространяется такое правило, а
Сентябрьский билд `ls` отказался от проекта `.env`. Одна сессия завершила целое
Конвейер Python был неработоспособен только из этого списка; каждый шаг работал, когда
измерено. Измерьте именно то значение, которое вас интересует.

**2. Подтвердите, что тестируемая команда действительно выполнялась в изолированной программной среде.**

```bash
echo $TMPDIR
```

Путь под корнем временной среды песочницы (`/tmp/claude-NNN`) означает измерение
имеет значение. Системный временный каталог (`/var/folders/.../T/`) означает вызов
сбежал, и ничто из того, что следует за ним, не доказывает ничего о поведении в песочнице.
Запустите это в отдельном вызове: привязка его к тестируемой команде изменит
ответ (шаг 3).

**3. Проверьте только команду, ничего до нее и ничего после нее.**

Начиная с версии 2.1.277, каждая команда в вызове должна соответствовать записи `excludedCommands`.
`cd ... &&`, `;`, канал, перенаправление на файл или подстановка `$(...)` сохраняют
весь вызов изолирован в изолированной среде, даже если запись для вашего инструмента существует и правильна.

Рабочий каталог оболочки сохраняется между вызовами Bash внутри проекта, поэтому
нет необходимости в `cd` на той же линии. Передайте путь в качестве аргумента, когда
команда принимает один.

```bash
# wrong: the call no longer matches any entry, everything stays sandboxed
cd /path/to/project && pnpm exec prisma migrate status
pnpm exec prisma migrate status | head -20
pnpm exec prisma migrate status > out.log 2>&1

# right: one command, bare, read the raw output
pnpm exec prisma migrate status
```

Более ранняя версия этого навыка рекомендовала `cd /path && command` как правильный вариант.
форма. Каждый зонд последующего диагноза содержал `| head` или
`&& echo`, и сессия ошибочно пришла к выводу, что `excludedCommands` инертен.

**3b. В измеряемой команде нет встроенного кода в кавычках.**

`node -e "console.log(require('fs').readdirSync('/path'))"` оставался в песочнице, пока
`node probe.js`, сделав то же самое, сбежал. Кавычки и скобки
победить анализ линии. Запишите код в файл с помощью инструмента Write,
затем запустите его по пути.

**3c. Никогда не принимайте зонд, введенный пользователем в командной строке `!`.**

Команда, введенная с префиксом `!`, в большинстве сеансов выполняется за пределами песочницы.
Он добивается успеха в любом состоянии `excludedCommands`, поэтому его успех доказывает
ничего. Измерено: тот же зонд возвращал список каталогов при вводе с помощью
`!` и `EPERM scandir` при одновременном запуске агента.

**4. Прежде чем обвинять песочницу, проверьте существование двоичного файла.**

Обертки, сжимающие выходные данные, часто заменяют чистое сообщение пустой ошибкой.
Отсутствующий двоичный файл и отказ безопасности выглядят на экране одинаково.

```bash
command -v <binary>
```

Если ничего не возвращено, это означает, что у вас проблема с установкой, а не с политикой.

**5. Прочтите настоящий код выхода, а не код канала.**

`cmd | head` возвращает статус выхода `head`, а не `cmd`. Отказ от чтения
ранее в сеансе также выдает предупреждение о каждой последующей команде, включая
те, которые добьются успеха, поэтому прочитайте последнее сообщение, а не первое.

Это противоречит шагу 3: перенаправление также сохраняет вызов в изолированной программной среде. Для
команда, которая зависит от `excludedCommands`, примите чистую форму и примите необработанный
выход. Используйте приведенное ниже перенаправление только для команд, которые все равно находятся в песочнице.

```bash
cmd > out.log 2>&1
echo "exit: $?"
```

**5b. Проверьте, находится ли переписчик команд между вами и сопоставителем.**

Это объяснило работу большинства блокаторов в день их обнаружения. Если
Хук `PreToolUse` перезаписывает команды Bash, например прокси-сервер для сжатия токенов.
который превращает `pnpm exec tsx x.ts` в `proxy pnpm exec tsx x.ts`, затем
Запись `excludedCommands`, записанная как `pnpm exec *`, больше ничему не соответствует.
Соответствует только переписанная форма.

Причиной является несоответствие: некоторые исключенные команды выходят из песочницы и
другие этого не делают, и это не имеет очевидной закономерности. Посмотрите, случаются ли те, которые работают
чтобы иметь префиксную запись в списке. Также можно накормить хук синтетикой.

перезаписывает первым, поэтому пустой ответ не принимается за сломанный зонд.

Любую запрашиваемую вами запись следует запрашивать в обеих формах, простой и с префиксом, и
В обоих случаях область действия одинаково узкая: префикс `proxy git *` охватывает каждую подкоманду git.

**5c. Запись соответствует команде точно так, как она написана.**

`git fetch origin` соответствует `git fetch *`. `git -C /path fetch origin` и
`git -c key=value fetch origin` нет, потому что опция стоит перед глаголом.
`pnpm --dir /path exec tsx x.ts` не соответствует `pnpm exec *`. Вызов двоичного файла
по абсолютному пути тоже не совпадает. Для ведомой звезды требуется хотя бы один
аргумент, поэтому пустой `git fetch` не соответствует `git fetch *` и остается в песочнице.
Перепишите свою команду в ее канонической форме, прежде чем что-либо делать.

**5d. Сопоставление не проходит через скрипты или циклы.**

Запись для `ps *` выпускает `ps`, набранный напрямую, а не скрипт, вызывающий `ps`.
внутри: строка, отправленная сопоставителю, — `bash script.sh`. Диагностика
скрипту нужна собственная запись, на своем пути, в обеих формах (с и без).
` *`). Аналогично, `for c in "top -l 1" "pgrep -x zsh"; do eval "$c"; done` остается
в «песочнице», даже если оба инструмента исключены. Группировка датчиков для экономии времени
дает ложноотрицательные результаты.

**6. Если конфигурация изменилась после открытия сеанса, перезапустите его, если вы не знаете ключ перезагрузки.**

Списки файловой системы, `credentials.files`, `excludedCommands` и сеть
список разрешений измерялся как применение к следующей команде без перезапуска.
Оставьте перезагрузку по умолчанию для любого другого ключа.

Если все одиннадцать проверок пройдены и блокировщик удерживается, переходите к шаблону отчета.

## Сеть: заблокированный хост или несуществующий хост

Белый список домена фильтрует данные, даже если строгий режим отключен. Измерьте с хостом, который вы
Знать находится за пределами вашего списка и встроенных настроек продукта по умолчанию.

В автоматическом режиме в версии 2.1.271 и более поздних версиях хост, который не был объявлен командой, отклоняется.
и назван в результате команды; прочитайте имя, прежде чем что-то спрашивать. В
в других режимах продолжительность показывает, какой сбой вы столкнулись: отказ из белого списка
зависало примерно на 5–7 секунд на 2.1.220, в то время как имя хоста не разрешалось
не удалось выполнить менее чем за 30 миллисекунд, включая случаи, когда в списке уже есть подстановочный знак
накрыл его. Проверьте ответы Apex, прежде чем запрашивать добавление домена.

Необработанный TCP на внешний хост — это отдельная тема. Все, что игнорирует прокси
переменные не имеют выхода: облачные Postgres, MySQL, Redis и простой SSH не работают,
и никакая запись в домене не может это исправить. На macOS git через SSH тоже не работает, даже с
хост разрешен. Команду необходимо исключить или запустить за пределами песочницы.

## Эскалация

Передайте заполненный шаблон тому, кто может редактировать файл настроек. Не редактируйте его
самостоятельно из Bash: пишет в файлы настроек, из песочницы отказывается
команда. В автоматическом режиме классификатор также может отказать в редактировании вашего собственного
настройки как самомодификация; подготовьте файл-кандидат в другом месте, покажите разницу,
и позвольте человеку применить это.

Ключи, которые стоит знать под `sandbox`, — это `excludedCommands`,
`credentials.files`, `credentials.envVars`, `filesystem.allowWrite`,
`filesystem.denyRead`, `network.allowedDomains` и `network.strictAllowlist`.
Два из них вводят в заблуждение.

## Исправление ограничений без настроек внутри песочницы

Проверено. Не возобновляйте расследование по этому поводу. Каждый из них исчезает, когда
команда выполняется за пределами песочницы через пустое совпадение `excludedCommands`, по адресу
стоимость полного доступа для этой команды.

| Лимит | Нахождение | Известный обходной путь |
|---|---|---|
| Бинарные файлы Setuid | `ps`, `top`, `su`, `login` не могут работать в песочнице | исключите голую команду (`ps *`) или `lsof -nP -iTCP -sTCP:LISTEN` не трогая конфиг |
| Розетки `AF_UNIX` | `bind()` отказался, пока находился в песочнице, настройки локальной привязки охватывают только TCP | запустите пустую команду без ее исключения или выполните пакет, а затем запустите обычный `node` |
| Прямой DNS | вырезал для всех, все HTTP идет через локальный прокси | исключить инструмент, если ему нужны необработанные сокеты |
| `.idea/` и `.vscode/` | запись файла внутрь запрещена в текущем проекте (защищенные пути) | исключить команду установки в обеих формах |

Поэтому двоичный файл setuid или сбой сокета часто являются проблемой шага 3:
команда была исключена, но прикована к чему-то другому.

В DNS никогда не предлагайте добавлять в DNS универсальный диагностический инструмент, такой как `dig`.
исключенный список. Он вернет правильные разрешения, в то время как остальная часть сеанса
остается отрезанным, что ставит именно такой ложный диагноз, как это умение
существует, чтобы предотвратить.

Область видимости `.idea` значит больше, чем кажется. Отказ распространяется на
текущий проект, поэтому аудит из соседнего репозитория сообщит, что
ничего не заблокировано, и ошибетесь.
