# Оценщик навыков

Откройте для себя каждый навык, классифицируйте его профиль распространения, оцените его по восьми критериям и отделите структурную достоверность от маршрутных доказательств. Каждая оценка указывает хост и профиль, к которому она относится.

## <a name="when-to-use"></a>Когда использовать

- Прежде чем зафиксировать или опубликовать навык
- После массового импорта навыков из другого проекта или библиотеки.
- Когда навык срабатывает слишком часто, слишком редко или только на одном хосте
- При принятии решения о том, можно ли отправить навык в Claude Code, Codex или загрузить навыки агента.

Прочтите все навыки в выбранной области. Не делайте вывод о качестве всей коллекции на основе выборки. Когда аргумент называет путь, проверяйте только этот путь.

## Открытие

### Claude Code локации

| Расположение | Путь | Аудиторская записка |
|---|---|---|
| Персональный | `~/.claude/skills/<name>/SKILL.md` | Пропустите `.trash/`. `synced/` содержит навыки, загруженные с claude.ai: сообщите о них, никогда не редактируйте их. |
| Проект | `.claude/skills/` в начальном каталоге и каждый родительский элемент до корня репозитория. | Commit-shared |
| Вложенный | `<subdir>/.claude/skills/<name>/SKILL.md` | Загружается, когда Claude работает с файлами в `<subdir>`. При конфликте имен обе загрузки и вложенная - `/<subdir>:<name>`. |
| Дополнительный каталог | `.claude/skills/` в каталоге, переданном с помощью `--add-dir`. | Session-scoped |
| Командный файл | `.claude/commands/**/*.md` | Устаревший формат. Тот же заголовок, кроме `name` и `paths`. |
| Плагин | `<plugin>/skills/<name>/SKILL.md` или корневой плагин `SKILL.md` | Пространство имен `/<plugin>:<name>` |
| Предприятие | `.claude/skills/` в каталоге управляемых настроек. | Только отчет |

Зарезервированные имена папок: папка с именем `synced` (в любом случае) пропускается в корпоративном, личном расположении и расположении проекта. Вне плагина не загружается папка или командный файл с именем `anthropic-skills` или начинающийся с `anthropic-skills:`.

### Codex локации

| Область применения | Путь |
|---|---|
| Репозиторий | `.agents/skills` в каждом каталоге от рабочего каталога до корня репозитория. |
| Пользователь | `~/.agents/skills` |
| Админ | `/etc/codex/skills` |
| Система | В комплекте с Codex |

Codex следует за папками навыков с символическими ссылками. Навык, отключенный записью `[[skills.config]]` (`enabled = false`) в `~/.codex/config.toml`, сообщается как отключенный, а не оценивается как сломанный.

```bash
find .claude/skills .agents/skills -name SKILL.md -not -path '*/.trash/*' 2>/dev/null
find .claude/commands -name '*.md' ! -name 'README*' 2>/dev/null
```

**Выполняется, когда:** для каждого файла в области указан его хост, местоположение и правило обнаружения, которое его загружает.

## Профили распространения

Классифицируйте каждый навык, прежде чем оценивать его. Профиль решает, какие поля действительны.

| Профиль | Где он работает | Frontmatter, который он может использовать |
|---|---|---|
| Claude Code родной | Claude Code на любом локальном уровне, включая навыки работы с плагинами | Каждое поле в таблице Claude Code ниже. |
| Спецификация навыков агента | Загрузка claude.ai, навыки API, упаковка с `package_skill.py` | `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`. Любой другой ключ не загружается с серьезной ошибкой. |
| Codex | Codex CLI, расширение IDE, настольное приложение ChatGPT | `name` и `description` обязательны. Метаданные отображения, политика вызова и зависимости инструментов входят в `agents/openai.yaml`. |

Навык, опубликованный в нескольких профилях, следует за их пересечением. Сохранение полей, специфичных для хоста, внутри `metadata` для записи происхождения допустимо для переносимого навыка и не является дефектом.

**Готово, когда:** каждый навык имеет один заявленный или предполагаемый профиль с доказательствами для вывода.

## Ссылка на фронтальную часть Claude Code

Claude Code читает вступительную часть только тогда, когда открывающая `---` является первой строкой файла. Он игнорирует неизвестное поле, не сообщая об ошибке. Когда YAML не анализирует, навык загружается без установленных полей: `/name` все еще работает, но Claude не может соответствовать описанию. Обнаруживайте ошибки синтаксического анализа с помощью `claude plugin validate <skills-dir>` (Claude Code v2.1.233 или новее). Логические поля принимают `yes`, `no`, `on`, `off`, `1` и `0` в любом случае, начиная с версии 2.1.218.

| Поле | Примечания |
|---|---|
| `name` | В личном каталоге или каталоге навыков проекта устанавливает команду, показанную в `/`, и вводит ее для ее вызова; имя каталога также вызывает его. По умолчанию используется имя каталога. В плагине он устанавливает последний сегмент после префикса плагина. Командные файлы получают свое имя от файла |
| `description` | Что делает навык и когда его использовать. Если этот параметр опущен, используется первая непустая строка тела. |
| `when_to_use` | Добавлено к `description` в листинге и засчитано в той же шапке |
| `argument-hint` | Подсказка автозаполнения, например `[issue-number]`. |
| `arguments` | Именованные позиционные аргументы для замены `$name`. Строка, разделенная пробелами, или список YAML. |
| `disable-model-invocation` | `true` удаляет описание из контекста: вызывать его может только пользователь. Также блокирует предварительную загрузку в субагенты и вызов запланированных задач. |
| `user-invocable` | `false` скрывает навык от `/`; Claude все еще может его вызвать. |
| `allowed-tools` | Предварительно утверждает перечисленные инструменты для хода, который активирует навык. Он не ограничивает инструменты: каждый инструмент остается вызываемым. Строка, разделенная пробелом или запятой, или список YAML. Доверие к рабочему пространству не ограничивает его |
| `disallowed-tools` | Удаляет инструменты из пула, пока навык активен. Очистится при следующем сообщении |
| `model` | Модель до конца текущего хода или `inherit`. Значение, исключенное `availableModels`, не используется. |
| `effort` | `low`, `medium`, `high`, `xhigh` или `max`. Доступные уровни зависят от модели |
| `context` | `fork` запускает тело как приглашение нового субагента, который не видит диалог. |
| `agent` | Тип субагента, используемый с `context: fork` |
| `background` | При использовании `context: fork` `false` ожидает результата на ходу вызова. По умолчанию `true` (v2.1.218 или новее) |
| `hooks` | Регистрируется при вызове навыка и сохраняется до конца сеанса. `once: true` удаляет хук после первого успешного запуска |
| `paths` | Шаблоны глобусов, ограничивающие автоматическую загрузку. Список YAML или строка, разделенная запятыми. |
| `shell` | `bash` (по умолчанию) или `powershell` для встроенного ввода команд. |
| `metadata` | Карта произвольной формы, читаемая с помощью ваших собственных инструментов. Значение, не относящееся к карте, удаляется. Не используйте повторно имена полей в качестве ключей. |
| `license` | Принято, но не выполнено |
| `compatibility` | Строка длиной до 500 символов. Принято, но не выполнено |

Поля вне этой таблицы, такие как `tags`, `category`, `keywords`, `usage` или `args`, не влияют на Claude Code и прерывают загрузку навыков агента. Отметьте их.

### Строковые замены

| Заполнитель | Значение |
|---|---|
| `$ARGUMENTS` | Полная строка аргумента. Если ни один заполнитель не получает аргументы, Claude Code добавляет `ARGUMENTS: <value>`. |
| `$ARGUMENTS[N]` | Аргумент с индексом N, отсчитываемым от 0 |
| `$N` | Сокращение от `$ARGUMENTS[N]`. Действительно без поля `arguments:`. |
| `$name` | Именованный аргумент, объявленный в `arguments:`. Расширяется до пустой строки, когда аргумент отсутствует. |
| `${CLAUDE_SESSION_ID}` | Идентификатор текущего сеанса |
| `${CLAUDE_EFFORT}` | Уровень активных усилий |
| `${CLAUDE_SKILL_DIR}` | Каталог, содержащий этот `SKILL.md`. Также заменено в правилах `allowed-tools` Bash. |
| `${CLAUDE_PROJECT_DIR}` | Корень проекта (v2.1.196 или новее). Также заменено в правилах `allowed-tools` Bash. |
| `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}` | Установка плагина и постоянные каталоги данных. Только навыки работы с плагинами |

Индексированный заполнитель без соответствующего аргумента остается в тексте без изменений. Экранируйте литерал `$` перед цифрой `ARGUMENTS` или объявленным именем с помощью одинарной обратной косой черты, как в `\$1.00`. Заполнители, такие как `${ARGS}` или `%ARGUMENTS%`, передаются как обычный текст. Документация по навыкам Codex не описывает подстановку аргументов: запишите поведение Codex для этих заполнителей как `UNKNOWN`, а не предполагайте его.

### Бюджет листинга

- **Claude Code:** список навыков занимает 1% контекстного окна модели. Объединенные `description` и `when_to_use` каждой записи ограничены 1536 символами, которые можно настроить с помощью `skillListingMaxDescChars`. `skillListingBudgetFraction` или `SLASH_COMMAND_TOOL_CHAR_BUDGET` увеличивают бюджет. При переполнении сначала удаляются описания наименее используемых навыков. Установка `skillOverrides` на `"name-only"` освобождает бюджет. `/skill-doctor` (v2.1.252 или новее) сообщает о стоимости и использовании каждого навыка.
- **Codex:** исходный список использует не более 2% контекстного окна или 8000 символов, если окно неизвестно. Codex сначала сокращает описания и может опускать навыки с предупреждением.

На обоих хостах предварительно загрузите вариант использования ключа, чтобы сокращенное описание по-прежнему соответствовало.

## Критерии оценки (25 баллов за навык)

| # | Критерий | Макс | Что проверяется |
|---|-----------|-----|-----------------|
| 1 | **идентичность** | 2 | `name` представлен строчными буквами, цифрами и дефисами (1), необходимыми для Codex; отсутствие неразрешенных конфликтов имен на одном хосте (1) |
| 2 | **Указатель контекста** | 4 | Описание идентифицирует возможности (1), называет отдельные триггерные ветви (1), приводит к отличительным терминам (1) и соответствует ограничению списка без наполнения синонимами (1). |
| 3 | **подгонка профиля** | 3 | Профиль заявлен или предполагаем (1); каждое поле действительно для этого профиля (1); гранты на инструменты, пропорциональные рабочему процессу (1) |
| 4 | **Призыв и усилие** | 2 | Управление вызовом соответствует побочным эффектам (1); `effort`, если он объявлен, соответствует предполагаемому уровню, и целевая модель поддерживает его (1) |
| 5 | **Контракт рабочего процесса** | 4 | Цель или границы ясны (1), упорядоченная работа выполнима (1), каждый шаг имеет наблюдаемый критерий завершения (1), и не остается текста-заполнителя (1). |
| 6 | **закрытие ресурса** | 3 | Требуемые локальные ссылки разрешаются (1), существуют необходимые сценарии и шаблоны (1), и ни один ресурс не выходит за пределы корня навыка без явного переносимого контракта (1). |
| 7 | **Инструкция по экономике** | 3 | Один источник истины для каждого правила (1), ни одна инструкция просто не повторяет значения модели по умолчанию (1), а материал раскрывается только для ветвей, а не всегда загружается (1) |
| 8 | **Доказательства маршрута** | 4 | Корпус имеет как минимум 8 положительных и 2 близких отрицательных значения (1), использует реалистичный язык и граничные падежи (1), записанные доказательства Claude Code (1), записанные доказательства Codex (1) |

**Thresholds**, как доля применимых баллов:

- ✅ Хорошо: 80 % и более (от 20 до 25 из 25).
- ⚠️ Требует доработки: от 60% до 79% (с 15 по 19 из 25).
- ❌ Исправлено: менее 60 % (14 или меньше из 25).

Явно вызванная оболочка команды может пропустить свидетельство автоматической маршрутизации. Запишите его как `explicit-only`, убедитесь, что каждый запрошенный хост может его обнаружить, и оцените его по 21 баллу: Хорошо 17 или больше, Требует работы от 13 до 16, Исправление 12 или меньше.

### Проверка личности

Устраните конфликты с правилом каждого хоста. Claude Code: предприятие важнее личного, а не проекта; умение работать с командным файлом; локальный навык заменяет связанную команду, но не ее псевдонимы; загружаются как вложенный навык, так и корневой навык; Навыки плагина находятся в пространстве имен. Codex не объединяет навыки, которые имеют общий `name`: оба могут отображаться в селекторах, что является конфликтом, о котором следует сообщить.

### Обзор указателя контекста

Считайте описание и текст `when_to_use` указателем, определяющим, будет ли загружаться навык. Перечисляйте ветки, а не кучу синонимов. Ветка — это запрос другого типа, обрабатываемый разными инструкциями. Если два описания могут претендовать на одно и то же приглашение, запишите конфликт как дефект корректности.

### Проверка соответствия профиля

- **Claude Code собственный:** `allowed-tools` — это предварительное одобрение, поэтому запись `Bash` с незаданной областью позволяет каждой команде оболочки запускаться без запроса во время этого хода, даже в ненадежном репозитории. Для рабочего процесса, доступного только для чтения, предварительно одобряйте только те команды, которые он выполняет, например `Bash(git status *)` или `Bash(${CLAUDE_SKILL_DIR}/scripts/check.sh *)`. Используйте `disallowed-tools`, когда автономный навык никогда не должен вызывать инструмент, например `AskUserQuestion` в фоновом цикле. Собственный навык без `allowed-tools` не наказывается: применяются настройки разрешений пользователя.
- **Спецификация навыков агента:** любое поле за пределами шести разрешенных ключей не соответствует критерию.
- **Codex:** `name` и `description` присутствуют; `agents/openai.yaml`, если он присутствует, анализирует, а его записи `dependencies.tools` называют доступные инструменты.
- **Переносимость между хостами: поля**, обеспечивающие соблюдение хоста, отсутствуют или хранятся внутри `metadata`. Не рекомендуется добавлять `allowed-tools` или `effort` в начало переносимого навыка.

### Призыв и обзор усилий

Рабочий процесс с побочными эффектами, такими как развертывание, публикация, отправка или удаление, устанавливает `disable-model-invocation: true` для Claude Code и `policy.allow_implicit_invocation: false` в `agents/openai.yaml` для Codex или указывает, почему автоматический вызов безопасен. Отсутствие `effort` не является дефектом. Объявленный `effort` должен соответствовать приведенному ниже выводу и поддерживаться целевой моделью: например, в руководстве не указан параметр усилий для устаревшей версии Haiku 4.5, тогда как Haiku 5.5 поддерживает его.

### Обзор завершения рабочего процесса

Для каждого заказанного шага определите условие, позволяющее начать следующий шаг. Принимайте выполняемые команды, созданные файлы, пройденные проверки, записанные решения или явные отчеты о заблокированных доказательствах. Отклонять такие критерии, как «анализ завершен» или «достигнуто понимание», если агент не может их проверить.

### Проверка закрытия ресурса

Разрешить локальные ссылки Markdown относительно файла, содержащего их. Также проверяйте сценарии, шаблоны, приспособления и ссылки, объявленные в тексте или примерах кода, когда от них зависит выполнение. На связанные сценарии следует ссылаться через `${CLAUDE_SKILL_DIR}` в Claude Code, а не через путь, который зависит от рабочего каталога. Отсутствие необходимого ресурса является препятствием, даже если заглавная тема и проза имеют хорошие оценки.

### Инструкция по обзору экономики

Примените три проверки предложение за предложением:

1. Изменит ли удаление этой инструкции вероятное поведение? Если нет, отметьте отсутствие операции.
2. Является ли то же правило авторитетным в других местах? Если да, сохраните один источник и укажите на него.
3. Нужен ли этот материал каждому призыву? Если нет, переместите его за указатель на конкретную ветку.

## Создание доказательств маршрутизации

Никогда не присуждайте точку маршрута без записанного пробега. Запишите `UNKNOWN` для хоста, который не тестировался.

- **Базовое сравнение (оба хоста):** запускает каждое приглашение в новом сеансе с доступным навыком и снова с отключенным (для `skillOverrides` установлено значение `"off"` в Claude Code, `[[skills.config]]` с `enabled = false` в Codex). Свежий сеанс имеет значение, потому что контекст, оставшийся от создания навыков, маскирует пробелы.
- Навыки использования плагина **Claude Code:** `claude plugin eval` запускает каждое приглашение в изолированном сеансе с плагином и без него; грейдер `tool_used: Skill` измеряет срабатывание, и команда завершается с ненулевым значением ниже порогового значения.
- **Claude Code настройка описания:** - официальный плагин `skill-creator` от `claude-plugins-official`, генерирует подсказки о том, что следует запускать и не следует запускать, и измеряет частоту попаданий.
- **Codex:** В документации по навыкам Codex не описана специальная команда оценки. Воспроизведите каждое приглашение в новом сеансе Codex и запишите, был ли выбран навык.

**Выполняется, когда:** каждый направленный навык имеет результат для каждого хоста или `UNKNOWN` с указанием причины.

## Вывод об уровне усилий

Определите уровень по описанию и телу. Сообщите об этом как о рекомендации только для собственных навыков Claude Code.

- **`low`:** механическое исполнение без конструктивного решения. Создание экземпляра шаблона, форматирование, синхронизация, извлечение. Короткий последовательный рабочий процесс, без субагентов.
- **`medium`:** ограниченный анализ и категоризация. Проверка одного различия, сортировка проблем, создание структурированной таблицы. Не более одного или двух субагентов с заданной областью действия.
- **`high`:** проектные решения, состязательные или межсистемные рассуждения. Аудит безопасности, анализ архитектуры, оценка компромиссов. Несколько субагентов или явные секции неопределенности.
- **`xhigh` или `max`:** исчерпывающий длительный синтез. Распределение по множеству параллельных агентов, динамические рабочие процессы, возможность использования нескольких репозиториев.

Ультракод — это отдельный переключатель в `/effort`, начиная с Claude Code v2.1.284, и он больше не подразумевает уровень усилий. Не воспринимайте слово `ultracode` в тексте навыка как сигнал усилия.

Если объявленный `effort` отличается от вывода, отметьте это:

> ⚠️ Несоответствие усилий: заявлено `low`, предполагаемо `high`. Skill создает четырех субагентов и выполняет анализ безопасности.
