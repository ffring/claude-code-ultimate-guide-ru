# git-ai-archaeology

Восстанавливает историю использования ИИ-кодирования из git: какие файлы когда появились, кто их поддерживал, как они распространялись между модулями, что было заброшено и как развивались коммиты с помощью ИИ. Входящий в комплект скрипт выполняет подсчет за один проход; агент проверяет классификацию и записывает повествование на основе данных.

**Output**: `{out}/{slug}-harness.json` и `{out}/{slug}-harness.md` (скрипт), затем `{out}/{slug}-git-archaeology.md` (нарратив).

```
/git-ai-archaeology repo_path=/path/to/repo [out=./reports] [slug=name] [ref=main] [since=2025-01-01] [remotes=yes]
```

## <a name="workflow"></a>Рабочий процесс

1. **Устраните область действия.** Проверьте путь с помощью `git -C {repo_path} rev-parse --git-dir`. Используйте ветку по умолчанию как `ref`, если только пользователь не назначит ее; ветвь функции искажает каждый счет. Решите, следует ли сканировать удаленные ветки (`--remotes`) на предмет несвязанной работы с жгутами. Готово, когда записаны репо, ссылка, период и выходной каталог.

2. **Запустите скрипт.**

   ```bash
   python3 -I ${CLAUDE_SKILL_DIR}/scripts/harness_archaeology.py \
     --repo {repo_path} --out {out} --ref {ref} [--since {since}] [--remotes] [--slug {slug}]
   ```

   Он проходит каждую фиксацию без слияния, касающуюся пути жгута один раз (`git log --raw --numstat -M`), поэтому его стоимость растет с длиной истории, а не с количеством запусков. Присутствие, копии и устаревание считываются из дерева `--ref`, а не из рабочей копии. При использовании `--since` файлы старше окна принимают первую фиксацию в окне в качестве даты создания, и в отчете указывается их количество. Он завершает работу с ненулевым значением без записи, если путь не является репозиторием git. Готово, когда он печатает `harness_commits` и оба файла существуют.

3. **Проверьте классификацию, прежде чем доверять номеру.** Прочтите таблицы «По семействам инструментов» и «Наиболее редактируемые файлы». Ищите ложные срабатывания (папка `commands/` набора тестов, папка `agents/` бизнес-документов) и файлы обвязки, в которых отсутствуют шаблоны:

   ```bash
   git -C {repo_path} -c core.quotePath=false ls-files | grep -iE 'agent|prompt|llm|copilot|claude|codex|cursor|mcp|skill' | grep -vE '\.(java|ts|py|go|kt)$' | head -50
   ```

   Повторите запуск с `--extra-glob 'path/**'` (повторяемый, семейство `custom`) для пропущенного местоположения и с `--exclude-glob 'path/**'` для файлов, которые являются содержимым продукта, а не снаряжением, например навыками, которые репозиторий публикует в качестве примеров. Оставленное ложное срабатывание сообщается в пределах повествования, а не скрывается. Выполняется после того, как были выбраны файлы каждого семейства и каждое исправление либо повторно запускается, либо заносится в список.

4. **Прочитайте события, затем запишите фазы.** Работайте с JSON, а не с памятью типичных проектов. Используйте [сетку чтения](references/reading-grid.md) для интерпретации каждого индикатора. Ищите: волны создания, один и тот же файл, добавленный во многие модули в один день (распространение), файлы, добавленные, а затем удаленные в течение нескольких дней (проб и ошибок), переименования из папки одного инструмента в другую (миграция), удаления, в теме которых указана политика, структурирование коммитов и работа, живущая только в удаленных ветках. Выведите фазы из этих перерывов; их количество и метки берутся из данных. Готово, когда каждая фаза называет свой период, количество коммитов и хотя бы один хэш.

5. **Сравните использование с активностью жгута.** В ежемесячной таблице установите долю AI-трейлера рядом с фиксации жгута. Трейлер — это нижняя граница: встроенное завершение ничего не оставляет, а `Co-authored-by: Copilot` не сообщает, какая функция была использована. Скрипт учитывает трейлер, если его адрес электронной почты принадлежит поставщику инструмента или когда он называет инструмент с помощью бота или не отвечает на него по электронной почте, поэтому коллега с именем Claude не учитывается. Готово, когда в описании будет указан первый месяц с трейлерами ИИ, последняя публикация и будет ли работа по использованию и использованию системы совмещена.

6. **Write `{slug}-git-archaeology.md`.** Разделы: область действия и метод; ключевые фигуры; график первых появлений на семью; этапы с доказательствами; распространение и дублирование; отток и заброшенность; кто его поддерживает (только считает и делится); использование против использования; неслитая работа; пределы. Каждая цифра взята из JSON или команды, указанной в отчете. Готово, когда пройден приведенный ниже контрольный список проверки.

## Правила

- **Только для чтения.** Нет команды git, которая записывает, нет проверки, нет выборки, если пользователь не попросит.
- **Privacy.** Авторы отображаются только как количество и доля. Не печатайте имена или адреса электронной почты, даже от `git shortlog`. Скрипт хеширует электронные письма со случайной солью за каждое выполнение, поэтому хэши не могут быть пересчитаны; передайте `--salt` только для сравнения двух прогонов и не допускайте попадания соли в выходные данные. При одном-двух вкладчиках доля все равно указывает на человека: так и скажем.
- **Проверьте перед утверждением.** Дата или событие, не найденное в git, записывается как «не найдено» при попытке команды.
- Переименование **A не является созданием.** Сценарий следует за переименованием путей проводки с помощью `-M` и указывает исходную дату создания. Файл, перемещенный по пути, не связанному с использованием, отображается как созданный при перемещении.
- **Показать фиксированные месяцы.** Скрипт перечисляет каждый месяц с момента первого фиксации, включая месяцы без каких-либо коммитов.

## Контрольный список проверки

- [ ] Ref — это ветка по умолчанию, или в отчете указано, почему бы и нет.
- [ ] Классификация выборочная; исправления повторяются или перечисляются как лимиты
- [ ] На каждой фазе указаны период, количество и хеш.
- [ ] Использование указано как нижняя граница с указанием доли за первый месяц и за последний месяц.
- [ ] Ни имя автора, ни адрес электронной почты ни в одном выводе не указаны.
- [ ] И выходные данные сценария, и повествование существуют в `{out}`.
