# Генератор целевой страницы

Создайте полную, готовую к развертыванию целевую страницу из любого репозитория, проанализировав его документацию и структуру.

## Когда использовать этот навык

- Создание целевой страницы для репозитория GitHub
- Генерация статических сайтов из существующей документации
- Стандартизация целевых страниц в нескольких проектах
- Преобразование контента README в страницы marketing/showcase

## Что дает этот навык

1. **Analyze Repository**: Прочтите README.md, CHANGELOG.md, package.json/VERSION, docs/, assets/
2. **Извлечение содержимого**: определите заголовок, слоган, функции, установку, снимки экрана.
3. **Карта с разделами**: Герой, Функции, Установка, Часто задаваемые вопросы, Нижний колонтитул (+ дополнительно: Баннер рисков, Цены)
4. **Создать лендинг**: Создать полный статический сайт (HTML + CSS + JS)
5. **Вывод, готовый к развертыванию**: включить рабочий процесс GitHub Actions для страниц GitHub

## Как использовать

### Основное использование

```
/landing-page-generator from ~/path/to/repo
```

### С опциями

```
/landing-page-generator from ~/path/to/repo --risk-banner --pricing-table
```

### Доступные варианты

| Вариант | Описание | По умолчанию |
|--------|-------------|---------|
| `--risk-banner` | Добавьте заметный баннер warning/disclaimer выше сгиба. | ЛОЖЬ |
| `--pricing-table` | Включить раздел сравнения цен | ЛОЖЬ |
| `--screenshots <path>` | Путь к папке со скриншотами | ./assets/ |
| `--theme [dark\|light]` | Вариант цветовой темы | темный |
| `--search` | Включить поиск Cmd+K | истинный |
| `--output <path>` | Выходной каталог | ./[имя-репо]-лендинг/ |

## <a name="workflow"></a>Рабочий процесс

### Шаг 1: Анализ репозитория

Прочтите и проанализируйте эти файлы из исходного репозитория:

```
README.md        → Primary content source (title, tagline, features, install)
CHANGELOG.md     → Version info, recent changes
package.json     → Version number, dependencies, metadata
VERSION          → Alternative version source
docs/            → Additional documentation pages
assets/          → Screenshots, images
LICENSE          → License type for badge
```

### Шаг 2. Карта извлечения контента

| Источник | Целевой раздел | Метод экстракции |
|--------|---------------|-------------------|
| README title/badges | Герой | Первые строки значков H1 + Shield.io |
| README ТЛ;ДР | Слоган героя | Первый абзац или цитата после заголовка |
| Возможности README | Сетка функций | Разделы H2/H3 со списками маркеров |
| README установка | Быстрый старт | Блоки кода с командами оболочки |
| Использование README | Примеры | Блоки кода с примерами |
| README Часто задаваемые вопросы | Частые вопросы | Шаблоны Details/summary или H3+P |
| История изменений | Что нового | Последние 1-3 релиза |
| активы/*.png | Скриншоты | Раздел Галерея |

### Шаг 3: Создание раздела

Создайте эти разделы по порядку:

1. **Header** (прикрепленный)
   - Logo/project имя
   - Навигационные ссылки: Возможности, Установка, Часто задаваемые вопросы
   - Действия: Поиск (Cmd+K), GitHub Star, основной призыв к действию.

2. **Риск-баннер** (если `--risk-banner`)
   - Стиль Orange/warning выше сгиба
   - Четкий и видимый текст отказа от ответственности
   - Ссылка на раздел подробного раскрытия

3. **Геройский раздел**
   - Название из README H1
   - Слоган из абзаца TL;DR/first
   - Значки статистики (версия, лицензия, платформа)
   - Призывы к действию: «Быстрый старт» (основной), «Просмотр на GitHub» (вторичный).

4. **Architecture/Overview** (если схема в README)
   - Диаграмма ASCII преобразована в стилизованный блок
   - Или обзорные карточки

5. **Сетка функций**
   - 4-6 карточек функций из функций README
   - Значок + заголовок + шаблон описания

6. **Таблица цен** (если `--pricing-table`)
   - Сравнительная таблица планов
   - Таблица Multipliers/usage, если присутствует

7. **Галерея скриншотов** (если есть ресурсы)
   - Галерея на основе вкладок или карусельная галерея
   - Подписи из альтернативного текста

8. **Раздел быстрого старта**
   - Однострочная команда установки (представленный блок кода)
   - Шаги настройки
   - Первый пример использования

9. **Раскрытие информации о рисках** (если `--risk-banner`)
   - Полный раздел об отказе от ответственности
   - Условия обслуживания
   - Рекомендации

10. **Раздел часто задаваемых вопросов**
    - Создано на основе часто задаваемых вопросов README или общих вопросов.
    - Выкройка разборных деталей

11. **Связанные проекты** (если ссылки в README)
    - Карты, ссылающиеся на репозитории dependencies/related

12. **Нижний колонтитул**
    - Быстрые ссылки
    - Лицензионный значок
    - Информация о версии
    - Ссылки Author/repo

### Шаг 4: Структура вывода

```
[project-name]-landing/
├── index.html              # Main landing page
├── styles.css              # Complete stylesheet
├── search.js               # Cmd+K search functionality
├── search-data.js          # Search index (FAQ, features)
├── favicon.svg             # Generated or copied
├── robots.txt              # SEO
├── CLAUDE.md               # Project instructions
├── README.md               # Landing repo documentation
├── assets/                 # Copied screenshots
│   └── [copied from source]
└── .github/
    └── workflows/
        └── static.yml      # GitHub Pages deployment
```

### Шаг 5: Контрольная точка проверки

Перед завершением проверьте:
- Все разделы корректно отображаются в браузере.
- Ссылки указывают на действительные цели (репозиторий GitHub, документы, команды установки)
- Адаптивный макет работает на мобильных устройствах (375 пикселей), планшетах (768 пикселей) и настольных компьютерах (1280 пикселей).
- Доступность: присутствуют ссылки для пропуска, метки ARIA на интерактивных элементах, цветовой контраст соответствует требованиям WCAG AA.

## Технический стек

- **Без этапа сборки**: чистый HTML + CSS + JS
- **Search**: MiniSearch с ленивой загрузкой из CDN и резервным вариантом
- **Развертывание**: GitHub Страницы с помощью действий
- **Styling**: пользовательские свойства CSS, адаптивность, темная тема по умолчанию.
- **Доступность**: пропуск ссылок, метки ARIA, навигация с помощью клавиатуры.

## Пример

**Пользователь**: `/landing-page-generator from ~/projects/my-project --risk-banner --pricing-table`

**Output**:

Создает `~/projects/my-project-landing/` с помощью:
- Полная целевая страница, демонстрирующая маршрутизатор с несколькими провайдерами
- Яркий баннер риска ToS (оранжевый, вверху)
- Карты провайдера (Anthropic, Copilot, Ollama)
- Таблицы цен от README
- Галерея скриншотов
- GitHub Страницы готовы к развертыванию

## <a name="tips"></a>Советы

- Всегда включайте `--risk-banner` для проектов, в которых учитывается legal/ToS.
- Скриншоты значительно улучшают качество целевой страницы — убедитесь, что ресурсы/заполнены
- Навык сохраняет язык README (English/French).
- Просмотрите созданные часто задаваемые вопросы – может потребоваться настройка
- Тестируйте адаптивный дизайн после генерации
