# /token-audit: аудит токена контекста

**Purpose**: Измерьте, сколько токенов потребляет ваша конфигурация Claude Code до начала выполнения любой пользовательской задачи. Определите самые большие источники накладных расходов. Разработайте конкретный план действий с оценками экономии.

**Когда использовать**:
- Вы достигаете лимита ставок до конца дня
- Сеансы кажутся медленными или контекст рано сжимается
- Вы добавили много файлов правил и хотите узнать реальную стоимость.
- После серьезного изменения конфигурации

---

## Что вы будете измерять

| Компонент | Загружено, когда | Типичный диапазон |
|-----------|-------------|---------------|
| `~/.claude/CLAUDE.md` + @imports | Всегда | 5-15 тыс. токенов |
| Проект `CLAUDE.md` | Всегда | 2-8 тыс. токенов |
| `.claude/rules/*.md` | Всегда (все файлы) | 5-40 тыс. жетонов |
| `MEMORY.md` | Всегда | 1-3 тыс. токенов |
| Системная подсказка Claude Code | Всегда | ~7500 токенов |
| Крюк стандартного вывода | За вызов инструмента | переменная |
| Команды, агенты, навыки | Только при вызове | 0 по умолчанию |

Основная идея: `.claude/rules/` загружает каждый файл `.md` в начале сеанса, независимо от его релевантности. Команды и агенты загружаются лениво — до их вызова они не требуют затрат. Файлы правил являются наиболее распространенным источником непредвиденных накладных расходов.

## Шаг 1. Запустите измерение.

Выполните эти команды из корня проекта:

```bash
# Component sizes
echo "=== PROJECT CLAUDE.md ===" && wc -c CLAUDE.md 2>/dev/null || echo "none"

echo ""
echo "=== RULES FILES (sorted by size) ===" && find .claude/rules -name "*.md" 2>/dev/null \
  | xargs wc -c 2>/dev/null | sort -rn | head -20

echo ""
echo "=== GLOBAL ~/.claude ===" && ls -la ~/.claude/*.md 2>/dev/null \
  | awk '{print $5, $9}' | sort -rn
```

Затем рассчитайте полный бюджет:

```bash
GLOBAL=$(cat ~/.claude/CLAUDE.md ~/.claude/*.md 2>/dev/null | wc -c)
PROJECT=$(wc -c < CLAUDE.md 2>/dev/null || echo 0)
RULES=$(find .claude/rules -name "*.md" 2>/dev/null | xargs cat 2>/dev/null | wc -c || echo 0)
MEMORY=$(find ~/.claude/projects -name "MEMORY.md" 2>/dev/null \
  | xargs grep -l "$(basename $(pwd))" 2>/dev/null | head -1 \
  | xargs wc -c 2>/dev/null | awk '{print $1}' || echo 0)
TOTAL=$(( GLOBAL + PROJECT + RULES + MEMORY + 30000 ))

echo "Global ~/.claude   : ~$(( GLOBAL / 4 )) tokens ($(( GLOBAL / 1000 ))K chars)"
echo "Project CLAUDE.md  : ~$(( PROJECT / 4 )) tokens"
echo "Rules (auto-loaded): ~$(( RULES / 4 )) tokens"
echo "MEMORY.md          : ~$(( MEMORY / 4 )) tokens"
echo "System prompt      : ~7,500 tokens"
echo "---"
echo "TOTAL fixed context: ~$(( TOTAL / 4 )) tokens"
echo "% of 200K window   : $(( TOTAL / 4 * 100 / 200000 ))%"
```

## Шаг 2 — классифицируем файлы правил

Для каждого файла в `.claude/rules/` классифицируйте его:

| Сорт | Определение | Действие |
|-------|------------|--------|
| **ALWAYS** | Применяется к большинству задач (условия, формат вывода, безопасность) | Оставлять автозагрузку |
| **ИНОГДА** | Актуально в 20-40% сеансов | Оставить, если маленький (<3 тыс. символов); ленивая загрузка, если она большая |
| **РЕДКО** | Релевантно для <10% сессий (Figma, Windows, система дизайна) | Удалить из автозагрузки |
| **NEVER** | Устарело или описано в другом месте | Удалить или заархивировать |

Запустите эту подсказку классификации:

```
Read every file in .claude/rules/. For each file, output a table row:

| File | Size (chars) | Class (ALWAYS/SOMETIMES/RARELY/NEVER) | Reasoning (one sentence) |

Sort by size descending within each class.
At the end, calculate: total chars that would leave the fixed context if all
RARELY and NEVER files were excluded. Convert to tokens (÷ 4).
```

## Шаг 3 — накладные расходы на контрольный хук

Хуки на `PreToolUse` и `PostToolUse` срабатывают при каждом вызове инструмента. Каждый вызов вводит свой стандартный вывод в контекст. Перехватчик, выводящий 500 символов при 150 вызовах инструментов за сеанс = 75 000 символов ≈ 19 000 дополнительных токенов.

Проверьте, что у вас есть:

```bash
# List hooks by event type
python3 - << 'EOF'
import json, os
for path in [os.path.expanduser("~/.claude/settings.json"), ".claude/settings.json"]:
    if not os.path.exists(path): continue
    print(f"\n--- {path} ---")
    data = json.load(open(path))
    for event, hooks in data.get("hooks", {}).items():
        for h in hooks:
            cmd = h.get("command", "?")
            matcher = h.get("matcher", "*")
            print(f"  [{event}] matcher={matcher} → {cmd[:80]}")
EOF
```

Для каждого перехватчика `PreToolUse` или `PostToolUse` оцените размер стандартного вывода, запустив его вручную. Умножьте на среднее количество вызовов инструмента за сеанс (отображается в `/cost` после сеанса).

**Красные флаги**:
- Перехватывает файлы `cat` без каких-либо условий.
- `git status` или `git log` при каждом вызове
- Многострочный эхо-вывод для отладки, который никогда не удалялся.
- Объекты JSON, внедренные в качестве контекста

## Шаг 4 — составьте план действий

Составьте таблицу приоритетов. Эмпирическое правило: включайте только действия, которые можно осуществить без внешней инфраструктуры (без RAG, без векторных баз данных, без пользовательских серверов MCP).

| Действие | Предполагаемая экономия токенов | Усилие | Риск |
|--------|------------------------|--------|------|
| Удалить РЕДКО файлы из автозагрузки | варьируется | 30 мин. | Низкий |
| Разделите большие правила на ядро ​​+ детали. | варьируется | 1-2h | Низкий |
| Обрезать стандартный вывод до важных полей | варьируется | 1h | Низкий |
| Сжатие подробных правил (см. §8 context-engineering.md) | 20-30% правил | 1-2h | Низкий |
| Архивировать устаревшие записи MEMORY.md | 500-1 тыс. жетонов | 30 мин. | Низкий |

## Шаг 5 — вопрос RAG

Иногда в качестве решения предлагается отложенная загрузка через базу данных векторов (RAG). Честно оцените это, прежде чем совершить:

1. Какие токены с фиксированным контекстом остаются после шагов 1–4? (Сначала измерьте это.)
2. Оправдана ли РАГ? Настройка pgvector + пользовательская установка MCP — это проект, занимающий 1–2 недели.
3. Безубыточность: если у вас есть 10 файлов правил, каждый из которых содержит в среднем 3 тыс. символов, классификация (30 минут) экономит столько же, сколько и RAG. RAG окупается за счет более 50 файлов правил, где маршрутизация на основе намерений является единственным масштабируемым решением.

## Выходной формат

После запуска аудита создайте этот отчет:

```markdown
## Token Audit — [PROJECT] — [DATE]

### Budget Summary

| Component | Tokens | % of total |
|-----------|--------|------------|
| Global ~/.claude | X | Y% |
| Project CLAUDE.md | X | Y% |
| Rules (auto-loaded) | X | Y% |
| MEMORY.md | X | Y% |
| System prompt | 7,500 | Y% |
| **TOTAL** | **X** | **100%** |

Context window used before any task: X% of 200K

### Rules Classification

| File | Chars | Class | Action |
|------|-------|-------|--------|
| ... | ... | ALWAYS/SOMETIMES/RARELY | keep/lazy-load/remove |

### Hook Overhead

| Hook | Event | Est. stdout | Calls/session | Total tokens/session |
|------|-------|-------------|---------------|----------------------|
| ... | PreToolUse | X chars | ~Y | ~Z tokens |

### Action Plan

| Action | Savings | Effort | Risk |
|--------|---------|--------|------|
| ... | -X tokens | 30 min | Low |

**Total achievable without infrastructure**: -X tokens → from Y to Z (N% reduction)

### RAG Verdict

[One paragraph: remaining overhead after action plan, whether RAG is justified,
estimated setup cost vs savings.]
```

## Интерпретация результатов

| Фиксированный контекст | Оценка |
|---------------|------------|
| < 20 тыс. токенов | Здоров – никаких срочных действий не требуется. |
| 20-40 тыс. токенов | Умеренный — пройдите классификацию, одержите легкие победы. |
| 40-60 тыс. токенов | Высокий — аудит правил стоит полудня |
| > 60 тыс. жетонов | Критично — вы сжигаете более 30% окна перед выполнением любой задачи. |

Снижение на 48% является типичным после первого прохода аудита сильно настроенного проекта без каких-либо изменений в инфраструктуре — просто удаление РЕДКО используемых файлов из автозагрузки.
