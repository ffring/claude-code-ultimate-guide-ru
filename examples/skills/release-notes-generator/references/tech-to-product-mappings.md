# Правила трансформации технологии в продукт

Этот документ определяет, как преобразовать сообщения технических коммитов в удобный для пользователя язык продукта.

## Категории трансформаций

### 1. ОБЩАТЬСЯ (преобразование на язык продукта)

| Технический узор | Сообщение о продукте |
|-------------------|-----------------|
| `N+1 queries`, `DataLoader`, `batching` | «Быстрая загрузка списка» |
| `embeddings`, `vector search`, `pgvector` | «Улучшенный интеллектуальный поиск» |
| `permissions`, `scope`, `access control` | «Исправлена ​​ошибка доступа» |
| `retry logic`, `resilience`, `connection errors` | «Лучшая стабильность соединения» |
| `SSE`, `real-time`, `WebSocket` | «Обновления в реальном времени» |
| `cache`, `memoization` | «Улучшенная производительность» |
| `responsive`, `mobile` | «Лучший мобильный опыт» |
| `accessibility`, `a11y`, `WCAG` | «Улучшенная доступность» |
| `monitoring`, `alerting`, `error tracking` | «Лучшее отслеживание ошибок» |
| `validation`, `sanitization` | «Повышенная безопасность» |

### 2. НЕ ОБЩАТЬСЯ (только internal/technical)

Эти шаблоны НЕ должны появляться в объявлениях Slack:

| Технический узор | Причина |
|-------------------|--------|
| `refactor`, `refactoring` | Качество внутреннего кода |
| `webpack`, `turbopack`, `bundler` | Инструменты для сборки |
| `eslint`, `prettier`, `linting` | Стиль кода |
| `kebab-case`, `naming convention` | Внутренние стандарты |
| `TypeScript`, `type safety` | Опыт разработчика |
| `test`, `spec`, `coverage` | Тестирование инфраструктуры |
| `chore`, `maintenance` | Текущее техническое обслуживание |
| `docs`, `documentation` | Внутренние документы |
| `deps`, `dependencies`, `bump` | Обновления зависимостей |
| `CI`, `CD`, `workflow` | DevOps инфраструктура |

### 3. БЕЗОПАСНОСТЬ (Всегда на связи, упрощенно)

| Технический | Продукт |
|-----------|---------|
| `CVE-XXXX-XXXXX` | «Исправлена ​​уязвимость безопасности» |
| `XSS`, `injection` | «Усиленная защита данных» |
| `authentication`, `auth bypass` | «Улучшенная безопасность входа» |
| `CORS`, `CSRF` | «Защита от веб-атак» |

## Контекстно-зависимые преобразования

### API-related
- «Исправить ограничение скорости конечной точки» -> «Улучшена стабильность API»
- «Добавить проверку запроса» -> «Улучшенная обработка ввода»
- «Оптимизация производительности запросов» -> «Более быстрая загрузка данных»

### Dashboard-related
- «Исправить отрисовку виджета приборной панели» -> «Исправлены проблемы с отображением на приборной панели»
- «Добавить функцию экспорта» -> «Новая функция экспорта данных»
- «Улучшить производительность диаграммы» -> «Быстрее загрузка панели мониторинга»

### Notification-related
- «Исправить очередь доставки электронной почты» -> «Улучшена надежность уведомлений»
- «Добавить логику повтора веб-перехватчика» -> «Более надежная интеграция»
- «Оптимизировать пакетную обработку уведомлений» -> «Быстрая доставка уведомлений»

### Search-related
- «Исправить состояние гонки при индексации поиска» -> «Повысить надежность поиска»
- «Добавить нечеткое соответствие» -> «Улучшить результаты поиска»
- «Оптимизировать выполнение поискового запроса» -> «Быстрый поиск»

## Ролевое воздействие

Всегда указывайте, кого это касается:

| Влияние | Роли |
|--------|-------|
| Изменения в панели управления | Конечные пользователи, администраторы |
| Изменения API | Конечные пользователи, Опытные пользователи |
| Админ-панель | Только администраторы |
| Billing/Payment | Администраторы, заинтересованные стороны |
| Reports/Analytics | Администраторы, Опытные пользователи |
| Уведомления | Все пользователи |
| Поиск | Все пользователи |

## Индикаторы серьезности

Используйте эти префиксы, когда это необходимо:

- **Critical** : Проблемы блокировки производства.
- **Important** : Ошибки, с которыми сталкиваются пользователи.
- **Minor** : Улучшение качества жизни.
- *Не упоминать*: Внутренние исправления.
