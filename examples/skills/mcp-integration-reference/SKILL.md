# Эталонный шаблон интеграции MCP

> Это шаблонный навык. Он показывает, как структурировать навык, который охватывает сервер MCP. Замените `sentry` на имя вашего сервера MCP и адаптируйте справочный файл по адресу `references/sentry-mcp.md`.

## Что решает этот шаблон

Когда навык вызывает сервер MCP без предварительного контекста, Claude угадывает синтаксис запроса. Это работает для простых вызовов, но не работает при неочевидном поведении: особенностях нумерации страниц, обязательных комбинациях параметров, ограничениях скорости или тонких ограничениях формата.

Исправление: файл `references/<mcp-name>.md`, в котором зафиксированы все ошибки. Навык читает этот файл перед выполнением любого вызова MCP. Ноль догадок.

В справочном файле содержится три типа контента:
1. Семантика параметров, отличающаяся от того, что подразумевает название инструмента.
2. Известные шаблоны ошибок и их основные причины
3. Примеры рабочих запросов (копипаста, размышлений не требуется)

---

## Шаг 1. Прочтите справочный файл MCP.

**Прежде чем делать что-либо еще**, прочтите полную ссылку на MCP:

```
Read: references/sentry-mcp.md
```

Этот файл содержит синтаксис запроса, известные ошибки и рабочие примеры для Sentry MCP. Не пропускайте этот шаг.

---

## Шаг 2. Получите данные от пользователя

Спросите пользователя:

- **Временной диапазон**: Последние 24 часа? 7 дней? Пользовательский диапазон?
- **Environments**: `production`, `staging` или оба?
- **Projects**: Все проекты или отдельные? (По умолчанию: все)

Если пользователь говорит «просто запустите его с настройками по умолчанию», используйте:
- Временной диапазон: последние 72 часа
- Окружающая среда: только `production`
- Проекты: все

---

## Шаг 3. Получите данные об ошибках

Используя знания об инструментах, полученные на шаге 1, извлеките:

1. **Список проблем**: активные нерешенные проблемы, упорядоченные по частоте.
2. **Сведения о событии**: полная трассировка стека для 5 основных проблем по количеству событий.

Ограничение результатов на уровне 50 выпусков. Если их больше, запишите их количество и сосредоточьтесь на наиболее часто встречающихся элементах.

---

## Шаг 4. Сгруппируйте и проанализируйте

Группируйте проблемы по основной причине, а не по сообщению об ошибке. Две проблемы с разными сообщениями могут иметь одну и ту же основную причину (общий путь к коду, одна и та же внешняя зависимость, одна и та же конфигурация).

Для каждой группы:
- Количество вопросов в группе
- Самая ранняя дата первого появления
- Количество затронутых пользователей (если доступно)
- Наиболее вероятная основная причина (одно предложение, основанное на фактических данных)
- Соответствующие пути к файлам из трассировки стека

---

## Шаг 5. Создайте отчет.

Выведите отчет об уценке со следующей структурой:

```markdown
# Error Report: [Project or Scope]

**Period**: [start] to [end]
**Environment**: [env]
**Total active issues**: [N]

## Summary

[2-3 sentences: what is the overall health picture?]

## Issue Groups

### Group 1: [Root Cause Label]

| Attribute      | Value                    |
|----------------|--------------------------|
| Issues         | N                        |
| Total events   | N                        |
| Affected users | N                        |
| First seen     | YYYY-MM-DD               |
| Key file       | path/to/file.py:line     |

**Root cause**: [One paragraph. Specific, evidence-based. Point to file and line.]

**Suggested investigation**: [One or two concrete next steps.]

---

[Repeat for each group]

## Out of Scope

[List issues explicitly excluded and why. Example: "404s on /static/ excluded - expected behavior for SPA asset versioning."]
```

---

## Правила области

- Этот навык обнаруживает и описывает проблемы. Он не изменяет код и не создает заявки.
- Если проблема неоднозначна, пометьте ее как «требует исследования», а не гадать.
- Не включайте информационные журналы или предупреждения, если они не связаны напрямую с ошибками.

---

## Адаптация этого шаблона

Чтобы разветвить этот навык для другого MCP:

1. Скопируйте этот каталог: `cp -r examples/skills/mcp-integration-reference examples/skills/<your-skill>/`
2. Переименуйте `references/sentry-mcp.md` в `references/<your-mcp>.md`.
3. Замените содержимое эталонного файла ошибками вашего MCP.
4. Обновите `allowed-tools` во вступительной части, чтобы оно соответствовало именам инструментов MCP.
5. Настройте этапы анализа в соответствии с вашей предметной областью.

Шаблон работает для любого MCP с неочевидным поведением запросов: Datadog, PagerDuty, Linear, Jira, Posthog, Mixpanel и т. д.
