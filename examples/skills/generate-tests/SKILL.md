# Создание тестов

Создавайте комплексные тесты для указанного кода.

## Инструкции

1. Чтение целевого файла(ов)
2. Определить тестируемые модули (функции, классы, методы)
3. Создавайте тесты в соответствии с соглашениями проекта.
4. Обеспечить высокий охват крайних случаев

## Процесс генерации тестов

### 1. Анализ цели
- Определить общедоступные интерфейсы
- Понимание зависимостей
- Обратите внимание на крайние случаи и границы

### 2. Определить тестовую среду
Проверьте:
- `jest.config.js` → Шутка
- `vitest.config.ts` → Витест
- `pytest.ini` → pytest
- `mocha` в package.json → Мокко

### 3. Генерация тестов
Следуйте обнаруженным соглашениям платформы.

## Категории тестов

### Счастливый путь
Нормальное ожидаемое поведение при действительных входных данных.

### Краевые случаи
- Пустые входы
- Значения Null/undefined
- Граничные значения (0, -1, MAX_INT)
- Один предмет против нескольких предметов

### Случаи ошибок
- Неверные типы ввода
- Отсутствуют необходимые параметры
- Network/IO сбои
- Сценарии тайм-аута

### Точки интеграции
- Взаимодействие с базой данных
- Внешние вызовы API
- Операции с файловой системой

## Выходной формат

```typescript
describe('[ComponentName]', () => {
  describe('[methodName]', () => {
    // Happy path
    it('should [expected behavior] when [condition]', () => {
      // Arrange
      // Act
      // Assert
    });

    // Edge cases
    it('should handle empty input', () => {});
    it('should handle null values', () => {});

    // Error cases
    it('should throw when [invalid condition]', () => {});
  });
});
```

## Конвенции

- Одно утверждение на тест (если это возможно)
- Описательные названия тестов
- Шаблон AAA (Аранжировать-Действовать-Утверждать)
- Нет взаимозависимости тестов
- Имитация внешних зависимостей

## Использование

```
/generate-tests src/utils/calculator.ts
/generate-tests src/services/
```
