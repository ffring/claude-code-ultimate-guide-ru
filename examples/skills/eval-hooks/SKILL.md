# Оценщик хуков

Обнаружьте все хуки Claude Code и Codex в области видимости, проверьте каждый из них на соответствие файловой системе и документированной семантике хуков хоста, а затем запустите интерактивный сеанс, чтобы подтвердить или улучшить их.

Цель – не просто забить; это значит, что каждый хук должен работать, иметь правильную область видимости и быть безопасным для запуска.

Источники истины: официальный справочник по хукам Claude Code (https://code.claude.com/docs/en/hooks) и документация по хукам Codex (https://developers.openai.com/codex/hooks). Если приведенное ниже правило и действующая документация не совпадают, побеждает документация; сообщите о несогласии вместо того, чтобы выставлять баллы по устаревшему тексту.

## <a name="when-to-use"></a>Когда использовать

- При первом добавлении хуков (проверьте перед фиксацией)
- Хук никогда не срабатывает или срабатывает при каждом вызове инструмента.
- Агент заметно зависает перед запуском инструмента
- Политический хук должен блокировать, но это не так
- После копирования перехватчиков из другого проекта, компьютера или хоста
- Периодическая гигиена: «все ли эти хуки еще приносят что-то полезное?»

## Область применения

| Аргумент | Аудит |
|---|---|
| никто | Все существующие местоположения Claude Code и Codex, перечисленные ниже. |
| `claude` или `codex` | Только этот хост |
| путь к файлу | Только этот файл (настройки JSON, `hooks.json`, `config.toml`, файл навыка или агента) |
| `audit-only`, или пользователь просит не вносить изменения | Только шаги 1–4 и 6: перечислите каждое предлагаемое изменение вместо того, чтобы спрашивать или редактировать, и опустите строки отзывов пользователей из отчета. |

Аудит каждого хоста по своим правилам. Никогда не сравнивайте хук Codex с семантикой Claude Code или наоборот.

Когда отчет `ctxharness doctor --format json`, созданный во время этой задачи, доступен, согласуйте его: каждый слой-перехватчик, обнаруживший его, должен появиться в аудите, а каждый дополнительный результат требует подтверждения `file:line`.

## Claude Code: Ключевые понятия

### Типы событий (33)

| Событие | Когда он срабатывает | Эффект выхода 2 |
|---|---|---|
| `SessionStart` | Сеанс начинается или возобновляется | Stderr только для пользователя |

| `PostToolUseFailure` | После сбоя вызова инструмента | Stderr к Claude |

| `PreCompact` | До уплотнения | Блокирует уплотнение |
| `PostCompact` | После уплотнения | Stderr только для пользователя |
| `PreModelSwitch` | Перед запрошенным переключением модели | Блокирует переключатель |
| `PostModelSwitch` | После изменения модели сеанса | Stderr только для пользователя |
| `Elicitation` | Сервер MCP запрашивает ввод пользователя. | Отрицает выявление |
| `ElicitationResult` | После того, как пользователь ответит на запрос | Блокирует ответ (становится отказом) |
| `SessionEnd` | Сеанс завершается | Stderr только для пользователя |

### Коды выхода и вывод JSON

- **Exit 2** блокирует события, в строке которых указано это. Никакой JSON не может его переопределить, даже `permissionDecision: "allow"`.
- **JSON считывается при каждом коде выхода**, а не только 0. Для событий со стандартной моделью принятия решений допустимое решение JSON вступает в силу при выходе 0 или любом другом коде, отличном от 2: `hookSpecificOutput.permissionDecision: "deny"` (PreToolUse, PreModelSwitch), `hookSpecificOutput.decision.behavior: "deny"` (PermissionRequest), `decision: "block"` верхнего уровня. (UserPromptSubmit, UserPromptExpansion, PostToolUse, PostToolUseFailure, PostToolBatch, Stop, SubagentStop, ConfigChange, PreCompact, TaskCreated, PreModelSwitch).
- **Любой другой ненулевой код без действительного JSON** является неблокирующей ошибкой: действие продолжается, и в расшифровке отображается первая строка stderr. Отсутствующий или неисполняемый сценарий завершается с кодом типа 127 и попадает в эту корзину, поэтому неправильно введенный путь автоматически отключает шлюз политики.
- **Exit 0 stdout** становится контекстом только для `UserPromptSubmit`, `UserPromptExpansion`, `SessionStart` и `PostModelSwitch`; в другом месте он попадает в журнал отладки.

Перехват политики правильно построен, когда он использует **either** выход 2 **or** решение JSON, поддерживаемое его событием. Только выход 1 является дефектом.

### Тайм-аут по умолчанию (секунды)

| Обработчик | По умолчанию |
|---|---|
| `command`, `http`, `mcp_tool` | 600 |
| то же самое, на `UserPromptSubmit`, `PreModelSwitch`, `PostModelSwitch` | 30 |
| то же самое, на `MessageDisplay` | 10 |
| `prompt` | 30 |
| `agent` | 60 |
| `SessionEnd` | 1,5 общий бюджет; `timeout` для каждого перехватчика повышает его до максимального настроенного значения, вплоть до 60. Тайм-ауты перехвата плагина не повышают его. `CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS` переопределяет это |

Перехватчик `command`, `http` или `mcp_tool` на `PreToolUse` с истекшим временем ожидания приводит к тому, что **not** блокирует вызов инструмента; на `PreModelSwitch` он блокирует переключатель. `timeout` не применяется к работающему перехватчику `async: true`; это обеспечивается `asyncRewake`.

### Типы обработчиков и где они разрешены

| Тип обработчика | Разрешено |
|---|---|
| `command`, `mcp_tool` | Каждое событие |
| `http` | Все события, кроме `SessionStart` и `Setup`. |
| `prompt` | `PermissionDenied`, `PostToolBatch`, `PostToolUse`, `PostToolUseFailure`, `PreToolUse`, `Stop`, `SubagentStop`, `TaskCompleted`, `TaskCreated`, `TeammateIdle`, `UserPromptExpansion`, `UserPromptSubmit`, `PermissionRequest` |
| `agent` (экспериментальный) | То же, что `prompt`, за исключением `PermissionRequest`, где перехват агента пропускается. |

На `PermissionDenied` запускаются перехватчики приглашений и агентов, но их выходные данные отбрасываются.

### Модель исполнения

- Все соответствующие перехватчики выполняются **параллельно**.
- Один и тот же обработчик, определенный в нескольких файлах настроек, запускает **once**. Копия одного и того же обработчика плагина или навыка остается отдельной.
- Перехватчики `PermissionRequest` также выполняются в сеансах, которые не могут отображать подсказки, например, фоновые субагенты в режиме `-p`; если ни один рычаг не принимает решения, вызов отклоняется.
- Некоторые решения `PreToolUse` разрешаются как `deny > defer > ask > allow`. В документации не определено, какой `updatedInput` выиграет, когда несколько перехватчиков перезаписывают один и тот же вызов.
- Продолжения `Stop` и `SubagentStop` через `decision: "block"` или `additionalContext` ограничены входом `stop_hook_active` и ограничителем из 8 последовательных продолжений.
- Перехватчики команд работают без управляющего терминала: интерактивные команды (`read`, `fzf`, `gum`, любой TUI) не могут получить ввод. Используйте `terminalSequence` в выводе JSON для уведомлений.

## Codex: Ключевые понятия

### Локации

| Расположение | Примечания |
|---|---|
| `~/.codex/hooks.json` | Пользователь |
| `~/.codex/config.toml` встроенный `[hooks]` | Пользователь |
| `<repo>/.codex/hooks.json`, `<repo>/.codex/config.toml` | Загружается только в том случае, если слой проекта `.codex/` является доверенным. |
| Плагин `hooks/hooks.json` или запись `hooks` в `.codex-plugin/plugin.json`. | Пути к манифесту должны оставаться внутри корня плагина. |
| Управляемый `requirements.toml` `[hooks]` | Доверено политикой; `allow_managed_hooks_only = true` пропускает перехватчики пользователя, проекта, сеанса и плагина. |

Каждый источник загружается; более высокие уровни не заменяют нижние. Слой, содержащий как `hooks.json`, так и встроенный `[hooks]`, объединяется с предупреждением при запуске: отметьте его и порекомендуйте одно представление для каждого слоя. `[features] hooks = false` отключает перехватчики (`codex_hooks` — устаревший псевдоним).

### Доверительный обзор

Каждый неуправляемый хук, включая хуки плагинов, должен быть проверен и проверен в `/hooks` перед его запуском. Доверие записывается по текущему хешу перехватчика, поэтому отредактированный перехватчик пропускается до тех пор, пока ему снова не доверят. При аудите сообщите, что измененный хук требует проверки; не думайте, что он работает. Браузер `/hooks` — это авторитетный взгляд на доверие. Текущие сборки Codex также сохраняют его под `[hooks.state]` в `config.toml`, что недокументировано: сообщайте о том, что вы наблюдаете там, не печатая хеш-значения, и никогда не рассматривайте `[hooks.state]` как событие. `--dangerously-bypass-hook-trust` обходит проверку только для одного вызова: помечает любую автоматизацию, которая на нее опирается.

Прежде чем читать состояние доверия как поведение во время выполнения, проверьте, как запускается `codex`: `type codex` и `which -a codex`. Интеграция терминала может сначала разместить оболочку для `PATH`, которая добавляет переопределения `--dangerously-bypass-hook-trust` и `-c hooks...` к каждому вызову; Затем Codex включает этот флаг в список предупреждений при запуске. Наблюдается с cmux, чья оболочка пропускает внедрение при `CMUX_CODEX_HOOKS_DISABLED=1`. Под такой оболочкой каждый хук выполняется без проверки: сообщается, что результаты доверия не описывают то, что выполняется.

### События (12) и матчеры

| Событие | Фильтры сопоставления |
|---|---|
| `PreToolUse`, `PostToolUse`, `PermissionRequest` | имя инструмента (имена `Bash`, `apply_patch`, MCP; `Edit` или `Write` также соответствуют `apply_patch`) |
| `SessionStart` | `startup`, `resume`, `clear`, `compact` |
| `SessionEnd` | на данный момент только `other` |
| `PreCompact`, `PostCompact` | `manual`, `auto` |
| `SubagentStart`, `SubagentStop` | тип субагента |
| `UserPromptSubmit`, `Stop`, `Interrupt` | не поддерживается (сопоставитель игнорируется) |

Сопоставители Codex представляют собой строки регулярных выражений. `Interrupt` и `SessionEnd` не работают для субагентов.

### Обработчики и вывод

- Запускаются только обработчики `command` и `mcp_tool`. Обработчики `prompt` и `agent` анализируются и пропускаются: помечайте их как мертвую конфигурацию.
- `timeout` указывается в секундах, по умолчанию 600. `SessionEnd` и `Interrupt` по умолчанию равны 1 и допускают максимум 3.
- Необязательные поля: `statusMessage`, `async`, `additionalContextLimit` (по умолчанию 2500 токенов; `0` передает все и может заполнять контекст), `commandWindows`/`command_windows`.
- Команды выполняются с сеансом `cwd`. Для локальных сценариев репозитория разрешайте их из корня git, а не из относительного пути `.codex/hooks/...`.
- `PreToolUse` игнорирует стандартный текстовый вывод. Он блокируется с помощью `permissionDecision: "deny"`, устаревшего `decision: "block"` или выхода 2 с указанием причины в stderr. Он перезаписывает вызов с помощью `permissionDecision: "allow"` плюс `updatedInput` (строка `command` для `Bash` и `apply_patch`, аргументы замены для инструментов MCP), ту же форму, которую использует Claude Code. `permissionDecision: "ask"`, `continue`, `stopReason` и `suppressOutput` здесь не поддерживаются: Codex помечает запуск перехватчика как неудачный, а **продолжает вызов инструмента**. Отметьте любую ловушку политики Codex, которая на них опирается.
- Фоновые перехватчики (`async`) не могут блокировать, утверждать или перезаписывать; одновременно работает не более восьми; `SessionEnd` всегда работает синхронно.
- `SessionEnd` не поддерживает перехваты инструментов MCP.
- Плагины, написанные для Claude Code, могут печатать отказы Codex. Наблюдается в Codex 0.159.2: перехватчик `SessionStart`, печатающий два объекта JSON (`{"async": true, ...}`, затем объект метрики), завершается сбоем с `hook returned invalid session start JSON output`, а перехватчик `Stop`, печатающий `{"metrics": ...}`, завершается сбоем с `hook returned invalid stop hook JSON output`. Прочтите файл перехватчиков, в котором указаны имена `.codex-plugin/plugin.json` плагина, которые могут отличаться от `hooks/hooks.json` (например, `hooks/codex-hooks.json`), запустите каждый перехват плагина один раз с образцом полезных данных для его события и проанализируйте стандартный вывод по контракту этого события. Рекомендую отключить плагин в Codex при сбое нескольких его событий.

### Шаг 2. Разрешение команд (только перехватчики команд)

Разбейте форму оболочки `command` на слова оболочки перед ее разрешением. Разделение первого слова с помощью `awk` неверно: оно сохраняет кавычки и разбивает `"$CLAUDE_PROJECT_DIR"/.claude/hooks/x.sh` на два слова. Используйте синтаксический анализатор слов-оболочек:

```bash
python3 - "$command" "$PROJECT_ROOT" <<'EOF'
import os, shlex, shutil, sys
cmd, root = sys.argv[1], sys.argv[2]
words = shlex.split(cmd.split(';')[-1].split('&&')[-1])
words = [os.path.expanduser(w.replace('${CLAUDE_PROJECT_DIR}', root).replace('$CLAUDE_PROJECT_DIR', root)) for w in words]
while words and (words[0] == 'env' or '=' in words[0].split('/')[0]):
    words.pop(0)  # skip env and VAR=value prefixes
exe = words[0] if words else ''
path = exe if '/' in exe else (shutil.which(exe) or '')
print('executable', exe, 'found' if path and os.path.exists(path) else 'not found', 'x' if path and os.access(path, os.X_OK) else '-')
if os.path.basename(exe) in {'bash', 'sh', 'zsh', 'node', 'python3', 'python', 'deno', 'bun'}:
    script = next((w for w in words[1:] if not w.startswith('-')), '')
    print('script', script, 'found' if os.path.isfile(script) else 'not found', 'readable' if os.access(script, os.R_OK) else '-')
EOF
```

- При использовании `args` (форма exec) `command` разрешается в `PATH` или как путь; Элементы `args` являются буквальными.
- Для `bash script.sh`, `node script.js`, `python3 script.py` проверьте, что скрипт существует и доступен для чтения; ему не нужен `chmod +x`.
- Перед тестированием замените `${CLAUDE_PROJECT_DIR}` на корень проекта и `$(git rev-parse --show-toplevel)` на корень репозитория.
- Для цепочки команд, такой как `export PATH=...; tool ...`, определите последнюю команду, выполняющую работу, и запишите цепочку.
- Имя, разрешенное на `PATH`, теперь подтверждает только `PATH` текущей оболочки, а не среду, которую хост предоставляет перехватчикам. Отметьте проблему как решенную и скажите, что среда выполнения `PATH` не проверена.

Flag:
- **Not Found**: по этому пути ничего не существует; для перехвата политики это автоматически отключает шлюз
- **Не исполняемый**: скрипт, выполняемый напрямую без `chmod +x`
- **Относительный путь**: разрешается из сеанса `cwd`, который варьируется
- **Интерактивная команда** (`read`, `fzf`, `gum`, TUI): хуки не имеют управляющего терминала

Выполняется, когда: каждый командный хук помечен как найденный или не найденный, исполняемый или нет, с указанием разрешенного пути.

### Шаг 3. Проверьте стратегию блокировки.

Для перехватов событий, которые могут блокироваться (см. таблицы выше), команда которых является локальным скриптом:

1. Прочитайте сценарий.
2. Classify:
   - **Выход 2 на блок-пути**: ✅
   - Решение **JSON, поддерживаемое событием и хостом** (`permissionDecision: "deny"`, `decision.behavior: "deny"`, `decision: "block"`): ✅, независимо от кода выхода
   - **exit 1 или общий ненулевой код на пути блока, без JSON**: ⚠️ действие продолжается
   - **exit 2 на `PermissionRequest`** (Claude Code): ⚠️ не в чести; используйте объект `decision`
   - **Codex `permissionDecision: "ask"` или `continue: false` на `PreToolUse`**: ⚠️ не поддерживается, вызов инструмента продолжается.
   - **Нет решения вообще**: 🔵 наблюдателен, хорош, когда задумано
3. Отмечайте медленные операции (`curl`, `sleep`, сетевые вызовы) без внутреннего ограничения тайм-аута в перехватчиках на интерактивном пути.
4. Прежде чем отмечать медленную операцию по короткому `timeout`, проверьте, выполняется ли он отдельно (`( ... ) &` с `disown`, `nohup`, `setsid`). Отдельная работа переживет хук, поэтому короткий тайм-аут здесь уместен; вместо этого сообщите об обособленной работе.
5. Для скомпилированного двоичного файла или сценария, слишком большого для полного прочтения, не угадывайте логику его решения. Запишите версию (`--version` или `--help`), классифицируйте стратегию блокировки как `UNKNOWN` и предложите канареечное поведение (пример полезных данных на стандартном вводе, затем код выхода и стандартный вывод).
6. Прежде чем рекомендовать или отклонить вариант перехватчика, специфичный для хоста (например, подкоманду `codex` вместо `claude`), запустите оба варианта на одном и том же образце полезной нагрузки из более чем одного рабочего каталога, включая временный репозиторий за пределами ваших обычных проектов, и сравните каждый результат с контрактом хоста. Вывод может зависеть от каталога: с rtk 0.50.0 `rtk hook claude` вернул `updatedInput` с `permissionDecision: "allow"` в одном репозитории и без решения в чистом репозитории, что Codex отклоняет (`PreToolUse hook returned updatedInput without permissionDecision:allow`); `rtk hook codex` вернул решение в обоих случаях. Обработчик с именем Claude в Codex не является дефектом только тогда, когда его выходные данные соответствуют контракту Codex в каждом протестированном каталоге.
7. Если статические проверки пройдены, но поведение вызывает сомнения, запустите живую канарейку: одноразовый репозиторий git, новый сеанс, одно небольшое приглашение на редактирование. Подсчитайте строки `Hook failed` и, для инструмента проверки точек, записи, записанные при каждом редактировании. Сообщите версию хоста и точные сообщения об ошибках.

Выполняется, когда: каждый поддерживаемый сценарием перехват события блокировки имеет одну из приведенных выше классификаций или `UNKNOWN` с предлагаемой канарейкой, и в каждом вердикте варианта, специфичном для хоста, указаны каталоги, в которых он был протестирован.

### Шаг 4. Проверьте дубликаты и устаревшую конфигурацию.

- Claude Code: один и тот же обработчик в нескольких файлах настроек запускается один раз. Сообщите об этом как о избыточной конфигурации, требующей очистки, а не как о двойном выполнении. Плагин или копия одного и того же обработчика запускается отдельно: сообщите об этом как о реальном дубликате.
- Сопоставитель события без поддержки сопоставителя (игнорируется).
- `if` для события, не связанного с инструментом (перехват никогда не запускается).
- `once` внешний заголовок навыка (игнорируется).
- Тип обработчика не разрешен для данного события (пропускается).
- `async: true` в сочетании с полем решения (без эффекта).
- Два или более перехвата `PreToolUse` на одном и том же сопоставителе возвращают `updatedInput` (победитель недокументирован).
- Перехватчик остановки, который всегда продолжается без чтения `stop_hook_active`.
- Codex: слой, содержащий `hooks.json` и встроенный `[hooks]`; хуки ожидают проверки доверия. Когда оба представления запускают один и тот же инструмент по одному и тому же событию, даже через разные командные строки (скрипт-оболочка и вызываемый им двоичный файл), сообщите о реальном двойном запуске и назовите установщик, которому принадлежит каждая запись.
- Секреты в источниках или настройках ловушек: литералы, подобные токенам, учетные данные в `headers` или `env`. Сообщите о файле и строке с отредактированным значением и порекомендуйте переместить значение из источника и повернуть его.

Выполняется, когда: каждый результат прикреплен к связанной записи или список явно пуст.

## Краевые случаи

- **Встроенный однострочный** (например, `rtk hook claude`): пропустить проверки на уровне скрипта, убедиться, что двоичный файл находится на `PATH`
- **`bash -c '...'` inline**: анализ внутреннего скрипта на наличие интерактивных команд и логики выхода.
- **`exit 1` в хуке политики без JSON**: ⚠️ неблокируется, действие продолжается
- **Тот же хук в настройках пользователя и проекта (Claude Code)**: запускается один раз; отметьте оба местоположения как резервную конфигурацию
- **`timeout: 0`**: пометить как вероятно недействительный
- **Unknown event** (например, `PreToolCall`): ❌ сообщить точную строку и предложить документированное имя для этого хоста.
- Событие только для **Claude в файле Codex** (например, `PostToolUseFailure`, `PreModelSwitch`) или наоборот (`Interrupt` в настройках Claude): ❌ никогда не срабатывает на этом хосте
- **Script не является исполняемым и запускается напрямую.**: происходит сбой с неблокирующей ошибкой; предложить `chmod +x`
- **Matcher для события, не соответствующего совпадению.**: молча игнорируется, предложите удалить его.
- **`async: true` с `decision` или `permissionDecision`**: ⚠️ нет эффекта
- **`asyncRewake: true`**: фон, пробуждает Claude на выходе 2 с помощью stderr (или stdout); используйте его вместо `async`, когда фоновый сбой должен достичь Claude
- **`prompt` или `agent` ловушка**: нет команды для разрешения; проверьте, что `prompt` присутствует и что событие допускает тип
- Перехватчик **SessionEnd выполняет тяжелую работу**: бюджет по умолчанию 1,5 с на Claude Code, 1 с по умолчанию и максимум 3 с на Codex; предупредить, что его могут убить
- **`PermissionRequest` в `-p` или фоновых субагентах (Claude Code)**: перехватчики все еще работают; если никто не решает, вызов отклоняется. По этой причине не рекомендуется переходить на `PreToolUse`.
- **`if` для события, не связанного с инструментом.**: перехватчик никогда не запускается; удалите `if` или измените событие
- **Стоп-хук без проверки `stop_hook_active`**: продолжения останавливаются на 8-ми последовательных кепках; прочитайте поле и выйдите из 0, если оно равно `true`
- **Жестко заданный локальный абсолютный путь к проекту**: предложите `${CLAUDE_PROJECT_DIR}/...` (Claude Code, предпочтительна форма exec) или путь на основе корня git (Codex)
- **Hooks не срабатывает должным образом**: Claude Code: откройте `/hooks` (браузер только для чтения, показывающий источник каждого перехватчика) и запустите с помощью `--debug`. Codex: откройте `/hooks`, чтобы просмотреть источники, ожидающие проверки доверия и отключенные перехватчики.
