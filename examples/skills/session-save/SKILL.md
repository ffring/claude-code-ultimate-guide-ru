# /session-save

Запишите текущий сеанс в структурированный файл передачи обслуживания, чтобы вы (или другой экземпляр) могли возобновить его с полным контекстом. Создает файл Markdown с отметкой времени в `.claude/sessions/`.

## <a name="when-to-use"></a>Когда использовать

- Прежде чем завершить сеанс, который не завершен
- Прежде чем переключиться на другую задачу
- Прежде чем контекст достигнет 75%+ (чтобы сохранить важные части)
- На естественных этапах долгой задачи (после каждого этапа)
- Для передачи второму экземпляру Claude

## Инструкции

Составьте акт о передаче, имеющий следующую структуру:

---

## Передача сеанса: [TIMESTAMP]

### Что делалось
[Один абзац: цель, подход, состояние дел в данный момент]

### Файлы изменили этот сеанс
[Перечислите все файлы, которые были созданы, отредактированы или удалены, с указанием характера изменений]

```
path/to/file.ts      - [what changed and why]
path/to/other.ts     - [what changed and why]
```

### Ключевые решения приняты
[Архитектурный выбор, принятые компромиссы, отвергнутые подходы и почему]

- **Decision**: [Что было решено]
  - **Обоснование**: [Почему]
  - **Альтернативы отклонены**: [Что еще рассматривалось]

### Текущий статус
[Где сейчас обстоят дела: что работает, что сломано, что в процессе]

- Работающий: [...]
- В ходе выполнения: [...]
- Известные проблемы: [...]

### Следующие шаги (заказано)
[Точные следующие действия, которые необходимо предпринять для продолжения, достаточно конкретные, чтобы можно было уловить свежий контекст, не перечитывая все]

1. [Первое действие]: `path/to/file.ts` - [что делать]
2. [Второе действие]: [...]
3. [...]

### Контекст для перезагрузки
[Файлы, которые необходимо прочитать, чтобы продолжить с полным пониманием, сделайте этот список коротким]

- `path/to/key-file.ts`: [почему это важно]
- `CLAUDE.md`: правила проекта

### Блокировщики/открытые вопросы
[Все, что не решено и требует решения или внешнего вмешательства, прежде чем продолжить]

- [ ] [Вопрос или блокировщик]: [who/what может решить эту проблему]

---

## Выполнение

Сохраните передачу в `.claude/sessions/handoff-[YYYY-MM-DD-HHMM].md`. Затем выведите путь к файлу, чтобы пользователь знал, где его найти.

## Шаблон резюме

Чтобы возобновить передачу обслуживания:

```
/session-resume .claude/sessions/handoff-YYYY-MM-DD-HHMM.md
```

Или вручную: прочитайте файл передачи, затем прочитайте файлы, перечисленные в «Контексте для перезагрузки», прежде чем продолжить.

## Примеры

### Пример 1. Сохранение промежуточных функций

```
/session-save
```

Claude захватывает:
- Промежуточное программное обеспечение аутентификации подвергалось рефакторингу (файлы: `src/middleware/auth.ts`, `src/middleware/jwt.ts`)
- Решение: перешёл с токенов сеанса на JWT (обоснование: лучше масштабируется между сервисами)
- Статус: проверка JWT работает, выполняется обновление логики
- Далее: внедрить `refreshToken()` в `src/services/auth.service.ts`, затем обновить тесты.

### Пример 2: Сохранение контекстного давления

Когда контекст достигнет 70 %, запустите `/session-save` перед `/compact`, чтобы сохранить контекст решения, который может быть потерян при сжатии.

## Примечания

- Оставьте «Контекст для перезагрузки» максимум на 5 файлах. Цель — быстрое резюме, а не полное перечитывание.
- «Следующие шаги» должны быть достаточно конкретными, чтобы Claude с холодным запуском мог выполнить шаг 1, не задавая вопросов.
- Не сохраняйте выходные данные инструмента или фрагменты кода при передаче; вместо этого ссылайтесь на пути к файлам.
