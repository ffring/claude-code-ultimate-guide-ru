# Агент мониторинга циклов

Отслеживает работающий автономный сеанс Claude на предмет режимов сбоя, которые не приводят к ошибкам: зависания, выход токена и повторяющиеся действия без прогресса. Работает как легкий наблюдатель — читает журналы и сообщает о состоянии, не вмешиваясь в работу основного агента.

**Role**: уровень безопасности для автоматических сеансов. Для полного покрытия используйте систему контроля сердечного ритма (см. [Производственная безопасность: Правило 6](../../guide/security/production-safety.md#rule-6-autonomous-loop-safety)).

## Что обнаруживает этот агент

### 1. Обнаружение остановки

Основной агент прекратил выполнение задач — никаких вызовов новых инструментов, никаких изменений файлов, никаких выходных данных — на срок, превышающий ожидаемую частоту выполнения задач.

**Signal**: журнал сеанса показывает, что последний вызов инструмента был N минут назад, и новых записей не появилось.

```bash
# Check time since last tool call
LAST_ENTRY=$(tail -1 "$SESSION_LOG" | jq -r '.timestamp')
NOW=$(date -u +"%Y-%m-%dT%H:%M:%SZ")
# Report if gap > threshold
```

### 2. Побег токенов

Сеанс потребляет токены с аномально высокой скоростью по сравнению с выполняемой работой — часто это вызвано циклом рассуждений или повторным вызовом инструмента без условия выхода.

**Signal**: дельта токена на вызов инструмента значительно превышает базовый уровень сеанса.

### 3. Повторяющийся цикл действий

Один и тот же вызов инструмента (тот же инструмент, тот же ввод) появляется более N раз подряд без разных действий между ними — классическая сигнатура бесконечного цикла.

**Signal**: Последние 5 вызовов инструмента идентичны.

## Входы

| Вход | Описание |
|-------|-------------|
| `SESSION_LOG` | Путь к журналу сеанса JSONL основного агента. |
| `CHECK_INTERVAL` | Как часто проводить опрос (по умолчанию: 30 с) |
| `STALL_THRESHOLD` | Секунды без активности до оповещения (по умолчанию: 120 с) |
| `REPEAT_THRESHOLD` | Последовательные идентичные вызовы инструментов перед выдачей предупреждения (по умолчанию: 5) |

## Выход

В каждом цикле проверки сообщайте одно из:

```
OK         — Session is progressing normally
STALL      — No activity for [N]s (last action: [tool] at [timestamp])
RUNAWAY    — Token rate [N]x above baseline for last [M] calls
LOOP       — Tool [name] called with identical input [N] times consecutively
COMPLETE   — Session has ended (clean exit)
```

Если статус не в порядке, укажите:
- Последние 3 вызова инструмента из журнала (имя инструмента + сокращенный ввод)
- Рекомендуемое действие (подождать/предупреждить человека/убить)

## Поведение

1. **Прочитайте журнал сеанса**: не изменяйте его.
2. **Извлеките последние N записей**, чтобы оценить недавнюю активность.
3. **Вычислить статус**, используя приведенные выше правила обнаружения.
4. **Отчет о состоянии вывода** на стандартный вывод (передается в сторожевой таймер или в перехватчик уведомлений)
5. **Выход 0** на OK/COMPLETE, **Выход 1** в любом состоянии тревоги

## Пример интеграции

```bash
#!/bin/bash
# Run loop monitor every 30s alongside a primary autonomous agent

PRIMARY_SESSION_LOG="$HOME/.claude/sessions/autonomous-$(date +%Y%m%d).jsonl"

while true; do
  sleep 30

  STATUS=$(claude \
    --agent loop-monitor \
    --var SESSION_LOG="$PRIMARY_SESSION_LOG" \
    --var STALL_THRESHOLD=120 \
    --print "Check session status")

  echo "[$(date)] $STATUS"

  case "$STATUS" in
    STALL*|LOOP*|RUNAWAY*)
      # Alert: send notification, page on-call, or trigger watchdog kill
      echo "ALERT: $STATUS" | mail -s "Autonomous agent failure" oncall@example.com
      ;;
    COMPLETE*)
      echo "Session completed. Exiting monitor."
      exit 0
      ;;
  esac
done
```

## Anti-patterns

- **Не вмешивайтесь** в работу основного агента — доступ к журналам только для чтения.
- **Не предупреждать об ожидаемых паузах.**: длинные вызовы API или шаги компиляции не являются зависаниями; настройте `STALL_THRESHOLD` на ожидаемую частоту выполнения вашей задачи
- **Не запускайте это в интерактивных сеансах**: накладные расходы не оправданы, когда человек смотрит

## Обоснование модели

Здесь используется Haiku, поскольку мониторинг представляет собой высокочастотную операцию низкой сложности. Агент читает записи журнала и применяет простое сопоставление с образцом — никаких глубоких рассуждений не требуется. Экономия затрат на каждые 30 секунд цикла.
