# Фрезерный станок BM25 для Codex и Claude Code

Этот хук `UserPromptSubmit` сравнивает активные навыки с тщательно подобранными примерами с Okapi BM25. Он поддерживает одну глобальную установку Codex, которая определяет навыки проекта и пользователя из подсказки `cwd`.

Хук носит рекомендательный характер. Он излучает только `additionalContext`. Он никогда не вызывает навык или не одобряет действие.

С точки зрения шаблона проектирования, перехватчик представляет собой детерминированный маршрутизатор [Content-Based Router](../../../guide/core/ai-design-patterns.md#content-based-router), помещенный перед выбором собственных навыков модели. Пошаговое руководство [](../../../guide/workflows/smart-suggest-routing.md#bm25-router-step-by-step) объясняет каждое решение на пути.

## Что изменилось по сравнению с первым примером

Первоначальная реализация была предназначена только для проекта и специфична для Claude. Он также маршрутизировал корпорации `conflict`, рассматривал любое отрицание как отказ, отображал долю оценок в виде процента достоверности и пропускал некоторые аннулирования кэша.

Эта версия:

- обнаруживает `.agents/skills` из `cwd` в корень Git;
- затем обнаруживает `~/.agents/skills`, `~/.codex/skills`, `/etc/codex/skills` и `SKILL_ROUTER_EXTRA_ROOTS`;
- позволяет ближайшему навыку проекта затенять глобальный навык с тем же `name`;
- маршруты только откалиброванного корпуса `status: ok` для активных навыков;
- хранит каждый кеш и дополнительный журнал вне репозиториев;
- обнаруживает добавления, изменения и удаления с помощью отпечатка пальца SHA-256 с версией алгоритма;
- сериализует перестроения с истекающим сроком действия блокировки и атомарно записывает файлы кэша;
- излучает `$skill-name` для Codex и `/skill-name` для Claude Code;
- никогда не регистрирует необработанное приглашение.

Навыки без действующего корпуса остаются доступными через встроенное сопоставление навыков Codex. В манифесте они обозначены как `native-only`.

## Требования

- Node.js 18 или новее
- нет зависимостей от npm
- хук Codex или Claude Code `UserPromptSubmit`

## Рекомендуемая установка Codex

Предварительный просмотр каждого пункта назначения, контрольной суммы и изменения ловушки:

```bash
node install.js --host codex --scope user --dry-run
```

Установите после просмотра превью:

```bash
node install.js --host codex --scope user --apply
```

Установщик копирует среду выполнения в `~/.codex/hooks/skill-router/`, отдельно сохраняет кэши в `~/.codex/skill-router-data/`, сохраняет существующие обработчики в `~/.codex/hooks.json` и создает резервную копию с отметкой времени перед чем-либо заменой. Вторая идентичная установка не вносит никаких изменений. Хранение данных кэша вне каталога среды выполнения также сохраняет их при обновлении маршрутизатора.

Codex требует, чтобы неуправляемые перехватчики были проверены и заслуживали доверия. Откройте `/hooks`, проверьте установленную команду и подтвердите ее хеш. Пока этот человеческий шаг не будет завершен, файлы могут существовать, пока перехватчик остается неактивным.

Не устанавливайте на ту же машину крюк проекта BM25. Codex сочетает в себе соответствующие глобальные и проектные хуки, поэтому два обработчика могут вводить дублирующийся контекст. Глобальный хук уже обнаруживает навыки проекта.

## Проектная установка

Для машины без глобального маршрутизатора:

```bash
node install.js \
  --host codex \
  --scope project \
  --project-root /absolute/path/to/repo \
  --dry-run
```

После проверки замените `--dry-run` на `--apply`. Среда выполнения устанавливается под `<repo>/.codex/hooks/skill-router/` и использует ту же логику обнаружения и кэширования. Сгенерированный хук устанавливает для `SKILL_ROUTER_DATA_DIR` значение `~/.codex/skill-router-data`, поэтому подсказки никогда не записывают файлы кэша в репозиторий.

В режиме проекта Claude Code используется `--host claude --scope project`. Синтаксис подсказки изменится на `/skill-name`. Не активируйте одновременно глобальный маршрутизатор Codex и маршрутизатор проекта Codex.

## Формат корпуса

Соседний корпус находится по адресу `<skill>/evals/scenarios.json`:

```json
{
  "skill": "my-skill",
  "positive": [
    "run the linter on this file",
    "check code style"
  ],
  "negative": [
    "review this PR for security",
    "deploy the application"
  ]
}
```

Значение `skill` должно равняться активному `name` в `SKILL.md` и соответствовать `^[a-z0-9][a-z0-9:_-]{0,127}$`. Для калибровки требуется не менее восьми положительных и двух контрастных отрицательных примеров.

Используйте `SKILL_ROUTER_OVERLAY_ROOTS` для навыка, каталог которого не может содержать `evals/`. Входящий в комплект корпус `agentic-project-finder` демонстрирует это. Наложение принимается только тогда, когда его навык активен в одном из разрешенных корней.

## Стройте и проверяйте

Создайте кеш для определенного рабочего каталога:

```bash
SKILL_ROUTER_CWD=/absolute/path/to/repo \
node routing/build-index.js
```

Проверяем, не записывая:

```bash
SKILL_ROUTER_CWD=/absolute/path/to/repo \
node routing/build-index.js --dry-run
```

Сгенерированные файлы для каждой области:

- `index.json`: токенизированные позитивные и контрастно-негативные сценарии;
- `thresholds.json`: калиброванные пороговые значения и статус `ok`, `conflict` или `excluded`;
- `manifest.json`: разрешенные корни, активные навыки, пути, покрытие, исключения и исходный отпечаток;
- `coverage.json`: `covered`, навыки перекрестных навыков `eligible` и `native-only`;
- `metrics.json`: начальное и закрытое качество исключения одного, удаления и глобальный F1;
- `verified.json`: временная метка последней глубокой проверки источника.

В подсказке BM25 могут появиться только навыки `ok`, которые также проходят перекрестную оценку. Если соответствующий набор остается ниже глобального F1 0,70, корпус проектов самого низкого качества остается `native-only`. Проверенные приемкой навыки наложения сохраняются, а шумные корпуса проектов удаляются. Навыки `conflict`, `excluded`, искаженные, неактивные и `native-only` остаются безмолвными.

## <a name="evaluation"></a>Оценка

Файл приема не зависит от учебного корпуса:

```bash
SKILL_ROUTER_CWD=/absolute/path/to/repo \
node routing/eval.js \
  --acceptance test/acceptance-prompts.json \
  --strict
```

Строгий режим требует точности не менее 0,80, F1 не менее 0,70 и отсутствия запрещенных совпадений. В отчете также указаны значения p50, p95 и максимальная задержка оценки в процессе.

Запустите все тесты:

```bash
node --test test/*.test.js
```

Измерьте 1000 теплых решений по маршрутизации в целевой области:

```bash
SKILL_ROUTER_HOST=codex \
SKILL_ROUTER_DATA_DIR="$HOME/.codex/skill-router-data" \
node routing/benchmark.js --iterations 1000 --cwd /absolute/path/to/repo
```

## Контракт времени выполнения

Каждая команда-перехватчик должна устанавливать `SKILL_ROUTER_HOST=codex` или `SKILL_ROUTER_HOST=claude`. Среда выполнения не определяет хост по нестабильным полям полезной нагрузки.

Пример вывода Codex:

```json
{
  "hookSpecificOutput": {
    "hookEventName": "UserPromptSubmit",
    "additionalContext": "Skill routing candidates:\n- $agentic-project-finder (/absolute/path/SKILL.md)\nUse only if the intent matches."
  }
}
```

Выходные данные содержат не более трех кандидатов и 500 символов. Обычное совпадение не имеет `systemMessage` и фальшивого процента достоверности.

Обычное отрицание не отключает маршрутизацию. Явные отказы, такие как `ne suggère aucune skill` и `disable skill routing`, действуют. Приглашение, которое уже содержит активное упоминание `$skill` для Codex или команду `/skill` для Claude Code, также проходит автоматически.

## Конфигурация

| Переменная | Цель |
|---|---|
| `SKILL_ROUTER_HOST` | Требуемый адаптер: `codex` или `claude`. |
| `SKILL_ROUTER_CWD` | Создать целевой рабочий каталог |
| `SKILL_ROUTER_HOME` | Домашнее переопределение для тестов или изолированных установок |
| `SKILL_ROUTER_DATA_DIR` | Кэш и дополнительный корень журнала |
| `SKILL_ROUTER_EXTRA_ROOTS` | Дополнительные авторизованные корни навыков, разделенные разделителем пути к ОС. |
| `SKILL_ROUTER_OVERLAY_ROOTS` | Внешние корни корпуса, разделенные разделителем пути ОС. |
| `SKILL_ROUTER_LOG=1` | Включить журналы маршрутизации только с метаданными |
| `SKILL_ROUTER_DEEP_CHECK_MS` | Интервал для проверки отдельного хеша контента, по умолчанию 60000 мс. |

## Откат

1. Удалите из соответствующего файла перехватчиков только тот обработчик, команда которого содержит `skill-router/bm25-suggest.js`.
2. Восстановите резервную копию с отметкой времени, напечатанную установщиком.
3. Откройте `/hooks` в Codex и убедитесь, что ни один измененный недоверенный перехватчик не остается активным.
4. Временно сохраните кэш для диагностики. Он содержит сценарии и метаданные, а не подсказки для пользователя.
