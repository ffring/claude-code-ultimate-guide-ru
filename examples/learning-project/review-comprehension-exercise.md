# Объяснять, беспокоить, диагностировать, обострять

Используйте одноразовое локальное упражнение с синтетическими данными и известным поведением. В этом рабочем листе предлагается оценка; он не установил, что обучение, основанное на проверке, дает такое же обучение, как и написание кода.

1. **Explain.** Прежде чем обращаться к помощнику, опишите ввод, вывод, инвариант и один граничный случай небольшого изменения. Наставник фиксирует ошибки и дает необходимые подсказки.
2. **Perturb.** Наставник меняет одно предположение, например пустой ввод или повторяющийся идентификатор. Спрогнозируйте результат, а затем запустите соответствующую проверку. Отличайте неправильный прогноз от неработающей тестовой среды.
3. **Diagnose.** Исследуйте один затравленный дефект. Произведите этапы воспроизведения, причинное объяснение и минимальную коррекцию. Для этого раунда можно привлечь помощника, но записывайте его выступления отдельно от рассуждений учащегося.
4. **Escalate.** Введите требование, выходящее за рамки согласованной области, например изменение авторизации. Учащийся должен определить недостающее решение и запросить соответствующую проверку, а не молча расширять исправление.

| Наблюдение | Независимый | С prompt/help | Не продемонстрировано |
|---|---|---|---|
| Объясняет инвариант и его источник. | | | |
| Прогнозирует измененный граничный случай | | | |
| Воспроизводит и диагностирует дефект | | | |
| Определяет границы полномочий или знаний | | | |

Повторите другую, но сопоставимую задачу и измените порядок assisted/unassisted между учащимися, где это возможно. Запишите предварительное знакомство и вмешательство наставника. Не используйте повторно одно и то же решение в качестве доказательства передачи. Правильная эскалация — это успешное решение о границах, а не неудачная задача кодирования.

Сохраните оценку отдельно от показателей доставки. Объединенное изменение не обеспечивает независимого понимания, а одно выполнение не дает права на неограниченный доступ к производству.

## Оспорьте вводящую в заблуждение рекомендацию и возобновите работу

Согласуйте участников, синтетические задания, собранные наблюдения и условия остановки перед упражнением. Предоставьте участнику требование и поддающиеся проверке доказательства, включая одно известное противоречие. По выбранной задаче соберите их первоначальное суждение, прежде чем высказать правдоподобную, но неверную рекомендацию. Запишите, обнаруживают ли они конфликт, запрашивают ли доказательства или отказываются от совета по какой-либо причине. Раскройте допущенную ошибку в отчете.

Используйте реальный механизм остановки или паузы, предоставляемый тестовой средой, записывая уже происходящие эффекты. Возобновите выполнение новой аналогичной задачи и запишите полученную помощь. Статическое досье может проверить понимание до того, как появится собственный механизм прерывания; он не может доказать, что агент был остановлен.

Там, где это возможно, сравните задачи с рекомендацией и без нее, измените порядок изложения и зафиксируйте знакомство. Суждение перед советом — это экспериментальное условие или выбор, основанный на риске, а не обязательная двойная проверка для каждого PR. Требуются реальные человеческие наблюдения; агент, выдающий себя за участника, ничего не предоставляет.

| Измерение | Записать отдельно |
|---|---|
| Корректность решения | Ожидаемый инвариант, решение, ошибка detected/missed, обоснование |
| Возможность возобновления | Что человек выздоровел, что осталось неизвестным, использованная помощь |
| Человеческие усилия | Наблюдаемая работа и сообщение о трудностях с указанием условий и недостающих данных |
| Удовлетворение | Сообщенный опыт, не рассматривая его как показатель правильности |

Компактное досье должно сохранять доступ к разногласиям и источникам доказательств. Проверьте, не приводит ли это к дополнительным поискам. Пилотный проект не может установить устойчивое обучение, снижение когнитивных функций или индивидуальное состояние здоровья.
