# Проблема: неполные доказательства выпуска могут выглядеть готовыми

## Ограниченная задача

Команда выпуска не должна принимать кандидата, если требуемая проверка не удалась, отсутствует, не имеет доказательств или появляется дважды. Недействительный JSON должен отличаться от действительного кандидата, который не готов.

Это эталонное решение устраняет проблему. Учащийся может использовать приведенный ниже контракт о приемке, чтобы воспроизвести работу с новой веткой и изменением, внесенным сначала для тестирования.

## Договор приемки

- Кандидат, прошедший проверку `tests`, `security` и `package`, выходит из `0` и сообщает `ready: true`.
- Действительный, но неполный кандидат выходит из `1`, сообщает `ready: false` и перечисляет все обнаруженные проблемы.
- Неверно сформированный JSON выходит из `2` и записывает ошибку синтаксического анализа в стандартную ошибку.
- Повторяющиеся имена проверок не пройдены, даже если один дубликат содержит проходящее доказательство.
- Нечувствительные к регистру маркеры `UNKNOWN`, `failed`, `not executed`, `unverified`, `NOT RUN` и `no retained output` не работают, поскольку они не идентифицируют сохраненный результат.
- Тесты выполняются через `node:test` без сторонних пакетов и доступа к сети.

## Исключения

CLI не выполняет аутентификацию в реестре, не выполняет строки свидетельства, не публикует пакеты, не создает контейнеры и не доказывает успешность внешнего развертывания. Эти действия остаются за рамками данного вопроса.
