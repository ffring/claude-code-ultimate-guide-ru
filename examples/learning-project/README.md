# Proofpack: один проект для курса обучения из семи модулей

Proofpack — это Node.js CLI без зависимостей, который решает, имеет ли кандидат на выпуск достаточно доказательств для отправки. Его окончательное состояние — эталонное решение. Учащийся может восстановить один и тот же результат в модулях с 01 по 07, не переключая проекты и не придумывая каждый раз новое упражнение.

Ограниченный рабочий элемент записывается в [ISSUE.md](ISSUE.md). CLI принимает кандидата JSON, проверяет необходимые свидетельства `tests`, `security` и `package`, печатает машиночитаемый отчет и возвращает отдельный код выхода в случае неполного свидетельства или неверного ввода.

## Запустите его без установки пакетов

Node.js 20 или новее — единственная тестовая зависимость.

```bash
node --version
npm test
npm run verify
```

`npm run verify` должен выйти из `0`. Сравните это с фиксацией преднамеренного отказа:

```bash
npm run verify:incomplete
```

Эта команда должна выйти из `1` и назвать неудачные и отсутствующие проверки. Неверный JSON выходит из `2`.

## Контракт на доказательства

Валидатор требует одну уникальную проверку для каждого из этих имен:

- `tests`
- `security`
- `package`

Для каждой проверки требуется `status: "pass"` и описание сохраняемого результата. Пустые доказательства и нечувствительные к регистру маркеры `UNKNOWN`, `failed`, `not executed`, `unverified`, `NOT RUN` и `no retained output` не работают. Это консервативный строковый экран, поэтому текст типа `0 failed` также не будет отображаться. Схема-кандидат не анализирует команду, статус выхода или контрольную сумму из этой строки. Поместите эти структурированные факты в [evidence/PROOF-LOG.md](evidence/PROOF-LOG.md). Версия должна использовать `MAJOR.MINOR.PATCH`. Повторяющееся имя является неудачей, поскольку более поздние доказательства не должны затмевать более ранние результаты.

[fixtures/release-ready.json](fixtures/release-ready.json) демонстрирует принятую схему. [fixtures/release-incomplete.json](fixtures/release-incomplete.json) демонстрирует неудачную проверку безопасности и отсутствие доказательств пакета. CLI не обращается к реестру, не выполняет строки свидетельства и не делает вывод о том, что указанная команда действительно выполнялась.

## Проверка и упаковка

Запустите полный локальный шлюз, прежде чем утверждать, что эталонное решение прошло успешно:

```bash
npm test
npm run verify
npm run package:check
```

Шлюз пакета проверяет оба файла JavaScript на `node --check`, а затем создает манифест npm без загрузки зависимостей или публикации артефакта. Именованный тест [package-check](test/package-check.test.mjs) внедряет недопустимый JavaScript во временную копию и требует ненулевого выхода. Это доказывает границу синтаксиса, а не выполнение упакованного CLI. [Dockerfile](Dockerfile) предоставляет дополнительную развертываемую форму. Для его сборки может потребоваться базовый образ `node:22-alpine` из реестра, поэтому прохождение теста Node.js не доказывает, что образ собирается или работает на другом хосте.

Шаблон протокола проверки [TESTING.md репозитория](../claude-md/TESTING.md) объясняет полный формат доказательств. В этом примере хранится заполненный журнал проверки [](evidence/PROOF-LOG.md)для конкретного проекта. Для выбора с более высокой стоимостью следуйте рабочему процессу [Best-of-N](../../guide/workflows/best-of-n.md) и сохраняйте отклоненных кандидатов, а также выбранного.

## Граница безопасности

Защита освобождения блокирует прямые вызовы инструментов `npm publish` и `docker push` с флагами и запутанными пустыми кавычками. Он также запрещает любую команду, в которой `npm` встречается с `publish` или `docker` появляется с `push`, даже если слова только напечатаны или обсуждаются. Эти консервативные ложные срабатывания являются преднамеренными. Перехватчик не перехватывает псевдонимы, закодированные команды, расширение переменных, других клиентов реестра или конструкции оболочки, которые разделяют слова непустым текстом в кавычках. Он никогда не разблокируется автоматически после прохождения проверки. Относитесь к нему как к средству обучения, а не как к анализатору оболочки или общему командному брандмауэру. Примените рекомендации по усилению безопасности репозитория [](../../guide/security/security-hardening.md), прежде чем адаптировать перехватчики к рабочей среде.

Для публикации также требуется владелец канала, учетные данные места назначения и явное решение. Рабочий процесс распространения [guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/docs/workflows/guide-distribution.md) отделяет эти внешние действия от локальных проверок упаковки. Эта страница предоставляется родительской интеграцией `main`; эта изолированная ветка сохраняет ссылку на внешний репозиторий до тех пор, пока оба коммита не будут объединены.
