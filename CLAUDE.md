# Claude Code Полное руководство — Контекст проекта

## Цель

Этот репозиторий является **комплексная документация по Claude Code** (Anthropic's CLI инструмент). Он учит пользователей, как использовать Claude Code эффективно с помощью руководств, примеров и шаблонов.

**Meta-note**: В этом репозитории документирован Claude Code, поэтому его собственная конфигурация должна быть образцовой.

### Слэш-команды (обслуживание)

Пользовательские команды косой черты, доступные в этом проекте:

| Команда | Описание |
|---------|-------------|
| `/release <bump-type>` | Версия руководства по выпуску (CHANGELOG + ВЕРСИЯ + синхронизация + фиксация + push) |
| `/update-infos-release [bump-type]` | Отслеживание выпусков обновлений Claude Code + дополнительный выпуск версии руководства |
| `/version` | Отобразить текущее руководство и версии Claude Code со статистикой. |
| `/changelog [count]` | Просмотр последних записей CHANGELOG (по умолчанию: 5) |
| `/sync` | Проверьте статус синхронизации guide/landing |
| `/audit-agents-skills [path]` | Аудит качества агентов, навыков и команд в .claude/config |
| `/security-check` | Быстрая проверка конфигурации по базе данных известных угроз (~30 с) |
| `/security-audit` | Полный 6-этапный аудит безопасности с баллом /100 (2-5 минут) |
| `/update-threat-db` | Исследование и обновление базы данных аналитики об угрозах |

**Examples:**
```
/release patch                 # Bump patch + release (3.20.4 → 3.20.5)
/release minor                 # Bump minor + release (3.20.4 → 3.21.0)
/update-infos-release          # Update CC releases only
/update-infos-release patch    # Update CC + bump guide (3.9.11 → 3.9.12)
/update-infos-release minor    # Update CC + bump guide (3.9.11 → 3.10.0)
/version                       # Show versions and content stats
/changelog 10                  # Last 10 CHANGELOG entries
/sync                          # Check guide/landing sync status
/audit-agents-skills           # Audit current project
/audit-agents-skills --fix     # Audit + fix suggestions
/audit-agents-skills ~/other   # Audit another project
/security-check                # Quick scan config vs known threats
/security-audit                # Full audit with posture score /100
/update-threat-db              # Research + update threat-db.yaml
```

Эти команды определены в `.claude/commands/` и автоматизируют:
- Отслеживание релизов Claude Code (YAML + Markdown + значок лендинга)
- Руководство по управлению версиями (файл VERSION + синхронизация между всеми документами)
- Обновления журнала изменений
- Проверка синхронизации лендинга
- Git зафиксировать и отправить в оба репозитория

### Соглашения об именах команд

Неявные префиксы, используемые в `.claude/commands/`:

| Префикс | Шаблон | Примеры |
|--------|---------|---------|
| `audit-*` | Проверки качества с оценкой результатов | `audit-agents-skills`, `audit-deps` |
| `update-*` | Синхронизируйте или обновите данные из внешнего источника. | `update-infos-release`, `update-threat-db` |
| `security-*` | Сканирование безопасности, возрастающая глубина | `security-check` (быстрый), `security-audit` (полный) |
| *(без префикса)* | Основные команды рабочего процесса руководства | `release`, `sync`, `version`, `changelog` |

При добавлении новой команды выберите префикс, соответствующий типу действия. Не создавайте новые категории префиксов, если существующие четыре не подходят.

## Поведенческие правила

Эти правила основаны на наблюдаемых закономерностях трения в реальных сессиях этого репо.

### Всегда обновляйте CHANGELOG.md
После любого изменения файла или реализации функции обновите `CHANGELOG.md` под `[Unreleased]`. Никогда не пропускайте этот шаг, если об этом явно не сказано. Это наиболее распространенный пропущенный шаг.

### Будьте исчерпывающими при первом проходе
Когда вас просят проанализировать, проверить или просмотреть что-либо, прочитайте каждый соответствующий файл. Не делайте поверхностное сканирование. Если вы не уверены в масштабах, спросите, а не давайте поверхностные результаты. Это относится к оценкам ресурсов, аудиту документации и проверкам кодовой базы.

### Публичный контент должен быть портативным

Применяйте это правило к руководствам, оценкам, примерам, журналам изменений, индексам, экспорту и целевому контенту, включая блоки кода, таблицы, подписи и цели ссылок.

1. Используйте пути относительно репозитория для файлов, распространяемых вместе с проектом, и проверенные общедоступные URL-адреса для внешних источников. Дайте командам чистый стартовый каталог, например корень клонированного репозитория.
2. Никогда не публикуйте личные домашние каталоги, временные пути оформления покупок, местоположения частных рабочих мест, URL-адреса локальных файлов или личные заметки и переписку в качестве доказательств, доступных читателю. Также проверьте скопированные журналы и сгенерированный контент. Если общедоступного источника не существует, укажите ограничение доказательств или опустите ссылку; никогда не придумывайте заменяющий URL.
3. Опустите бухгалтерский учет аудита, например столбцы «Локальный источник» и автономные хэш-таблицы версий. Используйте постоянные ссылки на общедоступные источники, когда происхождение имеет значение. Отображайте версию или хеш только тогда, когда читателям это необходимо для воспроизведения команды или понимания поведения, специфичного для версии.
4. Используйте общие заполнители, такие как `/path/to/project`, если для примера необходим абсолютный путь. Сохраняйте реальные системные пути, когда они являются предметом объяснения.
5. Зарезервируйте абсолютные пути к рабочей станции для отчетов о частных задачах и интерактивных ссылок на локальные файлы пользователя. Они не принадлежат к публичному контенту.

Перед публикацией запустите `python3 scripts/check-public-paths.py`. Включите построенную площадку, используя опцию сценария dist, если это применимо. Детектор охватывает шаблоны траекторий; вручную проверьте доступность источника и ненужные метаданные редакции.

### Заключительный контрольный список
После выполнения всех запрошенных задач всегда подтверждайте без запроса:
1. Файлы изменены (перечислите их)
2. CHANGELOG.md обновлен
3. Зафиксировано и отправлено (если применимо): включите хеш фиксации.

### Склонность к действию
Не тратьте слишком много времени на исследования и планирование. Создавайте файлы и конкретный результат заранее, а затем повторяйте. Если на каком-либо шаге застряло более двух попыток, объясните блокировщик вместо зацикливания.

## Конвенции

### Стиль документации
- **Точность в отношении маркетинга**: Никаких выдуманных процентов или непроверенных утверждений.
- **Практические примеры**: Каждая концепция имеет конкретный пример.
- **Атрибуция источника**: укажите вклад сообщества со ссылками
- **Выравнивание версий**: все номера версий должны соответствовать файлу `VERSION`.

### Организация файлов
- Новые гайды → `guide/`
- Новые шаблоны → `examples/{agents,commands,hooks,skills}/`
- Обновления навигации → Обновите `README.md` и `guide/README.md`.

### Управление версиями
- Файл `VERSION` — единственный источник правды.
- Запустите `./scripts/sync-version.sh` после смены версии.
- Файлы, содержащие версию: README.md, cheatsheet.md, ultimate-guide.md, reference.yaml.
- `CLAUDE.md`/`AGENTS.md` исключены из `sync-version.sh` намеренно: их примеры команд иллюстрируют изменения в версии (`3.9.11 → 3.9.12`), а слепое регулярное выражение скрипта `3.x.x` превратило бы эти примеры в бессмыслицу. Исправьте вручную отдельную линию «текущий X.Y.Z», когда она смещается.

## Конфигурация модели

**Рекомендуемый режим**: `/model opusplan`

**Rationale**: Этот репозиторий документации использует преимущества гибридного интеллекта:
- **Этап планирования** (Opus + мышление): Архитектурные решения, синтез исследований, многофайловый анализ
- **Фаза выполнения** (Sonnet): обновления документов, синхронизация версий, редактирование шаблонов, форматирование.

**Рабочий процесс OpusPlan**:
1. `/model opusplan` → Установить гибридный режим
2. `/plan` или `Shift+Tab × 2` → Планируйте с помощью Opus (мышление включено)
3. `Shift+Tab` → Выполнить с помощью Sonnet (быстрее, дешевле)

**Типичная разбивка задач**:
| Тип задачи | Модель | Обоснование |
|-----------|-------|---------------|
| Правка документа, исправление опечаток | Sonnet | Прямо, без глубоких рассуждений |
| Синхронизация версий, форматирование | Sonnet | Механическое сопоставление с образцом |
| Руководство по реструктуризации | Opus (план) → Sonnet (выполнить) | Сначала нужно подумать об архитектуре |
| Синтез исследований | Opus (план) → Sonnet (запись) | Комплексный анализ, затем четкое написание |
| Проверка целостности нескольких файлов | Opus (план) → Sonnet (исправление) | Анализ зависимостей, затем редактирование |

**Оптимизация затрат**: OpusPlan платит Opus только за планирование (обычно 10-20% токенов), Sonnet берет на себя 80-90% исполнительной работы.

## Рабочий процесс оценки ресурсов

Внешние ресурсы (статьи, видео, обсуждения) оцениваются перед интеграцией в руководство.

### Процесс

1. **Research**: Начальный поиск с недоумением → Сохранить подсказку + результаты в `claudedocs/resource-evaluations/` (частное)
1б. **Перекрестная ссылка**: Если ресурс находится в Claude Code, проверка претензий противоречит `https://code.claude.com/docs/llms-full.txt` (официальный источник ~ 98 КБ)
2. **Evaluation**: Систематическая оценка (1-5) → Создать файл оценки в `docs/resource-evaluations/` (отслеживается)
3. **Challenge**: Техническая проверка агента для обеспечения объективности
4. **Решение**: Интегрировать (оценка 3+), упомянуть (оценка 2) или отклонить (оценка 1)

### Организация файлов

| Расположение | Содержание | Отслеживание |
|----------|---------|----------|
| `docs/resource-evaluations/` | Итоговые оценки (167 файлов) | ✅ Git отслеживается (публично) |
| `claudedocs/resource-evaluations/` | Рабочая документация, подсказки, частные аудиты | ❌ Gitignored (частный) |

### Сетка подсчета очков

| Счет | Действие |
|-------|--------|
| 5 | Критически важно: интеграция немедленная (<24 часов) |
| 4 | Высокая ценность — интеграция в течение 1 недели |
| 3 | Умеренный – интегрируйте, когда есть время |
| 2 | Маргинальный – минимальное упоминание или пропуск. |
| 1 | Низкий – Отклонить |

Полную методологию см.: [`docs/resource-evaluations/README.md`](docs/resource-evaluations/README.md).

## Быстрый поиск

Для ответов на вопросы о Claude Code:
0. **Официальный документ Anthropic (оптимизированный для LLM)**: `https://code.claude.com/docs/llms.txt` (индекс ~65 страниц) или `https://code.claude.com/docs/llms-full.txt` (полный документ ~98 КБ) для официальных документов

2. Используйте эти номера строк, чтобы прочитать соответствующие разделы из `guide/ultimate-guide.md`.
3. Проверьте `examples/` на наличие готовых шаблонов.
4. Проверьте `guide/core/claude-code-releases.md` на наличие недавнего features/changes.
5. Si info manquante ou incertaine → require une recherche Perplexity (общение, сравнения, возвраты)
