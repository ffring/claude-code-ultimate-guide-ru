**Relationship**: Шаблоны создаются и поддерживаются в `examples/` этого репозитория. Репозиторий плагинов является опубликованной копией — **, источник истины находится здесь**.

**Install**:
```bash
claude plugin marketplace add FlorianBruniaux/claude-code-plugins
claude plugin install security-suite   # or any of the 8 plugins
```

**Plugins**: пакет безопасности, конвейер Devops, автоматизация выпуска, качество кода, рабочий процесс PR, инструменты сеанса, методология искусственного интеллекта, сводка сеанса

## 3в. Портфолио и блог Флориана

**For**: читатели приходят через развернутое письмо, а не через руководство.

| Аспект | Подробности |
|--------|---------|
| **Публикация** | https://florian.bruniaux.com/blog |
| **Содержимое** | 17 опубликованных статей, 6 полных руководств, около 20 черновиков, все коллекции контента Astro. |
| **Аудитория** | Практики и лица, принимающие решения, более глубокие и самоуверенные, чем руководство. |

**Коллекции контента** (`src/content/`):

| Коллекция | Роль | Опубликовать ворота |
|------------|------|--------------|
| `articles/` | Эссе продолжительностью от 12 до 48 минут, часто в формате `series`. | `draft: false` во фронтальной теме |
| `guides/` | 45-минутные уроки по `outcomes` и `prerequisites` | `draft: false` |
| `draft/` | Работа в стадии разработки, так и не построена | не публикуется независимо от темы |
| `notes/`, `projects/` | Краткие заметки, карточки проектов. | схема в `src/content/config.ts` |

**Отношение к этому репо**: в блоге утверждается, в руководящих документах. Несколько статей посвящены той же теме, что и разделы руководства на другой высоте (поверхность атаки на безопасность, разработка контекста, стоимость токена). При существенном изменении раздела руководства проверьте, не противоречит ли ему теперь опубликованная статья. Опубликованная статья, в которой говорится о том, что руководство с тех пор исправило, является действующей дезинформацией, а не просто устаревшим контентом.

**Также размещается распространение PDF-файлов**: `public/guides/` содержит PDF-файлы с техническими документами, а `api/guides.mjs` сопоставляет стабильные идентификаторы с версионными именами файлов для ссылок по электронной почте. См. `docs/workflows/whitepaper-build.md`, «Контрольный список развертывания PDF».

## Триггеры синхронизации Cross-Repo

| Изменять | Репозитории для обновления |
|--------|----------------|
| Увеличенная версия (Руководство по коду) | 1. Руководство по коду, 2. Код лендинга |
| Шаблоны added/removed | 1. Руководство по коду, 2. Лендинг кода, 3. Репозиторий плагинов. |
| Плагин added/updated | 1. Репозиторий плагинов, 2. Руководство по коду README, 3. Данные экосистемы Code Landing. |
| Обновление версии (Cowork) | 1. Руководство по коворку, 2. Лендинг по коворку |
| Подсказки added/removed | 1. Руководство по коворку, 2. Лендинг по коворку |
| Перекрестные ссылки изменены | Все репозитории |
| Исправлен раздел безопасности в `guide/`. | 1. Руководство по коду, 2. **Portfolio**: grep `src/content/guides/` и `src/content/articles/` для одного и того же утверждения, прежде чем предположить, что ничего не затронуто. |
| Технический документ PDF переработан | 1. Руководство по коду, 2. Портфолио `public/guides/`, 3. Портфолио `api/guides.mjs`, 4. Лендинг по коду `whitepapers-data.ts` |

**Скрипты проверки**:

```bash
# Check Code Landing sync
./scripts/check-landing-sync.sh

# Check Cowork sync
cd ../claude-cowork-guide && ./scripts/check-version-sync.sh
```

## Отношения и ссылки

**Руководство по коду → Руководство по совместной работе**:
- `guide/cowork.md`: Резюме со ссылками на специальный репозиторий.
- `guide/README.md`: Таблица с 6 ссылками на руководства Cowork
- `machine-readable/reference.yaml`: 23 записи, указывающие на GitHub.

**Кодовый лендинг ↔ Коворк-лендинг**:
- Двунаправленные перекрестные ссылки (герой, экосистема, разделы)
- Плавная навигация между двумя аудиториями

**Principle**: четкое разделение аудитории, простая навигация, постоянная синхронизация.
