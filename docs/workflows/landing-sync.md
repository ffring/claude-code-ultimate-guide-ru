# Синхронизация лендинга

Рабочий процесс для синхронизации `cc.bruniaux.com` с руководством после значительных изменений.

**Репо лендинга**: [claude-code-ultimate-guide-landing](https://github.com/FlorianBruniaux/claude-code-ultimate-guide-landing). Команды берут на себя руководство братом и сестрой и проверку приземления.

## Элементы для синхронизации

| Элемент | Источник (руководство) | Пункт назначения (посадка) |
|---------|----------------|----------------------|
| Версия | `VERSION` | Прочитано при сборке `src/pages/changelog/index.astro` (без жестко запрограммированной копии) |
| Количество шаблонов | Подсчет файлов `examples/` | Значки, заголовок, метатеги |
| Направляющие линии | `wc -l guide/ultimate-guide.md` | Значки |
| Золотые правила | README.md | Раздел главной страницы лендинга |
| Частые вопросы | README.md | Часто задаваемые вопросы по лендингу |

## Синхронизировать триггеры

После этих модификаций **вспомните**, чтобы обновить лендинг:

1. **Version jump** → Обновите `VERSION` здесь, затем приземлитесь
2. **Templates added/removed** → Пересчитать количество, обновить лендинг
3. **Золотые правила или часто задаваемые вопросы изменены** → Распространить на целевую страницу
4. **Значительное изменение руководства** (>100 строк)

## Guide Reader Rebuild (каждый выпуск)

На лендинге отображается содержание руководства по адресу `cc.bruniaux.com/guide/`. Содержимое генерируется из этого репозитория во время сборки — **никогда не фиксируется на целевой странице**.

```bash
# From the landing repo, before each push to main:
cd ../claude-code-ultimate-guide-landing
node scripts/prepare-guide-content.mjs && pnpm build
```

**Когда это делать**: в каждом выпуске (`/release patch|minor|major`), чтобы на сайте отображалась последняя версия руководства.

## Команда проверки

```bash
./scripts/check-landing-sync.sh
```

**Что проверяет скрипт (4 проверки):**

| Проверять | Источник | Сравнение |
|-------|--------|-----------|
| Версия | `VERSION` | Чтение во время сборки в `src/pages/changelog/index.astro` |
| Шаблоны | `find examples/` | Каталог `src/data/examples-data.ts` |
| Вопросы викторины | `questions.json` | Целевые страницы викторины |
| Направляющие линии | `wc -l ultimate-guide.md` | Посадочные бейджи (допуск ±500) |

**Ожидаемый результат (при синхронизации):**
```
=== Landing Site Sync Check ===

1. Version
   Guide:   3.8.1
   Landing: 3.8.1
   OK
...
=== Summary ===
All synced!
```

Если несоответствие: код выхода = количество найденных проблем. Проверьте `landing/CLAUDE.md`, чтобы узнать точные номера строк, которые нужно изменить.

## Индекс поиска (Cmd+K)

Палитра поиска Cmd+K лендинга включает в себя направляющие записи, созданные из `machine-readable/reference.yaml` (раздел `deep_dive`).

```bash
# From the landing repo, after any reference.yaml change:
cd ../claude-code-ultimate-guide-landing
pnpm build:search
```

Скрипт (`scripts/build-guide-index.mjs`) регенерирует `src/data/guide-search-entries.ts`. Как он обрабатывает привязки: для файлов руководств, обслуживаемых локально в `/guide/<slug>/`, привязка удаляется, и результаты поиска ссылаются на верхнюю часть страницы. Во всем остальном запись ссылается на GitHub с сохраненным якорем, поэтому устаревший якорь там означает мертвую ссылку в проде.

**Когда пересобирать**: после добавления, удаления или переименования ключей `deep_dive` в `reference.yaml`. Изменения только привязки в локально обслуживаемых файлах руководства не изменяют сгенерированные URL-адреса, но сохранение точности YAML в любом случае имеет значение, поскольку это индекс, ориентированный на LLM.

Файл: `src/components/global/AnnouncementBanner.astro` (лендинговый репозиторий)

**Обновление рабочего процесса**:
1. Редактировать текст баннера в компоненте
2. Увеличьте `BANNER_ID` (например, `banner-guide-2026-04`), чтобы сбросить состояние отклонения для всех посетителей.
3. `pnpm build` + фиксация + нажатие

**Когда обновлять**: большая новая страница, добавлен важный раздел, веха в руководстве, видимая новая функция.

## RSS-канал

Приземление открывает единый RSS-канал по адресу `/rss.xml`.

**Два объединенных источника** (отсортировано по дате, максимум 50 записей):
1. Релизы CC: авто из `src/data/releases.ts`
2. Записи руководства: **manual** в `src/data/rss-entries.ts`

**Доступные типы**: `guide_release | new_page | new_cheatcard | new_whitepaper | new_section`

**Когда добавлять запись вручную**:
- На сайт добавлена ​​новая страница (`new_page`)
- Новая серия карт (`new_cheatcard`)
- Доступен новый технический документ (`new_whitepaper`)
- Большой новый раздел в руководстве (`new_section`)

## Карта сайта

Файл: `src/pages/sitemap/index.astro` (лендинговый репозиторий)

**Rule**: добавляйте каждую новую страницу в карту сайта. Секции находятся в массиве `sections` во фронтальной части Astro.
