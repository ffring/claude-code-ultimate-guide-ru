# Рабочий процесс статуса перевода

Хранилище разделяет три факта, которые легко спутать:

1. **File parity** проверяет, содержат ли оба языка ожидаемые файлы публикации.
2. **Metadata parity** проверяет, записывает ли парная французская и английская публикация один и тот же базовый уровень руководства. `wp-version` для конкретного языка может отличаться и о нем сообщается отдельно.
3. **Свежесть перевода** проверяет, какая каноническая исходная версия и контрольная сумма создали переведенное полное руководство.

Машиночитаемый реестр — [`machine-readable/translations.json`](../../machine-readable/translations.json). Публичная страница статуса — [`guide/core/translations.md`](../../guide/core/translations.md).

## Местная проверка

```bash
python3 scripts/check-translations.py --check
```

Эта команда проверяет:

- каноническая английская версия и SHA-256 против `VERSION` и `guide/ultimate-guide.md`;
- поддерживаемая французская версия, хеш артефакта и записанная базовая версия английского источника;
- обязательные поля реестра, уникальные языки, происхождение исходного коммита и закрепленная задержка Git;
- заявленный неофициальный статус, доказательства авторства и границы охвата каждого перевода сообщества;
- 6 заявленных пар исходных текстов и известный префикс `03`, предназначенный только для французского языка;
- Имена исходных файлов карточек резюме на французском и английском языках;
- парные базовые версии руководства и метаданные `lang`, а также различия в версиях технических документов для конкретных языков.

Трансляция, которая точно отмечена `stale`, не нарушает шлюз по умолчанию. Команда по-прежнему печатает задержку. Используйте строгую форму перед публикацией поддерживаемого переведенного полного руководства:

```bash
python3 scripts/check-translations.py --check --require-current-maintained
```

## <a name="after-changing-the-english-full-guide"></a>После смены английского полного руководства

Происхождение перевода должно указывать на реальный объект Git. Никогда не привязывайте SHA-256 незафиксированного руководства рабочего дерева к более старому коммиту. Используйте два коммита:

1. Зафиксируйте каноническое руководство, справочные индексы и соответствующую документацию, не меняя ни одного зеркала `translations.json`.
2. Запустите каноническое обновление реестра для этого коммита:

   ```bash
   python3 scripts/check-translations.py --update-local
   ```

3. Скопируйте обновленный канонический реестр в `mcp-server/content/translations.json` и проверьте равенство байтов.
4. Зафиксируйте только два зеркала реестра перевода.

`--update-local` отказывается писать, а `guide/ultimate-guide.md` отличается от своей последней зафиксированной версии. Ожидается, что обычный `--check` перед первой фиксацией сообщит о отклонении SHA канонического рабочего дерева. Этот сбой является свидетельством того, что происхождение еще не зафиксировано, а не поводом изобретать коммит или ослаблять проверку.

После первого коммита обновление обновляет локальные факты, не утверждая, что перевод был регенерирован:

```bash
python3 scripts/check-translations.py --update-local
```

При этом обновляется каноническая версия и контрольная сумма, записывается зафиксированная контрольная сумма `source.commit:path`, считывается локальная французская версия и пересчитывается ее статус. Он не изменяет `translated_from` или `last_full_refresh_at`. Валидатор пересчитывает байты по адресу `source.commit:path` и требует, чтобы хэш был равен `source.sha256`.

## После регенерации полного руководства на французском языке

`scripts/translate-guide.py` записывает контрольную сумму входных данных кэша. Он отказывается повторно использовать фрагменты, созданные из другой исходной версии или модели. После полного перевода он вызывает:

```bash
python3 scripts/check-translations.py --update-local --record-french-refresh
```

Эта команда связывает вывод на французском языке с текущей английской версией и контрольной суммой. Запустите строгую проверку перед экспортом PDF или EPUB.

## Обзор перевода сообщества

Не делайте вывод о синхронизации только по дате изменения репозитория. Запишите следующие поля после просмотра удаленного проекта:

- заявленная версия;
- исходная фиксация или исходный базовый уровень, если таковой имеется;
- удаленная головная фиксация;
- дата последней наблюдаемой восходящей синхронизации;
- заявление о покрытии;
- дата рассмотрения.

Обновите соответствующий объект в `machine-readable/translations.json`. CI репозитория проверяет заявленное состояние, но не обращается к сторонним репозиториям во время сборки.

Для каждой удаленной проверки:

1. Подтвердите URL-адрес репозитория, сопровождающего, ветку по умолчанию, HEAD, лицензию и заявленную версию.
2. Найдите точный исходный коммит на английском языке из манифеста или предков Git. Если ничего не продемонстрировать, сохраните нулевую исходную фиксацию и нулевую числовую задержку вместо оценки.
3. Проверьте авторство в README, лицензии, описании репозитория или уведомлении о переводе.
4. Запись о покрытии, сообщенном сопровождающим, и отдельное наблюдение за файловой системой.
5. Пересчитать задержку фиксации только для руководства и всего репозитория для `measured_at_commit`.
6. Обновляйте `last_checked_at` только после проверки каждого записанного удаленного факта.

Не выполняйте скрипты из репозитория сообщества во время аудита. Проверяйте только исходные файлы и объекты Git.

## Парные публикации

Общедоступные источники технических документов объединяются по двузначному префиксу, а не по переведенному имени файла. Публичный каталог содержит 13 парных выпусков, а этот репозиторий содержит 6 парных префиксов исходных текстов `.qmd` и один объявленный только французский источник. Отсутствующие исходные файлы не считаются синхронизированными. Документы на французском языке, специфичные для клиента, без нумерованного общедоступного префикса, остаются за пределами этого шлюза паритета.

Пары карточек резюме по имени исходного файла. Наличие PDF-файлов является проблемой для экспорта; ворота перевода сравнивают источники `.qmd` и их вступительную часть.

Паритет публикаций не доказывает свежесть по сравнению с полным руководством. Технические документы и карточки с резюме представляют собой адаптацию или резюме темы, поэтому задержка их полного руководства остается `UNKNOWN` до тех пор, пока специальный аудит контента не зарегистрирует исходный базовый уровень.

## Официальные региональные ворота

Французский язык является текущим приоритетом. Не начинайте издавать официальное издание полного руководства на китайском языке или другое издание до тех пор, пока:

- Французский пас `--require-current-maintained`;
- человеческая проверка охватывает навигацию, примеры, ссылки, терминологию и непереведенные остатки;
- названный сопровождающий принимает постоянное право собственности;
- документированы частота обновления и манифест фиксации источника;
- на лендинге могут размещаться стабильные эквивалентные страницы.

Независимый перевод остается изданием сообщества, даже если его качество высокое.

## Лендинг, карта сайта, канонический формат и `hreflang`

После изменения `guide/core/translations.md` постройте площадку по чистому рабочему дереву направляющих:

```bash
GUIDE_REPO_PATH=/absolute/path/to/clean/guide-worktree pnpm build
pnpm test
```

Проверьте построенный вывод:

- `/guide/translations/` существует;
- его канонический URL-адрес указывает на себя;
- карта сайта XML содержит локальный маршрут ровно один раз;
- обычные ссылки раскрывают английский, французский язык и все зарегистрированные версии сообщества;
- URL-адреса репозитория сообщества отсутствуют в локальной карте сайта XML;
- `hreflang` не выдается для локали без эквивалентных страниц и взаимных аннотаций.

Получите развернутую страницу и карту сайта после развертывания. Локальная сборка, отправленная ветвь или текущий рабочий процесс не являются свидетельством развертывания.

## Упоминает границу страницы

Атрибуция перевода указана на странице статуса языка и в реестре. Если на отдельной странице «Упоминания» в портфолио перечислены переводы, проверьте их независимо и сохраните пометку «официальный» или «от сообщества». Руководство или целевая фиксация не доказывают, что развертывание портфеля активно.
