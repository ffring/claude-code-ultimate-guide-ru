## Краткое содержание

just-bash — это полный интерпретатор bash, написанный на TypeScript: лексер, анализатор рекурсивного спуска, AST и механизм выполнения, поддерживаемый виртуальной файловой системой в памяти. Ничего не появляется. Нет ни `child_process`, ни Worker, выступающего в качестве гостевой ОС, ни границы виртуальной машины WASM для самой оболочки. Интерпретатор просто проходит AST и вызывает функции TypeScript. Более 90 встроенных команд, эквивалентных coreutils (`grep`, `sed`, `awk`, `find`, `tar`, `jq`, `xan`, `yq`...), а также дополнительные CPython (через Emscripten), QuickJS (`js-exec`) и sql.js. каждый из них закрыт явным флагом согласия, поскольку каждый добавляет реальную поверхность безопасности.

Четыре серверные части файловой системы охватывают практический диапазон, необходимый приложению для встраивания: `InMemoryFs` (по умолчанию, без контакта с диском), `OverlayFs` (чтение реального диска, запись при копировании, используемое CLI), `ReadWriteFs` (чтение-запись реального диска, позволяющее агенту фактически изменять рабочую область) и `MountableFs` (составляет несколько серверных частей в одном пространстве имен, например база знаний только для чтения, установленная рядом с рабочей областью, доступной для записи). Класс `Sandbox` намеренно отражает `@vercel/sandbox` API, поэтому проект можно начать с простого bash и позже переключиться на настоящую микровиртуальную машину Vercel Sandbox, не затрагивая сайты вызовов.

`THREAT_MODEL.md` (31,5 КБ) — самый сильный артефакт в репозитории. Он называет трех субъектов угрозы (ненадежный автор сценария, источник вредоносных данных, скомпрометированная зависимость), рисует явные границы доверия и сводит в таблицу поверхность атаки: бомбы-токены, бомбы-расширения фигурных скобок, глубина подстановки команд, глобус-бомбы, загрязнение прототипа через ключи IFS/env, перепривязка DNS к дополнительному `curl`, при этом в каждой строке указывается защита, предельное значение и исходный файл. Каждый числовой предел (`maxCallDepth`, `maxSubstitutionDepth: 50`, `maxBraceExpansionResults: 10K`, `maxExecutionTimeMs: 30_000`...) настраивается для каждого экземпляра и переопределяется для каждого вызова `exec()` с профилями `normal` (либеральный) и `hardened` (более жесткий выбор).

## Модель изоляции и важное предостережение

README устанавливает свой собственный предел без хеджирования: «Все выполнение происходит без изоляции виртуальной машины». Между интерпретатором и внедряемым процессом Node нет границы процесса, не говоря уже о гипервизоре. Защита опирается на сдерживание на уровне JavaScript: `DefenseInDepthBox`, который обезьяньим образом исправляет `Function`, `eval`, `setTimeout`, `process.*` и `Module._resolveFilename` внутри контекста области действия `AsyncLocalStorage`, обратимые прокси через `Reflect`/`JSON`/`Math` и объекты нулевого прототипа для всего, ключами чего управляет скрипт (env, ассоциативные массивы, переменные AWK). Документы честно говорят о том, где этого не хватает: обратимое проксирование не может отозвать ссылку на скрипт, кэшированный перед активацией, `resourceLimits` Node не ограничивает надежно линейную память WASM, используемую CPython или sql.js, а всем, кому нужна жесткая память или гарантия процесса, рекомендуется использовать для этой части реальную границу worker/process или Vercel Sandbox.

Это делает изоляцию just-bash более слабой, чем изоляция в AgentOS (`docs/resource-evaluations/agentos-in-process-agent-vm.md`), которая, по крайней мере, помещает сайдкар Rust и изоляцию V8 между гостевым кодом и хостом. just-bash не помещает туда ничего, кроме дисциплинированного TypeScript. Платой за это является простота архитектуры: нет цепочки инструментов Rust, нет дополнительных процессов, которыми нужно управлять, и вся модель безопасности проверяется как обычный TypeScript плюс один файл уценки, в котором указаны все ограничения.

## Где он находится относительно существующего покрытия руководства

`guide/security/sandbox-isolation.md` §5 уже называет агентOS «в процессе разработки контрпримером» для четырех поставщиков облачных услуг (Fly.io Sprites, Cloudflare Sandbox SDK, Vercel Sandboxes, E2B). just-bash принадлежит к тому же подразделу, но не как дубликат AgentOS, а как другой конец спектра внутрипроцессного процесса: AgentOS запускает настоящую (хотя и без гипервизора) виртуальную машину с ядром Rust и изолятом V8; just-bash вообще не запускает виртуальную машину, а просто интерпретатор, совместимый с bash, написанный непосредственно на основном языке. Читателю, сравнивающему эти две точки зрения, нужны обе точки данных, поскольку фраза «в процессе, без облачной учетной записи» охватывает гораздо более широкий диапазон фактической силы изоляции, чем предполагает эта фраза сама по себе.

Это также прямой родственник существующей записи «Песочницы Vercel» в руководстве, написанной двумя подразделами выше (строка 435): Vercel поставляет обе стороны одного и того же компромисса в рамках одной компании: полноценный продукт Firecracker microVM для реальной изоляции и симулированную оболочку с нулевой инфраструктурой для разработки, тестирования и встроенного использования с низкими ставками. Эту взаимосвязь стоит указать явно, поскольку она не очевидна из документации ни к одному из продуктов.

Перекрестный поиск по восьми продуктам-агентам-песочницам, которые обычно сравнивают в этой области (Perplexity, 04.08.2026), подтверждает, что just-bash и WebContainers (StackBlitz) являются единственными двумя элементами «симуляция, а не изоляция»; E2B (холодный старт Firecracker ~150–200 мс), Daytona (~90 мс, Docker/Kata), модальные песочницы (gVisor, от доли секунды до ~3 с), песочницы Cloudflare и Fly Machines (~2–3 с) — все они платят за реальную задержку загрузки за реальную границу ОС. Такое разделение на две категории (имитировать и изолировать) представляет собой более чистую ментальную модель для читателей руководства, чем простой список поставщиков, и ни в одном из существующих разделов руководства об этом прямо не говорится.

## Решение

**Интегрируйте в `guide/security/sandbox-isolation.md` §5**в качестве подраздела рядом с AgentOS, явно сформулированного как аналог «моделируйте, не изолируйте» с честным заявлением о том, что он предлагает меньшую степень сдерживания, чем AgentOS, а не больше, в обмен на отсутствие движущихся частей. Добавьте одну строку TL;DR. Пропустите матрицу сравнения §6, тот же вызов, что и собственная интеграция AgentOS: большинство ее столбцов (Docker-in-Docker, изоляция ядра) не сопоставляются с внутрипроцессным симулятором. Укажите недостающий файл `LICENSE` напрямую, а не повторяйте утверждение Apache-2.0 README как факт.

**Повторное посещение триггера**: файл `LICENSE` приземляется (устраняет отмеченный пробел), второй специалист по сопровождению пересекает 15 % коммитов за скользящий квартал или изменение основной версии меняет модель изоляции (например, включается граница рабочего потока для основного интерпретатора, а не только для среды выполнения WASM).
