## Краткое содержание

Yagr — это автономный агент автоматизации, чей уровень выполнения генерирует детерминированные рабочие процессы n8n вместо эфемерных сценариев или слепых вызовов API. Когда пользователь описывает задачу на простом английском языке, Yagr проектирует, проверяет и развертывает реальный рабочий процесс n8n, который затем становится надежным, проверяемым и проверяемым артефактом. Построен на основе n8n-as-code (базовая библиотека имеет более 500 звезд GitHub; сам Yagr имеет 22 звезды по состоянию на 28 июля 2026 г.).

Ключевые факты:
- Установить: `npm install -g @yagr/agent@latest`
- Интерфейсы: TUI (`yagr tui`), шлюз Telegram, WebUI (`yagr webui`)
- Независимость от модели (Claude, GPT или любой настраиваемый поставщик)
- Архитектура: намерение пользователя → агент Yagr → n8n через n8n-как код → устойчивый рабочий процесс

Основное утверждение: «Рабочий процесс — это надежная память и мускулы агента».

## Примечания к вызовам (обзор технического писателя)

Агент по вызову выявил три критических пробела в предварительной оценке 3/5:

1. **Проблема с источником**: Единственными источниками являются собственная публикация автора в LinkedIn и GitHub README. Ни независимого обзора, ни публикации в сообществе, ни практического примера. По этой причине руководство уже применяло 2/5 (Rippletide, dclaude).

2. **Атрибуция количества звезд**: «500+ звезд» принадлежат n8n-as-code (базовой библиотеке), а не самому Yagr. Это отдельные проекты. Если Ягр сам по себе имеет 50 звезд, то сигнал тяги слабый.

3. **Deploy против генерирования**: README утверждает, что Yagr «развертывает» реальные рабочие процессы n8n, а не просто генерирует JSON. Это поддается фальсификации и не демонстрируется (ни демонстрационное видео, ни скриншот, ни выходные данные холста n8n не показаны).

4. **Риск неинтеграции = минимальный**: В руководстве уже рассматривается оркестровка рабочих процессов в ai-ecosystem.md. Yagr — это оболочка сообщества; если он наберет обороты, интеграция может произойти позже с нулевыми затратами.
