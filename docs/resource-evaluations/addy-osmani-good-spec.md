## Краткое содержание

Комплексное руководство по написанию эффективных спецификаций для агентов кодирования ИИ (Claude Code, Gemini CLI, Cursor, GitHub Copilot). Опубликовано Адди Османи (автором книги «Изучение шаблонов проектирования JavaScript» — О'Рейли, бывшим руководителем группы Chrome) 19 дней назад.

**Основной вклад:**
- Шесть основных областей спецификации (команды, тестирование, структура проекта, стиль кода, рабочий процесс git, границы)
- Трехуровневая пограничная система (Always/Ask first/Never) для оперативного принятия решений
- Стратегия модульных подсказок, позволяющая избежать перегрузки контекста
- Встроенная проверка и самопроверка
- Антипаттерны: монолитный CLAUDE.md, расплывчатая инструкция.

**Почему 4/5:** Заполняет определенные пробелы в нашем `guide/workflows/spec-first.md` (модульная конструкция, операционные границы, спецификации команд) с помощью шаблонов, непосредственно применимых к рабочим процессам Claude Code. От заслуживающего доверия практика, опубликованная недавно, решает ежедневные болевые точки пользователей.

## План интеграции

### Первичная интеграция: guide/workflows/spec-first.md

**Добавьте 4 новых раздела** (после строки 318, перед «См. также»):

1. **«Модульная конструкция»** (~50 строк, строки 320–369)
   - Шаблон: разделение больших спецификаций на несколько файлов CLAUDE.md (per-feature/domain).
   - Когда разделять: >200 строк, многодоменные проекты, совместная работа команды
   - Пример: `CLAUDE-auth.md`, `CLAUDE-api.md`, `CLAUDE-testing.md`.
   - Отсылка к принципу «сфокусированных фигур» Османи.

2. **«Операционные границы»** (~60 строк, строки 370-429)
   - Расширяйте MUST/MUST НЕ с помощью платформы **Always/Ask First/Never**
   - Сопоставьте режимы разрешений Claude Code:
     - **Always** → Режим автоприема (тесты, форматирование)
     - **Ask First** → Режим по умолчанию (изменения схемы, зависимости)
     - **Never** → План mode/blocked (производственный импульс, секреты)
   - Таблица решений с примерами

3. **«Шаблон спецификации команды»** (~ 40 строк, строки 430–469)
   - Шаблон для тестирования, CI, команд развертывания
   - Формат: `command → expected output → error handling`
   - Пример: `pnpm test` → отчет о покрытии → сбой при <80 %.

4. **"Анти-паттерн: Монолитный CLAUDE.md"** (~30 строк, строки 470-499)
   - Объясните проблему когнитивной нагрузки (>200 строк = загрязнение контекста)
   - Показать стратегии разделения (на основе функций, ролей, рабочих процессов)

## Риски НЕ интеграции

1. **Пользователи пишут раздутый, монолитный CLAUDE.md** → Загрязнение контекста → Снижение производительности → Разочарование.
2. **Нет операционной системы для границ** → Пользователям сложно сопоставить MUST/MUST НЕ с ежедневными решениями (когда доверять, а когда проверять)
3. **Пропущен передовой опыт из заслуживающего доверия источника** → Руководство теряет авторитет, когда практики цитируют Османи, но не находят ссылок на него здесь
4. **Нет шаблона спецификации команды** → Пользователи пишут только спецификации функций, упускают возможности настройки tooling/workflow

**Impact**: Средне-высокий. Это ежедневные проблемы рабочего процесса, а не крайние случаи.
