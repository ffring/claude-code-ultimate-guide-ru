## Краткое резюме

**Score**: **3/5** (Умеренный – интегрируйте, когда есть время)

Supermemory — это память API и контекстный движок, поддерживаемый венчурным капиталом (29 миллионов долларов США, октябрь 2025 г.), с тремя отдельными поверхностями интеграции для Claude Code: бесплатная универсальная конечная точка MCP без входа в систему (`mcp.supermemory.ai/mcp`), платный плагин Claude Code (`claude-supermemory`, требуется план Pro по цене минимум $19/mo) и самостоятельный хостинг. Локальный двоичный файл, лицензированный MIT, который явно является однопользовательским и даже размещается самостоятельно. В руководстве нет пробелов в охвате, и это закрывается: однопользовательская межсессионная память уже задокументирована (§3.1-3.8), а история команды Supermemory не превосходит существующий тезис §4.7 руководства о том, что ни один инструмент не может решить проблему с общей памятью дешево. Наиболее полезным вкладом в руководство является не новая возможность, а две конкретные точки данных из источников: внутреннее противоречие одного и того же поставщика в результатах тестов (95% против 85,4% Recall@15 в том же тесте) и интеграция Claude Code с оплатой по факту первого использования, где каждый сопоставимый однопользовательский инструмент, уже задокументированный (claude-mem, doobidoo, Mem0 Cloud MCP), на этом уровне бесплатен.

## Краткое содержание

**Что делает Supermemory**: размещенная память API (REST + MCP), которая принимает документы, разговоры и данные соединителей (Google Drive, Notion, Gmail, OneDrive, только в облаке) и возвращает их посредством семантического поиска, ограниченного «тегами контейнера». Три различных продукта имеют одно название:

1. **Supermemory MCP** (github.com/supermemoryai/supermemory-mcp): общая конечная точка `mcp.supermemory.ai/mcp`. Бесплатно, без входа в систему, можно использовать с любого клиента MCP, включая Claude Code сегодня.
2. **claude-supermemory плагин** (github.com/supermemoryai/claude-supermemory): плагин для Claude-Code с инструментами `memory`/`recall`/`context` и командой `/context`. Требуется план Supermemory Pro или выше, минимум $19/mo, невозможно использовать на бесплатном уровне. Последнее упомянутое обновление: «Claude Supermemory V2», 9 февраля 2026 г.
3. **Supermemory local**: самостоятельный одиночный двоичный файл, лицензированный MIT (подтверждено чтением файла `LICENSE` клонированного репозитория, авторские права 2025 supermemory). Один арендатор, один ключ API, отсутствие доступа к команде из нескольких участников, даже при самостоятельном размещении. Соединители доступны только в облаке и отсутствуют в этом режиме.

**Мультиарендная модель**: «теги контейнера» (жесткая граница изоляции) плюс роли организации и ключи API с ограниченной областью действия, функционально ближе к области видимости `user_id` Mem0, чем к блокам общей памяти Letta или ветвям групп Memoria. Нет документированной семантики слияния или разрешения конфликтов между личной и командной памятью; это остается на усмотрение логики приложения.

**Положение безопасности**: TLS при передаче, шифрование класса AES-256 при хранении, сертификация SOC 2 Type II, удаление в соответствии с GDPR (контейнер = единица удаления), доступно HIPAA BAA. Все три элемента соответствия (SOC 2, гарантии рабочего процесса GDPR, HIPAA BAA) привязаны к планам Scale/Enterprise, а не Free/Pro.. На дату исследования две проблемы GitHub открыты и нерешены: «Проблемы конфиденциальности и безопасности для многопользовательских приложений» и «Поддерживается ли сквозное шифрование?» На сегодняшний день шифрования E2E не существует.

Заявления **Benchmark** (все самооценки, взяты из supermemory.ai/research и supermemory.ai/docs/memorybench): #1 на LongMemEval, LoCoMo, ConvoMem; 95% Recall@15 при 99,4% уменьшении контекста; возврат менее 300 мс; В 10 раз быстрее, чем Zep, в 25 раз быстрее, чем Mem0; 100B tokens/month среди «сотни клиентов». Никакого стороннего воспроизведения ни для одного из них обнаружено не было. Тестовый набор (MemoryBench) имеет открытый исходный код, но каждое опубликованное число является собственным результатом Supermemory.

## Оценка релевантности: 3/5

### Почему 3/5 (умеренный)?

**Strengths**:

1. **Настоящий, финансируемый, активно поддерживаемый продукт**: начальный капитал в размере 29 миллионов долларов (октябрь 2025 г., Browder Capital / Scientifica Venture Capital / Susa Ventures лидирует, ангелы, включая Джеффа Дина и Логана Килпатрика, согласно стороннему профилю), ядро с лицензией MIT, подтвержденное прямой проверкой файлов, действительно бесплатная и не требующая входа точка входа MCP, которую можно использовать в Claude Code сегодня.
2. **Читатели спросят об этом**: учитывая финансирование и маркетинговую видимость, молчание в руководстве, в котором уже документировано более 15 инструментов памяти, является пробелом, даже умеренным.
3. **Конкретное значение перекрестной ссылки для двух существующих разделов**: несоответствие внутренних эталонных показателей 95%/85,4% является документально подтвержденной иллюстрацией скептицизма, уже рекомендованного в §9 руководства («цифры, сообщаемые поставщиками инструментов... следует воспринимать скептически»). Модель команды с тегами контейнеров, без семантики слияния и монотенантного самостоятельного хостинга, является свежей исходной точкой для аргументов §4.7 «отсутствие стандарта командной таксономии» и «одноарендной ДНК», а не контрпримером к ним.

**Почему не выше (4-5)**:

1. **Нет нового класса возможностей**: однопользовательская поверхность Supermemory (семантическая память на основе MCP) представляет собой шаблон, который руководство уже неоднократно документировало (claude-mem, Agentmemory, ICM, doobidoo, OpenMemory MCP). Это не заполняет пробел, как это сделал автоматический захват сеанса claude-mem.
2. **История команды не развивает аргументы руководства, а подтверждает их.**: теги контейнеров архитектурно ближе к существующей области видимости `user_id` Mem0, чем к чему-то новому, а самостоятельный режим явно не имеет многопользовательского доступа вообще.
3. **Коммерческое трение на одной поверхности с прикрепленным именем Claude Code**: плагин `claude-supermemory` оплачивается с первого реального использования (минимум $19/mo), в то время как каждый однопользовательский инструмент, который уже рекомендует руководство (claude-mem, doobidoo, уровень бесплатного пользования Mem0 Cloud MCP), на этом уровне бесплатен. Это настоящее препятствие для внедрения, а не деталь.
4. **Zero независимо воспроизвел цифры тестов, а также внутреннее противоречие**: каждое утверждение в заголовке сообщается им самим, а собственный сайт поставщика публикует два разных значения (95% против 85,4%) для одного и того же теста на двух разных страницах. Это худший показатель проверки, чем у Agentmemory, mem0 или Letta, которые, по крайней мере, появляются вместе в сторонней связке, указанной в существующей таблице репрезентативных результатов §9 руководства.
5. **Нерешенные открытые проблемы, касающиеся именно того, что беспокоит читатель, заботящийся о безопасности.**: многопользовательская конфиденциальность и шифрование E2E, оба помечены на трекере как открытые и на момент исследования не были исправлены.

## Ограничения и соображения

1. **Ценообразование по названной интеграции Claude Code**: `claude-supermemory` нельзя использовать ниже $19/mo.. Читатель, которому нужен именно «плагин Supermemory Claude Code», а не универсальный MCP, сталкивается с платным доступом при первом реальном использовании.
2. **Нет независимой проверки тестов, а также самостоятельно опубликованные несоответствия.**: воспринимайте все показатели производительности на supermemory.ai как маркетинговые, пока они не будут воспроизведены. Конфликт 95%/85,4% стоит привести дословно в качестве предостережения, а не резюмировать.
3. **Групповая память не более сложна, чем то, что уже документировано в руководстве.**: теги контейнера представляют собой примитив области видимости, а не модель слияния или разрешения конфликтов. Самостоятельный хостинг вообще не имеет многопользовательской истории.
4. **Пробелы в безопасности, которые важны для командной функции**: отсутствие шифрования E2E, две нерешенные проблемы GitHub, точно указывающие на этот пробел, а также самые строгие заявления о соответствии требованиям (SOC 2, HIPAA BAA), которые лежат в основе корпоративных цен.
5. **Пробел в полноте исследования**: в ходе исследования источника не удалось получить подробное сравнение Mem0/Zep/Letta с источниками, только Cognee. Любое будущее обновление, требующее такого сравнения, требует специального исследования, а не экстраполяции из этого файла.
6. **На момент проведения этой оценки не было проверенного количества звезд или независимых доказательств производственного использования**; не сообщайте цифры усыновления без свежего датированного чека.
