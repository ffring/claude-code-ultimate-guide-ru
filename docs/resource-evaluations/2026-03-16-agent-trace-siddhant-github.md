## Краткое содержание

`agent-trace` (пакет pip: `agent-strace`) — это инструмент Python (нулевые зависимости, только stdlib), который фиксирует каждый вызов инструмента, приглашение пользователя и ответ помощника в Claude Code с помощью перехватчиков, а затем позволяет воспроизводить сеансы в терминале или экспортировать как промежутки OpenTelemetry. Создано 15 марта 2026 г. 7 звезд на момент оценки (теперь 77 по состоянию на 28 июля 2026 г.).

Фрейминг «trace for AI Agents» удобен: он решает проблему «мой агент изменил 47 файлов, и я понятия не имею, почему», предоставляя вам воспроизводимую запись каждого момента принятия решения с отметкой времени.

---

## Ключевые моменты

- Хуки **Claude Code**: Настройка через `agent-strace setup`. Регистрирует PreToolUse, PostToolUse, PostToolUseFailure, UserPromptSubmit, Stop, SessionStart, SessionEnd в `.claude/settings.json`
- **Воспроизведение сеанса**: `agent-strace replay` показывает полный сеанс с метками времени, длительностью, входными данными инструмента, ошибками — недостающий слой между JSONL и пониманием
- **MCP proxy**: Обертывает любой сервер MCP (stdio или HTTP/SSE). Работает с Cursor, Windsurf и любым клиентом MCP.
- **OpenTelemetry экспорт**: вывод OTLP → Datadog, Honeycomb, New Relic, Splunk
- **Python декоратор API**: `@trace_tool`, `@trace_llm_call`, `log_decision()` для пользовательских агентов
- **Секретное редактирование**: полосы флагов `--redact` OpenAI, GitHub, AWS, Anthropic, Slack, JWT, токены на предъявителя, строки подключения

## Оценка релевантности: 2/5

**Подходит, но слишком незрел для немедленной интеграции.**

Угол воспроизведения сеанса является реальным и не охватывается существующими инструментами в руководстве. Но `claude-code-otel` уже обрабатывает вариант использования экспорта OTel, а ручные запросы jq в `guide/ops/observability.md:519-550` охватывают большую часть варианта использования аудита. Уникальное отличие — интерактивный повтор — требует проверки на производстве, прежде чем быть рекомендованным читателям.

## Примечания к вызовам (обзор технического писателя)

**Score должен быть 2/5, а не 3/5.**. Причины:

1. `claude-code-otel` уже экспортирует в Datadog/Honeycomb. Угол OTel не является аддитивным.
2. Запросы jq по адресу observability.md:519-550 уже охватывают большую часть случаев использования аудита. «Ниша повторов» тоньше, чем кажется.
3. ICM (1 звезда) был внесен в список наблюдения. Агент-трейс с 7 звездами заслуживает такого же отношения.

**Отсутствующие аспекты, отсутствующие в первоначальном анализе**:

- **MCP прокси = MITM-риск**: маршрутизация всего трафика MCP через неаудитированный прокси-сервер HTTP/SSE является поверхностью безопасности. В руководстве есть раздел с полным усилением защиты — добавление его в таблицу мониторинга без пометки было бы противоречивым.
- **Секретное редактирование не проверено**: токены в кодировке Base64, многострочные значения .env, временные учетные данные AWS — крайние случаи не проверялись. Может создать ложную уверенность.
- **Python декоратор API против MLflow SDK**: MLflow имеет управление версиями + отслеживание экспериментов + LLM-как судья. Agent-trace имеет меньшее трение. Реальный компромисс не упомянут.

**При размещении**: Если интегрировано, не в таблице инструментов внешнего мониторинга (это мониторинг, а не отладка). Лучше использовать сноску в разделе JSONL (~observability.md:565) как «оболочку более высокого уровня для воспроизведения сеанса».

**Риск НЕ интеграции**: Около нуля. Запросы jq + claude-code-otel охватывают основные варианты использования. Реальный риск направлен в другую сторону: добавление инструмента однодневной давности, который не поддерживается, = неработающая ссылка в таблице, которую читатели используют для принятия решений по инструментам.
