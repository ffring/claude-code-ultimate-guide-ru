# Оценка ресурсов: Switch (Flint AI / SandboxAQ, мост чата между агентом и человеком)

**URL**: https://github.com/sandbox-quantum/switch
**Type**: репозиторий GitHub (Apache 2.0 + пункт Commons), автономный сервер + настольная консоль Electron + разъемы для Claude Code/Codex/OpenCode.
**Дата оценки**: 27 августа 2026 г.
**Evaluator**: Claude Code Ultimate Guide Team
**Версия руководства**: 3.42.0
**Method**: анализ исходного кода клона репозитория, ветка `main` (перенесена 26 августа 2026 г.), а также `gh api repos/sandbox-quantum/switch` для метаданных репозитория. Никакая установка, никакое развертывание сервера, никакая живая комната Matrix не запускались против него.

---

## Краткое содержание

Switch — это инфраструктура, соединяющая агентов ИИ и людей в одном разговоре в приложениях для чата, которые команда уже использует (Slack, Microsoft Teams, Discord, Telegram, Mattermost). Он использует **Matrix** (сервер Tuwunel) в качестве внутренней шины сообщений: каждый участник, человек, агент или мост сотрудничества является клиентом Matrix (`matrix-nio`). Коммутационная комната сопоставляется с одним внешним каналом через строку базы данных, поэтому сопоставление сохраняется при перезапуске.

Три компонента: `core/switch_core/` (сервер FastAPI, агенты Agent Bridge регистрируются и аутентифицируются с помощью ключа API, а также мосты для совместной работы); `gateway/` (интерфейс администратора React для агентов, комнат, ресурсов, ключей); `console/` (настольное приложение Electron, разветвленное с восходящей атрибуцией, которое управляет локальными сеансами агента кодирования, к каким комнатам принадлежит агент, и автоматически запускает сеанс Claude Code при обращении к нему в Slack, при этом ни один из них не запущен).

Протокол (`docs/official/internals/agent-protocol.md`): один нисходящий поток SSE на каждое соединение, HTTP вверх для каждого действия агента, четыре модели соединения (`always_on`, `session_addressable`, `auto_session`, `session_passive`), описывающие, как агент на самом деле доступен, а не предполагая единообразную работоспособность. Авторизация представляет собой единую точку доступа (`authz.py`): `can(principal, action, resource)`, запрос, инициированный агентом, разрешается в личность его владельца и наследует именно разрешения этого владельца, видимость public/private для каждого ресурса.

 Claude Code разъем (`connectors/claude-code-plugin/hooks/switch_hook.py`) цепляется за Claude Code's pre/post жизненный цикл вызова инструментов для опосредования действий и сообщения о событиях обратно на мост; существуют эквивалентные разъемы для Codex и ОпенКод.

## Основной механизм, проверенный в коде

`core/switch_core/authz.py` — небольшой чистый модуль (без базы данных, без I/O), 89 строк: `Action = Literal["read", "write", "delete"]`, одна функция `can()`, единая для ссылок, документов, пакетов и комнат. Объединяет то, что говорит собственная строка документации модуля, которая ранее была разбросана в виде специальных проверок `owner == user or public or admin` по сайтам вызовов, что является реальным упрощением, если утверждение справедливо для всей базы кода (не отслеживается независимо от сайта вызова за сайтом вызова в этом проходе).

`docs/official/internals/collaboration-bridge.md` напрямую документирует контракт на адаптер моста: `start`, `stop`, `send_message`, `update_message`, `delete_message`, `send_typing`, `create_channel`, `add_agents_to_channel`, `translate_inbound`/`translate_outbound`. Поставляются пять адаптеров (режим Slack Socket, Mattermost WebSocket, Discord Gateway WebSocket, опрос Telegram Bot API, Microsoft Teams в качестве автономного прослушивателя HTTP, единственный из которых требует публичного адреса). Сам мост является участником Матрицы: он соединяет комнаты и видит только то, что происходит после присоединения, что является реальным ограничением при заполнении истории посредством недавно добавленного моста, а не просто примечанием к дизайну.

Распространение в большей степени ориентировано на производство, чем один репозиторий GitHub, который обычно существует шесть недель назад: `docs/official/deploy/self-host.md` документирует артефакт Docker Compose (`ghcr.io/sandbox-quantum/standalone-compose`) и диаграмму Helm (`oci://ghcr.io/sandbox-quantum/charts/switch`), оба с отметкой одной и той же версии выпуска, а также специальный `RELEASING.md` в корне репо.

## Где он находится относительно существующего покрытия руководства

Три секции были проверены в качестве домов-кандидатов, прежде чем пришел к выводу, что это настоящий пробел, а не неудачное размещение:

`guide/core/memory-systems.md` §4.7 («Почему разрыв между командами является структурным») документирует шесть препятствий на пути к *semantic* командной памяти (однопользовательское хранилище, стоимость OAuth, стандарты таксономии, корпоративные покупатели). Switch не имеет встроенного хранилища и уровня извлечения; это шина реального времени, а не система памяти. Модель наследования владельца `authz.py` является важной точкой данных, в частности, о барьере затрат OAuth, но размещение самого Switch в этом разделе приведет к неправильной классификации того, что это такое.

`guide/ecosystem/third-party-tools.md` «Многоагентная оркестровка» (abtop, Conductor, Agent Orchestrator, строки 1409-1536) и «Внешняя оркестровка» (Ruflo, Athena Flow, Pipelex + MTHDS) имеют одну ось: несколько экземпляров одного и того же агента кодирования на одной машине, координируемые посредством рабочих деревьев git и обратной связи PR/CI. Ось Switch другая: гетерогенные агенты (Claude Code, Codex, LangChain и все, что говорит по протоколу) достигают людей на пяти чат-платформах *external*, опосредованно через управляемую модель идентификации. Не вариация существующих записей, а другая категория.

`guide/ecosystem/ai-ecosystem.md` §8.1 «agent-chat» (строки 1655-1666) в собственном тексте руководства помечен как «Slack-like», что читается как покрытие одного и того же пространства до тех пор, пока код не будет проверен: это панель управления SSE только для чтения поверх журналов `beads.db` Gas Town и JSON Multiclaude, без активного подключения к внешней платформе, без модели аутентификации, явно несовместим с автономным Claude Code. Структурно это инструмент мониторинга, а не мост.

`third-party-tools.md` «Известные пробелы» (строки 1850-1866), раздел, в котором уже указаны пробелы в возможностях, которые руководство выявило, но не заполнило (Sandcastle, fp.dev и другие), не содержит записи для «межплатформенного чата между агентом и человеком с управлением». Это скорее подтверждает разрыв, чем устраняет его.

## Подсчет очков

| Критерий | Счет | Обоснование |
|---|---|---|
| Техническая новинка | 4 | Ни в одном месте текущего руководства не существует сопоставимой записи; формализованный протокол жизнеспособности агента (четыре модели подключения) и модель аутентификации по наследству владельца являются реальными проектными решениями, а не маркетинговыми заявлениями |
| Надежность производства | 2 | Pre-1.0 (`0.21.0`), 6 недель, коэффициент шины близок к 1 (80% один автор), независимо подтвержденного производственного развертывания не обнаружено, кроме собственных демонстрационных видеороликов поставщика. |
| Качество документации | 4 | Сайт полной опубликованной документации (`docs/official/`), явная спецификация протокола агента, контракт адаптера моста для совместной работы, инструкции для самостоятельного размещения с закрепленными артефактами с версионными версиями. |
| Приспособляемость | 2 | Требуется работа домашнего сервера Matrix плюс N мостовых процессов; более тяжелые эксплуатационные нагрузки, чем у большинства инструментов, которые рассматриваются в этом руководстве для отдельных пользователей Claude Code, хотя Switch Console снижает планку для первой пробной версии без самостоятельного хостинга. |
| Ориентировочная стоимость | 3 | Заполняет реальный, ранее незаполненный пробел в категории, но является ранним примером одного поставщика и пока не имеет сопоставимых аналогов, категория недостаточно обширна для выделенной страницы сравнения. |
| **Комбинезон** | **3** | Полезное дополнение, не срочное. Настоящий заполнитель пробелов в категории, но он слишком молод и имеет слишком одного поставщика, чтобы служить чем-то большим, чем указатель. |

Этот общий балл на один балл выше 2/5, полученного ранее на основе сводных данных, без доступа к истории git или показателям `gh api`. 252-звездочная 6-недельная тяга и технология выпуска Docker Compose/Helm, обнаруженные в этом проходе, являются более сильными сигналами о производственной форме, чем предполагалось «клонировано сегодня, нулевой перебор местности»; фактор шины и опасения, возникшие до версии 1.0, которые были подняты при оценке, сохраняются и отражаются в показателях надежности производства и приемлемости.

## Решение

**Не интегрируйте специальный раздел руководства. Добавьте одну строку в `third-party-tools.md` «Известные пробелы», указав категорию и указав Switch как первого наблюдаемого кандидата, а также запись в списке наблюдения.**

Прецедентом руководства для специального файла (`ai-executive-agents.md`, `agent-harness-landscape.md`) является сравнение многих одноранговых проектов с таблицей маршрутизации, а не описание одного поставщика. В ходе исследования нигде не было обнаружено однорангового узла Switch (управляемого, многоплатформенного, многоплатформенного чат-моста между агентом и человеком); написание отдельного раздела теперь будет восприниматься как страница продукта для выпуска OSS одной компании, а не как нейтральное для руководства освещение.

**Повторное посещение триггера**: появляется второй независимый инструмент чата с сопоставимой областью действия (что делает возможным составление сравнительной таблицы), или Switch достигает отмеченного выпуска `1.0.0` или независимо задокументированного производственного развертывания (не из SandboxAQ/Flint AI).
