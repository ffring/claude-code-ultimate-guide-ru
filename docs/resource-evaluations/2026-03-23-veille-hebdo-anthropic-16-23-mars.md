## Рекомендации по интеграции

### P1 — `thinking.display: "omitted"` (платформа API, 16 марта)

**Where**: `guide/ultimate-guide.md` — раздел «Расширенное мышление» (найдите «расширенное_мышление» или «бюджет мышления»)

**Что добавить**: Небольшой подраздел или примечание, поясняющее:
- `thinking.display: "omitted"` скрывает мыслительный текст в ответе, сохраняя поле `signature` для многооборотной непрерывности.
- Вариант использования: более быстрая потоковая передача, более чистый UX, когда контент не нужен конечному пользователю.
- Выставление счетов не изменилось: взимается полная стоимость токена мышления независимо от настроек дисплея.
- Компромисс: рабочие процессы внутреннего аудита или маркировки, основанные на мысленном тексте, должны использовать другой режим отображения.

### P2 — Возможности модели полей API (Платформа API, 18 марта)

**Where**: `guide/ultimate-guide.md` — API Раздел интеграции или новая заметка «Обнаружение модели».

**Что добавить**: `GET /v1/models` и `GET /v1/models/{model_id}` теперь возвращают `max_input_tokens`, `max_tokens` и объект `capabilities`. Это позволяет осуществлять динамический выбор модели в оркестраторах вместо жестко запрограммированных карт возможностей.

### P1 — компромиссы в скриптовом режиме с флагом `--bare` (пропущены на начальном этапе)

**Where**: `guide/ultimate-guide.md` — раздел использования скриптов/CI/CD (поиск по флагу `-p`, headless, конвейер)

**Что добавить**: `--bare` по сравнению со стандартной таблицей компромиссов `-p`. `--bare` пропускает перехватчики, LSP, синхронизацию плагинов и обход каталогов навыков; требуется `ANTHROPIC_API_KEY` или `apiKeyHelper` (без OAuth). Быстрый и минимальный для CI-скриптов, но теряет всю наблюдаемость, которую обеспечивают перехватчики. В командных средах, которым необходимы журналы аудита, вместо этого следует использовать стандарт `-p`.

## Челлендж (технический писатель)

**Score сохраняется: 3/5** (два пробела API + один пропущенный пробел CLI не преодолевают порог 4/5 «значительного интегрируемого улучшения»)

Ключевые исправления по итогам испытания:

- **`thinking.display: "omitted"` более важен, чем отмеченный. Руководство** охватывает расширенное мышление только с точки зрения CLI (строки 13539-13632). Многовитковые схемы API с непрерывностью цепи полностью отсутствуют. Актуально для разработчиков оркестраторов. Смещает приоритет с «пробела» на «отсутствие концепции».
- Возможности **Model API недооценены.** `GET /v1/models` с объектом `capabilities` обеспечивает динамический выбор модели во время выполнения при многоагентной маршрутизации — шаблон, который в руководствах документируется сегодня только вручную. Не сноска с метаданными; это сдвиг модели.
- Значения сценариев флага **`--bare` пропущены на начальном этапе.** В отслеживании выпусков указано «охвачено», но в руководстве не документированы компромиссы между `--bare` и стандартным `-p` для CI/CD.. Добавлен как P1.
- **Python SDK: пропустить, а не P3.** Руководство всегда выходило за рамки Python SDK. Никакой живой изгороди не нужно.
- Исследование **81k: отклонить (оценка 1), а не «P4 или пропустить». Исследование** охватывает потребительских пользователей Claude.ai, которые в целом хотят получить доступ к ИИ. Не по теме для руководства Claude Code CLI.

**Риски отсутствия интеграции**: разработчики оркестраторов платят ненужные затраты на токены или нарушают непрерывность цепочки из-за незнания `thinking.display: "omitted"`. Авторы конвейера CI не получают указаний о том, когда `--bare` уместен, а когда рискован.
