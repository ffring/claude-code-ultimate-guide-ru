## Краткое содержание

Технический анализ ограничений видимости полей Claude Code Tasks API (v2.1.16+), обнаруженных в ходе практического использования. Документирует, что `TaskList` опускает `description` и все поля `metadata`, что требует отдельных вызовов `TaskGet` для доступа к полной информации о задаче.

**Ключевая информация**: Задачи API имеют недокументированное архитектурное ограничение, при котором операции со списком (`TaskList`) предоставляют только подмножество полей (`id`, `subject`, `status`, `owner`, `blockedBy`), а подробные операции (`TaskGet`) предоставляют все поля. Это создает шаблон накладных расходов при множественных вызовах, не упомянутый в официальной документации или существующих руководствах.

## Оценка: 5/5 (КРИТИЧЕСКИЙ)

### Обоснование оценки

**Почему КРИТИЧЕСКОЕ (а не просто «высокое значение»)**:

1. **Нарушает рекомендуемый рабочий процесс**: Руководство явно рекомендует «Список задач → Показать все задачи» для возобновления сеанса (MODE_Task_Management.md:37). Без видимости `description` этот рабочий процесс незаметно нарушается.

2. **Скрытый множитель стоимости**: для просмотра 10 описаний задач требуется 1 TaskList + 10 вызовов TaskGet = **11x API накладные расходы**. Для 20 задач: 21 накладные расходы. Это напрямую влияет на:
   - Стоимость API (в 11 раз больше поездок туда и обратно)
   - Задержка сеанса (в 11 раз больше ожидания)
   - Потребление токенов (метаданные извлекаются индивидуально)

3. **Более, чем казалось на первый взгляд.**: Автор заявляет: «Метаданные НИКОГДА не видны ни в одном выводе» - сюда входят:
   - `description` (детали реализации)
   - `activeForm` (текст индикатора прогресса)
   - ВСЕ пользовательские поля `metadata` (приоритет, оценки, связанные файлы, теги)

4. **Значение безопасности**: без видимости полей в TaskList пользователи не могут предварительно фильтровать конфиденциальные задачи перед вызовом TaskGet. Риск случайного раскрытия конфиденциальных деталей реализации при совместном использовании идентификаторов списков задач.

5. **Калибровка доверия**: Если пользователи обнаруживают это ограничение самостоятельно после выполнения рабочих процессов руководства, это подрывает доверие к руководству («The Ultimate Guide не предупредило меня об этой ловушке»).

6. **Timing**: обнаружен через 2 дня после запуска Tasks API (v2.1.16: 22 января 2026 г.), что указывает на трудности среди первых пользователей. Интеграция этой обратной связи быстро предотвращает широко распространенное разочарование.
