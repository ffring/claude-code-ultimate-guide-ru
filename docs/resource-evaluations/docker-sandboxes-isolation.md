## Краткое содержание

1. **Docker Песочницы** (Docker Desktop 4.58+) обеспечивают изоляцию на основе microVM для агентов кодирования ИИ, заменяя старый подход на основе контейнеров. Claude Code работает с `--dangerously-skip-permissions` внутри песочницы, поскольку сама виртуальная машина является границей безопасности.
2. **Сетевые политики** предлагают режимы allowlist/denylist с фильтрацией на уровне домена, индивидуальной настройкой песочницы и встроенным мониторингом через `docker sandbox network log`. Частные диапазоны CIDR заблокированы по умолчанию.
3. **Пользовательские шаблоны** используют стандартные файлы Dockerfile, расширяющие `docker/sandbox-templates:claude-code`. Базовый образ включает Ubuntu, Node.js, Python 3, Go, Git, Docker CLI, GitHub CLI, ripgrep, jq.
4. **Более широкий спектр** включает Fly.io Sprites (микровиртуальные машины Firecracker, ~300 мс checkpoint/restore), Cloudflare Sandbox SDK (на основе контейнеров, интеграция Workers), E2B (Firecracker с открытым исходным кодом, холодная загрузка 150 мс) и песочницы Vercel (GA 2026-01-30, микровиртуальные машины Firecracker).
5. **Пробел в руководстве**: Нет документации по запуску Claude Code в изолированных средах. В предупреждении `--dangerously-skip-permissions` (ultimate-guide.md:3943) отсутствует безопасный альтернативный путь.

## Интеграционное решение

**Обоснование оценки**: 4/5 (высокое значение), а не 5/5, потому что:
- Docker Песочницы действительно полезны и заполняют реальный пробел (безопасная автономность)
- Официальная документация Docker надежна (источник уровня 1).
- Однако эта функция доступна только для настольных компьютеров Docker (без поддержки автономного движка Docker).
- Поддержка Linux ограничена устаревшим режимом контейнера (не microVM).
- MCP Шлюз пока не поддерживается внутри песочниц.
- Облачные альтернативы — это дополнительный контекст, а не специфичные для Claude Code функции.

**Action**: Создайте специальный файл руководства (`guide/security/sandbox-isolation.md`), охватывающий песочницы Docker в качестве основного решения с альтернативами для сценариев cloud/CI.
