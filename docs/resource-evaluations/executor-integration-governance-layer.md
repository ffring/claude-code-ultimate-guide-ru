## Краткое содержание

Executor — это уровень интеграции между AI-агентами и внешними API: лицензия MIT, монорепо Bun + Turborepo, версия `1.4.0-beta.0`. Идея: объявить интеграцию один раз (аутентификация и правила API), и каждый MCP-совместимый агент (Claude Code, Cursor, ChatGPT) будет использовать один и тот же каталог вместо того, чтобы каждый имел собственную копию одних и тех же учетных данных и проводки инструментов.

Четыре понятия в порядке зависимости:

1. **Integration** (спецификация: OpenAPI, GraphQL, существующий сервер MCP, Google Discovery), проиндексированный в каталог инструментов.
2. **Connection**— настроенный, аутентифицированный экземпляр интеграции, идентифицируемый `(scope, integration, name)`. Одна интеграция может содержать множество соединений (две организации GitHub, `work` и `perso`).
3. **Policy**, для каждого инструмента один из `allowed` / `require_approval` / `blocked`, со значениями по умолчанию, полученными из спецификации (запись не рассматривается как чтение).
4. **MCP воздействие**, одна конечная точка (`/mcp?toolkit=...`); агенты видят весь каталог через метаинструменты (`search` + `describe` + `execute`), а не каждую схему, загруженную заранее.

К этому механизму стоит отнестись серьезно: Connection никогда не хранит необработанные учетные данные, а только `SecretRef` (`op://`, `keychain://`, `env://`, `vault://`), разрешенные провайдером во время вызова через инструмент-прокси. `vision.md` утверждает, что аварийного выхода нет: `SecretRef` никогда не появляется в схеме input/output инструмента или в любом ответе MCP. Выполнение можно приостановить, поскольку вызов, заблокированный из-за отсутствия аутентификации или ожидающего утверждения, возвращает приостановленный запуск, возобновляемый с помощью `executor resume --execution-id exec_123`.

Четыре способа запуска, одинаковая функциональность: Executor Cloud (хостинг), CLI + демон (`apps/cli` + `apps/local`), настольное приложение, самостоятельный хостинг (Docker или Cloudflare Worker).

## Основной механизм, проверенный в коде

Заявление `SecretRef` имеет наибольшее значение, поскольку на нем основывается все ценностное предложение. `packages/core/sdk/src/` содержит `connection.ts`, `integration.ts` и всю поверхность OAuth (`oauth-flow.ts`, `oauth-client.ts`, `oauth-discovery.ts`, `oauth-callback-state.ts`, `oauth-gc.ts`, `migration-oauth-metadata.ts`). `packages/hosts/mcp/src/tool-server.ts` (41,9 КБ, тестовый файл размером 63,3 КБ, самое большое соотношение тест-источник среди всех проверенных файлов) — это фактическая поверхность MCP. Плагины секретного бэкэнда существуют отдельно для каждого провайдера: `packages/plugins/onepassword/`, `keychain/`, `workos-vault/`, `encrypted-secrets/`, `file-secrets/`.

В ходе этой оценки не отслеживался каждый сайт вызова, который касается `SecretRef`, чтобы подтвердить, что он никогда не попадает в сериализованный ответ; для этого потребуется запустить набор тестов и инструментировать путь прокси, что выходит за рамки прохода исходного кода только для чтения. Что подтверждено: шаблон архитектурно согласован (отдельные плагины секретного бэкэнда, специальный модуль OAuth, большой тестовый файл поверхности MCP), а `vision.md` явно заявляет инвариант как правило проектирования, а не деталь реализации, обнаруженную постфактум. Считайте утверждение «никогда не доходит до агента» как архитектурно хорошо обоснованное, а не независимо доказанное этим проходом.

**Bus Factor 1.** Частота вращения педалей снизилась на 76% с апрельского пика до июля. Два варианта одинаково правдоподобны вне проекта, и ни один из них не может быть решен путем чтения репозитория: усиление защиты до версии 1.0 перед стабильным выпуском или переключение внимания основателя на Executor Cloud и выход на рынок. Второй сопровождающий или отмеченный `1.0.0` решит эту проблему; ни того, ни другого еще не существует.

Соединение **Effect.** SDK предоставляет API на основе Promise (`@executor-js/sdk/promise`) наряду с собственным эффектом, поэтому его использование не требует изучения Effect. Внесение в него вклада или его более глубокое обертывание, чем документированная поверхность Promise, приводит к следующему: 35% исходных файлов импортируют `effect` напрямую, а `AGENTS.md` требует использования Effect Vitest для всех тестов (`bun test` явно запрещено). Пользователь производства, который сообщил, что использовал его в качестве ядра MCP для внешних агентов, независимо отметил именно это противоречие: «скорость очень высокая, за ней нужно постоянно следить, особенно если вокруг нее накладывать обертки».

## Агентская конфигурация в самом репозитории

Отдельно от продукта стоит назвать собственную конфигурацию репозитория для работы с агентами кодирования ИИ, поскольку она обобщает эту кодовую базу. Сосуществуют три каталога навыков: `.claude/skills/` (3 навыка), `.agents/skills/` и `.skills/` (6, включая `effect-atom-optimistic-updates`, `warden-security-review`, `effect-http-testing`, `cli-release`, `effect-use-pattern`, `graphite`), а также `.codex/environments/`. `AGENTS.md` — это 58-строчный контракт участника с жесткими правилами (требуется эффект Vitest, `bun test` запрещен, e2e запускается последним и с осторожностью, никогда не продается повторно пакет `@executor-js/emulate`). Три файла памяти агента намеренно игнорируются git: `MISTAKES.md`, `DESIRES.md`, `LEARNINGS.md`, частная рабочая память, а не общая командная память. `warden.toml` ограничивает сканирование навыков стража безопасности Sentry по пути. В разделе «Ссылки» README кодовые базы, передаваемые агенту, именуются в виде шаблонов: FumaDB, Effect, OpenCode, OpenClaw, Emdash, Pi.

Это рассматривается отдельно от оценки продукта, поскольку оно сохраняется независимо от успеха самого Исполнителя. См. руководство по решению интеграции ниже, чтобы узнать, где находится каждая часть.

## Где он находится относительно существующего покрытия руководства

`guide/security/enterprise-governance.md` §3 («Рабочий процесс управления MCP») уже документирует эту конкретную категорию вручную: рабочий процесс утверждения (§3.1), реестр YAML с полями `risk`/`restrictions` для каждого инструмента (§3.2), привязка, обеспечивающая его соблюдение (§3.3). Executor — это продуктовая версия того же шаблона, а не новая категория: его четыре концепции сопоставляются с полями этого реестра (Интеграция — `source` + `config` записи реестра, Соединение — именованный аутентифицированный экземпляр этой записи, Политика — поле `risk` реестра, обобщенное для allow/approval/block для каждого инструмента, Экспозиция MCP — одна конечная точка замена одной записи на сервер).

Таблица `guide/ecosystem/mcp-vs-cli.md` «Инструменты в этом пространстве» (RTK, mcporter, mcp2cli, Klavis AI/Strata, Arcade.dev) не подходит для нее: общая ось этой таблицы — это стоимость токена, а Executor не конкурирует по стоимости токена. Его ось — управление доступом, наиболее близкое к стороне OAuth/catalog Клависа, а не к трюку с устранением схемы mcp2cli.

## Решение

**Интегрировать как перекрестную ссылку в `enterprise-governance.md` §3, предназначенную для сравнения, а не как рекомендацию по замене. Не создавайте отдельную страницу управления интеграцией.**

Реестр `enterprise-governance.md` §3.2 YAML активно копируется командами, читающими руководство, в свой собственный `.claude/mcp-registry.yaml`. Новый подраздел, читающий как «вместо этого используйте Executor», подтолкнет читателей к бета-продукту с коэффициентом шины, равным единице, а для рабочего процесса руководство в настоящее время документирует как файл YAML без зависимостей плюс хук. Подраздел должен читаться так: «Вот как автоматизация этого шаблона реестра вручную в конечном итоге выглядит как продукт», с предостережением pre-1.0/bus-factor-1, указанным прямо, а не подразумеваемым.

Конфигурация агентной разработки (три каталога навыков, файлы памяти агента gitignored) реальна и может использоваться повторно, независимо от судьбы Исполнителя. Это задокументировано отдельно: gitignored `MISTAKES.md`/`DESIRES.md`/`LEARNINGS.md` в качестве четвертой точки данных в сравнении файловой памяти `guide/core/memory-systems.md` §3.7 и три сосуществующих каталога навыков в качестве новой записи шаблона в `guide/core/skill-design-patterns.md`. `warden.toml` и список «Ссылки» README исключены из этого прохода: ни один из существующих разделов не подходит ни к одному из них, и навязывать его на основе свидетельства единственного репозитория преждевременно.

**Триггер повторного посещения**: отмеченный выпуск `1.0.0` или второй сопровождающий, пересекающий 20 % коммитов за скользящий квартал, в зависимости от того, что наступит раньше.
