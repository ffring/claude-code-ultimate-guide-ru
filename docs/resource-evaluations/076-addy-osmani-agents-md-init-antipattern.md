## 1. Краткое содержание

Подкрепленная исследованиями критика рабочего процесса автоматического создания `/init` для контекстных файлов AGENTS.md / CLAUDE.md, синтезирующая две научные статьи 2026 года с практическими рекомендациями по архитектуре.

**Ключ утверждает**:
- **ETH Цюрихское исследование**: Контекстные файлы, созданные с помощью LLM, снижают успешность выполнения задач на 2–3 % и увеличивают затраты более чем на 20 %, поскольку агенты уже могут обнаружить, что содержат эти файлы.
- **Lulla et al. (ICSE JAWs 2026)**: Контекстные файлы, созданные людьми, сократили время работы настенных часов на 28,64% и потребление токенов на 16,58% — но только потому, что они содержали действительно необнаружимую информацию.
- **Фильтр обнаружения**: единственным критерием добавления строки является то, сможет ли агент найти ее, прочитав код; если да, то удали его
- **Эффект привязки «Розовый слон»**: упоминание технологии в CLAUDE.md склоняет агента к ней в каждом сеансе, даже если она устарела или используется редко.
- **Статические монолитные файлы архитектурно несовершенны**: они загружают один и тот же контекст независимо от типа задачи, тратя токены на ненужные инструкции.
- Платформа **ACE (ICLR 2026)**: уровень динамической маршрутизации превзошел по производительности статические подходы CLAUDE.md на 12,3% в тестах агентов.
- **Arize Автоматическая оптимизация с использованием искусственного интеллекта**: итеративное быстрое обучение позволило повысить точность перекрестного РЕПО на 5,19 % и внутри репозитория на 10,87 %.
- **Ментальный сдвиг модели**: CLAUDE.md как инструмент диагностики проблем с кодовой базой, а не постоянная конфигурация

**Depth**: ~3500 слов, исследовательский синтез + практические рекомендации по архитектуре. Достоверность источника высока — Османи является директором Google Cloud AI, в статье цитируются рецензируемые статьи 2026 года.

- **Последствия масштаба**: накладные расходы в размере 15–20 % при выполнении CI/CD — не включены в разделы затрат руководства.

**Почему 4/5, а не 5/5**:
- Гид уже дает правильный совет; это усиливает его данными и добавляет недостающие понятия
- 5/5 потребует, чтобы руководство было явно неправильным или имело полный пробел — здесь это частично описано, но недостаточно подтверждено.

## 4. Рекомендации по интеграции

### Где интегрировать

**Основной: §3.1 Файлы памяти (CLAUDE.md) — строка ~4589**

Добавьте специальный подраздел «Фильтр обнаружения» сразу после существующего раздела «Минимально жизнеспособный CLAUDE.md»:

```markdown
### The Discoverability Filter

Before adding any line to CLAUDE.md, apply this test: **can the agent discover
this by reading the codebase?** If yes, don't add it.

Two 2026 research studies quantify the cost of ignoring this: LLM-generated
context files (the output of `/init`) reduce task success by 2-3% and inflate
costs by 20%+ because they duplicate what agents find by exploring the repo
anyway (ETH Zurich, 2026). Human-authored files that contain genuinely
non-discoverable information perform better: -28.64% wall-clock time,
-16.58% token consumption (Lulla et al., ICSE JAWs 2026).

What earns a line:
- Tooling preference that can't be inferred: `Use uv, not pip`
- Operational landmine: `legacy/ is deprecated but imported by prod — do not delete`
- Non-obvious convention: `auth module uses custom middleware — do not refactor to Express standard`

What does not earn a line:
- Directory structure (agent reads it in the first tool call)
- Tech stack (agent reads package.json / go.mod / Cargo.toml)
- Testing conventions (agent reads existing tests)
```

**Secondary: документация по команде `/init` — строка ~21308**

Добавьте предупреждающее примечание рядом со списком команд о том, что автоматически сгенерированный вывод имеет тенденцию быть избыточным и может снизить производительность.

**Tertiary: новое предупреждение «Привязка контекста» в §3.1**

Добавьте выноску об эффекте розового слона/привязки: упоминание технологии в CLAUDE.md склоняет агента к ней в каждом сеансе. Устаревшие записи хуже, чем отсутствие записей.

**Дополнительно: раздел расширенных шаблонов**

Трехуровневая архитектура динамической маршрутизации (файл протокола + файлы persona/skill + субагент обслуживания) может быть включена в §4 (агенты) или §9 (расширенные рабочие процессы) в качестве образца архитектуры для команд, запускающих агенты в большом масштабе.
