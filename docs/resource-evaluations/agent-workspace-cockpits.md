### <a name="orca"></a>Орка

**Просмотр документации: 27 октября 2026 г. Пробная версия приложения отсутствует.** Эта оценка касается [stablyai/orca](https://github.com/stablyai/orca), среды рабочего стола под лицензией MIT, а не других репозиториев под названием Orca. Он размещает существующие интерфейсы командной строки агентов в рабочих деревьях с аннотациями различий, контекстом элемента браузера, выполнением SSH и мобильным помощником. Они пересекаются с существующими профилями рабочей области; они не оправдывают создание второго каталога объектов.

Полезное сравнение — конкретный цикл доставки. Документация [, размещенная на сервере Orca,](https://www.onorca.dev/docs/review/github) связывает рабочие деревья с PRs/MRs и предоставляет возможности проверок и потоков проверки. В случае неудачного PR GitHub **Fix неработающие проверки** передает имена и ссылки неудачных проверок агенту. Это документирует действие обратной связи, а не доказательство автоматического восстановления, правильной атрибуции фиксации или успешной CI. Поддержка обзора GitLab также задокументирована; эта оценка не проводилась ни одним поставщиком.

Два значения по умолчанию влияют на внедрение существующего рабочего процесса рабочего стола Codex:

- Интеграция [Codex](https://www.onorca.dev/docs/agents/codex) документирует отдельный фоновый сервер для каждого терминала Codex в Codex 0.157 и более поздних версиях. Функции общего сервера и сеансы, открытые через настольное приложение Codex или IDE, по умолчанию не видят эти сеансы Orca. Настройка каждого терминального сервера может быть отключена перед открытием новых терминалов. Передача обслуживания другому агенту запускает новый сеанс с ограниченным предшествующим контекстом; это не родное резюме. Непрерывность между приложениями здесь остается непроверенной.
- [Разрешения агента](https://www.onorca.dev/docs/agents/supported) Предварительно заполните аргументы обхода разрешений для запуска новых терминалов, включая обход как утверждений, так и песочницы для Codex. Настройка терминала **Agent Permissions** поддерживает ручной режим; В собственных чатах к новым чатам применяется отдельный параметр по умолчанию, а аргументы настраиваемого агента остаются переопределяемыми. Перед пробной версией проверьте действующие настройки запуска. Разделение рабочих деревьев не является ограничением процесса.

В прикрепленной к [документации по оркестрации](https://github.com/stablyai/orca/blob/3ddaa8df6f61e77ef095fba03532b2a13b3b2fdf/docs/site/content/docs/cli/orchestration.mdx), проверенной 27 октября, ее задачи, зависимости, контролируемые рабочие процессы, сообщения и шлюзы принятия решений помечены как экспериментальные. Устойчивый запуск описывается как координационное пространство имен, а не как автоматический планировщик.

**Редакционная оценка: 3/5.** Интегрируйте механизм обзора и обратной связи и границы внедрения Codex в общее сравнение. Тестируйте Orca, когда проблема заключается в едином ежедневном рабочем пространстве; сравните АО, когда проблема заключается в координации PR/CI/review на уровне проекта. Оба перекрываются, так что это гипотеза тестового выбора, а не рейтинг продукта. Местное исследование dependency/test-gate, проведенное Эскоуадом, не выявило поведения ни одной из альтернатив. Никакие измеренные преимущества в производительности, безопасности, удобстве использования или надежности не заявлены.

### Эмдаш

[, закрепленный README](https://github.com/generalaction/emdash/blob/761520624f1cafa740f5c88ddaf083b4fde2cc59/README.md), документирует настольное приложение для macOS, Windows и Linux с использованием установленных CLI агента кодирования и рабочего дерева для каждой задачи. Его рабочий процесс local/SSH является полезным критерием выбора для читателей, которые уже управляют собственным удаленным компьютером. Он распространяется под лицензией [Apache-2.0](https://github.com/generalaction/emdash/blob/761520624f1cafa740f5c88ddaf083b4fde2cc59/LICENSE.md).

Внедрение оказывает влияние на конфигурацию: для агентов с поддержкой перехватчиков жизненного цикла Emdash устанавливает перехватчики с маркерами в конфигурации уровня пользователя для статуса, уведомлений и возобновляемых сеансов. README говорит, что они ничего не делают вне сеансов Emdash; в этом обзоре не проверялось такое поведение или совместимость с существующими перехватчиками. Интерфейсы командной строки агентов могут отправлять запросы, код и контекст своим поставщикам, даже если Emdash документирует локальное хранилище SQLite и дополнительную телеметрию.

Оценка остается на уровне 3/5, поскольку это полезное отличие рабочего процесса, не имеющее заметного преимущества перед существующими профилями. Не заявляйте об уникальной поддержке SSH на всем рынке.

### Суперсет

[pinned README](https://github.com/superset-sh/superset/blob/e547103d8570a39327c051b80144e45c59203052/README.md) описывает рабочие деревья с терминалами, просмотр различий, обнаружение портов для каждой рабочей области и предварительный просмотр в браузере. Режим разработки отправляет выбранный контекст элемента пользовательского интерфейса агенту. Обратная связь по линиям связи с PR может передаваться как работающему, так и новому сеансу агента; публиковать этот отзыв в GitHub необязательно. Эти механизмы предоставляют конкретный пример разработки пользовательского интерфейса, выходящий за рамки еще одного списка параллельных терминалов.

В том же источнике описаны удаленный доступ, облачные рабочие пространства, Mobile Pro, планирование, поверхности CLI, SDK и MCP. Таким образом, интеграция не называет весь продукт локальным или бесплатным. macOS является основной целью, поддержка Linux AppImage является экспериментальной, а Windows недоступен в этом снимке.

Текущая лицензия [— Elastic License 2.0](https://github.com/superset-sh/superset/blob/e547103d8570a39327c051b80144e45c59203052/LICENSE.md). В руководстве используется **source-available**, а не общая метка с открытым исходным кодом. Его условия ограничивают hosted/managed предоставление существенной функциональности и вмешательство в функциональность лицензионного ключа; ознакомьтесь с лицензией для любого перераспределения или предложения услуг.

Оценка остается на уровне 3/5: за счет механизма browser/review, а не за исчерпывающий второй профиль продукта или рейтинг удобства использования.

### <a name="escouade"></a>Эскоуад

[1.8.8 README](https://github.com/guillaume-gagnaire/escouade/blob/9383ada96cf91190fc719a1fcac7ac72ab00c7c4/README.md) документирует Windows, macOS и Linux, интерфейс French/English, интерфейс Svelte 5, серверную часть Tauri 2/Rust и поддержку Claude Code, Codex, OpenCode и GitHub Copilot. CLI. В приведенном ниже испытании использовался только Claude Code, процессы которого используют `stream-json`; он не проверяет другие адаптеры или передачу обслуживания между поставщиками.

Его вкладом является рабочий процесс заявки: критерии приемки, зависимости, рабочие деревья, повторяющиеся попытки агента и настраиваемые действия test/delivery. Сервер MCP предоставляет агентам работу рабочей области. Это уровень управления рабочим процессом; отчет о том, что критерии соблюдены, не является независимым доказательством приемки. Текущее описание MCP включает проверку билета, действия test/merge, удаление билета и ответы на разрешения. Поэтому человеческое одобрение не является безусловным инвариантом каждого пути.

Лицензия — [GPL-3.0 или более поздняя версия](https://github.com/guillaume-gagnaire/escouade/blob/9383ada96cf91190fc719a1fcac7ac72ab00c7c4/README.md#licence); README явно сохраняет лицензию MIT для версий до 1.7.7. Более старый снимок MIT не должен определять метку лицензии для текущего проекта.

#### <a name="escouade-runtime-trial-october-22-2026"></a>Пробная версия Escouade: 22 октября 2026 г.

**Объем и метод.** Escouade [1.8.8](https://github.com/guillaume-gagnaire/escouade/releases/tag/v1.8.8) был скомпилирован из немодифицированного исходного кода релиза и запущен на Apple Silicon macOS в режиме разработки. Оценщик управлял официальным сервером MCP настольного приложения, операции с билетами которого вызывают те же основные функции, что и пользовательский интерфейс. При этом проверялся рабочий процесс приложения, а не навигация с помощью мыши или визуальное удобство использования. Испытание ограничивалось одноразовым репозиторием Git, отдельными данными приложения, отключенным автоматическим копированием файлов и явной командой тестирования перед слиянием. Удаленной публикации не было.

Задача заключалась в небольшой проверке документации с использованием стандартной библиотеки Python и синтетических документов Markdown. Два агента Claude Sonnet работали параллельно: один извлекал заголовки за пределы изолированного кода, другой проверял относительные ссылки на файлы. Третий билет зависел от обоих и собрал JSON CLI. Каждому билету принадлежали отдельные файлы реализации и тестовые файлы. Последняя ветвь прошла **19 тестов пилотного проекта** (18 написанных агентами и одна первоначальная проверка приспособлений), а также **3 приемочных теста**, созданных оценщиком до запуска агентов. Это не результаты тестового набора Escouade или независимый аудит продукта. В ходе приемочных тестов проверялись строки заголовков, исключение изолированного кода, закодированные пути и фрагменты, выходные данные JSON и коды выхода на наличие действительных и неработающих ссылок.

В результате CLI сообщил о намеренно отсутствующем файле, проигнорировал ссылку внутри изолированного кода и вернул ожидаемые коды выхода. Это был ограниченный прототип для оркестровки, а не замена существующих проверок документации в руководстве.

**Обнаружены ограничения.** Один билет остановлен с надписью «Bilan des critères manquant», несмотря на отчет, предоставленный агентом. Строка JSON содержала три обратных кавычки: [`last_block`](https://github.com/guillaume-gagnaire/escouade/blob/9383ada96cf91190fc719a1fcac7ac72ab00c7c4/src-tauri/src/board.rs#L137-L143) завершает отчет при их первом появлении, в том числе внутри строки. Переиздание отчета без этих символов разблокирует обзор. Это наблюдаемый сбой в отчетности, а не неудачный тест реализации.

- **Tests требует явной настройки.** [`BoardSettings::default`](https://github.com/guillaume-gagnaire/escouade/blob/9383ada96cf91190fc719a1fcac7ac72ab00c7c4/src-tauri/src/model.rs#L924-L946) отключает тесты перед доставкой и не предоставляет команду тестирования. Оба были настроены для суда; Сами по себе проверенные критерии агента не обеспечивают эти ворота.
- Сводки файлов **требуют перекрестной проверки Git.** Сводка агента MCP вернула `touchedFiles: []`, в то время как Git показывал новые файлы, написанные с помощью Bash. Панель Git рабочего стола не оценивалась, поэтому это наблюдение применимо только к этой сводке.
- Проверка дистрибутива **не удалась на тестовом компьютере.** `codesign --verify --deep --strict` сообщил о недействительной подписи Arm64 для приложений, извлеченных из обеих официальных загрузок macOS, tar.gz и DMG. Создание исходного кода выпуска с добавлением CMake во временную среду сборки позволило продолжить пробную версию. Причина и поведение сбоя подписи на других машинах не установлены.
- **Настройка запуска оценщика потребовала исправления.** Специальная программа запуска изначально загружала персональные перехватчики. Оба агента были прерваны перед редактированием файлов проекта; программа запуска была исправлена, а ее эффективные параметры процесса проверены перед возобновлением. Эта ошибка установки не является дефектом Escouade, а изолированная установка MCP/account не является типичной для обычной установки.

**Принятие решения.** Подтвержденный вклад представляет собой постоянный рабочий процесс, связывающий заявки, рабочие деревья, проверку и доставку с обязательными зависимостями. В текущем рабочем процессе Codex оценщика эти шаги координируются посредством диалогов и явных операций Git. Это делает Escouade кандидатом на выполнение ряда разделимых задач с последующей интеграцией. Этот небольшой прототип также можно было бы создать за один сеанс: испытание не доказывает, что такое разложение или переключение инструментов для одного изменения имеет смысл.

Не было эквивалентного запуска Codex A/B, измерения преимущества во времени или затратах, преднамеренного конфликта слияний, смены провайдера, сценария исчерпания квоты или теста ограничения ОС. Записи времени выполнения и пилотный репозиторий были сохранены локально, но не опубликованы в рамках этой оценки; приведенные выше наблюдения являются отчетом оценщика, а не публично воспроизводимым эталоном. Постоянные ссылки с общедоступным исходным кодом поддерживают выводы синтаксического анализатора и настроек по умолчанию, а не результаты выполнения.

**Предыдущий поиск копий файлов, не проверенный повторно в версии 1.8.8:** 17 октября зонд [закрепленный `copy_one` helper](https://github.com/guillaume-gagnaire/escouade/blob/b74b6526b3ba94df049a9a8ad1466e37706fe175/src-tauri/src/testlaunch.rs#L126) обнаружил, что он создает родительских объектов назначения и вызывает `std::fs::copy`, не отклоняя символическую ссылку назначения. Автономный зонд Rust, использующий именно эту функцию и фиктивные файлы, воспроизвел перезапись за пределами рабочего дерева. Вызов функции `copy_worktree_files` копирует игнорируемые файлы, соответствующие настроенным шаблонам, например `.env*`. Автоматическое копирование было отключено в пробной версии от 22 октября, поэтому эта пробная версия не подтверждает этот вывод и не демонстрирует исправления.

Чтобы воспроизвести узкий результат в Unix во временном каталоге:

1. Создайте `project/`, `worktree/` и `outside-sentinel`, содержащие фиктивный текст.
2. Поместите другой фиктивный текст в `project/dummy.env`.
3. Сделайте `worktree/dummy.env` символической ссылкой на дозорного за пределами `worktree/`.
4. Скомпилируйте закрепленную функцию `copy_one` без изменений в отдельной программе Rust и вызовите ее, используя эти два пути к каталогу и `dummy.env`.
5. Обратите внимание, что внешний страж теперь содержит исходный текст, затем удалите временный каталог.

При этом проверяется поведение вспомогательного канала назначения, а не сквозной эксплойт, поведение соединения Windows или каждый путь входа приложения. Никаких реальных секретов или репозиториев не использовалось. Более ранние результаты испытаний другой версии Escouade не были перенесены в качестве текущих доказательств.

Оставьте редакционную оценку на уровне 3/5:. Пробная версия с ограниченным временем выполнения подтверждает полезное поведение ticket/MCP, но не дает сравнительных доказательств производительности или безопасности. Используйте одноразовый репозиторий и фиктивную конфигурацию для пробной версии с отключенным автоматическим секретным копированием; проверьте тесты и разрешения на поставку, прежде чем применять их к важной работе. Это упоминание не является рекомендацией по безопасности.

## Какие дальнейшие сравнительные испытания необходимо установить

Используйте один и тот же небольшой репозиторий и ограниченную задачу для любого инструмента, включенного в короткий список. Запишите, может ли пользователь найти рабочую ветвь, агент, ожидающий ввода, измененные файлы, фактический тест command/result и следующее действие по доставке. Включите interruption/resume и случай конфликтующих изменений. Для SSH/cloud проверьте, где находятся код, учетные данные, перехватчики и процессы. В последующем Escouade реализовала часть этого протокола через MCP, включая interruption/resume, но не сравнивала эквивалентные прогоны и не оценивала визуальное удобство использования и конфликты. Эти пробелы остаются до того, как можно будет утверждать о сравнительной выгоде.
