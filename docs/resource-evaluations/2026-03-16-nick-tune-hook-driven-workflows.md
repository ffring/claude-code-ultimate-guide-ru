## Управляющее резюме

Ник Тьюн (уже цитируемый 4 раза в руководстве к его предыдущей статье на Medium) представляет новый шаблон, который рассматривает Claude Code хуки как **механизм обеспечения соблюдения рабочего процесса** с типизированным конечным автоматом, JSON сохранение и внедрение контекста для каждого состояния. В руководстве рассматриваются отдельные типы перехватчиков по отдельности и имеется диспетчер с одной записью на основе bash (раздел 7.5). Эта статья добавляет TypeScript Слой конечного автомата поверх хуков, которые не покрывает направляющая. Самый полезный автономный шаблон — повторное внедрение идентификаторов после сжатия — теперь можно интегрировать без полноценного конечного автомата.

## Краткое содержание

В статье представлен шаблон рабочего процесса, основанный на пяти основных идеях:

- **Hooks как конечный автомат**: перехваты SubagentStart, SubagentStop, PreToolUse и TeammateIdle используются в механизме рабочего процесса TypeScript, управляющем переходами состояний (SPAWN → ПЛАНИРОВАНИЕ → RESPAWN → РАЗРАБОТКА → ПРОВЕРКА → COMMITTING → CR_REVIEW → PR_CREATION → ОБРАТНАЯ СВЯЗЬ → ЗАВЕРШЕНО)
- **Отправка с одной точкой входа**: один обработчик для всех событий через карту `HOOK_HANDLERS`, диспетчеризация `hook_event_name` — аналогичная концепция для диспетчера bash §7.5, но TypeScript + с сохранением состояния
- **Внедрение контекста, зависящего от состояния**: SubagentStart считывает файлы `/states/<state>.md` и внедряет их в контекст агента — агенты видят только инструкции, относящиеся к текущему состоянию, избегая раздутых системных подсказок.
- **Шаблон возрождения**: после каждой итерации агенты разработчиков и рецензентов отключаются и появляются новые экземпляры, предоставляя каждой итерации чистое контекстное окно.
- **Повторное внедрение идентификаторов после сжатия**: перехватчики обнаруживают, когда агент забыл свой префикс идентификатора (после сжатия), и повторно внедряют инструкции идентификатора — наиболее автономный и переносимый шаблон в статье.

## Детальный анализ

### Точность и надежность (4/5)

Технические претензии проверяются документированным поведением перехватчика Claude Code:
- Хуки SubagentStart, SubagentStop, PreToolUse, TeammateIdle реальны и документированы.
- Поле `hook_event_name` при вводе крюка соответствует руководству §7.4 документации
- Шаблон `exitCode: EXIT_ALLOW`/`EXIT_BLOCK` действителен.
- Zod для проверки схемы является стандартной практикой TypeScript.
- Сохранение файла JSON с ключом к идентификатору сеанса — это практичный и правильный подход.

Одно существенное предостережение: автор прямо заявляет: «1 неделя экспериментов, пока не могу на 100% рекомендовать». Этот честный отказ от ответственности не является второстепенным уточнением — он означает, что он не подтвержден ни в каком значимом масштабе.

### Глубина и полнота (5/5)

Полный код TypeScript для диспетчера, проработанный пример `/states/developing.md`, схема персистентности JSON с реальными полями, карта перехода Zod, кадрирование DDD. Репозиторий GitHub с полным кодом существует. Это самая сильная сторона статьи — не пустая болтовня, а действительно реализуемая.

### Практическая ценность (4/5)

Основная проблема вполне реальна: добиться согласованности рабочих процессов в кодовых базах, которые вы не полностью контролируете. Сам по себе шаблон повторного внедрения идентичности стоит прочитать. Полный государственный автомат более сложен, но все же реализуем.

Барьер: для этого подхода требуется среда выполнения Node.js + TypeScript (`npx tsx`). Раздел хуков в руководстве по дизайну ориентирован на bash-first. Любая интеграция должна явно устранять это противоречие.

### Оригинальность и уникальность (3/5)

Диспетчер с одной точкой входа уже существует в §7.5 как bash. Функция команд агентов уже задокументирована. Что действительно нового: (1) присоединение типизированного конечного автомата к хукам, (2) внедрение контекста SubagentStart для каждого состояния из файлов, (3) возрождение для гигиены контекстного окна, (4) повторное внедрение идентификатора после сжатия. Сильная дельта по четырем конкретным моделям, а не по общему подходу.

### Готовность производства (2/5)

1 неделя тестирования. Собственные слова автора: «Не могу полностью рекомендовать». Известная сложность проводки («уродливая и временами хрупкая»). Конфигурация перехватчика JSON требует повторения одной и той же записи для каждого типа событий, что считается проблемой UX. Прежде чем это будет представлено в качестве рекомендуемого шаблона, потребуются месяцы проверки сообществом.

### Проверка сообщества (2/5)

Ник Тьюн — заслуживающий доверия практик (признанный автор сообщества DDD). Для этой конкретной статьи нет показателей внедрения. Репозиторий GitHub существует, но данные об участии в статье недоступны.

## Предварительные требования (не упомянуты в оценке v1)

Любая интеграция должна отмечать эти жесткие зависимости:

1. **Экспериментальный флаг команд агентов**: `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` — SubagentStart, SubagentStop, TeammateIdle — это события команд агентов. Без этого флага большинство паттернов в статье недоступны.
2. Требуется **Opus 4.6**: командам агентов требуется Opus 4.6+, который стоит значительно дороже, чем Sonnet.
3. **Node.js + TypeScript цепочка инструментов**: `npx tsx` должен быть доступен в проекте. Это не предположение Claude Code по умолчанию.

### Уровень 1 — интегрируйте сейчас (автономный шаблон)

**Повторное внедрение идентификаторов после сжатия** → `guide/ultimate-guide.md` §7.5 (Примеры перехватчиков)

Этот шаблон сразу же пригодится всем, кто использует перехватчики с длинными сеансами — не требуется флаг команд агентов, не требуется TypeScript. Дрейф идентичности, вызванный уплотнением, является известной болевой точкой. Обходной путь обнаружения и повторного внедрения на основе перехватчиков описан в §7.5 независимо от остальной части статьи.

```
### Handling Identity Drift After Compaction
When Claude's context compacts, agents in long sessions can "forget" their
role. A hook can detect this and re-inject identity instructions.
```

### Уровень 2 — интеграция с предварительным этапом (3–4 недели)

**Внедрение контекста SubagentStart для каждого состояния** → Добавить в agent-teams.md в качестве расширенного раздела шаблона. Обязательное условие: флаг команды агентов. Ключевая идея: внедряйте файлы с конкретным состоянием во время выполнения, а не объединяйте все в системном приглашении — это уменьшает раздувание системных приглашений и позволяет агентам сосредоточиться.

Конкретная проблема CodeRabbit + GitHub + рабочий процесс с 10 состояниями слишком самоуверен. Документировать архитектурные шаблоны; читатели определяют свои собственные состояния.

## Выводы по вызову (технический обзор)

Агент по вызову выявил несколько проблем при первоначальной оценке версии 1:

**Коррекция оценки**: первоначальная оценка 4/5 («интеграция в течение 1 недели») была слишком агрессивной для чего-то, что автор не проверял более 1 недели. Правильная оценка сейчас — 3/5, с запланированной повторной оценкой через 60-90 дней.

**Оригинальность была преувеличена.**: Диспетчер с одной точкой входа уже существует в §7.5 как bash. Руководство уже четыре раза ссылается на более раннюю работу этого автора. Реальная дельта уже: конечный автомат, внедрение для каждого состояния, возрождение, повторное внедрение идентичности.

**Отсутствуют предварительные условия**: флаг команды агента, Opus 4.6, Node.js + TypeScript — ничего из этого не было в v1. Любая интеграция без указания этих предварительных условий расстроит читателей.

**Повторное внедрение идентичности является наиболее актуальным шаблоном.**: Автономный вариант, не требующий экспериментального флага, напрямую решает задокументированную болезненную точку (дрейф, вызванный уплотнением). В оценке версии 1 это упоминалось, но не ставилось в приоритет как непосредственная цель интеграции.

**Рекомендация по интеграции была расплывчатой.**: «Интеграция в разделе хуков + новое руководство по рабочему процессу» без определения того, что и где происходит. Многоуровневый подход (уровень 1 сейчас/уровень 2 через 3–4 недели/уровень 3 через 60–90 дней) более эффективен.
