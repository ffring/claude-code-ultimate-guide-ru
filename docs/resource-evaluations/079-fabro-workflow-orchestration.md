## Краткое содержание

- **Оркестратор рабочих процессов для агентов ИИ-кодирования**: определите конвейеры как графы Graphviz DOT с ветвлением, циклами, параллелизмом и воротами одобрения человеком — с возможностью сравнения и контролем версий
- **Мультимодельная маршрутизация**: CSS-подобные таблицы стилей назначают разные модели LLM (Claude, OpenAI, Gemini) конкретным узлам рабочего процесса с автоматическими резервными цепочками.
- **Git контрольная точка для каждого этапа**: каждый этап фиксирует изменения кода и метаданные выполнения в выделенной ветке Git — уникальная функция, не имеющая прямого эквивалента в ландшафте
- **Облачные песочницы**: изолированные виртуальные машины Daytona с настройкой на основе моментальных снимков, сетевым контролем, доступом по SSH и автоматической очисткой.
- **Автоматические ретроспективы**: при каждом прогоне создается ретроспектива cost/duration/narrative для постоянного улучшения.
- **Прямая интеграция с Claude Code**: `curl -fsSL https://fabro.sh/install.md | claude` (примечание по безопасности: передача напрямую в Claude, без промежуточного этапа проверки)
- **Один двоичный файл Rust, нулевые зависимости во время выполнения**: не требуется ни Python, ни Node.js, ни Docker
- **REST API + потоковая передача SSE + React web UI**: запуск рабочих процессов программно или как услуга

**Окончательный счет: 3/5 (Смотреть)**

**Обоснование:** Fabro попадает непосредственно в категорию «Среды внешней оркестровки», уже описанную в руководстве (`third-party-tools.md`). Его графический подход DOT архитектурно отличается от всех трех существующих записей (Ruflo соответствует роям, Athena Flow соответствует слою перехватчиков, Pipelex соответствует DSL). Контрольные точки Git на каждом этапе — это настоящее отличие, аналогов которому нет в конкурирующих средах. Прямая интеграция Claude Code через конвейер `claude` является законной. Однако 28 звезд (теперь 1449 по состоянию на 28 июля 2026 г.) в возрасте 4 дней демонстрируют тот же профиль раннего созревания, что и Athena Flow (#073, оценка 2/5). Повышен до 3/5 по сравнению с Athena Flow из-за большей ясности архитектуры, более широкого набора функций с большим количеством доказательств и действительно уникального угла проверки контрольных точек Git.

| Инструмент | Категория | Звезды | Ключевое отличие от Фабро |

| **LangGraph** (LangChain) | Конвейеры на основе графов | ~34k | Библиотека Python (не отдельный двоичный файл), общего назначения (не специфичная для агента кодирования), без контрольных точек Git |
| **Гусь** (Блок) | Оркестровка агента кодирования | ~15k | Диалоговая архитектура на основе рецептов (а не графиков), без контрольных точек Git, но гораздо более зрелая. |
| **OpenHands** | Платформа агента кодирования | ~48k | Архитектура потока событий, песочницы Docker, ориентированность на исследования — без DOT-графика, без контрольных точек Git на каждом этапе |

| **AutoGen** (Майкрософт) | Мультиагентные разговоры | ~47.9k | Общего назначения, модель диалогового цикла, без особенностей кодирующего агента. |
| **CrewAI** | Ролевые агентские бригады | ~34.7k | Модель назначения ролей, без определения графа, без контрольных точек Git. |

**Уникальная комбинация Фабро** (ни один конкурент не делает все три):
1. Определение рабочего процесса графика DOT как отдельный двоичный файл
2. Контрольные точки Git для каждого этапа (код + метаданные, зафиксированные в ветках)
3. Встроенная интеграция Claude Code через `claude`

**Самая актуальная альтернатива для читателей руководств на сегодняшний день**: LangGraph для рабочих процессов на основе графов (гораздо более зрелый, Python), Goose (Block) для оркестрации агентов кодирования (лучшая тяга, MIT).

## Вызов (агент технического писателя)

**Первоначальный предлагаемый счет:** 4/5
**Оценка после вызова:** 3/5 (понижена)

Поднятые баллы:

- **Флаг незрелости**: 28 звезд/4 дня = та же картина, что и у Athena Flow (оценка 2/5). Непоследовательное применение этого подхода подрывает систему оценки. Компромисс: 3/5, потому что Фабро демонстрирует больше архитектурных свидетельств, чем Афина Флоу в том же возрасте.
- **`curl | claude` безопасность**: более опасен, чем обычный `curl | bash` — передается непосредственно в базу кода без этапа проверки. Собственный раздел безопасности Гида отметит это. Необходимо учитывать при любой будущей интеграции.
- **Амбициозный непроверенный набор функций**: облачные песочницы, DOT-маршрутизация, ретроспективы — ни один из них не был проверен сообществом на момент оценки.
- **Риск неинтеграции на данном этапе**: около нуля. Категория уже охвачена 3 записями.
- **Что действительно нового?**: определение DOT-графика как различающегося текста (в отличие от Ruflo/Pipelex/Athena) + контрольные точки Git для каждого этапа = углы, которые стоит отслеживать.
