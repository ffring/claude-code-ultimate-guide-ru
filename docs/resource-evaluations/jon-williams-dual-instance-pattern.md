## Краткое содержание

Джон Уильямс описывает рабочий процесс с двумя экземплярами, использующий два одновременных сеанса Claude Code с разными ролями:

- **Claude Zero (Planner)**: изучает кодовую базу, пишет планы, проверяет реализации, никогда не трогает код.
- **Claude Один (Реализатор)**: читает утвержденные планы, реализует функции, фиксирует изменения.

**Ключевое нововведение**: Вертикальное разделение (планировщик ↔ исполнитель) как альтернатива горизонтальному масштабированию (параллельные функции).

**Claims**:
- «Значительное улучшение качества и скорости» по сравнению с Cursor
- Поверхности планирования на основе собеседований упустили из виду соображения
- Готовые к агенту планы (пути к файлам + номера строк) сокращают время внедрения.
- Структура каталогов планов: `Review/` → `Active/` → `Completed/`.

## Оценка оценки: **4/5 (высокое значение)**

### Обоснование

**Изначально набрал 2-3/5**, но технический писатель-агент правильно определил занижение:

1. **Дополняет существующий контент.**: шаблон ортогонален (вертикальное или горизонтальное масштабирование) документированному шаблону Бориса Черного.
2. **Заполняет пробел в аудитории**: одиночные разработчики и команды с ограниченным бюджетом ($100-200/month) против шаблона Бориса ($500-1K+/month)
3. **Признанная инженерная модель**: Двухфазная фиксация, разделение задач, применяемое к LLM

5. **Проверяемый подход**: конкретная структура каталогов, понятный рабочий процесс, возможность тиражирования

**Не 5/5, потому что**:
- Один специалист (еще не проверен несколькими командами)
- Нет количественных показателей («значительное улучшение» субъективно)

## Результаты конкурса (агент технического писателя)

### Ключевые критические замечания

1. **Занижение оценки**: Происхождение (LinkedIn или академическая статья) не должно обесценивать практические закономерности.
2. **Идентификация зазора**: в руководящих документах предусмотрено горизонтальное масштабирование, но не вертикальное разделение.
3. **Разрыв в аудитории**: одиночные разработчики ($100-200/month) недостаточно обслуживаются моделью Бориса ($500–1 тыс.+)
4. **Распознавание образов**: двухфазное принятие решения, разделение задач = устоявшиеся принципы проектирования
5. **Отсутствует анализ затрат**: Руководство никогда не сравнивает «2 последовательных экземпляра и 1 экземпляр с исправлениями»

### Аспекты, изначально пропущенные

- **Ссылка на режим `/plan`**: двойной экземпляр — это расширение с постоянным контролем человека в цикле.
- **Механизм уменьшения ошибок**: Двухфазная фиксация → меньше ошибок при начислении процентов
- Каталог **Plans/ для управления рабочим процессом**: Review/Active/Completed = Рабочий процесс в стиле Канбан
- **Сигнал аудитории, не связанной с разработчиками.**: Джон — дизайнер продукта → шаблон помогает нетехническим пользователям.
- **Структура, готовая к работе с агентом**: в качестве рекомендуемой практики следует преподавать пути к файлам и номера строк.
