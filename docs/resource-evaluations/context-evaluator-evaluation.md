## Что это такое

context-evaluator анализирует файлы CLAUDE.md и AGENTS.md с использованием 17 специализированных оценщиков AI (13 ошибок + 4 категории предложений). Доступно как:

- Веб-приложение без установки на context-evaluator.ai (вставьте URL-адрес GitHub или загрузите файл)
- Предварительно скомпилированный двоичный файл для macOS/Linux/Windows (без зависимостей во время выполнения)
- Установка исходного кода (Bun/TypeScript)

Оценка занимает 1-3 минуты. Выводит оценочный отчет с уровнями серьезности (Critical/High/Medium/Low) и конкретными рекомендациями по исправлению. Функция автоматического исправления создает файл `.patch` для улучшений, созданных ИИ.

## Выявлены технические закономерности (источник прочитан)

### Шаблон 1. Ведение журнала подсказок во время выполнения (`runtime-prompt-logger.ts`)

**Постоянная блокировка записи на диск ПЕРЕД вызовом провайдера AI.** Не является флагом отладки — каждое приглашение сохраняется в `prompts/debug/` с именем файла с отметкой времени ISO-8601, независимо от состояния флага `--debug`. Запись — `await writeFile()` (блокировка). Если вызов провайдера завершается сбоем или истекает время ожидания, точное приглашение уже находится на диске.

Ключевые дизайнерские решения:
- Блокировка записи (а не принцип «выстрелил и забыл»): гарантирует, что файл существует до начала вызова AI.
- Никогда не выдает: ошибки регистрации регистрируют предупреждение и возвращают `null`, но не нарушают оценки.
- Отдельно от `--debug` (который сохраняется в `{workingDir}/debug-output/`): сохраняется навсегда и всегда активен.

**В настоящее время в руководстве нет.** В руководстве рассматривается использование флага `--debug`, но не упоминается «запись перед вызовом» как шаблон проектирования для навыков оценщика.

### Схема 2: Адаптивный режим unified/parallel (`runner.ts:764-775`)

**Переключение порога токена между выполнением с одним агентом и с параллельным агентом.** Перед запуском оценщиков система оценивает общее количество токенов во всех входных файлах. Если токенов меньше 100 тыс. (`DEFAULT_MAX_UNIFIED_TOKENS`), все файлы оцениваются с помощью единого вызова агента, который может обнаружить противоречия между файлами. Если указано выше, каждый файл оценивается независимыми параллельными агентами.

```typescript
export function canUseUnifiedMode(
  context: MultiFileContext,
  maxTokens: number = DEFAULT_MAX_UNIFIED_TOKENS,
): { viable: boolean; reason?: string } {
  if (context.totalTokenEstimate > maxTokens) {
    return {
      viable: false,
      reason: `Combined file content (~${context.totalTokenEstimate} tokens) exceeds limit (${maxTokens} tokens)`,
    };
  }
  return { viable: true };
}
```

**Не указано явно в руководстве.** В руководстве обсуждаются параллельные субагенты и оценка нескольких файлов, но не документируется шаблон переключения «проверить количество токенов, выбрать 1-агент против N-агента» с конкретным пороговым значением.

### Схема 3: Внедрение технической инвентаризации (`context-identifier.ts`)

Сначала собираются CLOC + структура папок + анализ `ls -la`, а затем вводятся в виде структурированного контекста во все 17 подсказок оценщика. Аналогично Shared Ground Truth Injection (уже задокументировано в версии 3.39.0 `skill-design-patterns.md`). **Новая документация не требуется.**: это вариант уже рассмотренного шаблона.

### Схема 4: Многоуровневая дедупликация

Трехэтапный конвейер: кластеризация на основе правил (допуск местоположения + сходство текста) → семантическая дедупликация ИИ → курирование воздействия. Интересно, но специфично для систем оценки. Низкая ценность для обычных пользователей CC, пропустите.

## <a name="limitations"></a>Ограничения

- Требуется поставщик ИИ (Claude Code, Cursor, OpenCode, GitHub Copilot, Codex)
- Обработка занимает 1-3 минуты за проход.
- Нет детерминированной оценки для ворот CI.
- Нет обнаружения дрейфа на основе git
- Совершенно новый инструмент (запущен в 2026 году, экспериментальный проект Packmind)
