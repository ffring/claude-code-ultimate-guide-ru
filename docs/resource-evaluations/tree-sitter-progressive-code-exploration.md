## Краткое резюме

**Score: 4/5** (высокое значение — интеграция в течение 1 недели)

Шаблон «умного исследования» использует синтаксический анализ AST с использованием дерева для сжатия исследования кода с 10–15 тысяч токенов на файл до ~ 200–500 токенов, сначала показывая сигнатуры и структуру функций, а затем углубляясь в конкретные функции только при необходимости. RTK обрабатывает выходные данные команд (экономия 60–90 %); этот шаблон обрабатывает чтение кода (экономия 90–97%). Вместе они охватывают оба основных приемника токенов в сеансе Claude Code.

Единой «официальной» реализации не существует — навыки Алекса Ньюмана являются частными. Но в экосистеме есть несколько рабочих реализаций, начиная от чистого подхода CLI и заканчивая готовыми к использованию серверами MCP.

---

## Шаблон: прогрессивное исследование кода.

Три слоя, выполненные по порядку:

```
Layer 1 — Structure (~200 tokens)
  tree-sitter parse file.rs → function signatures, types, fields
  Claude sees: "what exists?" without reading any body

Layer 2 — Search (~300 tokens)
  "Show me the body of filter_output()"
  tool returns lines 47-120 only, not the whole file

Layer 3 — Context (~500 tokens)
  "Who calls filter_output()?"
  cross-reference table, not file dumps
```

**против наивного подхода** (прочитать файл, прочитать другой файл, прочитать другой файл):
- Наивный: 10 файлов × ~ 1400 токенов = 14 000 токенов.
- Прогрессивный: 10 структур (2000) + 2 функции (1000) = 3000 жетонов.
- **Сокращение: в среднем ~78%, до 97% для крупных репо**

Тот же шаблон, который Aider (более 40 тысяч звезд) использует для своей карты репо, проверенный в масштабе.

**Что он делает**: Индексирует кодовую базу один раз с помощью Tree-Sitter, предоставляет символы через MCP. Claude вызывает `get_symbol("filter_output")` вместо чтения всего файла.

**Install**:
```bash
claude mcp add jcodemunch uvx jcodemunch-mcp
# or
pip install jcodemunch-mcp
```

Заявления **Token против реальности**:
| Источник претензии | Рисунок | Оценка |

### 5. Карта репо Aider (эталонная реализация)

**Project**: Aider (https://aider.chat), более 40 тыс. звезд (теперь 47 733 по состоянию на 28 июля 2026 г.)
**Подход**: Tree-sitter + график NetworkX + рейтинг PageRank + бинарный поиск для бюджета токена

**Как это работает**:
1. Разобрать каждый файл с помощью Tree-Sitter → извлечь символы + место ссылки на них.
2. Построить граф зависимостей (файлы = узлы, перекрестные ссылки = ребра)
3. PageRank: файлы, на которые ссылаются многие другие, оцениваются выше (публичный API > частный помощник)
4. Соответствие бюджету: двоичный поиск в пределах лимита `--map-tokens` (по умолчанию: 1000 токенов)

**Почему это важно**: Это наиболее технически документированная реализация шаблона. Изобретено в 2023 году, проверено по шкале 40 тысяч+ звезд. Нет сервера MCP, но показано, как выглядит идеальная реализация.

**Бюджет токенов по умолчанию**: `--map-tokens 1000` предоставляет всю структуру репо в 1 тыс. токенов.

## Оценка релевантности: 4/5

### Почему 4/5?

**Сильные стороны, поддерживающие интеграцию**:

1. **Сигнал из надежного источника**: Алекс Ньюман (Claude-MEM, 38 тысяч+ звезд) прямо называет это закономерностью, производящей «14 тысяч → 200 токенов». Не маркетинг, сигнал коллег.
2. **Множественные производственные реализации**: code-review-graph имеет 2 тыс. звезд и лицензию MIT, jCodeMunch поставляется с однострочным `uvx`, Aider проверяет шаблон в масштабе 40 тыс.+.
3. **Подлинный пробел в текущем руководстве**: Руководящие документы RTK (экономия на выводе команд), но не экономия на чтении кода. Эти две проблемы дополняют друг друга, и обе они полностью охвачены.
4. **Шаблон доступен для обучения**: Прогрессивное раскрытие (структура → поиск → детализация) работает даже без какого-либо внешнего инструмента, при дисциплинированном использовании только инструмента чтения Claude.
5. **Доверие к Aider**: шаблон не является экспериментальным — карта репо Aider находится в разработке с 2023 года.

**Почему бы не 5/5**:

1. **Навык Алекса «умное исследование» не является общедоступным.**: невозможно цитировать его напрямую или ссылаться на него. Руководство должно документировать шаблон + доступные реализации, а не «навыки Алекса Ньюмана».
2. **Бенчмарки сильно различаются**: от 6,8x до 49x до 95 % — честное число для типичных рабочих процессов определить труднее, чем измеренные RTK 60–90 %.
3. **grepai уже частично это делает.**: Руководство уже рекомендует grepai для семантического поиска кода. Tree-sitter добавляет структурную осведомленность (не только семантическую), но перекрытие реально.
4. Серверы **MCP находятся на ранней стадии**: mcp-server-tree-sitter не имеет тестов, у CodeRLM есть известная проблема с автономностью, jCodeMunch взимает плату за коммерческое использование.

## Технические примечания (для авторов руководств)

### Что такое сидящий на дереве, а что НЕТ

**Is**: библиотека синтаксического анализатора, которая превращает исходный код в AST (абстрактное синтаксическое дерево). Тот же движок, который использует VSCode/Neovim/Zed для подсветки синтаксиса и свертывания кода.

**— это не**: семантический анализатор. Он понимает синтаксис, а не смысл. `tree-sitter` может сказать вам: «Это функция с именем X с этими параметрами», но не «эта функция вызывается Y во всей кодовой базе» (это то, что делает граф grepai/Aider).

### Аналогия с DOM (для документации)

«Tree-sitter делает для кода то же, что браузер делает для HTML — превращает плоский текст в структуру с возможностью навигации. Вместо дерева DOM вы получаете AST: каждая функция, класс, структура и поле как типизированный узел с точной позицией в файле».

### Честная математика токенов

| Операция | Токены | Метод |
|---|---|---|
| Чтение 500-строчного файла | ~3,500 | Инструмент чтения Claude |
| Получить только файловую структуру | ~200 | подписи сидящих на деревьях |
| Чтение одной функции (50 строк) | ~350 | поиск смещения Tree-Sitter |
| Изучите модуль из 10 файлов (простой) | ~35,000 | Читать × 10 |
| Модуль «Изучите 10 файлов» (прогрессивный) | ~3,500 | Конструкция × 10 + дрель × 2 |

Реальное сокращение для типичной работы с функциями: **70-90%**. Цифры в 97% требуют гигантских баз кода и шаблонов удачного доступа.
