## Вердикт

шунт не является компрессором. Это делегатор: когда Claude пытается прочитать большой файл, перехватчик блокирует чтение и указывает Claude на скрипт, который отправляет файлы в другую модель (по умолчанию Gemini 2.5 Flash) через Spotify Portal. Claude получает только ответ рабочей модели. Показатель 90%, указанный в статье, измеряет количество токенов, входящих в контекст Claude, в трех сценариях чтения. Он не учитывает жетоны рабочей модели, точность ответа или дополнительный ход, вызванный блоком.

Сам инструмент работает только для клиентов портала. Portal — это управляемое коммерческое предложение Backstage от Spotify: бесплатная пробная версия, затем цены на основе продаж, включая помощника AiKA ([Portal вместо Backstage](https://info.backstage.byspotify.com/portal-vs-backstage)). Без экземпляра портала перехватчики блокируют чтение, но делегирование не выполняется.

Что заслуживает места в руководстве, так это шаблон, а не продукт: правило маршрутизации, реализуемое с помощью хука вместо рекомендательной строки в `CLAUDE.md`. Автор говорит прямо: первая версия представляла собой блок правил маршрутизации в `CLAUDE.md`, и "правила носили рекомендательный, а не принудительный характер". Это также противоречит предложению в руководстве, в котором маршрутизация модели рассматривается только как метод API-конвейера.

## Как это работает, с исходниками

1. **Read ловушка.** [`check-file-size`](https://github.com/spotify/portal-ai-plugins/blob/3c24ca30ff63e1f5bbad1c43fe5324daff579123/plugins/shunt/hooks/check-file-size) работает на каждом `Read`. Полное чтение (без `offset`, без `limit`) файла длиной более 350 строк (`SHUNT_MIN_LINES`) блокируется по причине, которая называет навык `/bulk-reader`.
2. **Bashook.** [`check-bash-read`](https://github.com/spotify/portal-ai-plugins/blob/3c24ca30ff63e1f5bbad1c43fe5324daff579123/plugins/shunt/hooks/check-bash-read) применяет то же правило к `cat`, `head`, `tail`, `less` и `more`, за исключением случаев, когда команда содержит трубку или `>`.
3. **Delegation.** [`bulk-read`](https://github.com/spotify/portal-ai-plugins/blob/3c24ca30ff63e1f5bbad1c43fe5324daff579123/plugins/shunt/scripts/bulk-read) оборачивает каждый файл тегами `<file path="...">`, добавляет вопрос и вызывает `portal-cli actions aika:invoke-chat` в режиме `bulk-reader`. [`code-write`](https://github.com/spotify/portal-ai-plugins/blob/3c24ca30ff63e1f5bbad1c43fe5324daff579123/plugins/shunt/scripts/code-write) отправляет спецификацию и один справочный файл в режим `code-writer` и может записать результат прямо на диск с помощью `--target`.
4. **Transport.** [`aika.sh`](https://github.com/spotify/portal-ai-plugins/blob/3c24ca30ff63e1f5bbad1c43fe5324daff579123/plugins/shunt/scripts/lib/aika.sh) передает запрос через argv (потолок 400 КБ на macOS, 120 КБ на Linux), разрешает режим по имени (сначала собственные режимы, затем группы вызывающего абонента, затем общедоступные) и отбрасывает любой ответ, где режим не был применен.

## Дефекты

Протестировано в реальном времени с `claude --plugin-dir` на Claude Code 2.1.284, без экземпляра Portal, поэтому использовалось только поведение перехватчика.

| Дефект | Статус |
|---|---|
| Полный `Read` длиной более 350 строк блокируется; файл в 35 строк читается нормально | Подтверждено в реальном времени (работает так, как задумано) |
| PDF-файл блокируется как текст: `wc -l` насчитал в PDF-файле 4471 байт новой строки, а `bulk-read` отправил двоичный файл в рабочую модель. | Подтверждено в прямом эфире |
| Хук Bash игнорирует любой путь, начинающийся с `~`: `head -100 ~/…` проходит, та же команда с абсолютным путем блокируется. Перехватчик проверяет `[ ! -f "$file_path" ]` на буквенной строке ([line 33](https://github.com/spotify/portal-ai-plugins/blob/3c24ca30ff63e1f5bbad1c43fe5324daff579123/plugins/shunt/hooks/check-bash-read#L33)), а `~` в кавычках не раскрывается. | Подтверждено в прямом эфире; не охвачен 51 оценкой репозитория |
| `head -n 5 file` проходит, поскольку анализатор принимает `5` в качестве имени файла; `head -100 file` (чтение 100 строк) заблокировано | Задокументировано как известная ошибка в собственных оценках репозитория (`bash-hook-evals.json`, случай 17). |
| `offset: 0` или `limit: 0` обходит хук Read, а само сообщение блокировки предлагает перечитать с помощью `offset`/`limit`. | Задокументировано в файлах evals; хук направляет, а не принуждает |
| Хуки печатают устаревшее поле `decision` верхнего уровня. Ссылка [hooks](https://code.claude.com/docs/en/hooks) отображает только `"approve"` и `"block"`; `{"decision": "allow"}`, которые хуки печатают при каждом проходе, не является документированным значением | Никаких видимых ошибок в живом тесте нет. Не было проверено, игнорируется ли оно или рассматривается как одобрение. |
| `code-write --target` записывает через вызов Bash, поэтому перехватчики и правила разрешений, ограниченные `Edit` и `Write`, не видят файл, а Claude никогда не читает сгенерированный код по замыслу. | Чтение кода |
| Разрешение режима предпочитает групповые режимы общедоступным: режим коллеги с именем `code-writer` получает ваши спецификации, а его выходные данные попадают в ваш репозиторий. | README и `aika.sh`; не тренировался |
| `npx --yes @spotify/portal-cli` запускает последнюю опубликованную версию CLI с вашими учетными данными портала, когда не существует глобальной установки. | Чтение кода ([`aika.sh` строка 37](https://github.com/spotify/portal-ai-plugins/blob/3c24ca30ff63e1f5bbad1c43fe5324daff579123/plugins/shunt/scripts/lib/aika.sh#L37)) |
| Тайм-аут вызова в 180 секунд превышает значение по умолчанию для инструмента Bash в 120 000 мс (`BASH_DEFAULT_TIMEOUT_MS`), поэтому длинные делегирования сначала обрезаются на стороне Claude. | Чтение кода; не тренировался |
| Без `jq` оба хука разрешают все молча | Чтение кода |

Что сделано хорошо: навыки рабочего процесса портала требуют пробного прогона и явного подтверждения перед любой мутацией и никогда не запрашивают учетные данные в чате, `aika.sh` отделяет stderr от конверта JSON и отклоняет ответы без режима, а README перечисляет то, что плагин не делегирует (отладка, редактирование, решения по архитектуре).

## Сравнение с существующим покрытием руководства

| Инструмент в руководстве | Слой | Механизм | Разница с шунтом |
|---|---|---|---|
| РТК | Вывод оболочки | Детерминированные локальные фильтры | Другой уровень: вывод bash составляет ~ 12% токенов сеанса, чтение файла ~ 65% |
| Lean-ctx, Tilth | Файл читает | Локальное структурное сжатие (дерево-сидение) | Тот же слой. Они вырезают токены, не добавляя модель и не отправляя код с машины. |
| Высота над головой | Выходные данные инструмента, структурированные данные | Локальное сжатие с извлечением без потерь | Реверсивный; резюме шунта не являются |
| Эджи | Шлюз между клиентом и API | Краткость вывода, сокращение каталога инструментов, обрезка результатов | Шлюз видит весь трафик; шунт видит только файлы, которые он делегирует |
| Субагент с `model: haiku` | Чтение файлов по требованию | Родная делегация в изолированном контексте | Тот же шаблон, код остается Anthropic, без дополнительных поставщиков. Не применяется, если на него не перенаправляется перехватчик. |
