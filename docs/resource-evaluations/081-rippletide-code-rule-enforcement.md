# Оценка ресурса № 081: Код Rippletide: применение правил во время выполнения для Claude Code

**Источник:** Сообщение LinkedIn (Патрик Жубер, генеральный директор Rippletide) + [rippletide.com/dev](https://www.rippletide.com/dev)
**Type:** Коммерческий инструмент — встроенный уровень применения правил для Claude Code
**Оценено:** 17 марта 2026 г.
**Примечание:** В отличие от eval 072 (28 февраля 2026 г.), в котором рассматривалась SaaS-среда выполнения Rippletide MCP/eval/decision. Это другой продукт: инструмент принудительного применения CLI (`npx rippletide-code`), встроенный в перехватчик, без накладных расходов MCP.

---

## 📄 Краткое содержание

1. **Решаемая проблема**: правила CLAUDE.md ухудшаются в масштабе — после примерно 40 правил Claude Code следует им непоследовательно; сжатие контекста приводит к потере правил между сеансами. Согласно Rippletide: «50% проблем Claude Code CLAUDE.md связаны с игнорированием правил» (цитируется более 18 общедоступных отчетов GitHub).

2. **Основной механизм**: считывает кодовую базу и существующий CLAUDE.md → строит «контекстный график», хранящийся вне контекстного окна LLM → использует перехватчики Claude Code для перехвата вызовов инструментов перед выполнением → блокирует нарушения до их запуска.

3. **Architecture**: собственный перехватчик (не MCP), позволяющий избежать накладных расходов на внедрение токенов. Блокировка перед выполнением (не ведение журнала после выполнения). Пример вывода: `[BLOCKED] Rule: "DO NOT modify .env files"`.

4. **Установка**: `npx rippletide-code` — бесплатная бета-версия, без ключа API, регистрация не требуется. График строится «менее чем за 5 секунд» (заявление компании).

5. **Background**: Основана в феврале 2024 года, Сан-Франциско + Париж, команда из 8 человек. Выиграла хакатон OpenAI Codex. Соучредители: Патрик Жубер (генеральный директор) + Янн Билиен (главный научный сотрудник). Доступен уровень Enterprise (индивидуальная цена, «2-недельный спринт проверки»).

**Оценка: 3/5**

**Justification**: устраняет реальную, задокументированную болезненную точку сообщества (ухудшение правил CLAUDE.md при масштабировании, потеря правил из-за уплотнения), которые в руководстве признаются, но не рассматриваются в решениях. Шаблон принудительного применения на основе перехватчиков является действительно новым в экосистеме Claude Code — ни один другой документированный инструмент не осуществляет блокировку перед выполнением. Однако многочисленные заявления не проверены (устойчивость к сжатию контекстного графика, построение графика «менее 5 секунд», «50% проблем»), продукт находится в бесплатной бета-версии без каких-либо сигналов о внедрении, и у компании есть предшествующая практика публикации непроверяемых заявлений о производительности (оценка 072: «<1% галлюцинаций» без методологии).

Оценка не превышает 3, потому что: достоверность руководства требует использования коммерческих инструментов для подтверждения стандартов, и этот инструмент не соответствует этому стандарту без независимого подтверждения.

**Приоритет 1 — Документируйте шаблон, а не только инструмент.**

Шаблон: используйте перехватчики `PreToolUse` для проверки вызовов инструментов на соответствие набору правил и выйдите с ненулевым выходом для блокировки. НЕ создавайте раздел в руководстве, который существует только для обоснования одного бета-продукта.

## 🔥 Челлендж (технический писатель)

**Счет после вызова: 3/5 (удержано)**

Ключевые моменты, поднятые в проблеме:

1. **Непроверенные утверждения, заложенные в качестве фактов**: Первоначально в оценке «устойчивость к сжатию контекстного графа» рассматривалась как проверенная функция. Это собственное заявление Rippletide. Руководство не должно повторять это без уточнений — та же ошибка, из-за которой в 2/5. сохранялось значение eval 072.

2. **Поверхность безопасности не адресована**: перехватчик перед выполнением на критическом пути каждого вызова инструмента имеет реальную поверхность атаки. Поведение при открытии и закрытии при сбое, когда служба контекстного графика недоступна, не указано. Недокументировано, запускает ли `npx rippletide-code` постоянный фоновый процесс с доступом к входным данным инструмента (которые могут содержать секреты).

3. **«Бесплатная бета-версия» — это флаг риска.**: нет страницы с ценами, нет плана после бета-тестирования, нет заявленной политики обработки данных для стандартного сканирования. В путеводителе есть Страуде с оговорками о передаче данных: Рипплетид заслуживает такого же внимания.

4. **«Автоматическое обнаружение неявных соглашений» не проверялось**: Как? Отправляет ли он код во внешнюю службу? Только местный? Прежде чем стать функцией, это вопрос безопасности и конфиденциальности.

5. **Последовательность интеграции имеет значение**: Не добавляйте раздел «Применение правил» в third-party-tools.md без предварительного добавления раздела «Применение правил» в таблицу «Известные пробелы». Категория перед инструментом, а не инструмент, создающий категорию.

6. **Более сильной точкой интеграции является PATTERN**: в руководстве должна быть описана концепция принудительного применения предварительного выполнения на основе перехватчиков. Rippletide — одна из реализаций. Минимальный пример «сделай сам» (перехватчик PreToolUse, который проверяет список правил и завершает ненулевое значение) будет служить читателям лучше, чем реклама коммерческого продукта.

**Риски НЕ интеграции**: Низкий-средний. Проблема деградации правил реальна и недостаточно документирована в руководстве. Неосвещение этого вопроса оставляет пробел, с которым регулярно сталкиваются практики. Но закономерность можно задокументировать и без Rippletide — риск решается путем освещения концепции, а не продукта.
