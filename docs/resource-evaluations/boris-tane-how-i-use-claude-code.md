## Ключевые идеи

### 1. Яркий исследовательский язык
Без сильного сигнала Claude скользит. Такие слова, как «глубоко», «подробно», «тонкости», переключают поведение с поверхностного сканирования на тщательное исследование. Вывод необходимо записать в файл — словесные резюме исчезают при сжатии контекста.

### 2. Цикл аннотации
Основная инновация: итерация `plan.md` с человеческими аннотациями до написания кода. Человек добавляет комментарии непосредственно в файл плана, агент вносит изменения и повторяет действия до тех пор, пока не останется открытых вопросов. Обычно: 1–6 итераций.

Подсказка «Ничего пока не реализуйте» имеет решающее значение — без нее Claude начнет кодировать во время планирования.

### 3. Markdown как общее изменяемое состояние
Цитата: «Файл уценки действует как общее изменяемое состояние между вами и агентом». Это ключевой вывод: файл плана — это не просто документация, это артефакт координации.

### 4. Краткие отзывы на этапе реализации
После утверждения плана его реализация становится механической. Короткая обратная связь («выглядит правильно», скриншоты) более эффективна, чем абзацы — решения уже приняты.

### 5. Дополнительные методы
- Выбор вишни: реализовать часть плана
- Сокращение объема: удаление элементов перед реализацией
- Справочное руководство: «делай как auth.ts»
- Откат и повторное масштабирование: `git revert` + перезапуск с более узким планом.
