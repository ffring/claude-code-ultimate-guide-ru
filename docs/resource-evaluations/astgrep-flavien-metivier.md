## Краткое содержание

**Основные претензии**:

1. Claude Code использует RAG (Voyage Embeddings), заброшенный с целью получения прибыли от grep/ripgrep
2. Смысл: «агентский поиск превосходит все остальное» (pas de sync, pas de sécurité à gérer, simplicité)
3. Коммунальная критика: «grep brûle 40% de tokens en bruit» (источник: блог Milvus)
4. ast-grep = опция плагина, требуется явный вызов
5. Quand utiliser ast-grep: миграции >100 тыс. строк, комплекс рефакторинга, шаблоны AST
6. Quand grep suffit: "90% des cas", проекты <50 тыс. строк
7. Философия Anthropic: «Ищите, а не индексируйте»

## Пробелы в исходном ресурсе

**Чего не хватает в сообщении LinkedIn**:

1. **Сложность установки**: затраты на установку, время обучения, затраты на обслуживание
2. **Сценарии сбоя**: При сбое ast-grep (сложность шаблона, ложные срабатывания)
3. **Экономика токенов**: Если grep «сжигает 40%», сколько экономит ast-grep? (данные отсутствуют)
4. **Пользовательский опыт**: отладка сложных шаблонов, синтаксические различия в разных языках.
5. **Сравнение альтернатив**: Нет упоминания о Серене MCP (семантический поиск), grepai (на основе RAG)
6. **Проблемы с производительностью**: ast-grep работает медленно на больших базах кода, нет стратегий снижения риска

**Что мы добавили**:
- Полное дерево решений (сравнение 4 инструментов)
- Матрица стоимости установки и стоимости
- 10 практических выкроек с примерами
- Руководство по устранению неполадок
- Рабочие процессы интеграции (предварительная фиксация, миграция, аудит безопасности)
- Требование явного вызова (критическое ограничение)
