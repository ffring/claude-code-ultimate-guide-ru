## Краткое содержание

**nao** — это платформа с открытым исходным кодом для создания и развертывания аналитических агентов с двухэтапной архитектурой: создайте контекст агента с помощью инструментов CLI, а затем разверните пользовательский интерфейс чата, чтобы конечные пользователи могли запрашивать данные в диалоговом режиме.

**Основные характеристики**:
- Конструктор контекста, поддерживающий гибкую интеграцию данных, метаданных, документации и инструментов.
- Независимость от базы данных (PostgreSQL, BigQuery, Snowflake, Databricks)
- Встроенная среда оценки с возможностями модульного тестирования.
- Самостоятельное развертывание с контейнеризацией Docker
- Встроенная визуализация данных в интерфейсе чата
- Технический стек: Fastify, Drizzle ORM, tRPC, React, Shadcn UI (TypeScript 58,9%, Python 38,5%)

## Результаты технического задания

Агент технического писателя выявил несколько ошибок в первоначальной оценке:

### Пропущенные баллы при первоначальной оценке

1. **Транспонируемая архитектура агента**: шаблон NAO `context builder`, применимый к агентам Claude Code
2. **Система оценки = критический пробел**: В руководстве НЕТ упоминания об оценке агента (метрики, тестирование, обратная связь)
3. **Шаблоны контекста базы данных**: Шаблоны для внедрения контекста из баз данных не документированы.

### Обоснование оценки

**Коррекция**: 2/5 → **3/5** (Умеренный)

**Аргументы в пользу 3/5**:
- Модели мобильной архитектуры (+1)
- Система оценки устраняет выявленные пробелы (+1)
- Используемые шаблоны контекста базы данных (+0,5)
- Открытый исходный код, хорошо документированный (+0,5)

### Необходимо устранить пробел «Оценка агента».

**YES, в руководстве ДОЛЖЕН быть этот раздел**, потому что:
- Разработчики создают агентов, не зная, как измерить качество
- В документах Anthropic упоминаются оценки, но не в контексте Claude Code.
- nao доказывает, что это осуществимо и полезно (готово к производству)

### Риски неинтеграции

1. **Разрыв в оценке остается недокументированным** → Разработчики не знают, как измерить качество агента
2. **Шаблоны контекста базы данных недокументированы** → Разработчики заново изобретают уже проверенные шаблоны
3. **Утрата доверия** → Если оценка станет стандартной, руководство будет отставать

### Почему первоначальная оценка была предвзятой

1. **Путаница между сферой применения и релевантностью**: Разная сфера применения ≠ не имеет значения
2. **Сосредоточьтесь на конечном продукте**: оценено nao как *конкурирующий продукт*, а не *Источник образца*
3. **Недооценка пробелов**: Оценка агента = критический пробел, ранее не выявленный
4. **Преждевременный отказ**: «Не интегрироваться», несмотря на обнаружение двух основных пробелов

**Урок**: Оцените ресурсы для *мобильные выкройки*, а не только прямая интеграция.
