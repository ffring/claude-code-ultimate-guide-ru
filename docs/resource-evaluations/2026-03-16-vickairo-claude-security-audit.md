## Управляющее резюме

Однофайловая косая черта `/security-audit` для Claude Code, которая запускает 16-секционный аудит веб-приложения, сопоставленный OWASP, с оценкой /10. Репо существует 18 дней. В руководстве уже есть полный охват OWASP через агент `security-audit.md`, `security-check.md`, `security-auditor.md` и `security-hardening.md` размером 41 КБ. Два шаблона в этом ресурсе действительно лучше того, что есть у нас: шаг контекста среды (dev/staging/prod) перед аудитом и проверка фактов против ложноположительных результатов перед сообщением о секретах (перед тем, как выдать результат, выполняется реальная история git). Одна область представляет собой настоящий пробел: аудит логики paywall/billing. Все остальное перекрывается.

- **16 разделов аудита** с OWASP Top 10 (2021) + идентификаторы CWE: заголовки HTTP, аутентификация, CSRF, открытое перенаправление, внедрение (SQL/XSS/command), управление IDOR/access, секреты и криптография, paywall/billing, уязвимые депс (npm аудит + pip-audit), CORS, files/config, WebSocket, SSRF, logging/monitoring, целостность данных, целостность программного обеспечения
- **Предварительный шаг с учетом контекста**: запрашивает dev/staging/prod перед запуском — позволяет избежать ложных срабатываний флагов отладки, конфигураций CORS `*` и HTTP, которые являются нормальными для локальной разработки.
- **Требование фактической проверки**: прежде чем сообщать о какой-либо секретной информации, запускает `git log --all -p -- '*.env'` и проверяет `.gitignore` — никаких результатов без конкретных доказательств
- **Scoring /10** со структурированной таблицей серьезности (CRITIQUE → HAUTE → MOYENNE → BASSE), файл: строка и рекомендуемое исправление с помощью кода.
- **Отказ от ответственности**: отчет содержит явное напоминание о том, что перед любыми действиями он должен быть проверен человеком.

## Решение

**Score: 2/5 — Не интегрирован с внешним ресурсом**

**Действие: автоматическое извлечение двух шаблонов в существующие команды**

1. Добавьте предварительный шаг контекста среды в `examples/commands/security-audit.md` (спросите dev/staging/prod перед этапом 1).
2. Усилить требования по борьбе с ложными срабатываниями на этапе 2 (мандат `git log --all -p` перед сообщением секретной информации)
3. Добавьте раздел аудита Paywall/Billing в `examples/agents/security-auditor.md`.
4. Повторно посетите репозиторий через 3 месяца, если он достигнет 200+ звезд с активным issues/PRs.

**Нет упоминания в руководстве.** Ресурс не соответствует порогу для ссылки сообщества, учитывая его возраст, минимальный профиль автора и отсутствие официального файла ЛИЦЕНЗИИ. В руководстве уже есть более широкий охват безопасности по нескольким направлениям (специфичные для Claude Code угрозы, защита от перехвата, оперативное внедрение). Извлекать полезные шаблоны внутри себя проще, чем отправлять читателей в незрелый репозиторий.

**Confidence**: Высокий — полный командный файл проверен, все утверждения проверены на соответствие источнику.
