## Что это такое

Semble — это инструмент семантического поиска на основе Python со встроенным сервером Claude Code MCP. Он выполняет поиск по коду, документации и файлам конфигурации в репозитории. При первом запуске он создает локальный индекс, используя встраивания Model2Vec плюс рейтинг BM25, объединенный с RRF (Reciprocal Rank Fusion). Последующие поиски попали в кэшированный индекс.

Ключевые факты, проверенные по репо:

| Атрибут | Подробности |
|-----------|---------|
| **Звезды** | ~5000 (сейчас 5718 по состоянию на 28 июля 2026 г., MIT, активная разработка) |
| **Установить** | `pip install semble`, затем `semble mcp` |
| Интеграция **MCP** | Собственный сервер, без слоя оболочки |
| **Требуется Оллама** | Нет. Model2Vec работает только с процессором, без внешнего сервиса. |
| **Индекс** | Создается при первом запуске, кэшируется автоматически. НЕ без индексирования (исправляя распространенное заблуждение в сообщениях сообщества). |
| **Объем** | Код + документация + файлы конфигурации |
| **Заявленная экономия** | Заявление поставщика из описания репозитория (MinishLab/semble, прочтено 30 сентября 2026 г.): «Использует на 99% меньше токенов, чем grep+read». Знаменатель: рабочий процесс grep + чтение файла. Независимые измерения здесь не проводились. |

## Semble требует индекса и может разделять кэши рабочих деревьев.

В первоначальной оценке было отклонено описание «без индекса, следовательно, совместимое с рабочими деревьями». Предположение об отсутствии индексов неверно: Semble строит и кэширует индексы. Вывод о том, что индексирование делает его несовместимым с рабочими деревьями, также оказался неверным.

Текущая реализация кэша [](https://github.com/MinishLab/semble/blob/0e5e02832ae0340c0feb637d2b7213fe065571fd/src/semble/cache.py) хэширует разрешенный путь каждого локального проекта, а затем выбирает индекс в каталоге кэша этого проекта. Поэтому отдельные каталоги рабочего дерева выбирают отдельные кэши, даже если местоположение родительского кэша является общим. Каждому каталогу необходима своя первоначальная сборка; это стоимость установки, а не несовместимость. Эта проверка источника устанавливает разделение на основе путей, а не проверку во время выполнения одновременной индексации или поиска в расходящихся рабочих деревьях.

Полезным отличием от документированной настройки grepai остается отсутствие службы Ollama, а не индекса. Здесь нет оснований утверждать, что большинству других индексаторов требуется один общий индекс для всех рабочих деревьев.

Никакое руководство не должно описывать Semble как неиндексируемый.

## Сравнение с документированными альтернативами

| Аспект | грепай | Сембл |
|--------|--------|--------|
| Семантический поиск | Да (Оллама + nomic-embed-text) | Да (Model2Vec, только для ЦП) |
| Интеграция MCP | С помощью инструментов MCP (grepai CLI переносится в MCP) | Родной сервер MCP |
| Требуется внешний сервис | Да (Оллама работает локально) | Нет |
| Поиск кода | Да | Да |
| Поиск документации | Нет (только код) | Да |
| Поиск конфигурации | Нет | Да |
| Звезды | N/A (инструмент CLI, не учитывается) | ~5,000 |
| Требуется индекс | Да | Да (кэшируется после первого запуска) |

**Настоящее отличие**: пользователи, которые не запускают Ollama локально, получают семантический поиск без какой-либо внешней зависимости. Более широкий объем (код + документация + конфигурация) является дополнительным преимуществом перед grepai.

## Проверка прецедента: отказ от qmd (оценка 2/5)

Руководство ранее отклонило qmd (Симона Руджеро) на том основании, что «с Grepai избыточно, утверждения не поддаются проверке». Применима ли та же логика к Semble?

Ключевые отличия:
- **Traction**: qmd получил незначительное признание в сообществе. У Сембла около 5 тысяч звезд.
- **Проверяемость утверждений**: утверждения qmd не поддавались проверке. Semble — это открытый исходный код с тестируемым конвейером индексирования.
- **Модель зависимостей**: qmd — это инструмент CLI, напрямую перекрывающий grepai. Semble решает проблему зависимости Ollama, от которой страдают примерно 40% пользователей CC (тех, у кого нет локального графического процессора или кто предпочитает не использовать Ollama).
- **Scope**: qmd искал только код, так же, как и grepai. Semble добавляет документацию и конфигурацию.

Прецедент qmd требует осторожности, а не отказа. Сембл устраняет конкретные возражения, которые вызвали сомнение в qmd.

## Оценка вызова

**Позиция агента по вызову**: Оценка должна упасть до 2/5, потому что «два инструмента семантического поиска на основе индексов в одном разделе создают избыточность и путаницу читателя».

**Контр-аргумент**: В руководстве уже документированы несколько инструментов с перекрывающимися возможностями во многих разделах (несколько серверов MCP, несколько инструментов сжатия). Политика заключается в документировании инструментов, которые обслуживают существенно разные аудитории или стеки зависимостей. Пользователь, который не может или не хочет запускать Ollama, сегодня не имеет пути к семантическому поиску в руководстве. Сембл – это тот путь. Запись должна быть краткой и явно позиционироваться как «если вы не используете Ollama», а не как замена grepai.

**Скорость сохраняется: 3/5.** Заявка должна позиционироваться как дополнение, а не как конкурент.
