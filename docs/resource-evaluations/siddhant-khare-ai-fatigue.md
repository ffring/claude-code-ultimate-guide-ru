## Краткое содержание

Харе утверждает, что инструменты искусственного интеллекта создают парадокс производительности: более быстрое выполнение задач не снижает рабочую нагрузку, а расширяет ожидания. В статье определяются пять источников истощения, связанного с ИИ:

1. **Парадокс продуктивности**: каждая задача занимает меньше времени → вы выполняете БОЛЬШЕ задач, а не меньше
2. **Creator → смена рецензента**: просмотр кода ИИ истощает когнитивные способности, а не заряжает творчество
3. **Стресс, связанный с недетерминизмом**: одинаковые подсказки → разные результаты вызывают постоянную тревогу
4. Беговая дорожка **FOMO**: распространение инструментов (CrewAI, AutoGen, LangGraph) требует постоянной оценки
5. **Атрофия мышления**: передача первоначального решения проблем на аутсорсинг ухудшает способности к рассуждению

**Предлагаемые решения:**
- Сеансы тайм-бокса (лимит 30 минут, максимум 3 попытки)
- Отделение времени обдумывания от времени выполнения (разделение morning/afternoon)
- Примите порог качества 70 % (против перфекционизма)
- Внедрение стратегических инструментов (не реактивное)
- Целенаправленный анализ кода (только критические области)

**Основные аргументы технического писателя:**
- Перекрытие контента на 90 % (парадокс продуктивности, нагрузка на проверку, атрофия навыков уже рассмотрены)

- Анекдоты в блогах и рецензируемые исследования гидов ослабляют доверие
- «Качество 70% нормально» противоречит протоколу UVAL руководства «100% понимание».
- Беговая дорожка FOMO (переключение инструментов) выходит за рамки руководства с одним инструментом

**Контраргументы для 3/5:**
- Стресс недетерминизма (выходная дисперсия) явно недооценен
- Таймбокс сессии (30 минут) отличается от еженедельного сплита 70/30
- Явная формулировка «усталость ИИ» помогает распознавать симптомы
- Ограничение в 3 попытки — действенная тактика, в настоящее время отсутствует

**Риски неинтеграции:** Минимальные. Пользователи, испытывающие усталость от искусственного интеллекта, найдут решения коренных причин в существующих шаблонах зависимостей, протоколе UVAL и разделенных разделах 70/30.

**Что добавлено:**

```markdown
| Prolonged sessions without breaks | **Session fatigue** — identical prompts yield varying outputs, causing anxiety | Time-box sessions: 30 min limit, max 3 attempts before manual implementation |
```

**Обоснование:** Самый доступный диагностический инструмент, самая действенная тактика

### Приоритет 2: Реальность продуктивности (строка 115)

**Что добавлено:**

```markdown
**AI-specific stress factor**: Nondeterministic outputs (identical prompts → varying results) create cognitive anxiety distinct from traditional debugging. This variability can trigger "AI fatigue" — mental exhaustion from unpredictable tool behavior that compounds over extended sessions. Mitigation: Time-box sessions (30 min max), limit retry attempts (3 max before reverting to manual implementation), and recognize when tool unpredictability signals a need for context reset (`/clear`) or manual problem-solving.
```

**Обоснование:** Рассматривает усталость как издержки производительности, устраняет пробел в недетерминированности

### Приоритет 3: протокол UVAL (строка 247).

**Что добавлено:**

```markdown
#### Step 2.5: Recognize Fatigue Signals (30 sec)

Before moving forward, pause and assess your cognitive state:

- **Session duration**: Been working >30 min? → Take a 5-min break, consider `/clear` to reset context
- **Retry count**: Tried the same prompt 3+ times with inconsistent results? → Switch to manual implementation
- **Frustration level**: Feeling anxious about unpredictable AI responses? → This is "AI fatigue" (nondeterminism stress), not your fault — it's the tool's inherent variability

This checkpoint prevents compounding exhaustion from extended sessions with diminishing returns.
```

**Обоснование:** Формирует проактивную привычку, интегрируется в существующую методологию
