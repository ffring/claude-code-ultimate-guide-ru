**Дата**: 17.03.2026
**Evaluator**: Claude (автоматически через /eval-resource)
**Status**: Список наблюдения — повторная оценка при 50+ звездах или отчет о проверке macOS

---

## 📄 Краткое содержание

- Панель управления **TUI** (Rust + Ratatui) для мониторинга нескольких агентов Claude Code, параллельно работающих в рабочих деревьях git.
- **Одна дорожка для плавания на каждого агента**: сначала репозиторий потенциальных клиентов, затем каждое рабочее дерево — отсортированное и визуально разделенное
- **Live-статус, передаваемый из файлов сеанса JSONL** (`~/.claude/projects/`): Работает/Ожидает вас/Неактивен/Готово/Ошибка
- **Отслеживание субагентов**: агенты, созданные с помощью инструмента «Задачи», отображаются как вложенные карточки в родительской полосе (заявление не проверено — см. раздел «Проверка фактов»).
- **Docker Видимость стека для каждого рабочего дерева.**: сопоставление стеков Compose через `COMPOSE_PROJECT_NAME` в `docker/.env`, показывает процент использования ЦП и памяти в реальном времени.

**Источник**: [github.com/oinant/claude-swarm-monitor](https://github.com/oinant/claude-swarm-monitor)
**Язык**: Ржавчина (≥ 1,80) | **Лицензия**: MIT | **Stars**: 10 (март 2026 г.) | **Платформа**: Linux протестирован; Windows/Docker Рабочий стол еще не поддерживается

## 🎯 Оценка: 3/5

| Счет | Значение |
|-------|---------|
| 5 | Существенный — серьезный пробел |
| 4 | Высокое значение — значительное улучшение |
| **3** | **Pertinent — Полезное дополнение** |
| 2 | Маргинальный — вторичная информация |
| 1 | Вне области действия |

**Justification**: claude-swarm-monitor заполняет два реальных пробела, не закрытых ни одним инструментом, включенным в настоящее время в руководство: (1) мониторинг с помощью собственных файлов сеансов JSONL, а не SSE/polling, и (2) видимость стека Docker для каждого рабочего дерева. Подход JSONL архитектурно отличается от чата агента (который предназначен для Gas Town/multiclaude). Однако при уровне 10 звезд (6 недель) и только Linux сигнал о принятии слишком слаб для рекомендации с высокой степенью достоверности. Оценка ограничена 3, ожидается проверка сообщества.

5. Измеряйте нагрузку на ресурсы с помощью более 10 рабочих деревьев и опросов Docker в режиме реального времени.

## 🔥 Челлендж (агент технического писателя)

Агент по вызову снизил первоначальную предложенную оценку с 4 до 3, сославшись на:

- **Сигнал принятия самый слабый в разделе экосистемы**: 10 звезд против мультиклауда (383+), Руфло (18,9к); даже Athena Flow (с явной пометкой «пока не рекомендуется») имеет больше внешних проверок
- Ограничение только **Linux является реальным ограничением** для целевой аудитории (многоагентные пользователи с большим количеством macOS)
- **Область безопасности не адресована**: инструмент считывает `~/.claude/projects/`, который содержит полную историю сеанса, включая конфиденциальный контекст, что соответствует шаблону руководства по маркировке области доступа к данным (см. записи Straude, Packmind).
- **Заявление субагента об отслеживании не проверено**: создание инструментов задач является внутренним по отношению к процессу Claude Code; неясно, пишут ли они отдельные файлы JSONL

- **Скорректированный балл**: 3/5 (из предложенного 4/5) — согласовано
- **Пропущенные баллы**: потребление ресурсов (накладные расходы на опрос), последствия для безопасности, пробел в поддержке macOS, проверка отслеживания субагента
- **Риск неинтеграции**: Низкий — агентский чат уже охватывает мониторинг; углы JSONL/Docker привлекательны, но служат узкому расширенному подмножеству
