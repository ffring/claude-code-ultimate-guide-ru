## 5. Техническое задание (от агента технического писателя)

### Проблемные вопросы

**Q1**: "Забейте 2/5 в высоком наборе для пост-де-де-3 линии без техники. Почему 1/5 не забил?"

**A1**: Различие между значением **signal** и значением **contenu**:
- **Contenu**: 1/5 (квазинуль)
- **Signal**: 3/5 (подтверждение того, что функция открыта для сообщества)
- **Score global**: 2/5 (много раздумий, с предвзятостью к содержанию)

Оценка 2/5 — это общий результат. Аргумент для 1/5 будет действительным.

**Q2**: «В сообщении упоминается недокументированная функция. Не достаточно ли этого для обоснования интеграции?»

**A2**: **Non**. Séparer deux выбирает:
1. **Feature `/insights`** → Важно, DOIT находится в документации
2. **Ce post LinkedIn** → Приложение для документирования

Процитируйте сообщение из 3 линий, как источник в руководстве из 11 тысяч линий, которое снижает доверие к гиду. А-ля место:
- Documenter `/insights` en se basant sur le deep Dive de Zolkos (надежная исходная техника)
- Проверка в официальном CHANGELOG Claude Code для ознакомительной версии
- Возможно упоминание в сообщении «открытие сообщества» в сноске, но чаще в качестве основного источника.

**Q3**: "Какие риски НЕ ПАС интегрированы в этот пост?"

**A3**: **Абсолютно рискованный**, вот что:
- Le vrai risque est de ne pas documenter `/insights` du tout
- Mais on peut (et doit) documenter `/insights` sans citer ce post
- Методы источников подтверждают существующие (глубокое погружение Золкоса)
- Не интегрировать анекдотический пост ≠ игнорировать функцию

**Q4**: "В руководстве упоминаются другие ресурсы сообщества с оценками 2-3/5.. Pourquoi Celle-ci Serait Différente?"

### Решение: **НЕ ИНТЕГРИРОВАТЬ** ❌

**Rationale**:
1. **Техника содержания, которую можно использовать** - Le post ne documente rien
2. **Источник альтернативного надежного существования** - глубокое погружение Zolkos в весь необходимый контент
3. **Dilution de crédibilité** - Цитата из сообщений 3-х линий, связанных с руководством
4. **Важная функция ≠ Опубликовать важное** - Documenter `/insights` без цитирования этого сообщения
