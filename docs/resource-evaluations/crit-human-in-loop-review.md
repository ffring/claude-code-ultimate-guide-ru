## 1. Краткое содержание

`crit` — это локальный интерфейс проверки, предназначенный для взаимодействия между разработчиком и агентом ИИ. Он предоставляет адаптивный пользовательский интерфейс для просмотра результатов, созданных искусственным интеллектом, в четырех режимах:

- Файлы **Markdown/plan**: визуализируются со встроенными комментариями в виде строки или диапазона перед выполнением агента.
- **Git diffs**: представление Split/unified с циклическим сравнением (дельта между итерациями агента, а не только фиксациями)
- **Live веб-приложения**: проксирует работающий локальный сервер и внедряет наложение с привязкой к DOM для пространственных комментариев, сопоставленных с исходным кодом.
- **Static HTML**: прямой рендеринг с той же системой наложения.

Цикл: агент выдает выходные данные → разработчик открывает критику → оставляет встроенные комментарии → агент читает эти комментарии → критика показывает, что изменилось от раунда к раунду.

**Основные особенности**:
- Живые потоки (непрерывный диалог, привязанный к определенной строке, а не одиночный разговор)
- `crit comment src/file.go:42 'message'`: программный CLI, позволяющий агентам вставлять свои собственные заметки.
- `POST /api/agent/request`: конечная точка HTTP, позволяющая агентам отправлять запросы на проверку человеку.
- GitHub PR двунаправленная синхронизация (комментарии read/write PR через `gh` CLI)
- `crit install claude-code`: первоклассная интеграция с Claude Code (записывает фрагменты конфигурации проекта)
- URL-адреса общего доступа для асинхронного просмотра для удаленного сотрудничества.

**Технический стек**: серверная часть Go 1.26+, внешний интерфейс JS/TS, встроенный в двоичный код. Ни базы данных, ни облака, ни телеметрии.

- Прямая интеграция Claude Code (`crit install claude-code` — документированная первоклассная команда)
- Заполняет настоящий пробел: ни один из существующих инструментов не показывает межраундовые различия в сеансе ИИ.
- Пространственные комментарии, привязанные к DOM, для действующих веб-приложений, не имеющие аналогов в стандартных инструментах PR.
- Активное обслуживание: 477 звезд, версия 0.16.2 выпущена 9 июня 2026 г., всего 665 коммитов.
- Лицензия MIT, без телеметрии, без зависимости от облака
- CLAUDE.md в репозитории является символической ссылкой на AGENTS.md, что означает, что сопровождающий понимает соглашения Claude Code.
- Устраняет проблему, которая проявляется в сеансах Claude Code: «как мне предоставить структурированную обратную связь по плану до того, как Claude его выполнит?»

**Почему 4/5, а не 5/5**:
- Один сопровождающий (коэффициент шины), степень участия неясна
- Режим `live` явно помечен как «требуется обратная связь», еще не стабилен.
- Требования к сборке Go 1.26+ (могут возникнуть проблемы со сборкой из исходного кода)
- В README нет видимого набора тестов.
- Документация функциональна, но скудна (нет специального сайта с документацией)

## 3. Технический анализ

### Межраундовая разница: уникальная ценность

Стандартные инструменты сравнения (GitHub PR, `git diff`, IDE diffs) показывают разницу между коммитами или ветвями. `crit` показывает разницу между итерациями агента в рамках одного сеанса проверки. Такой конкретной возможности нет ни в одном другом инструменте, кроме ручного создания закладок.

В частности, для пользователей Claude Code: когда вы запускаете Claude несколько раз для выполнения одной и той же задачи и хотите понять, «что изменилось со второй попытки к третьей попытке?», `crit` дает структурированный ответ.

### Проверка плана перед выполнением

Режим уценки позволяет просмотреть `plan.md` или аналогичные файлы непосредственно перед тем, как агент продолжит работу. Без `crit` для этого потребуется вручную открыть файл и передать отзыв через командную строку. В `crit` комментарии прикрепляются к конкретным строкам и могут быть прочитаны агентом через комментарий CLI API.

### GitHub PR-синхронизация

`crit` может читать и писать комментарии к обзору PR GitHub в двустороннем порядке через `gh` CLI. Это замыкает цикл: Claude Code открывает PR, рецензент оставляет встроенные комментарии в `crit`, эти комментарии синхронизируются с PR, Claude Code читает их через контекст PR.

## 5. Установка

```bash
# Homebrew (macOS/Linux)
brew install crit

# Go
go install github.com/tomasz-tomczyk/crit@latest

# Binary, Nix, Docker also available
```

**Основное использование**:
```bash
crit                          # Auto-detects uncommitted changes in repo
crit plan.md                  # Review a specific file before agent executes
crit http://localhost:3000    # Proxy and review a running web app
crit landing.html             # Review static HTML with spatial comments

# Claude Code integration setup
crit install claude-code      # Writes config snippets into the project
```

## 6. Актуальность для пользователей Claude Code.

**Прямое и явное**. Инструмент создан для этого рабочего процесса:

- `crit install claude-code` настраивает его для сеансов Claude Code «из коробки».
- HTTP API (`/api/agent/request`) предназначен для Claude Code в качестве принимающего агента.
- Межраундовые различия напрямую связаны с тем, как Claude Code выполняет одну и ту же задачу при нескольких запусках.
- Синхронизация PR устраняет разрыв между PR, открытым Claude Code, и структурированной человеческой проверкой.

Для читателей руководства: `crit` устраняет проблему, возникающую в многоитерациях сеансов Claude Code. Текущее руководство охватывает шаблоны проверки плана и обратной связи, но не содержит рекомендаций по инструментам для структурированного встроенного анализа с циклическим сравнением. Это восполняет этот пробел.

## 7. Красные флаги

Никаких серьезных проблем. Незначительные примечания:

- **Один сопровождающий**: Активен и заинтересован, но коэффициент шины реален и имеет 477 звезд.
- **Перейдите на версию 1.26+ для сборки из исходного кода.**: установка Homebrew/binary не затрагивается; пользователи, использующие сборку из исходного кода, могут столкнуться с этим
- **Live-режим нестабилен.**: в проблеме №557 явно указано, что она требует обратной связи от сообщества.
- **Одна открытая ошибка**: `@` в именах файлов (#656, 2 недели назад, неразрешенная, но область действия ограничена)
- **В README**не виден набор тестов: ни значок CI, ни тестовая команда не задокументированы.
- **`agent_cmd` доступен только глобально.**: преднамеренное решение по безопасности (предотвращает захват вредоносными репозиториями вашего агента), но ограничивает настройку агента для каждого проекта.

Никаких проблем с безопасностью. Никакой телеметрии. Никаких проблем с цепочкой поставок не видно.

## 8. Интеграционное решение

**INTEGRATE** и оценка **4/5**: упоминание в руководстве в разделе «Человек в цикле и инструменты проверки».

**Куда интегрировать**:
- Раздел, посвященный агентским рабочим процессам и моделям человеческого надзора (раздел руководства по итерации и проверке)
- Раздел экосистемы сторонних инструментов
- Потенциально: выноска в разделах рабочего процесса проверки мультиагентов/планов.

**Format**: Краткое упоминание со ссылкой и описанием того, что он решает уникальным образом (последовательные различия, проверка плана перед выполнением, веб-обзор с привязкой к DOM). Нет необходимости документировать полный набор функций, просто дайте ссылку на репозиторий GitHub. Однострочник: «структурированный встроенный интерфейс обзора между вами и Claude Code, с пошаговыми различиями между итерациями».

**Не является приоритетом над основной работой руководства**, но является чистым дополнением во время следующего прохождения сторонних инструментов.
