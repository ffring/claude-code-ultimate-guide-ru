## Краткое содержание

Мнение о влиянии искусственного интеллекта на практику разработки программного обеспечения в 2026 году, основанное на интервью с 7 французскими технологическими компаниями (Doctolib, Malt, Alan, Google Cloud, Brevo, ManoMano, Ilek, Clever Cloud).

**Основные аргументы**:
1. **Context Engineering** (фреймворк Thinkworks) — переход к полным спецификациям с ограничениями перед кодированием.
2. **Spec/Plan/Act Стандартизация рабочего процесса**: отраслевой консенсус по трехэтапному подходу
3. **Корпоративное управление ИИ**: организационные рынки для объединения навыков, агентов и правил ИИ
4. **QA через CI/CD**: традиционные методы (линтинг, тестирование, проверка), необходимые для проверки кода, сгенерированного ИИ.
5. Нарушение **HR**: обучение младших специалистов, набор персонала, карьерные траектории требуют реструктуризации

**Статистика, приведенная**:
- Ежемесячные затраты: ~$20/dev (внедрение), ~$200/dev (сильное внедрение), $200-1000+/dev (расширенный мультиагентный режим).
- Более 90 % инженеров компании Alan ежедневно используют помощников по программированию на базе искусственного интеллекта.
- Интервью: 7 компаний (подробные стенограммы не предоставлены)

## Извлеченные уроки

### Улучшения процесса оценки

1. **Проверка терминологии**: Всегда сверяйте названия фреймворков с авторитетными источниками (Perplexity, официальная документация).
2. **Строгость анализа пробелов**: проверьте существующее руководство, прежде чем заявлять об «отсутствующем контенте».
3. **Проверка статистики**: Требуйте документацию по методологии, а не только цифры
4. **Задание для технических писателей**: Оказались ценными — обнаружена переоценка новизны

### Что сработало

1. **Протокол проверки фактов**: Обнаружена терминологическая ошибка на раннем этапе
2. **Агентский вызов**: агент технического писателя провел жестокую, но точную проверку реальности
3. **Минимальная интеграция**: 10-минутные сноски вместо 2-часового полного раздела = более высокая рентабельность инвестиций
