## Вердикт

В руководстве не было проработанного примера большой миграции с Claude Code. Этот пост один: механический порт Zig-to-Rust из 535 496 строк в 1448 файлов за 11 дней, с прорисовкой рабочего процесса, фальстартами и полученными правилами, записанными оператором. Переносимая часть — это структура (сначала свод правил, пилотный проект с тремя файлами, оракул вне изменений, два состязательных рецензента, неудачи, превращающиеся в правила), которые объединяет руководство.

Оценка останавливается на 4/5.. Это самоотчет человека, который лучше всех знает кодовую базу, контролируемый им на протяжении большей части прогона, о наиболее выгодной форме миграции для агентов: сохраняющей поведение, против набора тестов, который не зависит от языка реализации. Он не публикует уровень дефектов после выпуска.

| Элемент | Причина |

| «Около 1300 строк кода в минуту» на пике | Показатель пропускной способности, не имеющий качественного аналога; не добавляет ничего, на что читатель мог бы воздействовать |
| Вторичные претензии (прирост производительности, двоичный размер) из сторонних отзывов. | Не о рабочем процессе агента |

## Испытание

**Возражение**: один исключительный инженер с исключительным набором тестов — это не эталонная архитектура. **Ответ**: согласен, и в гайде так написано. Интеграция сочетает этот случай с SWE Refactor Bench, где переписывание языка было самой слабой категорией, и утверждает, что результат не передается без эквивалентного оракула. То, что делает перенос, легко скопировать в любом масштабе: сначала напишите свод правил, пилотируйте три модуля, оставьте тесты вне изменений и превратите каждый фальстарт в правило.
