# Оценка: Worktrunk (worktrunk.dev)

**Date:** 25 января 2026 г. (обновлено после глубокого анализа)
**Оценщик:** Claude (Sonnet 4.5)
**Статус:** ⚠️ Условно рекомендуется (см. обновленное заключение)

## 📄 Резюме содержания

- **Worktrunk** - это CLI Rust для упрощения работы с рабочими деревьями git, созданный на максимум шестьдесят (создатель PRQL, 10 тысяч звезд)
- Переведите синтаксис `git worktree add -b feat ../repo.feat && cd ../repo.feat` в `wt switch -c feat`.
- 3 ядра команд: `switch`, `remove`, `list` + перехваты персонализируемых + сообщения фиксации LLM
- **GitHub: 1,6 тыс. звезд (6 103 или 28/07/2026), 54 форка, 15 участников, версия 0.18.2 (январь 2026 г.), 64 активных релиза**
- Спецификации для рабочих процессов с несколькими агентами IA (Claude Code упоминается в README)

**Пересмотренное обоснование:**

**Сохраняются баллы за первоначальную оценку:**
- Полное руководство по созданию рабочих деревьев git (раздел 9.17, команда `/git-worktree`)
- Worktrunk — это оболочка, имеющая фундаментальную функцию

**Новые открытия, которые увеличивают счет:**
1. **Подтверждено**: Несколько независимых устройств для создания оберток:
   - инцидент.io → пользовательская оболочка Bash `w` (официальное сообщение в блоге)
   - Выпуск № 1052 → Функции рыбной раковины завершены.
   - Worktrunk → Решение Rust для зрелой версии (1,6 тыс. звезд)
2. **Уникальные особенности, отсутствующие в git vanilla:**
   - Хуки автоматизации заливки на уровне проекта
   - Сообщения о фиксации на основе LLM через инструмент `llm`
   - Интегрированное отслеживание статуса CI
   - Генерация PR-ссылок
   - Настраиваемые шаблоны путей
3. **Значительное принятие**: 1,6 тыс. звезд + 64 релиза + мультиплатформенность (Homebrew, Cargo, Winget, AUR)
4. **Действительный шаблон**: Концепция «рабочего дерева-оболочки» заново изобретена независимо от дополнительных устройств для профессионалов.

### Источник 4: GitHub, проблема № 1052 (репозиторий клауд-кода).

**Découvertes:**
- ❌ **N'utilise PAS Worktrunk** - рабочий процесс Custom Fish Shell
- ✅ Завершение рабочего процесса **Pattern** с 8 функциями git custom:
  - `git worktree-llm` → создать + запустить Claude
  - `git worktree-merge` → завершить + перебазировать + объединить
  - `git commit-llm` → Коммиты, сгенерированные LLM
  - `git llm-message` → структурированный diff → фиксация через LLM
- ✅ **Статус проблемы**: ЗАКРЫТО как `NOT_PLANNED` (обмен документами, а не запрос функции)

**Шаблон рабочего процесса:**
```bash
git worktree-llm feature-name    # Start feature
# ... work with Claude ...
git worktree-merge                # Finish, commit, rebase, merge
```
