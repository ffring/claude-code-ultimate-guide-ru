## Что такое ClaudeKit

ClaudeKit — это npm-оболочка Claude Code, которая:
- Предоставляет 32 готовых шаблона субагентов.
- Реализует управление контрольными точками через git stash.
- Добавляет перехватчики конвейера проверки (typecheck, lint, test).
- Реализует защиту файлов через `.agentignore`.
- Добавляет команды разработки на основе спецификаций.
- Предоставляет DSL карты кодовой базы для внедрения статического контекста.
- Включает ловушку «уровня мышления» (ключевые слова megathink/ultrathink).

**Основная идея**: автоматизация общих шаблонов, которые Claude Code поддерживает, но не настраивает по умолчанию.

## Разбивка очков

### Точность: 4/5

**Что верно**:
- Git stash как механизм контрольной точки ✅
- Схемы хука PreToolUse/PostToolUse ✅
- Концепция защиты файлов ✅
- Концепция конвейера валидации ✅

**Что не так**:
- Перехватчик «уровня мышления» — **, фактически устаревший** начиная с Opus 4.5 (мышление всегда включено, ключевые слова косметические).
- Карта кодовой базы противоречит архитектуре Claude Code «Поиск без индексирования»

**Verdict**: В основном точные концепции, но есть 2 существенные ошибки.

### Глубина: 2/5

**Неглубокие участки**:
- 32 субагента острословят («Вы эксперт по Rust»)
- Никакого обсуждения режимов сбоя перехвата, производительности или крайних случаев.
- Нет объяснений, когда использовать контрольные точки и ветки.
- Нет руководства по асинхронному и синхронному перехвату

**Verdict**: Широта важнее глубины. Полезные шаблоны, но поверхностные объяснения.

### Практичность: 3/5

**Practical**:
- Рабочий процесс контрольной точки можно использовать сразу ✅
- Хуки — это функциональные шаблоны ✅
- npm install makes setup easy ✅

**Impractical**:
- Требуется глобальная установка npm (зависимость)
- Разрывы, если пакет заброшен или в нем есть критические изменения.
- Карта кодовой базы добавляет более 9 тысяч статического контекста (отходы токенов)

**Verdict**: хорош для быстрого прототипирования, рискован для долгосрочного использования.

### Уникальность: 2/5

**Не уникальный**:
- Хуки описаны в нашем руководстве (раздел 7).
- Субагенты описаны в Разделе 9.18.
- Разработка, основанная на спецификациях, находится в methodologies.md.

**Unique**:
- Автоматизированный контрольно-пропускной пункт по событию Stop (у нас такого не было)
- Единый файл-гард с обходом обнаружения (у нас были штуки, не унифицированные)
- Тестирование при изменении с интеллектуальным обнаружением (мы не автоматизировали это)

**Verdict**: 70 % совпадение с существующим руководством, 30 % новая автоматизация.

### Ремонтопригодность: 2/5

**Concerns**:
- Последняя активность: январь 2026 г. (последняя, ​​но замедляется?)
- Привязка уровня мышления уже устарела (показывает задержку в обслуживании)
- npm wrapper creates dependency on third-party package
- Критические изменения в Claude Code могут привести к поломке ClaudeKit.

**Verdict**: Риск обслуживания для долгосрочных проектов.

## Выявлены 3 пробела (действуемые)

### Недостаток 1: Рабочий процесс автоматической проверки ⭐ ВЫСОКИЙ ПРИОРИТЕТ

**Что делает ClaudeKit**:
- Остановить перехватчик, который автоматически создает git stash в конце сеанса
- Именование: `claude-checkpoint-{branch}-{timestamp}`
- Слэш-команды: `/checkpoint:create`, `/checkpoint:restore`, `/checkpoint:list`.

**Чего нам не хватало**:
- Шаблон хука для авто-чекпоинта
- Структурированный рабочий процесс: создать → экспериментировать → восстановить.
- Контрольная точка и руководство по ветвлению

**Принятые меры**:
- ✅ Создан `examples/hooks/bash/auto-checkpoint.sh`
- ✅ Добавлен раздел 2.4 «Шаблон контрольных точек» (~40 строк)
- ✅ Документировано, когда использовать контрольные точки и ветки.

**Impact**: обеспечивает безопасное экспериментирование без дополнительных затрат на ветки.

---

### Недостаток 2: Перехватчик конвейера проверки ⭐ СРЕДНИЙ ПРИОРИТЕТ

**Что делает ClaudeKit**:
- Отдельные перехватчики PostToolUse для проверки типов, проверки и тестирования.
- Запускается автоматически после каждого Edit/Write

**Чего нам не хватало**:
- Шаблон хука для `typecheck-on-save.sh`
- Шаблон хука для `test-on-change.sh` (с интеллектуальным обнаружением тестовых файлов)
- Шаблон для объединения шагов проверки

**Принятые меры**:
- ✅ Создан `examples/hooks/bash/typecheck-on-save.sh`
- ✅ Создан `examples/hooks/bash/test-on-change.sh`
- ✅ Добавлен раздел 7.5 «Шаблон конвейера проверки» (~80 строк).

**Impact**: Немедленная обратная связь для обеспечения качества кода без ручных тестовых запусков.

---

### Недостаток 3: унифицированная защита файлов ⭐ СРЕДНИЙ ПРИОРИТЕТ

**Что делает ClaudeKit**:
- Файл `.agentignore` с синтаксисом gitignore.
- 195 шаблонов по умолчанию
- Обнаружение расширения переменных Bash

**Чего нам не хватало**:
- Единая стратегия, сочетающая в себе разрешения.deny + перехваты + .agentignore
- Сложная система обнаружения обхода (расширение переменных, замена команд)
- Полный шаблон со всеми 3 слоями

**Принятые меры**:
- ✅ Создан `examples/hooks/bash/file-guard.sh`
- ✅ Добавлен раздел 7.4 «Стратегия защиты файлов» (~90 строк)
- ✅ Перекрестная ссылка security-hardening.md

**Impact**: Глубокая защита файлов с обнаружением обхода.

## Что мы игнорируем (намеренно)

| Функция ClaudeKit | Почему мы пропускаем |
|-------------------|-------------|
| Карта кодовой базы (внедрение DSL/tree) | Антишаблон для архитектуры Claude Code «Поиск без индексирования». Статический контекст 9K — это пустая трата токенов. |
| Инструмент миграции AGENTS.md | Уже описано в ai-ecosystem.md:1260. Достаточно простого `ln -s`. Инструменты npm являются излишними. |
| 32 готовых субагента | Мелкие остроты. Наши 6 шаблонов (раздел 9.18) более глубокие и педагогичные. |
| Oracle (интеграция GPT-5) | Выходит за рамки — мы документируем Claude Code, а не мосты к другим LLM. |
| STM (Мастер простых задач) | Claude Code изначально имеет TodoWrite/TaskCreate. STM — это резервный уровень. |
| Команда очистки от разработчиков | Тривиально — `find . -name "*.tmp" -delete` не нуждается в разделе. |
| npm install global | Мы документируем шаблоны, а не пакеты. Выдерживает отказ от инструмента. |

**Rationale**: Извлекайте шаблоны, игнорируйте детали реализации, связанные с конкретным пакетом.

## Рекомендация: выкройки не упаковываются.

**НЕ упоминайте ClaudeKit в руководстве**. Причины:

1. **Риск обслуживания**: пакет может стать заброшенным программным обеспечением (последнее действие: январь 2026 г.)
2. **Устаревшие функции**: хук на уровне мышления уже устарел (доказывает ненадежное обслуживание)
3. **Анти-шаблоны**: Карта кодовой базы противоречит архитектуре Claude Code
4. **Связывание зависимостей**: пакет npm создает хрупкую зависимость
5. **Мы стали лучше**: наша документация пережила прекращение поддержки пакетов

**Instead**: реализуйте 3 пробела как **оригинальный контент**, вдохновленный шаблонами (а не инструментом).
