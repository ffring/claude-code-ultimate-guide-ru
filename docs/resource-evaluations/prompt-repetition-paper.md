## 1. Краткое изложение результатов

### Основная претензия
Двукратное повторение запроса на ввод повышает точность для LLM **без режима рассуждения**, без увеличения длины вывода или задержки.

### Протестированные модели (прямо с бумаги)
- Gemini 2.0 Флэш/Флэш Лайт
- ГПТ-4о/ГПТ-4о-мини
- **Claude 3 Haiku**
- **Claude 3.7 Sonnet**
- Глубокий поиск V3

### Тесты
ARC (вызов), OpenBookQA, GSM8K, MMLU-Pro, MATH, NameIndex, MiddleMatch

### Ключевые результаты
| Метрика | Ценить |
|--------|-------|
| Победы (без рассуждений) | Комбинации эталонных моделей 47/70 |
| Потери | 0 |
| С CoT/reasoning | 5 побед, 1 поражение, 22 нейтральных результата |

### Специальные примечания для Claude (из бумаги)
- Протестировано на Claude 3 Haiku и Claude 3.7 Sonnet.
- **Увеличение задержки** наблюдается для моделей Claude при очень длинных запросах (повторение x3 или пользовательские тесты)
- Вероятно, из-за того, что этап предварительного заполнения занимает больше времени

## 2. Соответствие Claude Code

### Модельная ситуация (январь 2026 г.)

| Модель | Режим мышления | Применимо ли быстрое повторение? |
|-------|---------------|-------------------------------|
| Opus 4.5 | ВКЛ по умолчанию (максимальный бюджет) | НЕТ – мышление уже максимизирует рассуждения |
| Sonnet 4 | Нет в наличии | ДА - может принести пользу |
| Haiku 3.5 | Нет в наличии | ДА - может принести пользу |

### <a name="the-problem"></a>Проблема

Claude Code использует:
- **Sonnet по умолчанию** (85% использования по статистике руководства)
- **Haiku для простых задач** (оптимизация затрат)
- **Opus для сложных задач** (уже есть режим мышления)

Техника статьи специально предназначена для **non-reasoning** сценарии. Это делает его потенциально актуальным для Sonnet/Haiku в Claude Code.

### Улов

1. **Стоимость входных жетонов удваивается.**: повторяющееся приглашение = 2 входных жетона.
2. **Claude Code Контекст уже находится под давлением**: Руководство уделяет особое внимание управлению контекстом (практический предел 100 000)
3. **Масштаб усиления неясен**: В документе показано wins/losses, но не абсолютное улучшение в %
4. Проблема с задержкой, характерная для **Claude**: в бумажных заметках увеличена задержка для Claude при длинных подсказках.

## 4. Практические соображения по Claude Code

### Гипотетическая реализация хука

```bash
# pre-prompt-hook.sh (EXPERIMENTAL)
#!/bin/bash
# Double the prompt for Sonnet/Haiku
if [[ "$CLAUDE_MODEL" != "opus"* ]]; then
  echo "${1}

---
(Repeated for accuracy)
${1}"
else
  echo "$1"
fi
```

### Проблемы с этим подходом

1. **Нет доступа API для изменения подсказок в Claude Code** — перехватчики не могут перехватывать ввод пользователя
2. **Требуются изменения на уровне SDK** — функция не настраивается пользователем
3. **Удвоение стоимости** — удваивает входные жетоны, может компенсировать любой прирост точности.
4. **Раздувание контекста** — прямо противоречит принципам гигиены контекста руководства.

## 6. Рекомендация

### Оценка: 2/5 — НЕ ИНТЕГРИРОВАТЬ

### Обоснование

1. **Неправильная цель**: Техника нацелена на нерассуждающие LLM, но в сложных задачах Claude Code уже используется Opus (с мышлением). Простые задачи на Sonnet/Haiku не нуждаются в оптимизации точности — им нужна скорость.

2. **Не реализуется пользователем.**: пользователи не могут перехватывать свои собственные подсказки в Claude Code. Это потребует изменений SDK, а не документации.

3. **Нулевая проверка**: Никаких репликаций, никакого принятия сообществом, никаких отчетов об использовании в реальном мире через 5 недель.

4. **Запредельные затраты**: удвоение входных токенов противоречит акценту Claude Code на эффективности контекста и управлении затратами.

5. **Нишевое приложение**: Даже если оно действительно, оно помогает только в конкретных задачах в стиле эталонного тестирования (множественный выбор, математика), а не в задачах открытого кодирования, которые Claude Code обрабатывает.

### Что может изменить это

- Независимые репликации с Claude Sonnet 4
- Отчеты об внедрении в реальном мире от пользователей Claude Code
- Anthropic подтверждение или интеграция
- Доказательства того, что повышение точности в 2 раза превышает затраты на вводимые ресурсы

### Альтернативная рекомендация

Если пользователям нужна более высокая точность на Sonnet:
- Используйте **OpusPlan** (Opus для планирования, Sonnet для выполнения) — уже задокументировано.
- Переключитесь на Opus для принятия важных решений – уже задокументировано.
- Используйте структурированные подсказки (теги XML) — уже описано.

Это проверенные методы, описанные в руководстве, которые не удваивают затраты.
