# Оценка: диаграммы UML для кодовых баз ООП.

**Дата**: 25 января 2026 г.
**Источник**: LinkedIn Post - Денис Писковацков
**URL**: https://www.linkedin.com/posts/tigraff_uml-claude-wibecoding-activity-7420595633826258944-gGO5
**Score**: 3/5 (Соответствует - дополнительная утилита)

## Резюме

Предлагаемый шаблон: использование диаграмм архитектуры (UML/Mermaid) в качестве дополнительного контекста для комплексов ООП кодовых баз, в качестве компенсации ограничений LLM, а также обоснования полиморфности и зависимостей.

## Валидации

### ✅ Проблема с ООП подтверждена

**ACM 2024 Research**: [LLM все еще не могут избежать экземпляра](https://dl.acm.org/doi/10.1145/3639474.3640052)
- Подтвердите, что LLM сталкивается с трудностями с полиморфным обоснованием
- Разбиение фишек на структуры отношений (иерархии классов, реализации интерфейсов, межмодульные зависимости)

### ✅ MCP Инструменты проверены

**Archy MCP** (phxdev1, апрель 2025 г.):
- URL-адрес: https://www.pulsemcp.com/servers/phxdev1-archy
- Автоматическое создание Mermaid из репозиториев GitHub или текстовых описаний
- Поддержка: блок-схемы, диаграммы классов, диаграммы последовательности.

**Mermaid MCP** (hustcc):
- 61,4 тыс. пользователей
- Персональные темы, любимые темы, временные показы фильмов

**Blueprint MCP** (ArcadeAI):
- Описания текстур → техника диаграмм
- Использование асинхронных заданий

### ⚠️ Оригинальный источник не подлежит проверке.

**WibeCoding**: Упоминание в сообщении LinkedIn больше не встречается в публикации
**Contexte**: Шаблон отчета о проекте Java/Spring
**Limitation**: Недействительно в большой школе

## Интеграция

### Подходы к идентификации

| Подход | Обслуживание | Жетон Коута | Лучшая заливка |
|----------|-------------|------------|---------------|
| **Архи MCP** | Ноль (автогенерация) | По требованию | Репозитории GitHub с иерархиями классов |
| **Инлайн Mermaid** | Мануэль | 200-500 жетонов | Персональные архитектурные решения |
| **PlantUML ref** | Мануэль | Минимальный | Интеграция entreprise/IDE |

### Рекомендуемый рабочий процесс

1. **Эссесер Серены д'Аборд**: `get_symbols_overview` + `find_symbol` (нулевое обслуживание)
2. **Si insuffisant**: Использование **Archy MCP** для автоматического создания диаграмм классов
3. **Последующий возврат**: Mermaid встроенное вручную для личного пользования

### Cas d'usage

- Кодовые базы ООП >20 модулей с комплексным наследием
- Проекты Java/Spring с глубоким полиморфизмом
- Когда обзор символов Серены недостаточен

## Ключевое понимание

> «Структура контекста имеет большее значение, чем размер контекста» — отношения уточняют смысл LLM в ООП-архитектуре.

## Trade-offs

**Avantages**:
- ✅ Автоматическое создание инструментов MCP (без обслуживания с Archy)
- ✅ Академическая проверка проблем (ACM 2024)
- ✅ Доступна альтернативная Серена (без обслуживания)

**Limitations**:
- ⚠️ Оригинальный исходный код (WibeCoding) не опубликован.
- ⚠️ Выкройка не действительна в большой эшелле.
- ⚠️ Coût token pour inline Mermaid (200-500 токенов)
