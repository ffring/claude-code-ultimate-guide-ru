# Исполнительные агенты с искусственным интеллектом: виртуальные руководители и симуляторы советов директоров

> **Уверенность**: смешанная. OpenExecutive, Gstack и CrewAI соответствуют уровню 1/2 (проверено на соответствие исходным репозиториям, активная разработка). Большинство других проектов с открытым исходным кодом, перечисленных здесь, относятся к уровню 3 (от одной цифры до нескольких сотен звезд GitHub, ранняя стадия, проверка перед принятием). Коммерческие продукты цитируются на основе заявлений, опубликованных поставщиками и не прошедших независимую проверку.

**Время чтения**: ~12 мин.
**Предварительные требования**: [Многоагентная оркестровка](../workflows/README.md), [Переключение когнитивного режима (Gstack)](../workflows/gstack-workflow.md)
**Связанные**: Экосистема [AI](./ai-ecosystem.md), [Сторонние инструменты](./third-party-tools.md), [AI Роли](../roles/ai-roles.md)

## <a name="tldr"></a>ТЛ;ДР

Шаблон persona/agent, который пакеты навыков Claude Code используют для инженерных ролей (см. [Gstack](../workflows/gstack-workflow.md)), применяется к указанным должностям руководителей бизнеса: финансовый директор, директор по маркетингу, руководитель отдела кадров, главный юрисконсульт, главный операционный директор, совет директоров. [OpenExecutive](https://github.com/SenteLabsAI/OpenExecutive) — наиболее полный пример с открытым исходным кодом: 8 специализированных агентов Claude за одним последовательным «руководителем». У него есть сверстники, большинство из них маленькие и ранние. Почти ни один из этих проектов не претендует на юридическую или фидуциарную власть: вся категория позиционирует себя как дополнение, а не замена, независимо от того, насколько агрессивно читается маркетинговый текст.

```
Persona          →  a role definition layered on a general model (tone, scope, priorities)
Agent            →  a persona + tools + state + goal-directed multi-step behavior
AI executive     →  an agent explicitly named after a C-suite/board role, with enough
                     autonomy and persistence to be treated as a virtual team member
```

## <a name="gstack-is-not-this-category"></a>Gstack не из этой категории

Прежде чем идти дальше: [Gstack](../workflows/gstack-workflow.md) (Гарри Тан, 124,8 тыс.+ звезд) — это набор рабочих процессов для 6 навыков **по разработке программного обеспечения** (`/plan-ceo-review`, `/plan-eng-review`, `/review`, `/ship`, `/browse`, `/retro`). Имя команды `/plan-ceo-review` вызывает путаницу, но это шлюз продукта перед реализацией внутри сеанса кодирования, а не личность, имитирующая генерального директора для принятия бизнес-решений. Если вы пришли сюда в поисках Gstack из-за этого имени команды, вместо этого см. [Переключение когнитивного режима](../workflows/gstack-workflow.md). Что общего Gstack с проектами ниже, так это базовая архитектура: определения ролей + общий контекст + рабочие процессы слэш-команд внутри одного репозитория. Этот шаблон представляет собой сквозную линию этой страницы, примененную к другому домену.

## <a name="openexecutive-reference-architecture"></a>OpenExecutive: эталонная архитектура

[OpenExecutive](https://github.com/SenteLabsAI/OpenExecutive) (SenteLabsAI, Apache 2.0, 838 звезд по состоянию на 27 августа 2026 г.) — это наиболее явное сопоставление шаблона persona/agent со стандартным исполнительным комитетом. Восемь специализированных агентов Claude сидят за одним последовательным «руководителем», никогда не открывающимся индивидуально для пользователя:

```
User message
    ↓
Executive Orchestrator (claude-sonnet-4-6)
    ↓ tool use → parallel specialist calls
CSO / CFO / CHRO / GC / COO / CMO / CPO / Board Communications
    ↓ each specialist retrieves relevant context from ChromaDB
Built-in MBA knowledge + company documents
    ↓
Synthesized executive response
```

Стек: Python 3.11 + серверная часть FastAPI, Next.js 15 UI, ChromaDB для RAG (встроенная база знаний + загруженные документы компании, две отдельные коллекции), SQLite для эпизодической памяти (фоновый проход `claude-haiku-4-5` извлекает решения после каждого ответа), одноэкземплярный планировщик для упреждающих последующих действий и интеграция со Slack, электронной почтой, Telegram, Google Chat и Discord. `claude-opus-4-7` обрабатывает глубокие рассуждения для CSO/CFO/GC/Board; остальные по умолчанию — `claude-sonnet-4-6`. Он также работает на OpenRouter или локальных OpenAI-совместимых серверах (Ollama, LM Studio, vLLM) вместо Anthropic API.

Две вещи стоит отметить, а не принимать за чистую монету. Во-первых, слоган «Знания на уровне Гарвардского MBA» является маркетинговой копией, а не поддающимся проверке утверждением: база знаний представляет собой отслеживаемый git корпус Markdown, помещенный в ChromaDB, ее фактическая глубина здесь не проверяется. Во-вторых, README не документирует явных барьеров, отделяющих «это рекомендация» от «это решение», несмотря на то, что главный юрисконсульт и агенты по связям с советом директоров затрагивают правовую и управленческую территорию, где это различие имеет наибольшее значение. Что действительно надежно: кэширование подсказок правильно структурировано (личность, профиль компании и индекс знаний кэшируются отдельно, динамический контент RAG вводится в ход пользователя, а не кэшированное системное приглашение), и проект предоставляет настоящий шлюз оценки, 29 сценариев во всех 8 доменах, оцененных `claude-opus-4-7` как LLM-судья по 5 измерениям, с шлюзом CI, требующим среднего значения ≥3.5/5 и блокирующим любое падающее измерение. более 10% по сравнению с `main`.

## <a name="augmentation-not-replacement-so-far"></a>Увеличение, а не замена (пока)

Во всех рассмотренных здесь проектах маркетинговый язык варьируется от осторожного до агрессивного («штатный финансовый директор не требуется»), но ни один из них не претендует на юридическое лицо, фидуциарные обязанности или полномочия принимать окончательные решения. Ближе всего к теоретическому исключению является концепция **Synthetic Director**, предложенная юридической фирмой Stirling & Rose в 2023 году: система искусственного интеллекта, зарегистрированная регулирующим органом, получившая уникальный идентификатор и подвергнутая «проверке функциональной компетентности» на соответствие реальным директорским обязанностям (предотвращение неплатежеспособной торговли, соблюдение конституционных обязательств), с полномочиями приостанавливать или прекращать ее работу за отклоняющееся от нормы поведение. Сегодня такой основы не существует ни в одном законодательстве юрисдикции. Об этом стоит знать, потому что это единственная серьезная попытка определить, как бы вообще выглядела подотчетность, если бы одному из этих агентов когда-либо была предоставлена ​​реальная власть, а не потому, что какой-либо продукт здесь близок к квалификационному.

Независимо от того, насколько хороша базовая модель, применяются два барьера внедрения. Во-первых, интеграция данных: ИИ-финансовый директор или ИИ-директор по маркетингу хороши настолько, насколько хороши данные бухгалтерского учета, CRM и рекламной платформы, к которым он действительно может получить, а данные большинства организаций более беспорядочны, чем демо. Во-вторых, сроки соблюдения Закона ЕС об искусственном интеллекте и отсутствие прецедентного права по решениям руководителей, принимаемым под влиянием ИИ, означают, что любой агент, занимающийся наймом, увольнением или раскрытием финансовой информации, находится на действительно нерешенной правовой территории, а не просто на осторожной копии поставщика.

Общую формулировку Claude Code расширения и замены (другой контекст, инструменты разработки, а не бизнес-роли, но та же основная философия) см. в разделе «Экосистема [AI: расширение, а не замена](./ai-ecosystem.md#philosophy-augmentation-not-replacement)».

## Когда действительно использовать один из этих

- **Хотите увидеть сквозную реализацию шаблона**: прочитайте исходный код [OpenExecutive](https://github.com/SenteLabsAI/OpenExecutive). Это наиболее полная эталонная архитектура в этом списке, и Apache 2.0 позволяет использовать ее для вашего собственного домена.
- **Вам нужен узкий, дешевый агент, выполняющий одну роль.**: AI CFO Agent (CFO) или аналогичный узкий коммерческий инструмент — меньшая ставка, чем создание полноценной виртуальной команды руководителей.
- **Вам сегодня нужна оперативная сортировка в стиле начальника штаба.**: это единственная категория с зрелыми, финансируемыми коммерческими продуктами (alfred_, Линди, Виктор). Не создавайте это сами в первую очередь.
- **Вы ищете AI CHRO**: он еще не существует как фирменный продукт. Вместо этого создайте инструменты рекрутинга (Phenom, Greenhouse), производительности (Culture Amp, BetterUp) и планирования рабочей силы (Workday Adaptive Planning) или создайте уровень оркестрации самостоятельно с помощью CrewAI.
- **Вы оцениваете это как фактическое решение совета директоров или юридический вопрос**: ничто в этом списке не имеет фидуциарных или юридических полномочий. Относитесь к каждому результату как к рекомендации, которую должен проверить человек, а не как к решению.
