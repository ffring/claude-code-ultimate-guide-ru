# Инструменты сообщества Claude Code: более 40 расширений

На этой странице представлены инструменты, созданные сообществом и расширяющие Claude Code, сгруппированные по вариантам использования. Записи проверялись по общедоступным репозиториям или реестрам пакетов в разные даты; устаревшие версии, подсчеты и примечания о состоянии — это снимки, а не текущий аудит каждого инструмента. Для каждой категории сравнение «Когда использовать» объясняет, какой инструмент соответствует какому рабочему процессу, поскольку правильный выбор зависит от вашего стека и ограничений, а не только от количества звезд.

Это не список инструментов ИИ, которые в целом дополняют Claude Code. Он охватывает только инструменты, основной целью которых является расширение самого Claude Code CLI. Более широкий охват экосистемы ИИ см. в разделе [AI Ecosystem](./ai-ecosystem.md). Рекомендации по серверу MCP см. в разделе «Экосистема серверов [MCP»](./mcp-servers-ecosystem.md).

Эти расширения могут наблюдать, настраивать или координировать Claude Code, но они не обязательно владеют циклом агента. Используйте [Agent Harness Map](./agent-harness-landscape.md) для строгого сравнения времени выполнения и более широкого каталога с исходными кодами, [Agent Harness Engineering](../core/agent-harness.md) для границ слоев и [Agent Tools: Beyond Claude Code](./agentic-tools.md) для фреймворков, смежных со средой выполнения, и плоскостей управления. Оценивайте, наблюдайте и обеспечивайте безопасность добавленного инструмента с помощью [Agent Evaluation](../roles/agent-evaluation.md), [Session Observability](../ops/observability.md)и [Security Hardening](../security/security-hardening.md). Глоссарий [](../core/glossary.md) определяет различия.

> **История проверок**: Первоначальный каталог проверен в июне 2026 г.; выбранные записи были обновлены до октября 2026 г. Перед установкой проверьте исходный код каждого инструмента. Более 40 инструментов в 18 категориях.

## <a name="token--cost-tracking"></a>Отслеживание токенов и затрат

### обвинение

Самый зрелый инструмент отслеживания затрат для Claude Code. Анализирует данные локального сеанса для создания отчетов о расходах по дням, месяцам, сеансам или 5-часовому периоду выставления счетов.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [npm: ccusage](https://www.npmjs.com/package/ccusage) / [ccusage.com](https://ccusage.com) |
| **Установить** | `bunx ccusage` (самый быстрый) или `npx ccusage` |
| **Язык** | TypeScript (Node.js 18+) |
| **Версия** | 18.x (активно поддерживается) |

**Основные особенности**:

- `ccusage daily` / `ccusage monthly` / `ccusage session` — отчеты по агрегированным затратам
- `ccusage blocks --live` — мониторинг в реальном времени по 5-часовым окнам выставления счетов
- Флаг `--breakdown` для разделения затрат на модель (Opus/Sonnet/Haiku)
- Фильтрация даты `--since`/`--until`
- Выход JSON (`--json`) для программного доступа
- Офлайн-режим с кэшированными данными о ценах
- Интеграция с сервером MCP (`@ccusage/mcp`)
- Виджет macOS (`ccusage-widget`) и расширение [Raycast](https://www.raycast.com/nyatinte/ccusage)

**Ограничения**: опирается на локальный анализ JSONL; смета расходов может отличаться от официального счета Anthropic. Никакой агрегации команды без объединения журналов вручную.

> **Cross-ref**: Основное руководство описывает основные команды ccusage в [ultimate-guide.md, раздел 2.4](../ultimate-guide.md) (мониторинг затрат).
> Информацию об отслеживании затрат «Сделай сам» с помощью перехватчиков см. в разделе [Observability](../ops/observability.md).

### КодЗапись

CodeBurn читает те же журналы сеансов `~/.claude/projects/` JSONL, что и ccusage, но отвечает на другой вопрос. Там, где ccusage отвечает: «Сколько я потратил?», CodeBurn отвечает: «На что я потратил?» разбивая использование токенов по типам ходов и сопоставляя расходы с историей git с помощью команды `yield`.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: getagentseal/codeburn](https://github.com/getagentseal/codeburn) |
| **Установить** | `npm install -g codeburn` или `npx codeburn` |
| **Звезды** | 8100+ (июнь 2026 г.; сторонние индексаторы могут показывать ~2,7 тыс. из-за задержки обновления) |
| **Язык** | Node.js 22.13+ |
| **Версия** | v0.9.13 (14 июня 2026 г.) |
| **Multi-provider** | Claude Code, Codex, Gemini CLI, Курсор, Cline/Roo |

**Основные особенности**:

- `codeburn` — интерактивная панель TUI (по умолчанию за последние 7 дней)
- `codeburn today` / `codeburn month` / `codeburn overview` / `codeburn report` — временные сводки
- `codeburn optimize` — сканирование на наличие ненужных шаблонов: циклы повторов, избыточные повторные чтения, прерванные сеансы.
- `codeburn compare` — анализ производительности параллельных моделей
- `codeburn yield` — сопоставляет сеансы с git-коммитами (какие сеансы отправили код, а какие были заброшены или отменены)
- `codeburn models` — токен для каждой модели и разбивка стоимости
- `codeburn export` — вывод CSV или JSON
- `codeburn menubar` — виджет строки меню macOS (SwiftBar)
- `codeburn plan set [claude-max|claude-pro|custom]` — отслеживание плана подписки
- Сервер MCP (v0.9.12+): предоставляет данные об использовании и экономии другим агентам.

**Turn классификация**: CodeBurn классифицирует каждый поворот на 13 категорий, используя локальное детерминированное сопоставление с образцом (без вызовов LLM). Категории включают в себя кодирование, отладку, рефакторинг, тестирование, исследование, мозговой штурм, планирование, разработку функций, делегирование, операции Git и общение. Наиболее диагностический вывод на практике: повороты «разговора» (модель ответа без использования инструментов) часто составляют 40–56% затрат на сеанс. Примеры, о которых сообщил создатель, включают задачу аутентификации JWT, где 5 200 из 15 600 токенов пошли на исправление типа, и миграцию PostgreSQL, где 19 400 из 40 700 токенов пошли на отладку внешнего ключа. Это иллюстративные данные, а не воспроизводимые тесты.

**Limitations**: Доступно только для чтения, поэтому он не может прервать неконтролируемый сеанс. В оценках затрат используются цены LiteLLM, а не данные Anthropic выставления счетов API, поэтому цифры могут отличаться от счетов-фактур на $1-2/session. Зависит от формата: изменение схемы JSONL Anthropic нарушит синтаксический анализ до тех пор, пока CodeBurn не обновится. Не указан в реестре Awesome-Claude-Code.

**Когда использовать CodeBurn или ccusage**: ccusage является подходящим вариантом по умолчанию для мониторинга затрат и отслеживания периода выставления счетов. CodeBurn добавляет судебно-медицинский анализ: какие типы ходов влияют на ваши расходы, какие сеансы создали код, который был отправлен, где циклы повторных попыток увеличивают затраты. Используйте оба вместе.

### ccburn

TUI Python для визуального отслеживания скорости сжигания токенов. Отображает диаграммы, показывающие уровень потребления относительно окон выставления счетов Claude.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: JuanjoFuchs/ccburn](https://github.com/JuanjoFuchs/ccburn) / [Запись в блоге](https://juanjofuchs.github.io/ai-development/2026/01/13/introducing-ccburn-visual-token-tracking.html) |
| **Установить** | `pip install ccburn` |
| **Язык** | Python 3.10+ (богатый + графический текст) |

**Основные особенности**:

- Диаграммы терминала, показывающие потребление токенов с течением времени
- Индикаторы скорости сгорания (предупреждения о движении по маршруту/замедлении)
- Компактный режим отображения
- Визуальное отслеживание бюджета по лимитам

**Ограничения**: экосистема только на Python. Меньшее сообщество, чем ccusage. Нет интеграции с MCP.

**Когда следует выбирать ccburn вместо ccusage**: Если вы предпочитаете визуальные диаграммы скорости записи табличным отчетам или если ваша цепочка инструментов основана на Python.

### <a name="straude"></a>Штрауде

Социальная панель для отслеживания и обмена статистикой использования Claude Code (и OpenAI Codex). Перенесите данные о ежедневном потреблении и расходах токенов в общедоступную таблицу лидеров, чтобы отслеживать свою серию, еженедельные расходы и глобальный рейтинг.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [npm: Straude](https://www.npmjs.com/package/straude) |
| **Веб-сайт** | [straude.com](https://straude.com) |
| **Установить** | `npx straude@latest` |
| **Язык** | TypeScript (Node.js 18+) |
| **Версия** | 0.1.9 (активная разработка, создана в феврале 2026 г.) |
| **Maintainer** | Сообщество (oscar.hong2015@gmail.com) |

**Основные особенности**:

- `straude`: интеллектуальная синхронизация, аутентификация + использование push в одной команде
- `straude push --dry-run`: просмотр того, что будет отправлено без отправки.
- `straude push --days N`: заполнение за последние N дней (максимум 7)
- `straude status`: серия, еженедельные расходы, общее количество токенов, глобальный рейтинг.
- Отслеживает как Claude Code (`ccusage`), так и OpenAI Codex (`@ccusage/codex`).

**Что отправляется на сервер Straude**:

За день: стоимость в долларах США, количество токенов (чтение input/output/cache creation/cache), названия используемых моделей (например, `claude-sonnet-4-6`), разбивка стоимости по моделям. Плюс: хэш SHA256 необработанных данных, случайный UUID устройства и имя хоста вашего компьютера.

Ваш исходный код, ключи API и содержимое разговора доступны или передаются **not**.

**Примечания по безопасности**:

- Токен аутентификации хранится в `~/.straude/config.json` с разрешениями `0600` (только для владельца)
- Проект очень молодой (создан 18 февраля 2026 г., быстрая итерация) и не проходит аудит общественной безопасности.
- Имя хоста машины отправляется как `device_name`.
- По состоянию на март 2026 г. политика конфиденциальности не опубликована.
- Используйте `--dry-run`, чтобы проверить, что будет отправлено перед первым нажатием.

**Когда лучше выбрать Straude вместо ccusage/ccburn**:

Straude — один из двух социальных инструментов в этом списке: он загружает вашу статистику на общую платформу. Если вам нужна таблица лидеров, отслеживание серий или сравнение вашего использования с другими разработчиками, подойдут Straude или viberrank (ниже); ccusage и ccburn остаются только локальными и не требуют совместного использования данных.

> **Напоминание о безопасности**: Прежде чем запускать какой-либо инструмент сообщества CLI с `npx`, просмотрите его страницу npm и исходный код на наличие тревожных флажков. По мнению Штрауде, скомпилированный исходный код удобен для чтения и соответствует заявленной цели. Полный анализ см. в оценке ресурсов [](../../docs/resource-evaluations/straude-evaluation.md).

### viberank

Публичная таблица лидеров по использованию ИИ-кодирования, считывающая те же локальные данные `ccusage`, что и Straude, но с более широким охватом: материалы поступают от Claude Code, Codex, Gemini, CLI, Copilot, OpenCode и других инструментов, а не только от Claude Code и Codex.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: sculptdotfun/viberank](https://github.com/sculptdotfun/viberank) |
| **Веб-сайт** | [viberank.app](https://viberank.app) |
| **Установить** | `npx viberank-cli` |
| **Звезды** | 114 (2026-08-24) |
| **Лицензия** | Массачусетский технологический институт |
| **Язык** | TypeScript |
| **Created** | 3 июля 2025 г. |

**Основные особенности**:

- Глобальные таблицы лидеров и таблицы лидеров по отдельным инструментам (Claude Code, Codex, OpenCode и т. д.), ранжированные по измеренным расходам токенов.
- Уровни расходов от Spark (0 долларов США+) до Supernova (50 тысяч долларов США+)
- Подтвержденная ссылка на профиль GitHub и значки README
- Отправка через `npx viberank-cli`, команду Curl или загрузку через Интернет вручную.
- Публикует распределение совокупных расходов через бесплатный JSON API под CC BY 4.0.

**Что отправляется на сервер viberank**: только совокупные итоги, токены, стоимость, даты и названия моделей в соответствии с заявленным поведением CLI. В отличие от Straude, здесь нет имени хоста или UUID устройства.

**Когда выбирать viberank вместо Straude**: viberrank охватывает больше инструментов, чем Claude Code и Codex, а его набор данных публикуется открыто, а не остается за пользовательским интерфейсом таблицы лидеров. Straude добавляет отслеживание серий и презентацию в стиле приложения для тренировок; выберите подходящую социальную структуру и инструментарий.

### <a name="rtk-rust-token-killer"></a>RTK (Убийца жетонов ржавчины)

Прокси-сервер CLI, который фильтрует выходные данные команд **до того, как** достигают контекста Claude. 82 094 звезды (GitHub API, 30 сентября 2026 г.) по сравнению с 73 531 звездой и 4 597 вилками 27 июля 2026 г., 69 042 07 июля 2026 г., 24 397 в апреле 2026 г. и 446 в феврале 2026 г., и далее та же самая крутая кривая роста, которую стоит сверить с полным графиком звездной истории, прежде чем цитировать в контексте высоких ставок.

> **Disclosure**: автор этого руководства внес свой вклад в RTK на раннем этапе и остается его сторонником, не внося активного вклада в его код сегодня (а не его создатель). Независимые измерения всей задачи находятся в [context-engineering-tools.md](./context-engineering-tools.md).

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: rtk-ai/rtk](https://github.com/rtk-ai/rtk) |
| **Веб-сайт** | [rtk-ai.app](https://www.rtk-ai.app/) |
| **Установить** | `brew install rtk` (рекомендуется README), сценарий установки `curl -fsSL https://raw.githubusercontent.com/rtk-ai/rtk/refs/heads/master/install.sh \| sh` или `cargo install --git https://github.com/rtk-ai/rtk` (другой ящик «rtk» существует на crates.io) |
| **Язык** | Rust (автономный двоичный файл) |
| **Версия** | Последний выпуск v0.50.0 (30 сентября 2026 г.); список функций ниже был написан для версии 0.28.0 |

**Основные особенности**:

- `rtk git log` (снижение на 92%), `rtk git status` (снижение на 76%), `rtk git diff` (снижение на 56%)
- `rtk vitest run`, `rtk prisma`, `rtk pnpm` (снижение на 70-90%)
- `rtk python pytest`, `rtk mypy`, `rtk go test` (многоязычная поддержка)
- `rtk cargo test/build/clippy/nextest` (цепочка инструментов Rust)
- `rtk aws`, `rtk psql`, `rtk docker compose`, `rtk gt` (Графит CLI)
- `rtk wc` – компактный word/line/byte имеет значение
- `rtk init --global` — установка без подключения с автоматическим исправлением settings.json.
- `rtk gain` / `rtk gain -p` — аналитика экономии токенов (глобальная + по каждому проекту)
- **TOML Filter DSL**: добавляйте собственные фильтры вывода для любой команды без написания Rust, через `.rtk/filters.toml` (проект) или `~/.config/rtk/filters.toml` (глобально), более 33 встроенных фильтров.
- `rtk rewrite` — единый источник достоверной информации для сопоставления команд-перехватчиков (версия 0.25.0+, после обновления требуется `rtk init --global`)
- Конфигурация `exclude_commands` для исключения определенных команд из автоперезаписи

**Когда выбирать RTK или ccusage/ccburn**:

- RTK **снижает потребление токена** (предварительная обработка)
- ccusage/ccburn **monitor** это (постобработка)
- Используйте оба вместе для максимальной эффективности.

**Ограничения**: Не подходит для интерактивных команд или очень маленьких выходных данных (<100 символов).

### Монитор использования Claude Code

Мониторинг использования в режиме реального времени с прогнозами скорости сжигания и предупреждениями на уровне сеанса. Специализированный инструмент мониторинга для Claude Code с самой высокой оценкой по состоянию на май 2026 г., примерно 7955 звезд (8540 по состоянию на 27 июля 2026 г.).

| Атрибут | Подробности |

| **Установить** | `npx ccusage@latest` (CLI) или веб-интерфейс (см. GitHub) |
| **Звезды** | ~ 7955 (май 2026 г.) |

**Основные особенности**:

- Отслеживает потребление токенов, количество сообщений и стоимость в течение 5-часовых периодов выставления счетов за сеанс.

### Примечание о «слепой зоне» выставления счетов на уровне 4

Шлюзы уровня API (Helicone, Portkey, Langfuse, Bifrost, Compresr) перехватывают вызовы HTTP и измеряют использование токенов на уровне API. Это хорошо работает для приложений, вызывающих Anthropic API напрямую. Это не работает для подписок Claude Code Max или Pro, поскольку Claude Code подключается напрямую к серверам Anthropic, используя учетные данные подписки, а не ключ API. Не существует уровня HTTP, который мог бы перехватить шлюз.

Все четыре инструмента выше (Claude Code Usage Monitor, claude-spend, cc-statistics, claude-context-optimizer) работают путем анализа файлов локальных сеансов, которые Claude Code записывает на диск. Этот подход не зависит от режима выставления счетов: он одинаково работает как для выставления счетов по ключу API, так и для подписок Max/Pro. Если вы используете подписку Max и ваш шлюз показывает нулевой трафик Claude Code, это ожидаемое поведение, а не неправильная конфигурация.

### <a name="tokenade"></a>Токенада

Tokenade сочетает в себе локальную фильтрацию вывода, навигацию по коду, проксирование MCP, дедупликацию и краткие инструкции вывода. Покрытие зависит от интеграции агента; Codex CLI и Codex для рабочего стола — это отдельные записи в таблице совместимости поставщика.

| Атрибут | Доказательства рассмотрены 8 сентября 2026 г. |
|---|---|
| Распределение | [Public npm launcher/installer](https://github.com/pi-infected/tokenade-npm), отдельно распространяемый движок |
| Лицензия | [Проприетарная коммерческая лицензия](https://github.com/pi-infected/tokenade-npm/blob/main/LICENSE); Утверждение MIT в FAQ конфликтует с этим файлом |
| Активация | Требуется учетная запись; бесплатная квота и платные планы. Перед покупкой проверьте текущую цену |
| Интеграция | Хуки, прокси CLI и MCP; функции зависят от клиента |
| Статус оценки | Проверяются документация, лицензия, эталонные манифесты и опубликованные результаты; нет локального тестирования во время выполнения или независимой репликации |

**По сравнению с RTK:** Tokenade меняет не только вывод оболочки. Его манифест [THOL](https://github.com/pi-infected/token-harness-optimizer-leaderboard/blob/main/competitors/tokenade/manifest.json) также меняет инструкции и настройки контекста. RTK поддерживает компактное чтение файлов через CLI, включая вывод только подписей; его перехватчик Claude Code Bash не перехватывает собственные вызовы Read/Grep. Не повторяйте полное исключение из сравнения поставщиков сжатия файлов RTK или встроенной поддержки Windows.

**Граница контрольного показателя:** Поддерживаемые поставщиком данные кампании [THOL](https://github.com/pi-infected/token-harness-optimizer-leaderboard/blob/main/docs/data/results.json) для Claude Code 2.1.206 сообщают о коэффициенте затрат Tokenade 0.8.13, равном 0,768 по сравнению с контролем (95% интервал 0,647–0,900), и RTK 0,42,3 при 1,052 (0,913–1,190). Каждая рука имеет 170 успешных прогонов по 17 задачам. Это средние геометрические соотношения количества задач. Эксперимент отдает предпочтение полной конфигурации Tokenade в рамках этой кампании; он не выделяет вклад каждого механизма и не доказывает эквивалентность RTK. При оценке собственной рабочей нагрузки учитывайте лицензию, настройку, восстановление и качество.

Проверьте перекрывающиеся перехватчики перед объединением оптимизаторов. Публичный установщик не является свидетельством того, что фирменный движок сохраняет каждую деталь или передает только заявленную телеметрию.

### lean-ctx

Сервер CLI и MCP со сжатием локального контекста, написанный на Rust. Устанавливается один раз глобально и активируется в каждом проекте Claude Code без настройки для каждого проекта.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: yvgude/lean-ctx](https://github.com/yvgude/lean-ctx) |
| **Установить** | `curl -fsSL https://raw.githubusercontent.com/yvgude/lean-ctx/main/skills/lean-ctx/scripts/install.sh \| bash && lean-ctx setup` |
| **Язык** | Ржавчина |
| **Звезды** | ~1 366 |
| **Версия** | v3.6.3 |

**Как это работает**

Lean-ctx регистрируется как глобальный сервер MCP (`~/.claude.json`) и устанавливает в `~/.claude/settings.json` три перехватчика, которые срабатывают при каждом вызове инструмента:

- `PreToolUse hook redirect`: перехватывает собственные вызовы чтения и направляет их в `ctx_read` (анализ AST + файловый кеш)
- `PreToolUse hook rewrite`: маршрутизирует вызовы Bash через `ctx_shell` (сжатие оболочки на основе шаблонов).
- `PostToolUse / SessionEnd hook observe`: загружает межсессионную память CCP.

**4 измерения сжатия**

- **File читается с помощью AST-анализа.**: Tree-sitter анализирует TypeScript, Python, Rust и 15 других языков. Режим `signatures` возвращает только сигнатуры типов и функций (без тел). Режим `map` возвращает экспорт и зависимости. `schema.prisma` из 2364 строк сжимается до ~200 токенов. Неизмененные файлы передаются из кэша по ~13 токенов при повторном чтении.
- **Вывод оболочки**: более 60 шаблонов сжатия, специфичных для git, Cargo, npm, docker и kubectl. `git log -10 --stat` становится 10 строками фиксации плюс одно резюме.
- **Кросс-сессионная память (CCP: протокол непрерывности контекста)**: при выходе сохраняется сводка сеанса, состоящая примерно из 400 токенов. Следующий сеанс загружает его, а не холодным чтением более 50 000 токенов предыдущего контекста.
- **Codebasegraph**: граф зависимостей на основе SQLite, построенный на основе дерева imports/exports на 18 языках. `ctx_overview` использует его для оценки файлов по центру импорта и в первую очередь отображает наиболее связанные модули.

**Измеренные тесты (монорепозиторий TypeScript/T3, 2455 файлов)**

| Метрика | Ценить |
|--------|-------|
| Общая степень сжатия | 57.8% |
| ctx_read норма сбережений | 86% |
| ctx_search норма сбережений | 72% |
| Токены сохраняются за один день | 1.3M |
| Schema.prisma 2364L в режиме подписей | ~200 токенов (99%) |
| Перечтение файла (попадание в кэш) | 13 жетонов |

Результаты ниже в репозиториях с большим количеством Markdown, поскольку парсер AST находит меньше структур для сжатия в файлах документации, чем в исходниках TypeScript или Rust.

#### <a name="rtk-vs-lean-ctx-complementary-layers"></a>RTK против Lean-CTX: дополнительные слои

Оба инструмента сокращают потребление токенов, но работают в разных точках конвейера и не конфликтуют:

| Слой | Инструмент | Что он сжимает |
|-------|------|--------------------|
| Выход CLI (хук оболочки) | РТК | git, Cargo, npm, текст вывода tsc |
| Чтение файла (перенаправление MCP) | lean-ctx | Содержимое файла через AST+кеш |
| Межсессионная память | lean-ctx | Резюме сеансов через CCP |

RTK сжимает выходные данные оболочки более агрессивно (экономия 60–90%). Экономия Lean-ctx почти полностью достигается за счет чтения файлов (86% от общей экономии на измеренных сеансах). Используйте оба вместе.

**Мониторинг**

```bash
lean-ctx gain           # dashboard: tokens saved, USD, top commands
lean-ctx gain --daily   # day-by-day breakdown
lean-ctx cep            # efficiency score /100 (compression, cache hit rate, consistency)
lean-ctx dashboard      # web UI at localhost:3333
```

Глобальная косая черта `/lean-ctx-audit` (`~/.claude/commands/lean-ctx-audit.md`) запускает полный аудит из любого сеанса. См. [context-engineering.md §12](../core/context-engineering.md#12-token-compression-tools) для получения полного руководства по сравнению и настройке инструмента.

**Когда использовать Lean-ctx**

Наибольшее значение в проектах TypeScript, Rust или Python, где большие файлы считываются неоднократно в течение сеанса, сеансы заполняют контекст до завершения задачи или имеет значение межсессионная память. Менее влияет на репозитории документации, где большинство файлов имеют Markdown.

> **Примечание**: Lean-ctx выходит часто. Запустите `lean-ctx setup` после обновлений, чтобы обновить перехватчик и регистрацию MCP. Только для фильтрации вывода оболочки RTK является более простой отправной точкой.

### вспашка

Сервер MCP для навигации по структурному коду, нацеленный на максимальную стоимость одного токена в сеансе Claude Code: чтение файлов. Вместо загрузки всего содержимого файла Tilth предоставляет инструменты на базе Tree-Sitter, которые модель вызывает явно для навигации по коду по форме, а не по тексту.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [github.com/jahala/tilth](https://github.com/jahala/tilth) |
| **Установить** | `cargo install tilth`, затем `tilth install claude-code` |
| **Язык** | Ржавчина |
| **Архитектура** | Сервер MCP (устанавливается в Claude Code) |
| **Парсер** | сидящий на дереве (многоязычный) |

**Ключевые инструменты, доступные в модели**:

- Чтение файла с автоматическим структурированием: большие файлы возвращают структурный скелет с именами разделов и диапазонами строк; модель запрашивает определенные диапазоны по запросу
- Поиск символов: определения, использование и разрешенные вызываемые объекты в одном вызове, заменяя цикл grep-then-read
- `--callers`: все места вызова символа структурно, а не посредством текстового поиска.
- `--deps`: импорт и зависимые файлы для понимания радиуса взрыва перед рефакторингом.
- `grok <symbol>`: подпись, вызывающие, вызываемые, одноуровневые функции и связанные тесты для одного символа в одном вызове.
- Структурные различия: изменения суммируются на уровне функции, а не на уровне строки.
- Дедупликация сеанса: символы, уже показанные в текущем сеансе, помечаются как `[shown earlier]` вместо повторного расширения.

**Benchmarks** (160 прогонов, 4 реальных репозитория, метрика = стоимость правильного ответа):

| Модель | Изменение стоимости | Изменение точности |
|-------|-------------|----------------|
| Sonnet 4.6 | -44% | 84% → 94% |
| Opus 4.6 | -39% | 91% → 92% |
| Haiku 4.5 | -38% | 54% → 73% |
| Средний | -40% | 76% → 86% |

Эталонным показателем является цена за правильный ответ, а не изолированные токены. Это важно: инструмент, который экономит токены, но ухудшает качество вывода, не представляет реальной ценности. обработка почвы улучшается по обоим измерениям.

Почему чтение файлов является правильной целью: реальные данные о выставлении счетов показывают, что на них приходится примерно 65% общего использования токенов в сеансе Claude Code по сравнению с примерно 12% для вывода bash. Инструменты, сжимающие операции чтения файлов, приносят большую долю общих затрат, чем компрессоры вывода CLI.

```bash
cargo install tilth
tilth install claude-code   # registers the MCP server in Claude Code
```

После глобальной установки не требуется настройка для каждого проекта.

**Сравнение с Lean-ctx**: оба используют Tree-Sitter для снижения стоимости токена чтения файла. Lean-ctx работает как перенаправление на уровне перехватчика, которое прозрачно перехватывает собственные вызовы Read, не требуя никаких изменений в поведении модели. Tilth предоставляет явные инструменты навигации, которые модель должна вызывать напрямую, что дает ей больше контроля над тем, что она извлекает, но требует от модели использования API Tilt вместо стандартных операций чтения. Оба подхода действительны; правильный выбор зависит от того, предпочитаете ли вы пассивное сжатие или явную навигацию.

**Когда использовать Tilth**:

- Проекты TypeScript, Rust или Python, в которых большие исходные файлы читаются неоднократно.
- Сеансы, в которых контекст заполняется до завершения задачи.
- Базы кода, в которых часто используется навигация по графу вызовов (вызывающие, вызываемые, отделы).
- Если вам нужно повышение точности наряду со снижением затрат, а не только сжатие

### маки

Автономный агент TUI, написанный на Rust (с использованием ratatui), который полностью заменяет Claude Code, а не дополняет его. maki не является плагином Claude Code или дополнением MCP; это альтернативный агент со своим собственным интерфейсом и архитектурой управления контекстом.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [github.com/tontinton/maki](https://github.com/tontinton/maki) |
| **Язык** | Ржавчина (рататуи TUI) |
| **Архитектура** | Автономный агент (заменяет Claude Code) |
| Поставщики **LLM** | Anthropic, OpenAI, Google, Copilot, Ollama, Mistral, DeepSeek, OpenRouter |

**Инструменты повышения эффективности контекста, встроенные в maki**:

Инструмент `index`: скелет дерева с точными диапазонами линий. Измеренные накладные расходы за ход: +59 токенов (сам вызов индекса). Измеренная экономия за ход: -224 жетона при чтении. Нетто: -165 жетонов за ход. Маки README отмечает, что вывод bash составляет лишь 12% от общего использования токенов в типичном сеансе, поэтому сжатие bash в стиле RTK экономит в лучшем случае примерно 6% от общей стоимости. Чтение файлов (65% от общего числа) дает больший выигрыш.

Инструмент `code_execution`: встроенный интерпретатор Python (monty), который может фильтровать, преобразовывать и агрегировать данные до того, как они попадут в контекстное окно. Вместо того, чтобы модель читала необработанный файл для подсчета чего-либо, она пишет и запускает скрипт; только результат входит в контекст.

Инструмент `task`: делегирование субагента с динамическим выбором модели (хайку для простых подзадач, сонет или опус для сложных), сохранение дорогостоящих вызовов моделей, пропорциональных фактически требуемому обоснованию.

**Важное отличие**: maki архитектурно отделен от Claude Code. Вы не можете использовать maki как расширение Claude Code; выбор маки означает замену Claude Code для сеансов, в которых вы его используете. Команды, приверженные экосистеме Claude Code (приемы, навыки, иерархия CLAUDE.md, реестр MCP), не получат выгоды от внутренних инструментов maki. maki наиболее уместен, если вам нужен единый инструмент, который работает с несколькими поставщиками LLM, или вы предпочитаете автономный двоичный файл Rust без внешних зависимостей.

**Когда рассматривать маки**:

- Вы работаете с несколькими поставщиками LLM и хотите иметь единый интерфейс.
- Вам нужно детальное управление контекстом без установки отдельных серверов MCP.
- Вы создаете или экспериментируете с архитектурой агента и хотите получить доступ к внутренним компонентам.

**Когда Claude Code остается более подходящим**:

- Вы полагаетесь на систему перехватов Claude Code, навыки или определение пути CLAUDE.md.
- Ваша команда делится конфигурациями сервера MCP через `.mcp.json`.
- Вам нужны специфичные для Claude функции (расширенное мышление, проекты, системы памяти)

### mcp2cli

Универсальный мост CLI, который преобразует любой сервер MCP, спецификацию OpenAPI или конечную точку GraphQL в команды оболочки без внедрения схем инструментов в контекст LLM. Ключевой вывод: большинство клиентов MCP на каждом шагу помещают полную схему каждого зарегистрированного инструмента в контекст, независимо от того, нужно это агенту или нет. mcp2cli заменяет это ленивой загрузкой.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: knowsuchagency/mcp2cli](https://github.com/knowsuchagency/mcp2cli) |
| **Установить** | `uvx mcp2cli --help` (без установки) или `uv tool install mcp2cli` |
| **Язык** | Питон |
| **Звезды** | ~1 900 |
| **Статус** | Активный (Показать HN Лучшее за март 2026 г.) |

**Как работает отложенная загрузка**:

Вместо внедрения полных схем инструментов (~44 000 токенов для сервера GitHub MCP с 43 инструментами) агент:

1. Вызывает `mcp2cli --mcp <url> --list` → получает ~16 токенов за инструмент (название + краткое описание)
2. Вызывает `mcp2cli --mcp <url> <tool-name> --help` → получает ~120 токенов (полная схема, один инструмент)
3. Запускает инструмент с правильными аргументами

Полные схемы никогда не входят в контекст LLM, если это явно не запрошено.

**Benchmarks** (независимо воспроизведено Firecrawl, Scalekit, CircleCI):

- Сервер GitHub MCP (43 инструмента), простая задача: 44 026 токенов (родной MCP) против 1 365 токенов (паттерн gh CLI/mcp2cli), сокращение в 32 раза
- Частота неудач при выполнении одних и тех же задач: собственный MCP 28 %, шаблон CLI 0 % (переполнение контекста = пропущенные шаги)
- 120 инструментов, 25 ходов: нативный код MCP внедряет ~362 000 токенов схем до начала реальной работы

**Основные особенности**:

- **Мульти-исходный код**: MCP (HTTP/SSE/stdio), спецификации OpenAPI, GraphQL в одном двоичном файле
- **Auth**: OAuth 2.1 с PKCE для интерактивного использования, учетные данные клиента для конвейеров CI/CD, обновление кэшированного токена.
- **Daemon + пул соединений**: соединения MCP занимают 2–5 секунд. Демон сохраняет их в тепле для повторного использования с задержкой в ​​миллисекунды.
- Формат **`--toon`**: выходное кодирование с эффективным использованием токенов, которое сокращает количество токенов ответа на 40–60 % по сравнению с обычным JSON.
- **Семантические коды завершения**: `validation_error`, `auth_failure`, `tool_error`, `connection_error`, поэтому сценарии оболочки могут разветвляться без анализа текста

```bash
# No-install test
uvx mcp2cli --mcp https://mcp.example.com/sse --list

# Execute a tool
mcp2cli --mcp https://mcp.example.com/sse search --query "test"

# Local stdio server
mcp2cli --mcp-stdio "npx @modelcontextprotocol/server-filesystem /tmp" --list

# OpenAPI spec
mcp2cli --spec ./openapi.json --base-url https://api.example.com list-pets

# Reusable config (baked alias)
mcp2cli bake create petstore --spec URL && mcp2cli @petstore --list
```

**Когда использовать mcp2cli**:

- Вы используете серверы MCP со многими инструментами (более 10) и видите заполнение контекста схемами еще до начала реальной работы.
- Вы хотите отладить или протестировать сервер MCP с терминала, не поднимая полноценный клиент.
- Ваш конвейер CI/CD программно использует инструменты MCP.

**Когда не использовать**:

- Корпоративные многопользовательские контексты, требующие OAuth для каждого пользователя и журналы аудита (родные шлюзы MCP справляются с этим лучше)
- Агенты, использующие известные собственные интерфейсы командной строки (gh, git, kubectl): модель знает их интерфейс на основе обучающих данных, мост не требуется.
- Менее ~10 инструментов на сервер: выигрыш реален, но не срочен.

> **Осторожно при использовании имен**: по крайней мере четыре несвязанных проекта имеют имя «mcp2cli» в GitHub (Python, Go, Bun и другие). Эталонная реализация для этого варианта использования — [knowsuchagency/mcp2cli](https://github.com/knowsuchagency/mcp2cli). Перед установкой проверьте автора.

### <a name="entire-cli"></a>Весь CLI

Интегрированный в Git захват сеансов агентов и терминальный клиент Entire Git Forge.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: entireio/cli](https://github.com/entireio/cli) (MIT) / [docs.entire.com](https://docs.entire.com) / [entire.com](https://entire.com) |
| **Установить** | `brew install --cask entireio/tap/entire`, `curl -fsSL https://entire.com/install.sh \| bash` или `irm https://entire.com/install.ps1 \| iex` на Windows |
| **Язык** | Идти |
| **Компания** | Entire, основанная Томасом Домке (бывшим генеральным директором GitHub), объявлено о посевном капитале в размере 60 миллионов долларов 10 февраля 2026 г. |
| **Статус** | CLI 0.10.x (октябрь 2026 г.). Размещенная кузница запущена 26 октября 2026 г. |

**Основные функции (локальный CLI, учетная запись не требуется):**

- **Захват сеанса**: каждый коммит с работой агента получает контрольную точку (подсказки, расшифровка, затронутые файлы), связанную с трейлером `Entire-Checkpoint`
- **Git-родное хранилище**: одна ссылка на каждую контрольную точку в `refs/entire/checkpoints/` (по умолчанию, начиная с CLI 0.10.0; более старые репозитории используют ветку `entire/checkpoints/v1`). В вашу ветку не добавляется коммит
- **Объясните и найдите**: `entire checkpoint explain`, `entire why`, `entire blame`, `entire search`
- **Кросс-агентское резюме**: `entire session resume <branch>` восстанавливает сеансы филиала в вашем агенте.
- **Redaction**: секретное сканирование перед каждой записью, определяемые пользователем пакеты правил, дополнительный уровень PII
- **Agents**: Claude Code, Codex, Cursor, Copilot CLI, OpenCode, Antigravity, Factory AI Droid, Pi и многое другое с помощью плагинов.

**Только размещенная кузница:** Маршруты с оценкой агентов и слиянием Gates (утверждения людей, выводы, CI), распределенный хостинг Git, общая память проекта. См. [Агентный Git подделывает](#agent-native-git-forges-2026).

**Случаи использования:**

| Сценарий | Почему весь CLI |
|----------|---------------|
| **Аудиторские доказательства** | Подсказки, расшифровка и файлы, связанные с каждым коммитом, хранятся в Git. |
| **Многоагентные рабочие процессы** | Возобновляемые сеансы между агентами |
| **Отладка решений ИИ** | Проследите линию до ее приглашения и сеанса. |
| **Объединение управления** | Ворота на тропах (размещается кузница) |
| **Передача команды** | Возобновить ветку с ее сеансами |

**vs Клод-код-просмотрщик:**

| Особенность | claude-code-viewer | Весь CLI |
|---------|-------------------|-----------|
| **Цель** | Просмотр истории только для чтения | Захват сеанса, связанный с коммитами + возобновление |
| **Хранилище** | Читает локальные журналы Claude Code. | Контрольные точки, добавленные вместе с репозиторием |
| **Контекст** | Только разговор | Подсказки + стенограмма + затронутые файлы |
| **Управление** | Нет | Объединить Gates в размещенной кузнице |
| **Multi-agent** | Нет | Да (межагентское резюме) |
| **Накладные расходы** | Никто | Ссылки на контрольные точки в репозитории (измерьте) |

**Когда выбирать «Весь» вместо программы просмотра кода:**

- ✅ Команда должна поделиться контекстом коммитов
- ✅ Аудит свидетельства кода, написанного агентом
- ✅ Многоагентные рабочие процессы
- ❌ Просто хочу просмотреть свою историю → Используйте claude-code-viewer (более легкий)

**Limitations:**

- До 1.0 CLI; формат хранения уже менялся один раз (переход к refs)
- Расшифровки отправляются вместе с репозиторием: общедоступный репозиторий публикует их, если только контрольные точки не переходят в отдельный частный репозиторий (`entire configure --local --checkpoint-remote github:<owner>/<repo>`).
- Теневые ветки локально хранят неотредактированные снимки рабочего дерева.
- Аттестация SOC 2, ISO 27001, HIPAA или FedRAMP для Entire не найдена на сайтах Whole.com или docs.entire.com (27 октября 2026 г.)

**Дельта против обычных существующих настроек:**

| Нуждаться | Типичная существующая установка | Что добавляет Entire |
|------|----------------------|-----------------|
| Журнал вызовов инструментов | Локальный JSONL (7-дневная ротация) | Отредактированные стенограммы хранятся в Git. |
| Атрибуция Human/AI | Ничего | Атрибуция отображается за сеанс на сайте Whole.com (размещено) |
| Передача агента | Копирование контекста вручную | `entire session resume` между агентами |
| Передача данных между разработчиками | Гит commits/PRs | Контрольные точки, добавленные с помощью кода |
| Сохранение сеанса | Только локально, эфемерно | Git-родной, общий доступ |
| Управление | Пользовательские перехватчики перед фиксацией | Объединение ворот на тропах (размещенная кузница) |

**Оценка (рекомендуется повышение перед развертыванием команды):**

```bash
entire enable  # Install on throwaway branch

# After 2-3 normal sessions:
git for-each-ref refs/entire/checkpoints/ | wc -l   # Checkpoints created
git count-objects -vH                               # Repository growth
time git push                                       # Push overhead → flag if > 5s
ls .git/hooks/                                      # Verify no conflict with existing hooks
```

Критерии остановки (примерные значения, адаптируйтесь к вашей команде): рост репозитория, который вы не можете поглотить, увеличение накладных расходов > 5 секунд или перехват конфликтов.

Все приведенные ниже показатели производительности являются измерениями поставщиков: независимого воспроизведения обнаружено не было.

**Вся кузница на практике:**

- **Trails** оценивает каждый запрос с помощью агентов проверки, работающих в песочницах (Claude Code и Codex под капотом). Результаты имеют степень серьезности и предлагаемое исправление. Gates для каждого репозитория блокирует слияние до тех пор, пока не будут получены утверждения, выводы и CI. Результаты CI поступают из Buildkite или Depot.
- **Режим зеркала** сохраняет GitHub в качестве источника истины: клоны и выборки поступают из Entire, push-уведомления перенаправляются в GitHub, где по-прежнему применяются защита ветвей и необходимые проверки. Во время сбоя GitHub агенты могут продолжать отправлять сообщения во все собственные незеркальные ветки.
- **Регионы**: ЕС (Франкфурт), США (Огайо), Австралия (Сидней), Индия (Мумбаи), Великобритания (Лондон) и Сингапур, согласно странице регионов хостинга [](https://entire.com/regions) с 19 октября 2026 г.
- **Memory**: `entire-graph` создает локальную карту кода с помощью Tree-Sitter, `entire-brain` связывает ее с прошлыми сеансами.
- **Вендорский тест**: Entire сообщает о 418 нажатиях в секунду против 4,7 у GitHub («до 89x»), измеренных с помощью собственного инструмента с открытым исходным кодом [ForgeMark](https://github.com/entireio/forgemark). Относитесь к этому как к сравнению путей хранения, а не как к показателю полного обзора, цикла непрерывной интеграции и слияния.
- **Ценообразование**: Платные функции используют предоплаченные кредиты ([Условия кредитования](https://entire.com/credit-terms)); цена за место не указана

**Anthropic Scion, что он показывает:** Anthropic сообщает, что количество объединенных изменений в день в мае 2026 года увеличилось с примерно 2500 до более 30 000 в день в сентябре, а также около 25 миллионов проверок кода в день для CI. Scion создает коммиты, перебазирование и слияния на сервере («нечего отправлять»), а Anthropic инвестировал в тестирование после слияния и перед развертыванием вместо глобальной блокировки слияния («Например, правильная очередь слияния не имеет особого смысла в масштабе агента»). Это внутренние цифры. Полезный урок для большинства команд заключается в том, что объем агента давления оказывает влияние на очереди слияния и CI, а не на сам инструмент.

**Как выбрать:**

| Ситуация | Разумный первый шаг |
|-----------|----------------------|
| Ограничения скорости GitHub или сбои в работе замедляют работу ваших агентов | Зеркально отразить один репозиторий (режим полного зеркала, синхронизация с Origin) и сохранить GitHub в качестве источника истины. |
| Очередь на проверку, насыщенная PR агентов | Проверка пробного агента на одном репозитории перед переносом хостинга |
| Продукты, которые создают репозитории для каждого сеанса агента | Программируемое хранилище Git (Cloudflare Artifacts) |
| Нужно полностью покинуть Git | Ни один из вышеперечисленных продуктов не предлагает этого; Scion является внутренним для Anthropic. |

Прежде чем применять какой-либо из них, проверьте, что вы можете экспортировать помимо данных Git: просмотрите историю, результаты, шлюзы и память сеансов.

## <a name="security-scanning"></a>Сканирование безопасности

Два взаимодополняющих уровня: инструменты, которые проверяют вашу конфигурацию Claude Code на предмет неправильных конфигураций, внедрения перехватчиков и рисков MCP; и сканеры на базе агентов, которые находят уязвимости логического уровня в самом коде приложения.

### АгентЩит

Сканер безопасности, который оценивает ваш каталог `.claude/` по шкале от 0 до 100 (A–F) по 102 правилам в 5 категориях. Создано на хакатоне Claude Code (Cerebral Valley x Anthropic, февраль 2026 г.).

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: affaan-m/agentshield](https://github.com/affaan-m/agentshield) |
| **Установить** | `npx ecc-agentshield scan` (нулевая установка) или `npm install -g ecc-agentshield` |
| **Язык** | TypeScript (Node.js) |
| **Лицензия** | Массачусетский технологический институт |
| **Статус** | Ранняя стадия (выпущена в феврале 2026 г.): правила не прошли независимую проверку. |

**Основные особенности**:

- **5 категории сканирования**: секреты (14 шаблонов: `sk-ant-`, `ghp_`, AWS, Stripe…), разрешения (подстановочный знак `Bash(*)`, отсутствующие списки запретов), перехватчики (34 правила: внедрение команд через `${var}`, эксфильтрация данных, молчаливые ошибки, обратные оболочки), серверы MCP (23 правила: цепочка поставок, `npx -y`, удаленный транспорт), агенты (25 правил: инструкции автозапуска, скрытые директивы Unicode, быстрое отражение)
- **Auto-fix**: `agentshield scan --fix` заменяет жестко запрограммированные секреты ссылками на переменные окружения.
- **Несколько форматов вывода**: терминал (по умолчанию), JSON (`--format json`), Markdown, автономный HTML
- **GitHub Action**: публикует встроенные аннотации к затронутым файлам, выдает выходные данные `score` и `grade`, поддерживает порог `fail-on-findings`.
- **Opus состязательный анализ** (`--opus --stream`): трехагентный конвейер (Атакующий → Защитник → Аудитор) с использованием Opus 4.6 для глубокого моделирования угроз

```bash
# Scan your Claude Code config (no install required)
npx ecc-agentshield scan

# Auto-fix safe issues
agentshield scan --fix

# JSON output for CI
agentshield scan --format json

# Three-agent adversarial analysis (requires ANTHROPIC_API_KEY — incurs API cost)
agentshield scan --opus --stream
```

**GitHub Действие**:

```yaml
- name: AgentShield Security Scan
  uses: affaan-m/agentshield@v1
  with:
    path: "."
    min-severity: "medium"
    fail-on-findings: "true"
```

**`runtimeConfidence` context**: результаты взвешиваются по источнику: `active-runtime` (полный вес) против `template-example` (0,25x) против `docs-example` (0,25x), поэтому большой каталог шаблонов MCP не увеличивает оценку, как десятки активных серверов.

**Limitations**:
- Правила не подвергаются независимому аудиту; воспринимайте оценку как полезный сигнал, а не как сертификат соответствия
- Режим `--opus` запускает вызовы Opus 4.6 API; запланируйте соответствующий бюджет перед включением в CI
- Поверхность API может развиваться; привязать к конкретной версии в производстве

> **См. также**: [Руководство по усилению безопасности](../security/security-hardening.md) для получения информации о ручных шаблонах перехвата и разрешений.

### ДипСек

Сканер уязвимостей на базе агента от Vercel Labs, который находит ошибки безопасности на логическом уровне в коде приложения, которые пропускают инструменты SAST на основе регулярных выражений. Если AgentShield, описанный выше, проверяет вашу конфигурацию Claude Code, DeepSec проверяет само приложение.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: vercel-labs/deepsec](https://github.com/vercel-labs/deepsec) |
| **Установить** | `npx deepsec init` (загружает каталог `.deepsec/` в корне репо) |
| **Язык** | TypeScript |
| **Лицензия** | Апач 2.0 |
| **Статус** | Vercel Labs: экспериментальный, не готовый к производству |

**Как это работает**: DeepSec использует пятиэтапный конвейер. Сначала быстрое сканирование регулярных выражений определяет чувствительные зоны (потоки аутентификации, криптовызовы, вводимые пользователем данные). Затем агенты ИИ отслеживают потоки данных через каждый файл-кандидат и выдают результаты. Второй проход агента повторно проверяет эти выводы и обращается к истории git для фильтрации уже исправленных проблем. Конечный результат имеет структуру Markdown или JSON и готов для вставки в заявки.

Используемые модели **AI**: Claude Opus 4 с расширенным мышлением (по умолчанию) и GPT-5.5 через существующую подписку Anthropic или OpenAI. Vercel AI Gateway рекомендуется для производственного сканирования.

**Доля ложных срабатываний**: примерно 10–20% после этапа повторной проверки.

```bash
# Initialize at repo root
npx deepsec init
cd .deepsec && pnpm install

# Run the full pipeline
pnpm deepsec scan       # fast regex pass
pnpm deepsec process    # AI agent investigation (slow, costs tokens)
pnpm deepsec triage     # P0/P1/P2 classification
pnpm deepsec revalidate # reduce false positives
pnpm deepsec export --format md-dir --out ./findings

# PR mode: scan only changed files (much cheaper)
pnpm deepsec process --diff

# Distributed mode for large monorepos (Vercel Sandboxes)
pnpm deepsec sandbox process --sandboxes 10 --concurrency 4
```

**Когда использовать**: DeepSec находит крайние случаи в условиях аутентификации и тонкие проблемы с потоком данных, которые не могут быть обнаружены инструментами на основе шаблонов. Он хорошо подходит для периодического глубокого аудита критически важных сервисов или в качестве шлюза `--diff` для чувствительных к безопасности запросов, а не в качестве сканера для каждой фиксации.

**Предупреждение о стоимости**: полное сканирование кодовой базы из 50 тысяч строк может стоить 10–50 долларов США в токенах Claude Opus. Большие монорепозитории могут достигать тысяч долларов. Запустите режим `--diff` для повседневного использования; зарезервируйте полное сканирование для целевого аудита.

**Configuration**: создайте `.deepsec/INFO.md` (50–100 строк), документируя шаблоны аутентификации и конфиденциальные зоны для конкретного проекта. Без этого агенты рассуждают без контекста и выдают больше ложных срабатываний. Система плагинов позволяет настраивать сопоставления регулярных выражений, соответствующие вашей архитектуре.

**Положение безопасности**: DeepSec имеет полный доступ к оболочке; относитесь к нему как к агенту кодирования. Vercel рекомендует развертывать микровиртуальные машины в песочнице (Firecracker), чтобы ключи API не могли быть удалены из рабочих процессов.

> **См. также**: [Объявление в блоге Vercel](https://vercel.com/blog/introducing-deepsec-find-and-fix-vulnerabilities-in-your-code-base) для получения подробной информации об архитектуре и примеров из реальной жизни.

### СкиллСпектор

Сканер безопасности от NVIDIA, который проверяет навыки перед установкой. AgentShield проверяет вашу действующую конфигурацию; DeepSec проверяет код вашего приложения. SkillSpector заполняет пробел, который ни один из них не покрывает: статический анализ файла навыков или репозитория до того, как они коснутся вашей машины.

Мотивация конкретна: исследование 2026 года (Лю и др.) по 42 447 навыкам на крупных рынках показало, что 26,1% содержат по крайней мере одну уязвимость, а 5,2% демонстрируют вероятный злой умысел. Навыки работы с исполняемыми скриптами были в 2,12 раза более уязвимы.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: NVIDIA/SkillSpector](https://github.com/NVIDIA/SkillSpector) |
| **Установить** | `uv venv .venv && source .venv/bin/activate && make install` |
| **Язык** | Питон 3.12+ |
| **Лицензия** | Апач 2.0 |
| **Статус** | Активный (поддерживается NVIDIA) |

**Покрытие обнаружения**

64 шаблона в 16 категориях. Категории, наиболее актуальные для пользователей Claude Code:

- **Быстрое внедрение** (5 шаблонов): переопределение инструкций, скрытые директивы в комментариях, команды эксфильтрации, манипулирование поведением, вредоносный контент
- **Эксфильтрация данных** (4 шаблона): внешняя передача, сбор переменных окружения, перечисление файловой системы, утечка контекста
- **MCP Отравление инструмента** (4 шаблона): скрытые инструкции в метаданных (комментарии HTML, символы нулевой ширины, base64), обман Юникода (гомоглифы, переопределения RTL), внедрение описания параметров, несоответствие описания и поведения
- **Злоупотребление триггером** (3 шаблона): слишком широкие ключевые слова для триггера, теневые команды (навык, переопределяющий встроенный), травля ключевыми словами.
- **Цепочка поставок** (6 шаблонов): незакрепленные зависимости, шаблоны `curl | bash`, выполнение obfuscated/encoded, поиск CVE в реальном времени через OSV.dev, заброшенные пакеты, опечатки
- **Мошеннический агент** (2 шаблона): самомодификация во время выполнения, несанкционированное сохранение через сценарии cron/startup.

Примечателен шаблон SC4: он запрашивает [OSV.dev](https://osv.dev) в реальном времени для проверки заявленных зависимостей по всей базе данных рекомендаций. Ключ API не требуется; результаты кэшируются в памяти в течение 1 часа. Возвращается к статическому списку, если сеть недоступна.

**Двухступенчатый трубопровод**

Этап 1 — быстрый статический анализ (регулярное выражение + проверка AST по всем файлам). Этап 2 — это необязательная семантическая оценка LLM, которая фильтрует ложные срабатывания и добавляет удобочитаемые объяснения. Приглашение LLM включает защиту от взлома, предотвращающую манипулирование вредоносным навыком собственным аудитом.

```bash
# Scan a local skill directory (static only)
skillspector scan ./my-skill/ --no-llm

# Scan a GitHub repository
skillspector scan https://github.com/user/my-skill

# Scan a single SKILL.md
skillspector scan ./SKILL.md

# With LLM analysis (Anthropic)
export SKILLSPECTOR_PROVIDER=anthropic
export ANTHROPIC_API_KEY=sk-ant-...
skillspector scan ./my-skill/

# JSON output for scripting
skillspector scan ./my-skill/ --no-llm --format json --output report.json

# SARIF for IDE tooling and CI
skillspector scan ./my-skill/ --format sarif --output report.sarif
```

**Оценка рисков**: КРИТИЧЕСКИЕ результаты добавляют 50 баллов, ВЫСОКИЕ добавляют 25, СРЕДНИЕ добавляют 10, НИЗКИЕ добавляют 5. Навыки, содержащие исполняемые сценарии, получают множитель 1,3x. Оценка выше 50 вызывает рекомендацию «НЕ УСТАНАВЛИВАТЬ».

Опция **Docker** для сред с воздушным зазором или CI без Python:

```bash
docker build -t skillspector .
docker run --rm -v "$PWD:/scan" skillspector scan ./my-skill/ --no-llm
```

**Когда использовать**: перед установкой любого навыка из незнакомого источника, особенно тех, которые имеют исполняемые скрипты (`scripts/`, `.sh`, `.py` наряду с SKILL.md). Работа с `--no-llm` занимает несколько секунд и фиксирует большинство моделей цепочки поставок и кражи. Включите анализ LLM для навыков, которые вы планируете добавить в общую команду.

**Отчетная точность**: ~87% после прохождения повторной проверки LLM. Статический режим имеет более высокий уровень отзыва, но больше ложных срабатываний для законных шаблонов, таких как `subprocess`, в инструментах сборки.

> **См. также**: [NVIDIA SkillSpector README](https://github.com/NVIDIA/SkillSpector) для получения полного каталога шаблонов и руководства по развертыванию Docker.

## <a name="configuration-quality"></a>Качество конфигурации

Инструменты, которые оценивают, проверяют и поддерживают качество существующих конфигураций агентов ИИ с течением времени, а не создают их с нуля.

> **Context**: CLAUDE.md не является одноразовым артефактом. По мере развития кодовой базы контекст, который она предоставляет ИИ, может меняться: пути, на которые имеются ссылки, больше не существуют, знания предметной области устаревают, новые шаблоны появляются, не документируясь. Приведенные ниже инструменты предназначены для этого уровня обслуживания.

### <a name="caliber"></a>Калибр

CLI, который оценивает качество конфигурации вашего агента ИИ (0–100), генерирует индивидуальные конфигурации на основе снятия отпечатков кодовой базы и обнаруживает расхождение между вашим кодом и вашим CLAUDE.md. Работает для Claude Code, Cursor и Codex.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: rely-ai-org/caliber](https://github.com/rely-ai-org/caliber) |
| **Установить** | `npx @rely-ai/caliber score` (нулевая установка) или `npm install -g @rely-ai/caliber` |
| **Язык** | TypeScript (Node.js ≥20) |
| **Лицензия** | Массачусетский технологический институт |
| **Статус** | Ранняя стадия (выпущена в марте 2026 г.): API могут развиваться. |

**Основные особенности**:

- **Локальная оценка**: детерминированная 100-балльная рубрика по 6 категориям (Существование, Качество, Обоснованность, Точность, Свежесть, Бонус), без вызовов LLM, не требуются ключи API
- **Обнаружение дрейфа**: на основе git, определяет, когда код фиксирует обновления конфигурации; кеш становится недействительным при сигнатуре дерева или изменении HEAD
- **Генерация конфигурации**: снятие отпечатков кодовой базы (языки, платформы, описания) → генерирует предложения CLAUDE.md + MCP через существующую подписку AI (место Claude Code, место курсора или ключ API).
- **Процесс проверки**: оценка → предложение → проверка различий → accept/decline → резервное копирование в `.caliber/backups/` → `caliber undo`
- **GitHub Action**: публикует PR-комментарии с оценкой, оценкой, дельтой и базовой ветвью; объединение дополнительных пороговых блоков `fail-below`

```bash
# Score your current config (read-only, zero install)
npx @rely-ai/caliber score

# Generate or improve configs
npx @rely-ai/caliber init

# Detect drift after code changes
caliber refresh

# GitHub Action (fail PR if score < 75)
# uses: rely-ai-org/caliber@v1
# with: { fail-below: 75 }
```

**Категории оценок**:

| Категория | Макс | Что он измеряет |
|----------|-----|-----------------|
| Существование | 25 | CLAUDE.md присутствует, навыки, конфигурация MCP, кроссплатформенный паритет |
| Качество | 25 | Бюджет токена, блоки кода, коэффициент конкретности, отсутствие дубликатов |
| Заземление | 20 | % проекта dirs/files, указанного в конфигурации |
| Точность | 15 | Ссылочные пути существуют на диске, фиксируются с момента последнего обновления конфигурации. |
| Свежесть | 10 | Устаревание конфигурации и история git, никаких секретов |
| Бонус | 7 | Хуки настроены, AGENTS.md, изученный контент присутствует. |

**Delta по сравнению с другими инструментами настройки в этом разделе**:

| Нуждаться | Существующий инструмент | Что добавляет Калибр |
|------|--------------|-------------------|
| Создать конфигурацию с нуля | AIBlueprint | N/A |
| Аудит качества существующей конфигурации | Ничего | Критерий оценки + конкретные неудачные проверки |
| Обнаружение отклонения конфигурации из кода | Ничего | Обнаружение дрейфа на основе Git |
| Распространение стандартов в масштабах организации | Packmind | N/A |

**Ограничения**: Инструмент ранней стадии (март 2026 г., ~65 звезд на момент написания статьи; с тех пор проект был переименован в `ai-setup` под названием caliber-ai-org и к 27 июля 2026 г. достиг 1223 звезд). Поддержка нескольких инструментов (Claude Code + Cursor + Codex + Copilot) может создавать в целом адекватные конфигурации, а не глубоко специфичные для Claude Code. Критерий оценки не представлен как отдельный документ: категории являются детерминированными, но не видны пользователю без чтения источника.

**Примечание о безопасности**: `caliber refresh` и `caliber watch` имеют доступ на запись в CLAUDE.md. Тот же класс риска, что и у Packmind: проверьте сгенерированные выходные данные перед принятием, особенно при использовании внешних источников (`caliber config`). Относитесь к файлам конфигурации `.caliber/` так же, как к менеджеру секретов.

> **Cross-ref**: Для создания конфигурации с нуля см. [AIBlueprint](#aiblueprint). Для распространения и обеспечения соблюдения стандартов в масштабе организации см. [Packmind](#packmind). Информацию об авторстве руководства CLAUDE.md см. в разделе [ultimate-guide.md 3](#31-memory-files-claudemd).

### context-evaluator

Инструмент OSS от Packmind, который оценивает качество CLAUDE.md и AGENTS.md с помощью 17 специализированных оценщиков искусственного интеллекта. Доступен в виде предварительно скомпилированного двоичного файла или установки исходного кода Bun. Размещенное веб-приложение, задокументированное в проекте, было недоступно во время проверки 2 сентября 2026 г.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: PackmindHub/context-evaluator](https://github.com/PackmindHub/context-evaluator) |
| **Установить** | Бинарный файл из выпусков GitHub или из исходного кода с помощью Bun |
| **Язык** | TypeScript (Булочка) + интерфейс React |
| **Лицензия** | Apache-2.0 |
| **Статус** | Активен (экспериментальный проект Packmind, 2026 г.) |

**Основные особенности**:

- 17 оценщиков разделили 13 типов ошибок (существующие проблемы) и 4 типа предложений (пробелы в анализе кодовой базы): качество контента, structure/formatting, полнота команд, руководство по тестированию, осведомленность о безопасности, противоречивые инструкции, устаревшие пути и т. д.
- AGENTS.md и CLAUDE.md обрабатываются одинаково: работают с форматами Claude Code, Cursor, GitHub Copilot и Codex.
- Снятие отпечатков кода: сначала запускается CLOC + анализ папок + обнаружение файла конфигурации, поэтому каждое приглашение оценщика включает фактические языки, платформы и ключевые папки проекта. Проблемы специфичны для проекта, а не общие.
- **Единый режим**: когда все файлы соответствуют токенам 100 000, один агент оценивает их вместе и может обнаружить противоречия между файлами. При превышении порогового значения агенты запускаются независимо для каждого файла.
- **Автоматическое исправление**: выберите проблемы в веб-интерфейсе, выберите целевой формат (Claude Code, Курсор, GitHub Copilot, Курсор), и ИИ создаст файл `.patch`. Примените вручную с помощью `git apply remediation.patch`. Никакие изменения не вносятся без рассмотрения.
- Несколько поставщиков ИИ: Claude Code (по умолчанию), Cursor, OpenCode, GitHub Copilot, OpenAI Codex.

**Delta против Caliber**:

| Особенность | Калибр | context-evaluator |
|---------|---------|-------------------|
| Поставщик ИИ не требуется | Да (детерминированный) | Нет (требуется AI CLI) |
| Рубрика начисления очков (0-100) | Да | Нет |
| Обнаружение дрейфа Git | Да | Нет |
| Обзор контента на основе LLM | Нет | Да (17 оценщиков) |
| Обнаружение противоречий между файлами | Нет | Да (унифицированный режим) |
| Автоматическое исправление (файл исправления) | Нет | Да |
| Размещенная веб-версия | Нет | Задокументировано в восходящем направлении, но недоступно во время проверки 2 сентября 2026 г. |

**Когда выбирать контекстную оценку**:

- Вы хотите получить обратную связь по шкале LLM о реальном содержании вашего CLAUDE.md, а не о структурной рубрике.
- В вашей конфигурации могут быть противоречивые инструкции, устаревшие пути или отсутствующие соглашения платформы, которые не будут уловлены детерминированной оценкой.
- Вам нужно автоматическое исправление с возможностью просмотра различий (а не перезапись на месте).

**Когда вместо этого выбирать Caliber**:

- Вам нужна нулевая оценка LLM для CI-ворот (порог `fail-below`).
- Вам нужно обнаружение отклонений на основе git по мере развития кода.

**Ограничения**: Требуется поставщик ИИ с доступом к CLI. Обработка занимает 1-3 минуты. Нет детерминированной оценки для CI. Нет обнаружения дрейфа git.

> **Cross-ref**: Для детерминированной оценки конфигурации см. [Caliber](#caliber). Для создания конфигурации с нуля см. [AIBlueprint](#aiblueprint). Шаблоны ведения журнала подсказок во время выполнения и адаптивного режима Unified/Parallel из исходного кода этого инструмента документированы в [Skill Design Patterns](../core/skill-design-patterns.md).

## <a name="project-context-bootstrapping"></a>Начальная загрузка контекста проекта

Инструменты, которые компилируют знания структурированной базы кода перед началом сеанса Claude Code, поэтому ИИ понимает маршруты, схемы, зависимости и важные файлы из первого сообщения, не тратя токены на исследование файлов.

> **Context**: Claude Code исследует базу кода, вызывая Glob, Grep и Read. В крупных проектах это стоит тысячи токенов, прежде чем начнется какая-либо реальная работа. Приведенные ниже инструменты предварительно компилируют это исследование в единый структурированный артефакт (или набор целевых вики-статей), который Claude читает один раз в начале сеанса. Думайте об этом как о «загрузке проекта в оперативную память до открытия сеанса».

### <a name="codesight"></a>кодовое прицеливание

CLI с нулевой зависимостью, который анализирует кодовую базу с помощью AST и генерирует структурированные контекстные карты для Claude Code и других инструментов искусственного интеллекта. Экономит 7–12 токенов при базовом сканировании по сравнению с исследованием файлов вручную; до 83-131x с целевыми вики-запросами (самооценка по 3 производственным проектам).

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: Houseofmvps/codesight](https://github.com/Houseofmvps/codesight) |
| **Установить** | `npx codesight` (ноль зависимостей, нулевая конфигурация) |
| **Язык** | TypeScript, заимствует компилятор TS из вашего проекта, если он присутствует. |
| **Лицензия** | Массачусетский технологический институт |
| **Статус** | Ранняя стадия (выпущена в апреле 2026 г., ~386 звезд на момент написания, 1253 по состоянию на 27 июля 2026 г.), API могут развиваться. |

**Основные команды**:

```bash
# Scan current project — generates .codesight/ folder
npx codesight

# Generate wiki knowledge base (.codesight/wiki/) — targeted articles per topic
npx codesight --wiki

# Generate CLAUDE.md, .cursorrules, codex.md, AGENTS.md from project scan
npx codesight --init

# Show blast radius for a file (all files transitively affected by changing it)
npx codesight --blast src/lib/db.ts

# Start as MCP server (11 tools) — Claude calls it on demand
npx codesight --mcp

# Generate optimized config file for a specific AI tool
npx codesight --profile claude-code

# Watch mode — rescans on file changes
npx codesight --watch

# Open interactive HTML report in browser
npx codesight --open
```

**Что генерируется**:

| Файл | Содержание |
|------|---------|
| `.codesight/CODESIGHT.md` | Комбинированная контекстная карта: один файл с полным пониманием проекта. |
| `.codesight/routes.md` | Каждый маршрут API с методом, путем, параметрами и тем, чего он касается (аутентификация, база данных, кеш, платежи). |
| `.codesight/schema.md` | Каждая модель базы данных с полями, типами, первичными ключами, внешними ключами и отношениями. |
| `.codesight/graph.md` | График импорта: какие файлы что импортируют, какие файлы больше всего ломаются при изменении |
| `.codesight/middleware.md` | Аутентификация, ограничение скорости, CORS, проверка, ведение журнала, обработчики ошибок |
| `.codesight/config.md` | Каждая переменная окружения (обязательно или по умолчанию), файлы конфигурации, ключевые зависимости. |
| `.codesight/wiki/` | Постоянная база знаний: по одной статье на тему (`auth.md`, `database.md`, `payments.md` и т. д.) |

**Покрытие обнаружения**:

- Маршруты: автоматически обнаруживается более 25 фреймворков (Express, Hono, Fastify, NestJS, tRPC, FastAPI и др.).
- Схема: 10 ORM (Drizzle, Prisma, TypeORM, Mongoose, SQLAlchemy, ActiveRecord, Ecto, Eloquent, Entity Framework, Sequelize)
- Компоненты: React, Vue, Svelte, Flutter, SwiftUI.
- Языки: TypeScript (полный AST), JavaScript, Python, Go, Ruby, Elixir, Java, Kotlin, Rust, PHP, Dart, Swift, C# (резервное выражение для не-TS)

Интеграция **MCP**: после настройки Claude вызывает его напрямую, не запуская `npx`:

```json
{
  "mcpServers": {
    "codesight": {
      "command": "npx",
      "args": ["codesight", "--mcp"]
    }
  }
}
```

Доступные инструменты MCP: `codesight_scan`, `codesight_get_wiki_index`, `codesight_get_wiki_article`, `codesight_get_routes`, `codesight_get_schema`, `codesight_get_blast_radius`, `codesight_get_hot_files`, `codesight_get_env`, `codesight_get_summary`, `codesight_lint_wiki`, `codesight_refresh`.

**Как вики сокращает использование токенов**:

| Вопрос | Без вики | С вики |
|----------|-------------|-----------|
| «Как работает аутентификация?» | ~12 тыс. токенов (чтение более 8 файлов) | ~300 токенов (`auth.md`) |
| «Какие модели существуют?» | ~5 тыс. токенов (полный CODESIGHT.md) | ~400 токенов (`database.md`) |
| Начало новой сессии | ~5 тыс. токенов (полная перезагрузка) | ~200 токенов (`index.md`) |

**В каком масштабе переключаться с CODESIGHT.md на wiki**: в малых и средних проектах (менее ~1500 файлов) практична загрузка `CODESIGHT.md` в начале сеанса через CLAUDE.md. В больших проектах (монорепозиторий Next.js + tRPC на 1700 файлов генерирует CODESIGHT.md токенов на 35 000) загрузка полного файла становится контрпродуктивной. Вместо этого используйте сервер `--wiki` + MCP: Claude извлекает одну целевую статью (~ 200-400 токенов) на каждый вопрос, а не загружает всю карту заранее.

**Ограничения и предостережения**:

- Контрольные показатели рассчитываются самостоятельно по 3 производственным проектам без независимой проверки на момент написания.
- Точность AST применима только к TypeScript; другие языки используют резервный вариант на основе регулярных выражений
- `--init` автоматически генерирует CLAUDE.md; он может перезаписать существующий. Создайте резервную копию CLAUDE.md перед запуском в проекте с установленной конфигурацией.
- Инструмент ранней стадии (апрель 2026 г.): поверхность API может меняться в разных выпусках.
- Проекты MongoDB правильно сообщают об 0 моделях схемы (без объявлений SQL ORM)
- Работники Cloudflare, использующие необработанные обработчики HTTP (без признанной платформы), сообщают о 0 маршрутах: среда выполнения работника выходит за рамки списка более 25 поддерживаемых платформ.
- Проекты Next.js App Router сообщают об 0 маршрутах: маршрутизация на основе файлов не имеет явных объявлений маршрутов для статического анализа для анализа; маршруты определяются на основе путей к файлам, а не шаблонов кода
- Проекты Rust выдают почти пустой вывод: нет поддержки AST, резервное выражение регулярного выражения захватывает только импорт модулей верхнего уровня (`src/main.rs` → `mod X`); маршруты, структуры и бизнес-логика невидимы. Бесполезно в кодовых базах Rust.

Интеграция **CI** (сохраняет актуальность контекста при каждом нажатии):

```yaml
name: codesight
on: [push]
jobs:

    runs-on: ubuntu-latest

          node-version: 20

        with:
          name: codesight
          path: .codesight/
```

## <a name="engineering-standards-distribution"></a>Распространение инженерных стандартов

Инструменты, которые решают проблему организационного масштаба: синхронизация технических стандартов в десятках репозиториев и нескольких агентах кодирования ИИ.

> **Context**: Руководство охватывает авторство CLAUDE.md на уровне проекта (раздел 3 Полного руководства). Приведенные ниже инструменты предназначены для следующего уровня: распространения и поддержки этих стандартов во всей инженерной организации.

### Packmind

Платформа «ContextOps» с открытым исходным кодом (термин Packmind, обозначающий инженерный контекст как управляемый артефакт с жизненным циклом). Один раз собирает стандарты и распространяет их в виде контекста, читаемого ИИ, каждому агенту кодирования ИИ, который использует команда.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: PackmindHub/packmind](https://github.com/PackmindHub/packmind) |
| **Установить** | `npx @packmind/cli init` |
| **Лицензия** | Апач-2.0 (CLI); Уровень SaaS на сайте Packmind.com (цена не указана) |
| **Self-hosted** | Docker / Kubernetes |
| **Язык** | TypeScript |

**Основные особенности**:

- Единый сценарий → генерирует команды `CLAUDE.md` + косую черту + навыки для Claude Code, `.cursor/rules/*.mdc` для курсора, `.github/copilot-instructions.md` для второго пилота, `AGENTS.md` для обычных агентов.
- Сервер MCP: создавайте стандарты и управляйте ими непосредственно из сеанса Claude Code.
- Цикл непрерывного обучения (заявлено): ошибка исправлена ​​→ основная причина фиксируется с помощью Skill+MCP → предлагается обновление сборника правил → проверяется человеком → распространяется по репозиториям
- Получение знаний из командных инструментов через серверы MCP: GitHub PR-комментарии, Slack, Jira, GitLab MR, Confluence, Notion ([демонстрационные примеры использования](https://github.com/PackmindHub/demo-use-case-skills))

**Ментальная модель**: Думайте о Packmind как о версии модульного шаблона `.claude/rules/` на уровне организации. Если `.claude/rules/*.md` обеспечивает согласованность одного проекта, то Packmind поддерживает согласованность 40 репозиториев и синхронизируется со всеми инструментами искусственного интеллекта, которые использует команда, а не только с Claude Code.

Относитесь к конфигурации Packmind как к конфиденциальному артефакту, применяйте те же элементы управления доступом, что и к менеджеру секретов, и внимательно просматривайте предлагаемые обновления сборника сценариев перед объединением.

## <a name="hook-utilities"></a>Подключить утилиты

Инструменты, расширяющие систему перехватчиков Claude Code за счет дополнительной логики, условного выполнения или шаблонов автоматизации. Примеры хуков, сделанных своими руками, см. в разделе «Хуки» [в полном руководстве](../ultimate-guide.md).

### gitdiff-watcher

Утилита Stop-hook, которая обеспечивает контроль качества до того, как Claude вернет управление. Запускает команды оболочки (сборка, тесты, анализ) только при изменении соответствующих файлов, что делает правила качества CLAUDE.md детерминированными.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: fcamblor/gitdiff-watcher](https://github.com/fcamblor/gitdiff-watcher) |
| **Установить** | `npx @fcamblor/gitdiff-watcher@0.1.0` (глобальная установка не требуется) |
| **Язык** | Node.js |
| **Версия** | 0.1.0: работа в стадии разработки, API могут измениться |
| **Автор** | Флориан Камблор |

**Проблема, которую он решает**: CLAUDE.md Правила типа «тесты должны пройти перед передачей управления» недетерминированы. По мере расширения контекста эти правила конкурируют с недавними результатами инструмента за внимание модели и могут быть лишены приоритета, поэтому Claude иногда возвращает управление с неработающим кодом, даже если правило является явным. Перехват Stop выполняется вне контекста LLM, что делает его структурно невозможным для пропуска.

**Как это работает**:

1. Принимает шаблон подстановки (`--on`) и одну или несколько команд оболочки (`--exec`).
2. При каждом событии Stop SHA-256 хэширует все файлы, соответствующие glob, которые появляются в `git diff` (проиндексированные + непроиндексированные).
3. Сравнивается с предыдущим снимком, хранящимся в `.claude/gitdiff-watcher.state.local.json`.
4. Если существенных изменений нет: автоматически завершает работу из 0 (команда не выполняется)
5. При обнаружении изменений: запускает все команды `--exec`.
6. Если какая-либо команда завершается неудачно (код выхода 2): Claude получает stderr и повторяет попытку; снимок НЕ обновляется, поэтому на следующем ходу проверка запускается снова
7. При полном успехе: обновляет снимок.

**Пример конфигурации** (`.claude/settings.json`):

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "npx @fcamblor/gitdiff-watcher@0.1.0 --on 'src/**/*.{ts,tsx}' --exec 'npm run build'",
            "timeout": 300,
            "statusMessage": "Checking TypeScript build..."
          },
          {
            "type": "command",
            "command": "npx @fcamblor/gitdiff-watcher@0.1.0 --on 'src/**/*.{ts,tsx}' --exec 'npm test -- --passWithNoTests'",
            "timeout": 300,
            "statusMessage": "Checking tests..."
          }
        ]
      }
    ]
  }
}
```

Несколько перехватчиков выполняются параллельно (Claude Code порождает один субагент на каждую запись перехватчика).

**Основные модели поведения**:

- **Conditional**: срабатывает только при изменении соответствующих файлов, поэтому не тратится время CI на несвязанные изменения.
- **Retry-safe**: при неудачных запусках снимок сохраняется, поэтому при следующей попытке выполняется та же проверка.
- **Parallel**: несколько команд `--exec` в одной записи перехвата выполняются последовательно; используйте отдельные записи перехватчиков для параллельного выполнения
- **Silent on no-op**: выходит из 0 без вывода, когда не обнаружено никаких существенных изменений.

**Limitations**:

- v0.1.0 (явно «в разработке»), параметры CLI и формат файла состояния могут измениться.
- Использует `git diff (staged + unstaged)` для обнаружения файлов, поэтому файлы, не отслеживаемые git, не видны наблюдателю.
- Циклы повторов: неправильно настроенная проверка, которая всегда терпит неудачу, приведет к тому, что Claude будет повторять попытки бесконечно; добавьте `--exec-timeout` и убедитесь, что ваши команды имеют правильные коды выхода.
- Каждый отказ стоп-хука запускает новый ход Claude, поглощая контекст. Около предела в 200 тысяч повторяющиеся сбои ускоряют потребление контекста.

**Когда использовать gitdiff-watcher вместо встроенного Stop-хука**:

Тот же гейт такого же качества можно написать примерно за 20 строк bash без gitdiff-watcher. Используйте gitdiff-watcher, когда вам нужна условная логика изменения файла и сохранение состояния без написания ее самостоятельно, или когда вам нужны параллельные проверки в многоязычной кодовой базе (например, сборка TypeScript + тесты Kotlin одновременно).

> **Cross-ref**: Механика стоп-хука в секции хуков [ultimate-guide.md](../ultimate-guide.md). Для проверок сборки PostToolUse (срабатывает после каждого редактирования файла, а не при передаче), см. пример раздела перехватчиков в строке ~ 8262.

## <a name="terminal-rendering-mods"></a>Терминальный рендеринг (моды)

В Claude Code 2.1.287 добавлен [mods](../ultimate-guide.md#claude-mods-v21287): плагины, обработчики которых работают внутри Claude Code и могут перерисовывать то, что он показывает. Мод рендеринга сохраняет собственный интерфейс терминала Claude Code и меняет внешний вид ответов. В этом разница с [альтернативными UIs](#alternative-uis) ниже, которые заменяют интерфейс. Отключение плагина мода в `/plugin` возвращает рендерер по умолчанию.

### <a name="prismantis"></a>призмантис

Мод Claude Code, который перерисовывает ответы в терминале: цветные таблицы, код с подсветкой синтаксиса, диаграммы и диаграммы-русалки, текстовые фигуры и кнопки копирования на каждом блоке. Он также перерисовывает строки инструментов (редактирование становится карточкой различий), вывод команды с косой чертой и ваши собственные подсказки. Автор данного руководства использует его и рекомендует.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [NahumLitvin/prismantis на GitHub](https://github.com/NahumLitvin/prismantis)и стартовый пост сопровождающего [prismantis: реальные диаграммы, таблицы и код в терминале Claude Code](https://www.catchkill9.dev/posts/prismantis.html) |
| **Версия** | 0.38.2 (30 октября 2026 г.), 64 выпуска GitHub с 2 октября 2026 г. |
| **Требуется** | Claude Code 2.1.287 или новее |
| **Лицензия** | Массачусетский технологический институт |
| **Сигналы** | 266 звезд и 24 участника по состоянию на 31 октября 2026 г.; указан в Awesome Claude Code (уведомление[№ 209](https://github.com/NahumLitvin/prismantis/issues/209), 18 октября 2026 г.) |
| **Проверено на** | терминал macOS вручную, согласно README; CI проводит тесты на macOS, Linux и Windows. Приложение для ПК, VS Code и мобильное устройство еще не проверяются вручную. |

**Install** (внутри Claude Code):

```text
/plugin marketplace add NahumLitvin/prismantis
/plugin install prismantis@prismantis
```

Затем `/prismantis setup` знакомит вас с темой и стилями с помощью нарисованных предварительных просмотров, `/prismantis demo` знакомит с основными функциями, а `/prismantis theme <name>` переключается между 17 темами (16 палитр плюс `mono`).

**Update** (из оболочки), затем запускайте `/reload` в каждом открытом сеансе, поскольку сеанс сохраняет загруженную версию:

```bash
claude plugin marketplace update prismantis && claude plugin update prismantis@prismantis
```

**Настройте** через строки призмантиса в `/config` или под `pluginConfigs` в `~/.claude/settings.json`, затем `/reload`. Настройки проекта не считываются для параметров плагина, поэтому значение применяется к каждому проекту.

#### Копирование вывода в Slack, GitHub или документ

| Блокировать | Кнопка | Что попадает в буфер обмена |
|-------|--------|-----------------------------|
| Стол | `⧉ md` | Оригинальный Маркдаун |
| Стол | `⧉ art` | Текстовая таблица в рамке, которая хорошо вставляется в Slack. |
| Стол | `⧉ html` | Отформатированная таблица плюс копия, разделенная табуляцией. Локальный терминал macOS или графический сеанс Linux с запущенным CopyQ |
| Таблица, схема, рисунок | `▣ png` | PNG нарисованного изображения в локальном терминале macOS или Windows. |
| Схема, рисунок | `⧉ source` / `⧉ art` | Источник русалки или фигуры, или нарисованный текст |
| Код, список, цитата | `[ ⧉ copy ]` | Код без рамок, список в виде Markdown, цитата без маркеров `> ` |
| Ответить несколькими блоками | `⧉ copy reply` | Весь ответ, как его написал Claude |

Без мыши `/prismantis copy` копирует последний ответ, а `/prismantis copy code` — последний блок кода. Используйте в терминалах команды, которые копируют при выборе (README называет Warp), где нажатие кнопки может вместо этого получить слово «копировать».

Выбор списка с помощью мыши используется для копирования нарисованных глифов `•` и `◦`, которые Slack отображает в виде текста, а не в виде списка. Начиная с версии 0.38.0, `listMarker: dash` рисует `-` на каждом уровне, поэтому выбранный список вставляется как список Markdown. Нумерованные списки сохраняют свои номера.

```json
{
  "pluginConfigs": {
    "prismantis@prismantis": {
      "options": { "listMarker": "dash" }
    }
  }
}
```

#### Сколько стоит `diagramHints` и когда его отключать

Claude редко пишет график, если не знает, что терминал может его нарисовать. Если `diagramHints` включен (по умолчанию), prismantis прикрепляет примечание, которое читает только модель, к каждому вводимому вами приглашению и к каждому приглашению, отправляемому другим плагином. В заметке указано, какие элементы визуализируются, запрашиваются команды в огороженных блоках и объясняется, когда фигура работает лучше, чем диаграмма русалки. README дает около 630 токенов на одно приглашение и около 710 с включенным `latex`, если учитывать токенизатор Claude. Это цифры сопровождающего; в этом руководстве они не измерялись. Примечание пропускается для первого запроса запуска `claude -p` без заголовка и для фоновых уведомлений.

Заметка меняет то, что пишет Claude, а не только то, что это стоит. Выключите его с помощью `"diagramHints": false` и `/reload`, когда:

- Вы составляете текст для вставки в другое место (сообщение Slack, PR-описание, электронное письмо). Блоки и фигуры Mermaid поступают туда в качестве источника, а `⧉ art` или `▣ png` помогают только одному блоку за раз.
- Накладные расходы на каждое приглашение имеют для вас большее значение, чем изображения, например, в длительных сеансах, когда вы наблюдаете за использованием контекста.

Рендеринг продолжается без подсказок: таблицы, код и все диаграммы, которые Claude еще пишет, рисуются как и раньше. Поскольку параметры плагина считываются только из пользовательских настроек, этот переключатель применяется к каждому проекту, пока вы не включите его снова.

#### Безопасность

Мод — это код без изолированной программной среды, выполняющийся в процессе Claude Code (см. примечания по безопасности в разделе [mods основного руководства](../ultimate-guide.md#claude-mods-v21287)). README утверждает, что prismantis не выполняет сетевые вызовы и запускает программу только для помощника буфера обмена `⧉ html` и `▣ png` по щелчку мыши и для средства рендеринга LaTeX, когда `latex` включен. Чтобы проверить, что заявлено в версии, перед ее установкой:

```bash
git clone https://github.com/NahumLitvin/prismantis
claude plugin validate ./prismantis
```

При фиксации `dc51f35` (v0.38.2) проверка пройдена. В строке `calls:` был указан `$.process.run` через помощник буфера обмена и наборщик LaTeX, строка `hooks:` включала `tool.call` и `prompt.submit`, а `env writes:` была пустой. Текстовый поиск по поставляемому коду `hooks/` для `fetch`, `http`, `https`, `net` и `WebSocket` ничего не нашел. Это статическая проверка одной версии, а не аудит кода.

#### Оперативность сопровождающего

30 октября 2026 г. в 06:10 UTC автор этого руководства открыл [issue #319, удобные для копирования списки для вставки в Slack](https://github.com/NahumLitvin/prismantis/issues/319). Сопровождающий опубликовал выпуск [версии 0.38.0 с опцией `listMarker`](https://github.com/NahumLitvin/prismantis/releases/tag/v0.38.0) в 08:53 UTC, затем ответил и закрыл проблему в 09:05 UTC. Одна устаревшая точка данных, а не обязательства по поддержке.

**Когда использовать**: вы читаете таблицы, различия и диаграммы в ответах Claude и хотите, чтобы они были нарисованы, а не показаны как источник Markdown, или вы часто копируете выходные данные Claude в Slack, GitHub или документ. **Пропустить** для безголовой работы `claude -p`, где ничего не прорисовывается, или на машинах, где администраторы разрешают только управляемые моды (`allowManagedModsOnly`).

## <a name="alternative-uis"></a>Альтернативные интерфейсы

### Claude шик

Стилизованный пользовательский интерфейс терминала для Claude Code, созданный на основе claude-agent-sdk Anthropic. Заменяет TUI Claude Code по умолчанию на визуально улучшенный интерфейс.

| Атрибут | Подробности |
|-----------|---------|

| **Установить** | `uvx claudechic` |
| **Язык** | Python (текстовый + claude-agent-sdk) |
| **Статус** | Альфа |

- Сообщения с цветовой кодировкой (оранжевый: пользователь, синий: Claude, серый: инструменты)

- Управление рабочим деревом Git из пользовательского интерфейса
- Несколько агентов в одном окне
- Средство просмотра `/diff`, сочетания клавиш vim (`/vim`), команды оболочки (`!ls`)

**Ограничения**: Альфа-статус — ожидайте серьезных изменений. Цепочка зависимостей Python. Требуется claude-agent-sdk. Только macOS/Linux.

### <a name="conductor"></a>Дирижер

Настольное приложение macOS, которое координирует работу агентов кодирования в рабочих пространствах Git с локальным или облачным выполнением, проверкой различий и рабочим процессом pull-request. Документация проверена 17 октября 2026 г.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [conductor.build](https://conductor.build) |
| **Docs** | [Документация по проводникам](https://www.conductor.build/docs) |
| **Установить** | Скачать с [conductor.build](https://conductor.build) |
| **Платформа** | клиент macOS; локальные рабочие области или облачные песочницы Linux |
| **Агенты** | Claude Code, Codex, Курсор, Открытый код |
| **Автор** | Мелти Лабс |

**Workflow**: создайте рабочую область для функции или исправления, запустите агент, проверьте его изменения, отправьте отзыв на уровне строки, затем создайте или просмотрите PR. Рабочая область объединяет ветку, файлы, терминал и диалог. Средство просмотра [diff](https://www.conductor.build/docs/reference/diff-viewer) поддерживает проверку файлов и коммитов; [Checks](https://www.conductor.build/docs/reference/checks) объединяет состояние PR, CI, комментарии и задачи, если они доступны. Проверки могут блокировать или препятствовать слиянию в зависимости от рабочего процесса; их присутствие не доказывает, что требуемый тест был проведен.

**Локальный и облачный**: локальные рабочие области используют рабочие деревья Git на Mac. [Облачные рабочие области](https://www.conductor.build/docs/cloud) выполняются в изолированных программных средах Linux с настроенными зависимостями и переменными среды и могут продолжать работу, пока ноутбук закрыт, пока рабочая область не перейдет в спящий режим. Организации могут совместно использовать облачные рабочие пространства и чаты. Это расширяет возможности выполнения за пределы рабочего стола; он не добавляет настольный клиент Windows или Linux.

**Граница разрешений**: рабочее дерево [Git](https://www.conductor.build/docs/concepts/git-worktrees) разделяет рабочие файлы, одновременно предоставляя общий доступ к истории и ссылкам Git. Локальные агенты запускаются с разрешениями учетной записи пользователя. Облачное выполнение использует песочницы Vercel, но пользователи могут явно разрешить облачным агентам действовать на их локальном компьютере. Просмотрите этот параметр, прежде чем рассматривать облачное рабочее пространство как изолированное от Mac. См. [безопасность и разрешения](https://www.conductor.build/docs/reference/security-and-permissions).

**Когда тестировать**: вы используете Mac и хотите, чтобы выполнение агента, отзывы о различиях и проверки связей с общественностью проводились в одном рабочем пространстве, включая облачную опцию. Это запатентованный продукт; Доступ агента-провайдера и доступность облака имеют свои собственные требования. Это документированные возможности, а не измеренный прирост производительности.

### <a name="agent-orchestrator-ao"></a>Оркестратор агента (AO)

Настольное приложение с открытым исходным кодом и CLI, которые координируют существующие агенты кодирования, рабочие деревья проекта и состояние доставки PR. Его демон наблюдает за CI и анализирует события, а также может отправлять отзывы соответствующему сеансу агента.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [OrchestratorInc/agent-orchestrator](https://github.com/OrchestratorInc/agent-orchestrator), ранее известный как AgentWrapper и ComposioHQ. |
| **Установить** | Используйте официальные версии [для настольных компьютеров](https://github.com/OrchestratorInc/agent-orchestrator/releases); октябрьская пробная версия использовала встроенный демон через CLI |
| **Лицензия** | Apache-2.0 в корне репозитория |
| **Платформа** | Настольные сборки для Windows, macOS и Linux; здесь выполнялась только операция macOS CLI/daemon |
| **Trial** | 27 октября 2026 г.: AO v0.14.6, Codex CLI 0.159.2, один синтетический репозиторий и PR. |

**Проверено в пробной версии**: AO создал рабочее дерево Codex, отслеживал PR и окончательную фиксацию и автоматически пересылал неудачную проверку GitHub в Codex. Агент исправил локально воспроизведенную ошибку. AO также принял встроенный комментарий к обзору вместе со своим файлом и строкой, но доставка в Codex не наблюдалась в течение более пяти минут после приема, в том числе после окончания утверждения. Для завершения исправления обзора потребовалось пробуждение вручную; Затем прошли пять местных тестов.

**Remote CI остался заблокированным**: GitHub не запустил задание из-за выставления счетов по счету или ограничения расходов. В уведомлении АО содержалась ошибка выборки журнала, а не диагноз. Прохождение локальных тестов не подтверждает успех удаленного CI. Частные протоколы испытаний являются доказательствами оценщика, а не публично воспроизводимыми артефактами CI.

**Inspect по умолчанию перед внедрением**: протестированное сопоставление разрешений [Codex](https://github.com/OrchestratorInc/agent-orchestrator/blob/v0.14.6/backend/pkg/agentruntime/command.go#L198) позволяет `default` AO обходить утверждения и песочницу. В ходе испытания был выбран `accept-edits` и отдельно настроен Codex с разрешениями `workspace-write` и `on-request`. В документации по телеметрии [выпуска](https://github.com/OrchestratorInc/agent-orchestrator/blob/v0.14.6/docs/telemetry.md) также описываются данные, связанные с учетной записью, и настройки конфиденциальности для отключения удаленного сбора; более раннее описание полностью анонимной телеметрии не сохранилось.

**Когда оценивать AO**: протестируйте его для консолидированного надзора PR/CI/review. Прежде чем полагаться на автоматический цикл, потребуйте реального удаленного тестирования красного и зеленого цвета и проверки доставки после утверждения. В ходе этого испытания не сравнивались скорость, стоимость, графическое удобство использования или надежность с Codex Desktop, Conductor, Orca или Escouade. Он также не устанавливает историческое утверждение «повторить попытку CI дважды, а затем повысить уровень».

Полная оценка и пределы доказательств: [`Agent Orchestrator with Codex`](../../docs/resource-evaluations/agent-orchestrator-composio.md).

## <a name="model-routing"></a>Маршрутизация модели

Эти инструменты выбирают, какую модель и объем работ получит задача кодирования, вместо того, чтобы оставлять одно значение по умолчанию для всего сеанса. [AI Экономика устройства](../ops/ai-unit-economics.md#route-by-complexity) объясняет три уровня маршрутизации и почему экономию необходимо измерять на собственных задачах.

### <a name="agent-router"></a>Агент Маршрутизатор

Локальный Rust CLI, который выбирает модель, усилия и навыки для каждого этапа задачи Claude Code или Codex (планирование, выполнение, проверка) и объясняет выбор. Разрешения, бюджет, риск и отсутствие доказательств хоста удаляют кандидатов до того, как будет подсчитана какая-либо оценка, и те же входные данные воспроизводятся в том же квитанции о решении. Каждая утвержденная фаза выполняется как отдельный хост-процесс в изолированной программной среде ОС, при этом записи ограничиваются рабочим деревом Git; он не меняет модель разговора, в котором вы находитесь.

> **Status**: общедоступен с 28 октября 2026 г. в качестве экспериментального кандидата на исходный код (тег `v0.0.1`, без пакетного выпуска). Статус README от 27 октября 2026 г. говорит о том, что автономная маршрутизация работает, а автоматическое ежедневное использование Claude Code или Codex еще не сертифицировано.
>
> **Disclosure**: Agent Router написан автором данного руководства.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: FlorianBruniaux/agent-router](https://github.com/FlorianBruniaux/agent-router) |
| **Лицензия** | Apache-2.0 |

### <a name="yylo"></a>ЙЙЛО

Оркестр командной строки для агентов кодирования, владеющий уровнем доставки: типизированная задача, проверка и границы слияния вокруг рабочих деревьев git для каждой задачи. YYLO (команды `yylo` и `yy`) делегирует внутренний цикл агента существующим CLI агента кодирования, таким как Pi и Codex CLI, и управляет жизненным циклом вокруг них.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: yylo-dev/yylo](https://github.com/yylo-dev/yylo) |
| **Установить** | `npm install --global '@yylo/cli@latest'` |
| **Язык** | Python (распространяется через npm CLI) |
| **Лицензия** | Массачусетский технологический институт |
| **Команды** | `yylo` и `yy` (эквивалентные); `ypl` — это `yy pi --live` |

**Основные особенности**:

- `task start` замораживает защищенный целевой SHA, создает выделенный branch/worktree для каждой задачи и завершает настроенную гидратацию зависимостей перед отправкой отчета `WORKING`.
- `task preflight` доступен только для чтения и обнаруживает дефекты закрытия до дорогостоящих вентилей; `task finish` требует чистой зафиксированной подсказки и ставит задачу в очередь; оно не сливается
- `merge land` создает ровно один неизменяемый источник задачи в частном отдельном кандидате и помещает его с защитой ожидаемых старых ссылок Git; перенесенная цель перегруппирует силы и возобновит проверки
- При слиянии не запускаются модели, не выбираются рецензенты и не планируются пакеты: тесты и семантические проверки остаются явными проверками проекта за пределами этапа слияния.
- Машинный вывод с подтверждением квитанции (`--format json|ndjson --raw`) для команд задачи, слияния и интеграции с сохраненными доказательствами.

**Usage**:

```bash
npm install --global '@yylo/cli@latest'
yy init --task "Document the onboarding path" --subagent pi
yy task start TASK_ID       # freeze target SHA, create the task worktree
yy task preflight TASK_ID   # read-only closure checks before finishing
yy merge status             # observe the queue
```

**Ограничения**: Раннее внедрение, 60 звезд и примерно 900 загрузок в минуту в месяц по состоянию на сентябрь 2026 г. Объединение компоновки и приземления работает; он не проверяет его, и ниже среды выполнения агента нет изолированной программной среды на уровне ОС. Только английская документация.

> **Когда использовать**: когда несколько агентов кодирования работают параллельно в одном репозитории и вы хотите, чтобы типизированная задача → рабочее дерево → граница слияния, которую оркестраторы с первой диспетчеризацией оставляют оператору. В спецификации Symphony говорится: «Если вам нужен цикл проверки или шлюз слияния, вы создаете его сами»; YYLO — это готовый уровень слияния, а сам цикл проверки остается с собственными проверками вашего проекта.

### <a name="concord"></a>Конкорд

Сервер MCP, который предоставляет агентам кодирования, работающим в одном и том же репозитории, общее рабочее состояние: кто присутствует, какую задачу и файлы заявлял каждый агент, перекрывают предупреждения перед тем, как кто-либо редактирует, подсказки и ответы между агентами, работающими в разных связях, а также передачу данных проверки. Concord не создает агентов и рабочих деревьев; он находится рядом с тем, что их запускает (терминал, средство запуска рабочего дерева, настольное приложение).

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: Get-Concord-AI/concord-mcp](https://github.com/Get-Concord-AI/concord-mcp) |
| **Установить** | `npm install -g @concord-ai/concord-mcp`, затем `concord setup` в репозитории |
| **Язык** | TypeScript (Node.js 22.12+) |
| **Лицензия** | Массачусетский технологический институт |
| **Клиенты** | Claude Code, Codex, Курсор, Gemini CLI, Грок Билд, Гусь, Google Антигравитация; любой клиент MCP может использовать эти инструменты |

**Основные особенности**:

- `concord setup` регистрирует сервер для Claude Code, Cursor, Gemini, Grok и Codex и записывает инструкции инструментов в `CLAUDE.md`, `AGENTS.md` и `.cursor/rules/`, объединяя их в существующий конфиг; безопасно повторить запуск
- Пять инструментов MCP: `start_work` утверждает задачу и ее ожидаемые файлы или модули, а возвращаемые данные перекрываются с активными заявками других агентов; `inspect_work` показывает, кто присутствует, активную работу и устаревшие претензии; `update_work` записывает контекст или отправляет запрос или ответ другому агенту; `transfer_work` назначает, отключает и переназначает; `finish_work` записывает доказательства и отмечает работу как готовую или завершенную.
- Связанные рабочие деревья git разрешаются для первичной проверки, поэтому каждое рабочее дерево репозитория использует одно рабочее пространство Concord: сеансы, запущенные исполнителем рабочих деревьев, видят утверждения друг друга до того, как их ветки встретятся.
- Изменения владельца имеют версии: если два агента работают над одной и той же версией задачи, успешным будет только первый переход, а каждое изменение сохраняется в истории, доступной только для добавления.
- State — это база данных SQLite в каталоге `.concord/` репозитория, которая игнорирует себя через свой собственный `.gitignore`; `HANDOFF.md` и `REVIEW_PACKET.md` экспортируются для людей.
- Дополнительный хук Claude Code `PreToolUse` (`concord setup --claude-hooks`), который предупреждает, когда редактирование затрагивает файл, на который претендует другая активная задача, и блокирует его, когда в `CONCORD_TASK` установлена ​​собственная задача сеанса.

**Usage**:

```bash
npm install -g @concord-ai/concord-mcp
cd your-repo && concord setup   # register the MCP server and agent instructions, then restart agent sessions
concord status                  # roster, active work, overlaps, stale claims, review-ready tasks
concord dashboard               # read-only live TUI of agents, tasks and alerts
concord adapters status         # which installed agents can receive live prompts, and how
```

**Ограничения**: Молодой проект: v0.14.2, 562 звезды и около 3400 загрузок в минуту за 30 дней до 18 октября 2026 г. Координация является совместной: агенты должны вызывать инструменты (программа установки устанавливает соответствующие инструкции), и за пределами хука Claude Code ничто не мешает агенту редактировать заявленный файл. Быстрая доставка в реальном времени зависит от принимающего ремня; Сеансы Goose пока не могут получать запросы, а запрос недостижимому агенту вместо перенаправления завершается с ошибкой. Состояние является локальным для одной кассы и ее рабочих деревьев, если вы не войдете в дополнительный режим Concord Cloud. Телеметрия включена по умолчанию: имена операций, результаты и время без кода, путей к файлам, сообщений или содержимого задач; сервер хранит IP-адрес запроса и производную страну без автоматического истечения срока действия. Отключите его с помощью `CONCORD_TELEMETRY_DISABLED=1` (или `DO_NOT_TRACK=1`). Первый интерактивный `concord setup` также предлагает глобальный режим (по умолчанию да), который регистрирует Concord на уровне пользователя и добавляет короткий раздел в файлы пользовательских инструкций, такие как `~/.claude/CLAUDE.md`; `concord setup --no-global` удаляет именно то, что добавил.

> **Когда использовать**: когда два или более агента, часто в разных связях (скажем, Claude Code и Codex), одновременно работают в одном репозитории, и вы хотите, чтобы они разделили работу перед редактированием, а не обнаруживали коллизию во время слияния. Средства запуска рабочих деревьев, такие как multiclaude или claude-squad, разделяют файлы каждого агента; Concord добавляет общее представление о том, кто и что делает в этих рабочих деревьях. Оно дополняет их, а не заменяет.

## Внешние структуры оркестровки

> **Архитектурные различия**: Приведенные выше инструменты (Gas Town, multiclaude) запускают несколько экземпляров Claude Code параллельно. Внешние платформы оркестрации идут дальше: они заменяют или дополняют внутренний уровень оркестрации Claude Code собственной средой выполнения, добавляя сверху координацию роя, постоянную память и специализированные пулы агентов. Сначала используйте собственные возможности Claude Code (инструмент задач, субагенты); используйте эти рамки, когда вы их исчерпали.

### Руфло (ранее Клод-Флоу)

**GitHub**: [github.com/ruvnet/ruflo](https://github.com/ruvnet/ruflo) (66,3 тыс. звезд по состоянию на 27 июля 2026 г., по сравнению с 18,9 тыс.+ в марте 2026 г.)
**npm**: `ruflo` (ранее `claude-flow`) | **Лицензия**: MIT

Наиболее распространенная внешняя структура оркестровки для Claude Code. Превращает ее в мультиагентную платформу с иерархическими роями (королева + рабочие), 98 специализированными агентами (кодировщиками, тестировщиками, рецензентами, архитекторами, аудиторами безопасности) и постоянной памятью через SQLite (AgentDB).

**Два пути установки** (очень разные площади поверхности):

| | Путь к плагину | Путь CLI |
|---|---|---|
| Что вы получаете | Слэш-команды + определения агентов для каждого плагина | Полный цикл: 98 агентов, 30 навыков, сервер MCP, хуки, демон. |
| Файлы в рабочей области | Ноль | `.claude/`, `.claude-flow/`, `CLAUDE.md`, помощники, настройки |
| Зарегистрирован сервер MCP | Нет | Да (`memory_store`, `swarm_init`, `agent_spawn` и т. д.) |
| Лучшее для | Пробуем один плагин без каких-либо коммитов | Производственное использование |

```bash
# Plugin path
/plugin marketplace add ruvnet/ruflo
/plugin install ruflo-core@ruflo    # or any of the 33 available plugins

# CLI path (full install — inspect source first)
npx ruflo@latest init wizard
# Do NOT use the curl|bash variant: it pulls from the old repo name (claude-flow) and bypasses package manager security
```

**Основные функции**:
- Маршрутизатор Q-Learning направляет задачи нужному агенту на основе прошлых шаблонов
- Более 30 встроенных навыков, 27 хуков, встроенных в Claude Code.
- Сервер MCP с 314 инструментами (только путь CLI)
- Сохранение сеансов на базе SQLite с разделением памяти между агентами (AgentDB)
- **Агентная федерация**: межмашинное сотрудничество с нулевым уровнем доверия посредством mTLS и удостоверения ed25519, с удалением личных данных перед выходом и оценкой поведенческого доверия для каждого узла. В отличие от LangGraph или CrewAI (по умолчанию с одним экземпляром), агенты Ruflo могут координировать действия между машинами и организациями, не обмениваясь необработанными данными. Управляется с помощью 9 инструментов MCP и 10 команд CLI.
- 33 собственных плагина на торговой площадке Claude Code (swarm, память RAG, безопасность, тестирование браузера, Интернет вещей и многое другое)
- Дополнительный веб-интерфейс по адресу [flo.ruv.io](https://flo.ruv.io/) и планировщик целей GOAP по адресу [goal.ruv.io](https://goal.ruv.io/).
- Неинтерактивный режим CI/CD

> **Примечание к претензиям**: проект публикует показатели производительности (оценки SWE-Bench, множители скорости, более 22 миллионов загрузок экосистемы) без полностью независимой методологии. Суть теста SOTA для сравнения с LangGraph, AutoGen и CrewAI существует, но независимое воспроизведение не подтверждено. Считайте все цифры непроверенными.

> **Примечание о зрелости**: в начале 2026 года переименован из claude-flow. Пакет npm теперь называется `ruflo` (подтверждено). Проверьте исходный код перед развертыванием в производстве.

## <a name="knowledge-graph"></a>График знаний

### Графифицировать

Инструмент CLI, который отображает базу кода (а также любое сочетание документов, PDF-файлов, изображений и видео) в граф знаний с возможностью запроса. Вместо того, чтобы просить Claude Code перечитывать файлы каждый сеанс, чтобы понять структуру, вы строите граф один раз и запрашиваете его. Выгода: гораздо меньше токенов, потраченных на ориентацию, и обнаруженные соединения, которые пропускают grep и ручной просмотр.

**GitHub**: [github.com/safishamsi/graphify](https://github.com/safishamsi/graphify)
**PyPI**: `graphifyy` (обратите внимание на двойной y: пакет single-y — это другой, несвязанный проект)
**License**: MIT | **Язык**: Python 3.10+

| Атрибут | Подробности |
|-----------|---------|
| **Установить** | `uv tool install graphifyy` (рекомендуется) или `pipx install graphifyy` |
| **Платформы** | Claude Code, Cursor, Copilot CLI, Aider, Codex, Gemini CLI, OpenCode и еще 8 |
| **Подтвержден** | Май 2026 г. (v0.8.9) |

**Выходы за прогон:**

| Файл | Содержание |
|------|---------|
| `graphify-out/graph.html` | Интерактивная визуализация с кликабельными узлами и фильтрацией |
| `graphify-out/GRAPH_REPORT.md` | Ключевые понятия, удивительные связи, предлагаемые вопросы |
| `graphify-out/graph.json` | Данные структурированного графа повторно используются в каждом запросе. |

**Под капотом: файлы кэша в `graphify-out/`:**

Помимо трех общедоступных файлов, Graphify поддерживает уровень кэша, который обеспечивает поэтапное восстановление. Эти скрытые файлы появляются после первого запуска:

| Файл | Роль |
|------|------|
| `.graphify_ast.json` | Необработанный AST от Tree-sitter, весь код, без вызова API, часто 15-20 МБ. |
| `.graphify_detect.json` | Вывод `collect_files()`: полный манифест файла |
| `.graphify_chunk_XX.json` | Пакеты файлов отправляются в AI API для семантического извлечения. |
| `.chunk_manifest_XX.json` | Какие файлы принадлежат каждому фрагменту, используемому `--update` для изоляции изменений |
| `.graphify_semantic.json` | Семантические внедрения после дедупликации сущностей |
| `.graphify_uncached.txt` | Файлы, еще не кэшированные при последнем запуске |
| `cache/` | Хэши контента для каждого файла для обнаружения изменений |

На `--update`: Graphify сравнивает текущие хеши контента с кешем, определяет, какие файлы были изменены, повторно обрабатывает только их фрагменты с помощью AI API, затем реконструирует `graph.json` из неизмененных фрагментов и новых. Файлы, которые не были изменены, стоят нулевых токенов API.

**Инициализировать в проекте:**

```bash
# 1. Build the graph from project root
graphify .

# 2. Register with Claude Code — installs the /graphify skill
graphify install --platform claude

# 3. Commit the output so teammates start with a pre-built map
git add graphify-out/ && git commit -m "chore: add graphify knowledge graph"
# Or exclude it entirely: echo "graphify-out/" >> .gitignore

# 4. Subsequent runs: --update uses semantic caching by content hash
#    Only changed files get re-processed — saves API cost on large repos
graphify . --update
```

**Запрос графа:**

```bash
graphify query "what connects auth to the database?"
graphify path "UserService" "DatabasePool"
```

После регистрации в Claude Code установленный навык позволяет Claude читать `graph.json` напрямую, а не сканировать файлы, поэтому запросы выполняются внутри диалога без повторного чтения источника.

**Основные аналитические функции:**

- **God nodes**: архитектурные хабы с высокой степенью связи, компоненты, от которых зависит все остальное
- **Удивительные связи**: межмодульные связи, ранжированные по степени неожиданности
- **Извлечение обоснования дизайна**: извлекает ПОЧЕМУ из встроенных комментариев и строк документации, а не только ЧТО
- **Теги доверия**: все отношения помечаются тегами `EXTRACTED` (явный import/call), `INFERRED` (выводится из контекста) или `AMBIGUOUS` (помечается для проверки)

**Поддержка файлов**: 31 язык программирования, Markdown, RST, YAML, HTML, PDF-файлы. Видео и аудио: `pip install graphifyy[video]` (локальный быстрый шепот, без внешнего вызова API). Офисные документы: `pip install graphifyy[office]`.

**MCP режим сервера:**

```bash
# Exposes: query, shortest_path, god_nodes, neighbor_traversal tools
graphify mcp
```

Для больших баз кода (graph.json более ~5 МБ) режим MCP значительно более эффективен. Без него Claude сначала загружает `GRAPH_REPORT.md` для ориентации, а затем при необходимости извлекает целевые разделы `graph.json`. При работающем MCP Claude вызывает `god_nodes`, `query "auth flow"` или `shortest_path` напрямую и получает только соответствующий подграф, без полной загрузки графа в контекст. Полная загрузка `graph.json` объемом 22 МБ стоит гораздо больше токенов, чем 4-5 целевых вызовов инструмента MCP, возвращающих тот же ответ.

**Как Claude использует установленный навык:**

После `graphify install --platform claude` навык вводит правило: если `graphify-out/` существует в текущем проекте, рассматривайте вопросы архитектуры как запросы к графу, а не как чтение файлов. Порядок разрешения на практике:

1. Claude сначала читает `GRAPH_REPORT.md`, компактный (обычно 150-200 КБ), дает ориентацию на божественные узлы и неожиданные связи.
2. По конкретным запросам Claude обращается к целевым разделам `graph.json`.
3. При работающем сервере MCP: Claude вызывает инструменты `query`, `shortest_path`, `god_nodes` или `neighbor_traversal` напрямую, что намного дешевле при масштабировании.

Без Graphify: Claude перечитывает исходные файлы в каждом сеансе, чтобы понять структуру, сжигая токены при ориентации. С Graphify: эта стоимость оплачивается один раз во время сборки, а затем амортизируется во всех сеансах.

**Дополнительный экспорт**: вики в стиле Википедии с вики-ссылками между сообществом, хранилище Obsidian с макетами Canvas, HTML со складным деревом D3, диаграммы потоков вызовов Mermaid с интерактивным zoom/pan, графическая отправка Neo4j.

**Privacy**: файлы кода обрабатываются локально с помощью Tree-Sitter, API не вызывает анализ кода. Документы и PDF-файлы отправляются на настроенную вами модель искусственного интеллекта API. Для полностью локального вывода: `pip install graphifyy[ollama]`.

**Рабочий процесс команды**: передача `graphify-out/` в git дает каждому товарищу по команде общую карту в клоне. Graphify предлагает драйвер слияния git, который предотвращает появление маркеров конфликтов в `graph.json`, а также дополнительные перехватчики git для автоматического перестроения при фиксации.

**Pipeline:** `detect() → extract() → build_graph() → cluster() → analyze() → report() → export()`: каждая ступень изолирована, нет общего состояния. Добавление языка требует регистрации экстрактора в `extract.py`, а также зависимостей Tree-Sitter.

**Limitations:**

- Имя пакета `graphifyy` (двойная буква y) является основным моментом: `pip install graphify` устанавливает несвязанный инструмент без каких-либо ошибок.
- Извлечение Doc/PDF выполняет вызовы AI API; стоимость зависит от объема документации, а не от размера кода
- v0.8.x быстро развивается; некоторые флаги CLI смещаются между второстепенными версиями, перед обновлением проверьте журнал изменений.

**Когда использовать**: Большие или незнакомые базы кода, где Claude Code сжигает токены, перечитывая файлы только для понимания структуры. Постройте график один раз, а затем запросите его. Высокая ценность для адаптации устаревшего кода, навигации по монорепозиториям и проверки архитектуры перед PR.

## <a name="skills-observability"></a>Наблюдение за навыками

### Скиллсайт

Единственный инструмент с открытым исходным кодом для анализа использования навыков на уровне команды. Принимает телеметрию Claude Code OTEL и показывает, какие навыки на самом деле используются (кем, как часто, в каких сеансах), а не какие навыки, по вашему мнению, используются.

| Атрибут | Подробности |
|-----------|---------|
| **Источник** | [GitHub: PackmindHub/skillsight](https://github.com/PackmindHub/skillsight) |
| **Автор** | Седрик Тейтон (Packmind) |
| **Лицензия** | Апач 2.0 |
| **Версия** | 0.2.1 (активен, 101 коммит) |
| **Stack** | Bun + Hono + PostgreSQL + React 18 (автономное размещение Docker) |
| **Проглатывание** | OTLP HTTP из Claude Code или Loki из Grafana Cloud |

**Что он отслеживает: вызовы навыков** для каждого пользователя и сеанса, каталог плагинов (синхронизированный с торговыми площадками Git), когортную сегментацию, журнал аудита, поток событий в реальном времени.

**Два режима приема:**

*Direct OTLP push*: Claude Code отправляет телеметрию прямо в Skillsight. Меньшая задержка, более простая настройка:

```json
// ~/.claude/settings.json
{
  "env": {
    "OTEL_LOGS_EXPORTER": "otlp",
    "OTEL_EXPORTER_OTLP_LOGS_ENDPOINT": "http://your-skillsight:4200/api/v0/telemetry/v1/logs",
    "OTEL_EXPORTER_OTLP_LOGS_HEADERS": "Authorization=Bearer <your-ingestion-token>",
    "OTEL_EXPORTER_OTLP_PROTOCOL": "http/json",
    "OTEL_LOG_TOOL_DETAILS": "1",
    "OTEL_LOGS_EXPORT_INTERVAL": "5000"
  }
}
```

*Loki pull*: Skillsight опрашивает конечную точку Grafana Cloud Loki по настраиваемому расписанию. Полезно, если вы уже агрегируете там журналы.

Токен приема создается на основе пользовательского интерфейса Skillsight (`/tokens`) и имеет отдельный от токенов сеанса тип JWT: он может только записывать данные телеметрии, но не имеет доступа к интерфейсу администратора.

**Настройка (прямое нажатие):**

1. `docker compose up -d`: запускает Skillsight на порту 4200 + Postgres
2. Войдите в `http://localhost:4200` с первоначальными учетными данными администратора.
3. Перейдите на страницу адаптации: она генерирует полный фрагмент settings.json с предварительно созданным токеном приема.
4. Скопируйте фрагмент в `~/.claude/settings.json` или в свой проект `.claude/settings.json`.
5. Запустите сеанс Claude Code: события появятся на панели управления в течение 5 секунд.

**Предостережения по развертыванию (прочитайте перед запуском в производство):**

- **Никогда не развертывайте без переопределения `JWT_SECRET` и `ADMIN_PASSWORD_INITIAL`**: поставляемые значения по умолчанию представляют собой буквальные общедоступные строки (`change-me-in-production...` и `admin`). Предупреждение во время загрузки не выдается. Любой экземпляр, доступный из Интернета с этими настройками по умолчанию, тривиально скомпрометирован.
- **Установите `PUBLIC_BASE_URL`** в `.env`: эта переменная управляет как политикой CORS, так и конечной точкой, показанной во фрагменте адаптации. Без него CORS является разрешающим (отражает источник запроса), а фрагмент показывает `https://your-domain.com`.
- **Запускайте миграцию Drizzle вручную при обновлении**: контейнер не запускает `drizzle-kit migrate` автоматически при запуске (начиная с версии 0.2.1). При обновлении с версии 0.1.x запустите миграцию перед запуском нового контейнера, иначе приложение выйдет из строя из-за устаревшей схемы.

Это известные проблемы, находящиеся в активной разработке. Исправления просты; отслеживать разрешение в репо.

**Limitations:**

- Только самостоятельное размещение: никаких предложений SaaS.
- Управление исходным кодом Marketplace доступно только для API (пока нет пользовательского интерфейса, в документации нет примеров Curl).
- Несоответствие имени изображения в README (`skills-obs` и фактическое `skillsight`): следуйте `docker-compose.yml`, а не фрагменту завитка README.
- v0.2.x: молодой проект, некоторые недочеты в документации; однако CLAUDE.md действительно полезен для участников.

**Когда использовать:** Вы хотите знать, какие навыки ваша команда фактически использует на практике, а какие вы применяете. Полезно для оценки рентабельности инвестиций в библиотеку навыков, измерения эффективности адаптации и выявления мертвых навыков.

> **По теме:** [Packmind ContextOps Platform](#engineering-standards-distribution): тот же авторский инструмент для *, распространяющий стандарты* на ИИ-агенты. Skillsight сообщает вам, какие навыки используются; Packmind помогает вам создавать и синхронизировать их.
> **Оценка:** [2026-05-18-skillsight-packmind.md](../../docs/resource-evaluations/2026-05-18-skillsight-packmind.md)

См. [Переключение когнитивного режима](../workflows/gstack-workflow.md) для выбранного пути, а не для полного перечня навыков. Пакет документов контроля; он не определяет бережливый результат или измеряемую выгоду от реализации. Создано Гарри Таном. Информацию об агентах ИИ, которые имитируют исполнительные роли, а не анализируют решения по продукту, см. в разделе [AI Executive Agents](./ai-executive-agents.md).
- **[Навыки Мэтта Покока](https://github.com/mattpocock/skills)**: индивидуальные, компонуемые инженерные навыки. `/triage` обрабатывает входящую работу, `/to-spec` сохраняет решения, когда работа охватывает сеансы, `/to-tickets` создает независимо тестируемые вертикальные срезы, а `/tdd`, `/code-review` и `/retro` замыкают цикл обучения. Автор прямо советует пропускать `/to-spec`, когда работа умещается в один сеанс. Рассматривайте их как возможные элементы управления бережливым производством и измеряйте их влияние на незавершенное производство, ожидание и принятые результаты, прежде чем называть рабочий процесс «бережливым».
- **[Ponytail](https://github.com/DietrichGebert/ponytail)**: режим «Ленивый старший разработчик» для ИИ-агентов. Прежде чем писать код, агент останавливается на первой ступеньке, которая отвечает: должна ли она существовать? → стандартная библиотека? → встроенная функция платформы? → установлена ​​зависимость? → одна строка? → только тогда тот минимум, который работает. Его README (прочитано 30 сентября 2026 г.) сообщает в среднем примерно на 54 % меньше кода (до 94 % на одну задачу), на 22 % меньше токенов и примерно на 20 % меньшую стоимость выполнения 12 функциональных задач с Haiku 4.5 (n = 4), а также утверждает, что прежний показатель 80–94 % был потолком для каждой задачи, а не средним значением. Сторонний тест, проведенный компанией Stet, показал +20%, а затем -2% стоимости рабочей нагрузки за два повторения, с большим количеством проигрышей в тестах, чем побед (см. [независимые тесты](./context-engineering-tools.md#independent-benchmarks)). Три уровня интенсивности: `lite` (предложить более ленивый путь, позволить пользователю выбрать), `full` (принудительно использовать лестницу, по умолчанию), `ultra` (экстремист YAGNI, бросает вызов требованию в том же ответе). Намеренные ярлыки отмечены комментарием `ponytail:`, указывающим потолок и путь обновления; `/ponytail-debt` собирает их в реестр, чтобы «позже» оставалось видимым. Четыре команды: `/ponytail [lite|full|ultra|off]`, `/ponytail-review` (дополнительный анализ текущих различий), `/ponytail-audit` (сканирование всего репозитория), `/ponytail-debt` (ярлык реестра). Установите: `/plugin install ponytail@ponytail`. Массачусетский технологический институт. Поддерживает 13 агентов: Claude Code, Codex, GitHub Copilot CLI, Gemini CLI, Антигравитация CLI, OpenCode, pi, OpenClaw, Cursor, Windsurf, Cline, Kiro и VS Code с расширением Codex.
- **[fable-mode](https://github.com/mrtooher/fable-mode)**: Навык дисциплины выполнения для сложных задач, структурированный в виде 4-шагового цикла: (1) напишите пронумерованную карту этапов с ожидаемыми результатами, прежде чем прикасаться к чему-либо, (2) делегируйте независимые этапы параллельным подагентам, где позволяет среда выполнения, (3) проверьте каждый этап проверкой, которая может фактически потерпеть неудачу (тесты, различия, чтение исходных кодов, не самооценка), (4) самокритика в качестве скептически настроенного рецензента перед сдачей. Назван в честь модели Claude Fable, но работает на любой модели; честно говоря, это формирует процедуру, а не потолок возможностей. Три варианта: `fable-mode` (встроен в текущую модель), `fable-sonnet` (прикрепляет субагент Sonnet), `fable-haiku` (прикрепляет субагент Haiku для экономичной работы). Включает в себя 4 проработанных примера в разных областях (ошибка с нулевым путем API, ошибочно приписываемое исследовательское заявление, нули SQL, молча удаленные из AVG, многосессионный рефакторинг без готовых критериев), каждый из которых точно показывает, где неудачная проверка обнаруживает, а что - одиночный промах. Стоит отметить два эксплуатационных правила: отображать накопленные предупреждения на пороге 3, а не одно за другим; привязывайте замены sed к границам слов, чтобы избежать повреждения составных слов. Установка: скопируйте каталог навыков туда, откуда ваша среда Claude загружает навыки (записи в реестре плагинов пока нет). Нет лицензии. 802 звезды, 86 вилок по состоянию на 27 июля 2026 г. (было 477 звезд, 54 вилки через 5 дней после запуска в июне). 2026).

Развертывание с оговорками (см. [Skills Observability](#skills-observability)). |

| **Воспроизведение сеанса** | ✅ **FILLED**: [Entire CLI](#entire-cli) хранит каждый сеанс агента как контрольную точку, связанную с его фиксацией, которую можно объяснить с помощью `entire checkpoint explain` и возобновить с помощью `entire session resume`. |
| **Автоматическое сканирование безопасности `.claude/`** | ✅ **FILLED**: [AgentShield](https://github.com/affaan-m/agentshield) (запущен в феврале 2026 г.): сканер на 102 правила с оценкой A–F, интеграцией действий `--fix` и GitHub. |
| **Отслеживание проблем в собственном агенте** | Нет установленного инструмента для отслеживания проблем на основе уценки и git-commit с Claude Code. [fp.dev](https://fp.dev/) — это решение на ранней стадии (сначала локальное, навыки `/fp-plan` + `/fp-implement`, просмотр различий), но ему не хватает сигналов внедрения, и для настольного приложения требуется Apple Silicon. | **Программная оркестровка в песочнице** | Смотреть: [Sandcastle](https://github.com/mattpocock/sandcastle) (`@ai-hero/sandcastle`, Мэтт Покок): TypeScript API для запуска агентов в контейнерах Docker/Podman/Vercel с управлением стратегией филиалов и шаблонами подсказок. Уникальная ниша, но не готовая к руководству по версии 0.5.x (активные ошибки, только для TypeScript, требуется отдельная жесткая зависимость `ANTHROPIC_API_KEY`, Docker/Podman). Вернитесь к версии 1.0. |
| **Кроссплатформенный чат-мост между агентом и человеком с управлением** | Смотреть: [Switch](https://github.com/sandbox-quantum/switch) (Flint AI / SandboxAQ): шина на основе матрицы, соединяющая разнородных агентов (Claude Code, Codex, OpenCode, все, что говорит по его протоколу) и людей в одной комнате, двунаправленно ретранслируемая в Slack, Microsoft Teams, Discord, Telegram и Mattermost, с централизованной моделью авторизации по наследству владельцев. В этом списке нет сопоставимого многоплатформенного и многоплатформенного моста; Agent-chat, указанный выше, является наиболее близким совпадением имени, но представляет собой локальную панель мониторинга, доступную только для чтения, а не работающий внешний мост. До 1.0 (`0.21.0`), 252 звезды за 6 недель, коэффициент шины близок к 1. Оценка: [switch-agent-human-chat-bridge.md](../../docs/resource-evaluations/switch-agent-human-chat-bridge.md). |
