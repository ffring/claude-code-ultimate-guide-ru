# Распространение плагинов и подсказки по рекомендациям

Плагин объединяет повторно используемые навыки Claude Code, агенты, перехватчики, серверы MCP, серверы LSP, мониторы и настройки. Используйте автономную конфигурацию `.claude/` для локальной или специфичной для проекта итерации; используйте плагин, когда тому же расширению требуется общедоступный модуль распространения с поддержкой версий. Документация по плагину [Anthropic](https://code.claude.com/docs/en/plugins) является авторитетным источником поддерживаемой структуры и поведения загрузки.

Эта страница отделяет распространение от рекомендаций. Торговая площадка делает плагин доступным. Маркер `<claude-code-hint />` может спросить пользователя, следует ли устанавливать соответствующий официальный плагин после выполнения команды CLI. Ни один из механизмов не устраняет необходимости проверять код, который может запускать перехватчики, команды, серверы MCP или исполняемые файлы.

## Распространять через торговую площадку

Официальный маркетплейс — это каталог плагинов и их исходников. Его `marketplace.json` может ссылаться на локальные относительные пути, GitHub или другие URL-адреса Git, подкаталоги git, пакеты npm, архивы HTTPS и каталоги плагинов, созданные командой. Тип источника определяет, как Claude Code получает плагин; он не устанавливает, что плагин безопасен для конкретной организации.

Для распространения командой или сообществом создайте плагины, перечислите их в `marketplace.json`, разместите этот каталог в репозитории Git или другом поддерживаемом источнике, затем попросите пользователей добавить торговую площадку и установить отдельный плагин. Пользователи обновляют свою копию на местном рынке с помощью `/plugin marketplace update`. Руководство по торговой площадке [Anthropic](https://code.claude.com/docs/en/plugin-marketplaces) определяет манифест, типы источников, поведение версий и зарезервированные официальные названия торговой площадки.

Протестируйте плагин перед публикацией в локальном каталоге:

```bash
claude --plugin-dir ./my-plugin
```

Локальный тест показывает, что Claude Code может загрузить плагин. Это не доказывает, что его перехватчики, серверы MCP, зависимости или пути к исполняемым файлам подходят для машины другого пользователя. Просмотрите эти компоненты под теми же элементами управления цепочкой поставок, которые используются для других зависимостей исполняемых файлов.

## Рекомендательный канал `<claude-code-hint />`

Протокол подсказок позволяет команде сопровождающего CLI или SDK рекомендовать официальный плагин Anthropic для торговой площадки. Когда команда выполняется с помощью инструмента Bash Claude Code или PowerShell, она выдает один самозакрывающийся тег в отдельной строке. Claude Code удаляет маркер из вывода команды до того, как этот вывод достигнет модели, проверяет целевой плагин и может отображать приглашение на установку в основном сеансе интерактивного терминала.

```text
<claude-code-hint v="1" type="plugin" value="example-cli@claude-plugins-official" />
```

Документированные границы валидации узки и конкретны:

| Проверка или поведение | Что он устанавливает | Что не установлено |
|---|---|---|
| Маркер занимает собственную линию | Claude Code распознает синтаксис протокола. | Вывод команды заслуживает доверия. |
| Цель находится на рынке, контролируемом Anthropic. | Claude Code принимает только соответствующую официальную торговую площадку. | Испускающая команда и плагин принадлежат одному и тому же издателю. |
| В приглашении указывается отправляющая команда | Пользователь может увидеть, какая команда запросила рекомендацию. | Рекомендация командования необходима или подходит. |
| Маркер удаляется перед вводом модели. | Модель не получает линию маркера в качестве вывода команды. | Другие команды, выводимые на экран, или инструкции на экране безопасны. |
| Подтверждение пользователя | Claude Code не устанавливается автоматически. | Плагин, одобренный пользователем, можно безопасно включить. |

Последний столбец представляет собой оперативный вывод из документированных элементов управления, а не утверждение о том, что протокол проверяет происхождение между CLI и издателем плагина. Отнеситесь к подсказке как к рекомендации названного производителя, а затем проверьте плагин и его запись на рынке перед утверждением.

## Пользовательский контроль и ограничения подсказок

Claude Code показывает не более одной подсказки за сеанс и не более одной подсказки для данного плагина. Он не выдает запросы в субагентах, при запуске `claude -p` или агента SDK, хотя строки подсказок там все равно удаляются. Время ожидания запроса истекает как **No** через 30 секунд. Пользователь может отклонить один запрос или выбрать вариант, отключающий подсказки по установке плагина в будущем.

Подсказки не срабатывают, когда аналитика отключена, включая документированные переменные отказа от телеметрии и ситуации поставщика с автоматическим отказом от телеметрии. В командах-перехватчиках Claude Code удаляет и игнорирует тег. Таким образом, подсказка не является надежным каналом автоматизации или механизмом обеспечения соблюдения политики.

## Руководство для сопровождающих CLI и SDK

Выдавайте подсказку только для плагина, который указан на официальной торговой площадке Anthropic. Документированный протокол поддерживает версию `1`, тип `plugin` и значение `name@marketplace`. Запишите его в stderr в отдельной строке и запишите его выброс в переменную среды Claude Code.

Выбирайте ворота намеренно:

| Переменная | Документированная область применения | Trade-off |
|---|---|---|
| `CLAUDECODE` | Присутствует для команд, запускаемых Claude Code, а также в некоторых интегрированных терминалах, сеансах tmux и подпроцессах stdio MCP. | Широкий охват, но человеческий терминал может видеть необработанный тег. |
| `CLAUDE_CODE_CHILD_SESSION` | Присутствующий для подпроцессов Claude Code сам запускается. Требуется Claude Code v2.1.172 или новее. | Обычно избегает человеческого терминала, но более старые сеансы не получают подсказки, и долгоживущие дочерние процессы могут сохранять переменную. |

Отправка из полезной, понятной пользователю точки взаимодействия, такой как `--help`, неизвестная ошибка подкоманды, успешная аутентификация или сообщение при первом запуске. Не добавляйте тег в надежде, что он повлияет на модель или приведет к принудительной установке. Официальная ссылка на плагины [](https://code.claude.com/docs/en/plugin-hints) является источником протокола.

## Граница безопасности распределения

Цель официального рынка — это требование протокола для подсказок, а не общий вердикт безопасности для поведения исполняемого файла плагина. Прежде чем включать распределенный плагин, определите его манифест, компоненты, источник, поведение при установке зависимостей и область действия. Примените настройки плагина [и Marketplace](../core/settings-reference.md#plugins-and-marketplaces) и [Руководство по усилению безопасности](../security/security-hardening.md) перед распространением перехватчиков, конфигурации MCP или исполняемых файлов.
