# Инструменты агента: Beyond Claude Code

Claude Code — это один из инструментов в области, которая резко расширилась с 2024 года. Поставлены десятки агентских фреймворков, автономных программистов и мультиагентных систем, каждая из которых имеет разные компромиссы. На этой странице это поле сопоставлено, чтобы вы могли решить, когда Claude Code является правильным вызовом, а когда что-то другое подходит лучше.

**О чем рассказывается на этой странице**: терминальные агенты кодирования, автономные кодировщики, платформы многоагентной оркестрации и инструменты оркестрации агентов. Собственные мультиагентные возможности Claude Code (команды агентов, рабочие процессы, управляемые событиями, программное использование) документируются отдельно и повсюду связаны ссылками.

**Чего он не охватывает**: сравнения только для редактора. IDE, ADE и продукты, сочетающие в себе несколько интерфейсов, описаны в экосистеме [AI §6](./ai-ecosystem.md#6-ide-ade-and-hybrid-coding-environments). Гибридный продукт появляется здесь только тогда, когда его агент кодирования также можно использовать в качестве среды выполнения терминала. Инструменты оркестрации Multi-Claude (Gas Town, multiclaude, настольное приложение Conductor) находятся в [Сторонние инструменты: Multi-Agent Orchestration](./third-party-tools.md#multi-agent-orchestration).

Для полного поля CLI, IDE и облачных агентов используйте [Agent Harness Landscape](./agent-harness-landscape.md). Информацию о цикле, контексте, инструментах, разрешениях, восстановлении, наблюдаемости и автоматической оптимизации жгутов см. в разделе [Agent Harness Engineering](../core/agent-harness.md). Подробные циклы обратной связи, графики рабочих процессов, правила остановки и границы ответственности можно найти в [Loop & Graph Engineering](../core/loop-graph-engineering.md). Глоссарий [](../core/glossary.md) отделяет обвязки среды выполнения от обвязки репозитория, обвязки оценки, оркестраторов и метаобвязок.

## Спектр

Инструменты агента делятся на диапазон от интерактивных до автономных:

```
Interactive pair programmer
  Claude Code, Codex CLI, Aider, Goose, opencode, Gemini CLI, crush
        |
  Hermes Agent (interactive + scheduled + messaging gateways)
        |
Autonomous issue fixer
  SWE-agent, Devin, claude -p in CI
        |
Multi-agent framework (build your own)
  CrewAI, LangGraph, AutoGen/MAF, MetaGPT
        |
Agent orchestrator (manage a fleet)
  Symphony (issue → run), Paperclip (goal → org chart)
```

**Интерактивные агенты**: вы остаетесь в курсе, утверждаете действия, перенаправляете агента. Лучше всего подходит для ежедневного кодирования, отладки и исследовательской работы при изменении требований.

**Автономные агенты**: вы назначаете задачу и возвращаетесь к результату. Лучше всего подходит для четко определенных, ограниченных задач: исправить эту ошибку, реализовать эту спецификацию, просмотреть этот PR. Качество описания задачи определяет качество результата больше, чем выбор агента.

**Мультиагентные платформы**: библиотеки для создания пользовательских агентских систем. Не сами инструменты кодирования. Вы используете LangGraph для создания агента, а не для написания кода.

**Оптимизаторы и мета-обвязки**: системы, которые изменяют целевую обвязку и сравнивают возможные версии. Они не являются еще одной категорией агентов терминального кодирования. [ADAS](https://proceedings.iclr.cc/paper_files/paper/2025/hash/36b7acf6f6010652b3f2a433774a66fe-Abstract-Conference.html), [AFlow](https://arxiv.org/abs/2410.10762), [Meta-Harness](https://arxiv.org/abs/2603.28052)и [Agentic Harness Engineering](https://arxiv.org/abs/2604.25850) работают в этом внешнем контуре. Сравните их через слой исследования [Landscape](./agent-harness-landscape.md#harness-optimizers-and-meta-harnesses), а не размещая их рядом с Claude Code или Codex в таблице объектов времени выполнения.

## Раздел 1: Агенты терминального кодирования

Эти инструменты делают то же, что и Claude Code: сидят в вашем терминале, читают вашу кодовую базу, пишут код, запускают команды. Различия заключаются в поддержке моделей, модели стоимости и конкретных возможностях.

### 1.1 Codex CLI (OpenAI)

Прямой ответ OpenAI на Claude Code. Запущен в апреле 2025 года, создан на Rust, с открытым исходным кодом под Apache 2.0.

#### Что такое Codex CLI?

Терминальный ИИ-агент для написания, редактирования и запуска кода, созданный на основе семейства моделей OpenAI. Архитектура во многом повторяет Claude Code: вы описываете задачу, агент читает файлы, вносит изменения, запускает тесты и выполняет итерации. Основное отличие заключается в поставщике модели: Codex CLI взаимодействует с GPT-4o, o3, o4-mini и другими моделями OpenAI, а не с Claude.

Подписчики ChatGPT Pro и Team получают использование Codex CLI, включенное в их план, что делает его инструментом с нулевой предельной стоимостью для команд, уже платящих за OpenAI.

#### Claude Code против Codex CLI

| Аспект | Claude Code | Codex CLI |
|--------|-------------|-----------|
| **Модели** | Только семейство Claude (Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.1) | GPT-4o, o3, o3-mini, o4-mini, а также будущие модели OpenAI |
| **Язык** | TypeScript | Ржавчина |
| **Лицензия** | Открытый исходный код | Апач 2.0 |
| **Подписка** | Anthropic Claude Макс ($20-$200/mo) | OpenAI ЧатGPT Pro/Team ($20-$30/mo) |
| **MCP Поддержка** | Родная, растущая экосистема | Совместимость с MCP |
| **Каденция выпуска** | Еженедельно | Очень высокий (800+ релизов за 13 месяцев) |
| **Память** | CLAUDE.md + Автопамять | Соглашение AGENTS.md |
| **Skills/Hooks** | Полная система | Совместим со стандартом Agentskills.io. |

#### Когда выбирать Codex CLI

Подходит, если вы уже используете план ChatGPT Pro или Team и хотите избежать второй подписки. Это также правильный выбор, если вы предпочитаете GPT-4o или o3 для конкретных задач (рассуждение, анализ длинного контекста) и вам нужен терминальный агент, который использует эти модели изначально.

Плохо подходит, если ваша команда вложила средства в рабочие процессы Claude Code, файлы CLAUDE.md и шаблоны, специфичные для Anthropic. Когнитивные издержки переключения контекста между двумя средами агентов вполне реальны.

```bash
npm install -g @openai/codex
export OPENAI_API_KEY=sk-...
codex
```

### 1.2 Агент Гермеса (ранее OpenClaw)

Самая популярная платформа агентов с открытым исходным кодом по состоянию на май 2026 года. Создана Nous Research, лабораторией искусственного интеллекта, известной серией точно настроенных моделей Hermes. До конца 2025 года назывался OpenClaw, когда был переименован в Anthropic, восстановив поддержку подписки.

| Атрибут | Подробности |
|-----------|---------|
| **GitHub** | [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent) |
| **Звезды** | 170 000+ (май 2026 г.) |
| **Установить** | `pip install hermes-agent` или `curl -sSL install.hermes-agent.dev \| sh` |
| **Язык** | Питон (89%), TypeScript (8%) |
| **Лицензия** | Массачусетский технологический институт |
| **Версия** | v0.15.1 (июнь 2026 г.) |
| **Каденция выпуска** | Еженедельно (v0.10, 16 апреля → v0.15.1, июнь 2026 г.) |
| **Авторы** | 215+ |
| **Создатель** | Nous Research (Teknium, @teknium1) |

#### Что такое агент Гермес?

Самосовершенствующийся терминальный агент, который работает с более чем 200 провайдерами LLM, работает на любой платформе и подключается к 22 платформам обмена сообщениями (Telegram, Discord, Slack, WhatsApp, Signal, Teams, LINE, SimpleX и другим). Отличительной особенностью является цикл обучения (GEPA): после выполнения задач Hermes анализирует то, что сработало, извлекает повторно используемые шаблоны и автоматически генерирует навыки. Тесты сообщества показывают, что агенты с более чем 20 автоматически сгенерированными навыками выполняют аналогичные задачи на 40 % быстрее, чем новые экземпляры на той же базе кода.

История OpenClaw важна по двум причинам. Во-первых, путь миграции чист: `hermes-agent` импортирует воспоминания, навыки и настройки OpenClaw во время установки, поэтому затраты на переключение невелики. Во-вторых, разногласия по поводу выставления счетов Anthropic, возникшие в начале 2026 года, конкретно касались использования OpenClaw/Hermes в подписках Claude Max без надлежащего программного атрибуции выставления счетов. Объявление Anthropic в мае 2026 года поместило Hermes в корзину программного использования, и с тех пор это изменение было приостановлено (см. [Billing: Programmatic vs Interactive](../ultimate-guide.md#the-interactiveprogrammatic-billing-split-announced-then-paused)).

#### Claude Code против агента Гермеса

| Аспект | Claude Code | Агент Гермеса |
|--------|-------------|--------------|
| **Модели** | только Claude | 200+ через OpenRouter, OpenAI, Anthropic, HuggingFace, локально |
| **Self-improvement** | Каждая сессия начинается заново | Навыки автоматически генерируются на основе повторяющихся шаблонов |
| **Обмен сообщениями** | Терминал + IDE | Терминал + 22 чат-платформы |
| **Cron-планирование** | Подпрограммы (облако Anthropic) | Встроенный cron, работает локально. |
| **Биллинг** | Подписка или API | Оплатите напрямую своему провайдеру LLM |
| **Агент SDK** | Anthropic-specific | Плагин `ctx.llm` для любого провайдера |
| **Навыки** | Система SKILL.md | Центр навыков (agentskills.io) + генерируется автоматически |
| **Память** | CLAUDE.md + Автопамять | Межсессионная постоянная память, курируемая агентом |

#### Когда выбирать агента Hermes

Модельно-независимый случай является самым сильным аргументом. Если вы хотите использовать Claude для генерации кода, GPT-4o для конкретных задач рассуждения и локальную модель (через Ollama) для автономной работы, Hermes обрабатывает все три в одном агенте. Claude Code не может.

Цикл самосовершенствования действительно дифференцирован. За 30–40 сеансов работы с одной и той же кодовой базой Hermes создает библиотеку навыков, специфичных для шаблонов вашего проекта. Тесты сообщества показывают, что совокупный прирост составляет 40% быстрее при выполнении задач после накопления 20+ навыков. CLAUDE.md создан человеком и намеренно; Навыки Hermes генерируются машиной и зависят от проекта. Разные механизмы, оба стоит иметь.

Интеграция 22 платформ обмена сообщениями полезна для команд, которые хотят взаимодействовать со своим агентом через Telegram или Slack, а не через терминал. Не является приоритетом для большинства разработчиков, но критичен для некоторых рабочих процессов.

Плохо подходит, если вы инвестируете в экосистему Anthropic (подписка Claude Max, подпрограммы, агент SDK). Anthropic не позволяет сторонним разработчикам направлять запросы через учетные данные Free, Pro или Max от имени своих пользователей ([Claude Code, юридические вопросы и соответствие требованиям](https://code.claude.com/docs/en/legal-and-compliance)). Anthropic также объявил, а затем приостановил введение отдельного программного кредита за использование сторонних приложений; пока он приостановлен, это использование зависит от ограничений вашей подписки. Учитывайте и то, и другое.

#### Быстрый старт

```bash
pip install hermes-agent

# Or one-line installer
curl -sSL install.hermes-agent.dev | sh

# Import from OpenClaw if migrating
hermes import --from openclaw

# Start (terminal-only, no WebUI, no dashboard)

```

У Hermes нет официального графического интерфейса. Точка входа — `hermes chat` в терминале. На Windows требуется WSL2; Встроенная поддержка Windows не существует. Проект сообщества (`hermes-webui`) существует, но не поддерживается Nous Research.

#### Известные эксплуатационные проблемы (v0.15.x)

Некоторые режимы сбоя повторяются в производственных развертываниях и не очевидны из документации. Следующие сведения взяты из отчетов сообщества и проверенных проблем на трекере проекта.

**Агент выполняется перед анализом.** Поведение по умолчанию — немедленное начало написания кода без перечисления затронутых файлов и предложения подхода. При сложных рефакторингах это приводит к частичной записи до того, как будет понятна область действия. Добавьте этот блок в `SOUL.md` (файл идентификации, добавляемый при каждом запуске сеанса):

```
## Defaults
Before any development action, explicitly list:
1. Files that will be modified
2. Proposed approach
3. Identified risks
Never write code before confirming these three points.
```

`SOUL.md` сохраняет личность и поведение агента. `AGENTS.md` содержит правила, специфичные для проекта (пути, порты, команды). Их смешивание создает путаницу при переключении проектов.

**Kanban параллелизм флуд.** Конфигурация по умолчанию имеет `max_in_progress_per_profile: null` (без ограничений) в сочетании с `auto_decompose_per_tick: 3`. Пакет из 10 задач может создать более 30 одновременно работающих работников за считанные секунды. Явные ограничения в `.hermes/config.yaml`:

```yaml
kanban:
  max_in_progress_per_profile: 2
  auto_decompose_per_tick: 1
  task:
    max_runtime_seconds: 300
```

**Subprocess PATH не унаследован.** Двоичные файлы вне `/usr/bin` и `/usr/local/bin` невидимы для подпроцессов Hermes (открытый код, узел, управляемый nvm, pyenv Python, любой инструмент, установленный под `$HOME`). Исправление в `.hermes/config.yaml`:

```yaml
terminal:
  env_passthrough:
    - PATH
```

Начиная с версии 0.15.1, эта проблема частично решена для сред Docker (npx, npm, разрешение узла против `/usr/local/bin`). Собственные установки по-прежнему требуют ручной настройки, описанной выше.

**Workers, которые завершают работу без закрытия задач.** Worker, который завершает свою работу и завершает работу без вызова `kanban_complete` или `kanban_block`, навсегда оставляет задачу в состоянии «в процессе». Диспетчер может перезапустить работника в цикле (ошибка № 28712). Добавьте это правило в каждый рабочий профиль:

```
Every session must end with an explicit call to kanban_complete or kanban_block.
Exiting without this call is a protocol violation and blocks downstream tasks.
```

Повреждение **SQLite на `kanban.db`.** Быстрое создание задач, частые перезапуски шлюза через SIGTERM и одновременный доступ шлюза к одному и тому же файлу могут привести к повреждению базы данных. Минимальная гарантия:

```bash
# Hourly backup (add to crontab)
0 * * * * cp ~/.hermes/kanban.db ~/.hermes/kanban.db.bak.$(date +%Y%m%d%H)
```

Доступно восстановление с помощью `sqlite3`: дамп в SQL, реимпорт в новый файл, замена. Открытый RFC (#23717) предлагает заменить SQLite подключаемым серверным компонентом (PostgreSQL, MySQL) для многоагентных развертываний.

**`HERMES_HOME` не распространяется на подпроцессы.** В режиме профиля подпроцессы, запускаемые шлюзом, запускаются с минимальной средой и не наследуют `HERMES_HOME`. Они молча возвращаются к `~/.hermes`, записывая воспоминания и данные сеанса не в тот профиль. Обходной путь до тех пор, пока не будет исправлено вышестоящее исправление:

```bash
export HERMES_HOME=~/.hermes/profiles/your-profile-name
hermes ...
```

Издержки **Token значительны.** Каждый вызов LLM несет около 13 900 токенов фиксированных издержек перед любым содержимым задачи: определениями инструментов (~8-9 КБ) и системными приглашениями (~5 КБ). Интеграция шлюза обмена сообщениями (Telegram, LINE, Discord) добавляет к этому 15-20 тысяч токенов за запрос. Анализ сообщества (проблема № 4379) зафиксировал 4 миллиона токенов, израсходованных за два часа на неправильно настроенном шлюзе Telegram. Ограничить контекст явно:

```yaml
context:
  max_tokens: 32000
```

### <a name="13-aider"></a>1.3 Помощник

Оригинальный программатор AI-пар терминала. Запущенный в 2023 году Полем Готье еще до появления Claude Code, Aider установил многие из соглашений, которые были приняты более поздними инструментами: прямое редактирование файлов, автоматические фиксации git, многофайловые контекстные окна.

| Атрибут | Подробности |
|-----------|---------|
| **GitHub** | [Aider-AI/aider](https://github.com/Aider-AI/aider) |
| **Звезды** | 45 400+ (май 2026 г.) |
| **Установить** | `pip install aider-install && aider-install` |
| **Язык** | Питон (80%) |
| **Лицензия** | Апач 2.0 |
| **Создатель** | Поль Готье (Поль Готье) |
| **Загрузки PyPI** | 5.3M+ |

#### Что такое Айдер?

Помощник по кодированию на основе Python, который редактирует файлы в локальном репозитории git и автоматически фиксирует их с описательными сообщениями. Ключевая характеристика: почти универсальная поддержка моделей через LiteLLM, охватывающая GPT-4o, семейство Claude 5, Gemini, Ollama и десятков других поставщиков. Эйдер популяризировал форматы редактирования «весь файл» и «разница», которые информировали о том, как последующие агенты обрабатывают изменения файлов.

Траектория тестов SWE-Bench хорошо отражает эту историю: Aider удерживал высший балл в SWE-Bench Verified в течение нескольких месяцев в 2024–2025 годах, прежде чем модели с более широким контекстом и более способные агенты превзошли его. Этот рекорд закрепил за ним репутацию серьезного инструмента, а не просто удобной оболочки.

#### Claude Code против Айдера

| Аспект | Claude Code | Айдер |
|--------|-------------|-------|
| **Поддержка модели** | только Claude | GPT-4o, Claude, Gemini, Ollama, более 50 поставщиков |
| **Интеграция с Git** | Нативный (читает .git, запускает git) | Глубокий (автоматические фиксации, сообщения о фиксации, контекст обвинения) |
| **Архитектура** | Anthropic собственный | Открытый исходный код, LiteLLM под капотом |
| **Редактирование файлов** | На основе инструментов (редактирование, запись) | В модель отправляется весь файл или формат различий. |
| **Веб-поиск** | Через MCP | Не родной (требуется плагин) |
| **Агентный контур** | Полная (многооборотная, с использованием инструмента) | Полный (автоматически принимает изменения в режиме архитектора) |
| **Каденция выпуска** | Еженедельно | Ежемесячно (последняя версия: v0.86.0, август 2025 г.) |

Здесь имеет значение последняя дата выпуска, август 2025 года: Aider остается поддерживаемым и функциональным, но частота выпуска замедлилась по сравнению с Claude Code и Hermes. Это не является предупреждающим знаком само по себе, но перед внедрением сверьте его с необходимостью использования последних функций.

#### Когда выбирать Айдер

В лучшем случае: вам нужна поддержка нескольких моделей в зрелом, проверенном в боевых условиях инструменте и вы не хотите эксплуатационных расходов, присущих Hermes. Aider проще в настройке, чем Hermes, занимает меньше места и имеет многолетнюю документацию сообщества.

Также хорошо подходит для команд, которые имеют строгую дисциплину git и хотят, чтобы каждое изменение ИИ было явно зафиксировано с четким сообщением. Поведение автоматической фиксации Aider более агрессивно, чем у Claude Code (который по умолчанию запрашивает перед фиксацией).

#### Быстрый старт

```bash
pip install aider-install && aider-install

# With Claude
export ANTHROPIC_API_KEY=sk-ant-...
aider --model claude-sonnet-5-5

# With GPT-4o
export OPENAI_API_KEY=sk-...
aider
```

См. [aider.chat](https://aider.chat) для получения полного списка моделей и вариантов конфигурации.

### <a name="14-goose-aaifblock"></a>1.4 Гусь (AAIF/block)

Агент общего назначения, а не просто инструмент кодирования. Первоначально построенный Block (ранее Square), передан в AAIF (Фонд агентской инфраструктуры искусственного интеллекта) Linux Foundation для обеспечения долгосрочной нейтральности управления.

**Полное покрытие экосистемы [AI §11.1: Goose](./ai-ecosystem.md#111-goose-open-source-alternative-block).**

Краткая статистика: 51 819 звезд по состоянию на 27 июля 2026 г. (45 900+ в мае 2026 г.), Rust (63%) + TypeScript (30%), Apache 2.0, ежедневная активная разработка, более 368 участников. Основное отличие от Claude Code: независимость от поставщика (Claude, GPT, Gemini, Ollama, более 15 поставщиков), с многократно используемыми рабочими процессами на основе рецептов и гетерогенными командами субагентов, где каждый субагент может запускать свою модель.

### <a name="15-opencode-anomaly-formerly-sst"></a>1.5 Открытый код (аномалия, ранее SST)

Самый популярный инструмент в этой категории, делающий ставку на нейтральность поставщика и разделение client/server вместо фиксированного пользовательского интерфейса терминала.

| Атрибут | Подробности |
|-----------|---------|
| **GitHub** | [anomalyco/opencode](https://github.com/anomalyco/opencode) |
| **Звезды** | 199 400+ (август 2026 г.) |
| **Установить** | `curl -fsSL https://opencode.ai/install \| bash` или `npm i -g opencode-ai@latest` |
| **Язык** | TypeScript |
| **Лицензия** | Массачусетский технологический институт |
| **Версия** | v1.18.19 (август 2026 г.) |
| **Авторы** | 1000+ (GitHub API, август 2026 г.) |

#### Что такое открытый код?

Агент кодирования терминала, построенный на основе разделения client/server: сам агент запускается как серверный процесс, а терминал, плагин IDE или отдельная машина подключается к нему в качестве клиента. Эта архитектура делает автономные операции и возобновляемые сеансы первоклассными, а не автоматическими, поскольку отключение клиента не останавливает сеанс на стороне сервера. opencode изначально был проектом SST; он перешел в компанию Anomaly, и проект сохранил это название.

Поддержка моделей — еще один заголовок: более 75 поставщиков через единую поверхность конфигурации, включая локальные модели, поэтому ничто в связке не предполагает конкретно Claude, GPT или Gemini. Эта широта также является причиной того, что проект стал эталонной точкой по умолчанию для «агента кодирования, который работает где угодно и на чем угодно».

#### Claude Code против открытого кода

| Аспект | Claude Code | открытый код |
|--------|-------------|----------|
| **Модели** | Только семейство Claude | 75+ поставщиков, включая местные модели |
| **Архитектура** | Одиночный терминальный процесс | Client/server; агент работает как сервер, терминал — один из возможных клиентов |
| **Язык** | TypeScript | TypeScript |
| **Лицензия** | Собственный | Массачусетский технологический институт |
| **Skills/Hooks** | Полная собственная система | Плагин и расширение на основе MCP |
| **Память** | CLAUDE.md + Автопамять | Соглашение AGENTS.md |
| **Управление** | Anthropic, один поставщик | Аномалия (компания), ранее SST |

#### Когда выбирать открытый код

Самым сильным примером является гибкость провайдера: команда, которая хочет маршрутизировать между Claude, GPT, Gemini и локальной моделью внутри одного жгута, без переключения инструментов для каждого провайдера, получает это изначально здесь. Дизайн client/server также выгоден любому, кто запускает агент на удаленном компьютере или внутри CI и наблюдает за ним с ноутбука.

Честно говоря, слабым местом является глубина интеграции каждого провайдера. Наличие нескольких поставщиков по замыслу означает, что ни одна модель не получает собственной доработки. Claude Code предоставляет конкретно модели Claude (быстрое поведение кэширования, навыки, перехватчики, настроенные на формат использования инструментов одного поставщика). Количество звезд здесь также не является показателем стабильности: проект уже однажды менял управляющих (от SST до Anomaly), и команда, делающая ставку на долгосрочную стабильность поверхности API, должна прочитать историю миграции, прежде чем стандартизировать ее.

Широта поставщика также не устраняет операционное одобрение или риск версии. Практик рассказывает о средстве проверки кода ИИ, созданном для заявленного объема работы в 200 инженеров, описанном с использованием OpenRouter для быстрого прототипирования с помощью одного API, а затем перехода на Vertex AI и Gemini для более строгого мониторинга, журналов, бюджетов и контроля безопасности. После того, как более позднее обновление модели снизило удовлетворенность рецензента, команда вернулась к предыдущей модели и заметила восстановление. В докладе не сообщается ни о количестве активных пользователей, ни о стоимости миграции, ни о показателях удовлетворенности. Считайте списки разрешенных поставщиков, закрепленные версии моделей, телеметрию качества и откат критериями приемки для использования нескольких поставщиков. Источник: [«Как мы создали программу проверки кода AI для 200 инженеров», 17:19](https://www.youtube.com/watch?v=dTye2zVfSco&t=1039s) и [21:44](https://www.youtube.com/watch?v=dTye2zVfSco&t=1304s), AI DevCon, опубликовано 29 мая 2026 г.

#### Быстрый старт

```bash
curl -fsSL https://opencode.ai/install | bash
opencode
```

Полный список провайдеров и настройки по адресу [opencode.ai/docs/providers](https://opencode.ai/docs/providers/); серверная архитектура [opencode.ai/docs/server](https://opencode.ai/docs/server/).

#### <a name="opencode-go-the-subscription-tier-and-why-it-does-not-scale-to-a-team"></a>Opencode Go: уровень подписки и почему он не масштабируется для команды

Помимо использования ключа собственного поставщика, opencode предлагает подписку под названием Go за $10/month.. Текущий каталог включает Grok 4.6 и GPT 5.6 Luna, а также модели DeepSeek, Qwen, GLM, Kimi и другие, так что это курируемая подписка на модель кодирования, а не уровень только с открытым весом. Использование ограничено в долларовом выражении, а не в фиксированном количестве запросов: 12 долларов США за 5-часовой период, 30 долларов США в неделю и 60 долларов США в месяц. Официальные оценки в настоящее время варьируются от 110 до 45 300 запросов за 5-часовой интервал, но эти оценки предполагают профили запросов для конкретной модели с большими объемами кэшированных входных данных и не являются гарантиями запросов. Источник: [opencode.ai/docs/go](https://opencode.ai/docs/go/), проверено 30 августа 2026 г.

План явно одноместный: только один участник в каждом рабочем пространстве может подписаться на Go. Ограничения на использование также не обязательно являются жестким финансовым препятствием. Если подписчик включает **Use Balance**, Go возвращается к балансу OpenCode Zen рабочей области после достижения предела вместо блокировки запросов. Go может служить для индивидуальной оценки, но это не документированный способ обеспечения работы команды или управления ею. Источник: [opencode.ai/docs/go](https://opencode.ai/docs/go/), проверено 30 августа 2026 г. Сравнение подписок разных поставщиков в масштабе команды см. в разделе «Стратегия подписки [» на сайте Team Scale](../ops/subscription-strategy.md).

### 1.6 Gemini CLI (Google)

Собственный терминальный агент Google, созданный для моделей Gemini, с достаточно щедрым уровнем бесплатного пользования, чтобы стать основной причиной его выбора.

| Атрибут | Подробности |
|-----------|---------|
| **GitHub** | [google-gemini/gemini-cli](https://github.com/google-gemini/gemini-cli) |
| **Звезды** | 106 600+ (август 2026 г.) |
| **Установить** | `npm install -g @google/gemini-cli` или `npx @google/gemini-cli` или `brew install gemini-cli` |
| **Язык** | TypeScript |
| **Лицензия** | Apache-2.0 |
| **Версия** | v0.56.0 (август 2026 г.) |
| **Авторы** | 690+ (GitHub API, август 2026 г.) |

#### Что такое Gemini CLI?

Агент терминального кодирования, созданный и поддерживаемый Google, подключенный к моделям Gemini, а не предлагающий широкую поддержку нескольких поставщиков. Доводы в пользу этого не основаны на новизне оборудования: цикл агента, набор инструментов и модель утверждения выглядят аналогично тому, что уже делают Codex, CLI и Claude Code. Дело касается бесплатного уровня: личные учетные записи Google получают 60 запросов в минуту и ​​1000 запросов в день бесплатно, что является самым щедрым разрешением среди основных терминальных агентов.

По умолчанию агент работает в режиме ограниченной автономии (пошаговый, а не автономный) и поддерживает возобновляемые сеансы. По умолчанию он читает `GEMINI.md` для инструкций проекта; одна настройка переключает его на общее соглашение `AGENTS.md`, которое используют другие инструменты, поэтому миграция инструкций в любом направлении обходится дешево.

#### Claude Code против Gemini CLI

| Аспект | Claude Code | Gemini CLI |
|--------|-------------|-------------|
| **Модели** | Только семейство Claude | Семейство Gemini (собственные) |
| **Уровень бесплатного пользования** | На самом CLI нет. | 60 req/min, 1,000/day в личных аккаунтах Google |
| **Лицензия** | Собственный | Apache-2.0 |
| **Память** | CLAUDE.md + Автопамять | GEMINI.md по умолчанию, AGENTS.md через одну настройку |
| **MCP Поддержка** | Родная, растущая экосистема | Родной |
| **Стюард** | Anthropic, один поставщик | Google, один поставщик |

#### Когда выбирать Gemini CLI

Ясным примером является стоимость: разработчик или небольшая команда, уже использующая Gemini или желающие опробовать рабочий процесс агентного терминала, прежде чем платить за него, получают рабочую установку с реальной дневной квотой и без подписки. Это также разумный вариант по умолчанию, если остальная часть стека команды уже работает в Google Cloud и Gemini.

Честное ограничение заключается в том, что это не инструмент для нескольких поставщиков: переключение моделей означает полное переключение на другое оборудование, в отличие от opencode или Aider. Любой, кто рассчитывает сравнить выходные данные Claude, GPT и Gemini для одной и той же задачи внутри одного терминального агента, не получит этого здесь.

#### Быстрый старт

```bash
npm install -g @google/gemini-cli
gemini
```

Или попробуйте без установки: `npx @google/gemini-cli`. Полную настройку и подробную информацию об уровне бесплатного пользования можно найти на странице [Gemini CLI README](https://github.com/google-gemini/gemini-cli#readme).

### <a name="17-crush-charm"></a>1.7 Давка (очарование)

Агент кодирования терминала Charm, созданный командой Bubble Tea и Lip Gloss, библиотеки TUI, на которых построена большая часть терминальных интерфейсов этой категории.

| Атрибут | Подробности |
|-----------|---------|
| **GitHub** | [charmbracelet/crush](https://github.com/charmbracelet/crush) |
| **Звезды** | 27 500+ (август 2026 г.) |
| **Установить** | `brew install charmbracelet/tap/crush` или `npm install -g @charmland/crush` или `go install github.com/charmbracelet/crush@latest` |
| **Язык** | Идти |
| **Лицензия** | FSL-1.1-MIT (Функциональная лицензия на исходный код; см. предупреждение ниже) |
| **Версия** | v0.90.0 (август 2026 г.) |
| **Авторы** | 144+ (GitHub API, август 2026 г.) |

#### Что такое раздавить?

Терминальный агент кодирования без привязки к модели (мультипровайдер, та же позиция, что и у Opencode и Aider по этой оси) и двумя отличительными ставками: сохранение сеанса для каждого проекта и интерфейс терминала, созданный с использованием собственных инструментов TUI от Charm, который демонстрирует ежедневную доработку. Ограниченная автономия, возобновляемые сеансы.

В лицензии нужен прямой флаг. Crush работает под FSL-1.1-MIT (Functional Source License), а не под стандартной лицензией открытого исходного кода, одобренной OSI, при выпуске. Каждый выпуск автоматически преобразуется в полный MIT через два года после выпуска, поэтому более старые версии со временем становятся простыми MIT, но текущий выпуск доступен с исходным кодом, а не с открытым исходным кодом в смысле OSI. Это подходит для индивидуального использования или использования внутри команды. Это становится реальным ограничением, если план предполагает перераспределение Crush, размещение его в качестве конкурирующего сервиса или объединение его в другой коммерческий продукт до закрытия двухлетнего окна этого выпуска; прочитайте текст лицензии, прежде чем делать что-либо из этого.

#### Claude Code против краша

| Аспект | Claude Code | раздавить |
|--------|-------------|-------|
| **Модели** | Только семейство Claude | Мультипровайдер, без привязки |
| **Язык** | TypeScript | Идти |
| **Лицензия** | Собственный | FSL-1.1-MIT (преобразуется в MIT через 2 года после каждого выпуска) |
| **Сохранение сеанса** | Нативный, для каждого проекта | Нативный, для каждого проекта |
| **Терминал UI** | Anthropic-built | Набор блесков Charm's Bubble Tea/Lip |
| **Стюард** | Anthropic, один поставщик | Очарование |

#### Когда выбирать влюбленность

Самая веская причина выбрать Crush вместо Opencode или Aider — это сам опыт работы с терминалом: Charm уже много лет создает инструменты TUI, и это наиболее совершенный интерфейс среди терминальных агентов с несколькими поставщиками, описанных здесь. Сохранение сеансов для каждого проекта также делает его разумным выбором для разработчиков, которые манипулируют несколькими базами кода и хотят, чтобы агент запоминал состояние каждого репозитория без дополнительной настройки.

Слабые места реальны. У него самое маленькое сообщество из трех инструментов, добавленных в этот раздел (27 500+ звезд против 199 400+ у Opencode и более 106 600 у Gemini CLI), он моложе, а лицензия FSL является настоящим препятствием для любого, кто создает на его основе продукт для перепродажи, а не использует его в качестве личного или внутреннего инструмента. Если ясность лицензии важнее, чем полировка терминала, opencode или Aider полностью избегают этого вопроса.

```bash
brew install charmbracelet/tap/crush
crush
```

### <a name="18-deepseek-harness-dsh"></a>1.8 Ремень DeepSeek (dsh)

Официальная среда выполнения агента DeepSeek. Это технически амбициозный проект, явно экспериментальный, и его не следует путать с безопасной по умолчанию производственной песочницей.

| Атрибут | Подробности |
|-----------|---------|
| **GitHub** | [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) |
| **Интерфейс** | Локальный веб-интерфейс и безголовый CLI |
| **Лицензия** | Массачусетский технологический институт |
| **Статус** | Предварительный просмотр для разработчиков; ожидаются изменения, нарушающие совместимость |
| **Архитектура** | Дерево плагинов Cordis: модели, инструменты, навыки, сеансы, песочница, хранилище, утверждения и пользовательский интерфейс — это составные плагины. |

#### Что такое ремень безопасности DeepSeek?

DeepSeek Harness, представленный как `dsh`, представляет собой локальную среду выполнения, которая формирует профиль из плагинов, а не поставляет одну фиксированную поверхность агента. Его официальная архитектура документирует профили и пакеты для цикла агентов, адаптеров моделей, инструментов, MCP, навыков, субагентов, рабочих процессов, песочницы, разрешений, хранилища и пользовательского интерфейса. Это делает его интересным справочником для строителей: швы видны, а не скрыты одной командой CLI.

Начните с официального пакета, а не с одноименного проекта сообщества:

```bash
npx @deepseek-ai/dsh web

# Inspect the fully composed profile before trusting it
npx @deepseek-ai/dsh --profile web --dump-config
```

В проектных документах профили «Стандартный», «Режим PTC/Code», «Минимальный» и «Ориентированный на создание». Его журнал событий сеанса может записывать сообщения, вызовы инструментов и решения об утверждении для воспроизведения. Это помогает отладке, но также поднимает вопрос об обработке данных: проверьте телеметрию и настройки экспорта, прежде чем запускать собственный код или секреты через локальный запуск.

#### Безопасность и эксплуатационные ограничения

В репозитории dsh отмечена предварительная версия для разработчиков. Относитесь к этому как к оперативному ограничению, а не как к скромной формулировке. Локальный агент по-прежнему может читать враждебное содержимое репозитория, вызывать мощный инструмент и писать в рабочую область. Используйте изолированную виртуальную машину или контейнер для ненадежного кода, начните с профиля с наименьшими привилегиями и обеспечьте возможность просмотра последующих действий вне собственного цикла рассуждений модели. Не включайте предустановку `danger-full-access` на основном компьютере.

В одном внешнем исследовании, [arXiv:2608.16393](https://arxiv.org/abs/2608.16393), оценивалась одна фиксация и конфигурация DeepSeek Harness в 14 560 контролируемых тестах с непрямым подсказкой. Его результаты являются свидетельством проверенной конфигурации, а не универсальным рейтингом безопасности. Долгосрочный урок проще: сама по себе песочница не доказывает, что ненадежный контент не может повлиять на агента, использующего инструмент. Сохраняйте происхождение, независимую авторизацию и контрольные данные в изолированной программной среде.

Официальные отправные точки: подсистема песочницы [README](https://github.com/deepseek-ai/deepseek-harness), [architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md), [подсистема песочницы](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/sandbox.md)и настройки разрешений [](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/permission-presets.md). Снимок проверен 2 сентября 2026 г.

#### Когда следует выбирать ремень DeepSeek

Выберите dsh, чтобы изучить или расширить среду выполнения, ориентированную на плагины, или поэкспериментировать в изолированной среде с ее явной моделью композиции. Не стандартизируйте его для производственной группы только потому, что он локальный или с открытым исходным кодом. Claude Code остается лучшим значением по умолчанию в этом руководстве для стабильного, документированного рабочего процесса кодирования; dsh — это быстро развивающаяся альтернатива, которую стоит оценить за четкими воротами безопасности и обслуживания.

### <a name="19-warp-agent-cli"></a>1.9 Агент варпа CLI

Warp Agent — это собственный агент кодирования, чей автономный CLI работает на сторонних терминалах, а также в Warp. Это имеет значение для классификации: Warp больше не является просто терминальным приложением со встроенным помощником. Теперь поставщик представляет агент как среду выполнения терминала с собственной интерактивной поверхностью, возможностью координации нескольких агентов и возможностью продолжения работы в облаке.

| Атрибут | Подробности |
|-----------|---------|
| **Официальный источник** | [Представляем варп-агент](https://www.warp.dev/blog/introducing-the-warp-agent-cli-coding-agent) |
| **Интерфейсы** | CLI, интерактивный пользовательский интерфейс терминала и веб-мониторинг для работы в облаке |
| **Поддержка терминала** | Автономное использование в терминалах, включая Ghostty, iTerm2, терминалы VS Code и терминалы Windows. |
| **Модель исполнения** | Работа локального терминала с дополнительной передачей обслуживания облачным агентам Warp |
| **Модельная стратегия** | Маршрутизация, управляемая поставщиком, плюс настраиваемая маршрутизация модели |
| **Лицензия** | Собственный |

#### Что его отличает?

Warp подчеркивает предельную точность. Его агент может мультиплексировать псевдотерминалы и взаимодействовать с полноэкранными приложениями, такими как отладчики, редакторы и клиенты баз данных, вместо того, чтобы рассматривать каждую команду как одноразовый подпроцесс. Согласно стартовой статье Warp, одна и та же поверхность продукта может координировать работу нескольких агентов и делегировать работу внешним агентам кодирования, включая Claude Code и Codex.

Передача обслуживания в облаке является вторым отличием. Задача может начаться в локальном терминале и продолжиться удаленно, при этом прогресс будет виден с поверхности облака Warp. Это гибридная модель выполнения, а не свидетельство того, что каждая команда остается локальной. Прежде чем разрешить удаленный запуск, команды должны решить, какие репозитории, учетные данные и выходные данные команд могут пересекать эту границу.

#### Граница доказательств

Приведенные выше возможности взяты из стартовой статьи Warp от 4 августа 2026 года. В этом руководстве не проводились независимые проверки совместимости терминалов, качества маршрутизации модели, облачной изоляции или многоагентной надежности. Рассматривайте профиль как исходную карту продукта, а затем перед внедрением проверьте точную версию клиента, путь к данным, модель разрешений и цены в репрезентативном репозитории.

#### Когда выбирать Warp Agent

Добавляйте его в короткий список, когда интерактивные терминальные программы играют центральную роль в задаче, когда разработчикам нужен один и тот же агент в нескольких терминальных приложениях или когда передача обслуживания из локального в облако является реальным требованием рабочего процесса. Предпочитайте агент терминала с открытым исходным кодом, когда возможность проверки или самостоятельное размещение не подлежат обсуждению. Предпочитайте более простой CLI, когда удаленное продолжение и мультиплексирование терминалов не оправдывают использование другой собственной поверхности управления.

### <a name="21-devin-cognition"></a>2.1 Девин (Познание)

Первый коммерческий полностью автономный инженер-программист. Закрытый исходный код, размещение в облаке, корпоративная цена.

| Атрибут | Подробности |
|-----------|---------|
| **Веб-сайт** | [devin.ai](https://devin.ai) |
| **Тип** | Облачное SaaS, проприетарное |
| **Цены** | Core: $20/mo (ACU с оплатой по факту использования), Team: $500/mo (250 ACU), Enterprise: пользовательская |
| **Запущен** | 2024 |
| **Оценка** | 25 миллиардов долларов (сбор средств в апреле 2026 г.) |
| **Значительное приобретение** | IDE с поддержкой искусственного интеллекта для виндсерфинга (июль 2025 г.) |
| **Корпоративные клиенты** | Goldman Sachs, Microsoft, Palantir, Citi, Dell |

#### Что такое Девин?

Автономный инженер-программист, работающий на облачной виртуальной машине Linux с собственной оболочкой, редактором кода и браузером. Девин планирует свой подход, пишет код, запускает тесты, читает сообщения об ошибках и выполняет итерации до тех пор, пока задача не будет завершена или не застрянет. Основной интерфейс — Slack: вы отправляете сообщение типа «исправить проблему № 342», и Девин открывает PR, когда все готово.

Выставление счетов производится в ACU (вычислительных единицах агента), где 1 ACU соответствует примерно 15 минутам работы агента. Сложная функция может потреблять 10–20 ACU; простое исправление ошибки может использовать 1-3.

#### Claude Code против Девина

| Аспект | Claude Code | Девин |
|--------|-------------|-------|
| **Среда выполнения** | Ваша локальная машина | Облачная виртуальная машина Linux (в песочнице) |
| **Модель взаимодействия** | Интерактивный (вы смотрите) | Асинхронный (назначить и проверить) |
| **State** | Session-scoped | Настойчивость в выполнении задачи |
| **Цены** | Подписка (20–$200/mo) | Выставление счетов ACU за задачу (приблизительно 0,07–$0.15/ACU) |
| **Кто ездит** | Ты (парное программирование) | Агент (автономный, вы проверяете) |
| **Спецификация задачи** | Разговорный, итеративный | Предварительно (лучшие характеристики = лучший результат) |
| **Доступ через браузер** | Через MCP (Playwright) | Встроенный, родной |
| **Интеграция проверки кода** | Вы просматриваете в своем IDE | Девин публикует пиар, ваш обзор на GitHub |

#### Когда выбирать Девин

Девин работает лучше всего, когда задача четко определена, ограничена и не требует постоянного принятия решений. Рефакторинг конкретного модуля, реализация документированной конечной точки API, исправление регрессии с известной первопричиной: это задачи Devin. Проектирование новой архитектуры системы, отладка неясной производственной проблемы или написание кода, который зависит от неявного контекста вашей кодовой базы: для этого требуется более интерактивный цикл.

План команды $500/month (250 ACU) является существенным. В этой ценовой категории вы платите за асинхронную ценность: разработчики не блокируются в ожидании выходных данных агента, агенты работают параллельно над несколькими задачами, нет переключения контекста. Если вашим узким местом является внимание разработчиков, а не чистая пропускная способность, Devin того стоит. Если вы хотите оставаться в курсе и выполнять итерации в интерактивном режиме, Claude Code по адресу $200/month обеспечивает большую отдачу от доллара.

Приобретение Windsurf (июль 2025 г.) сигнализирует о переходе Cognition к полноценной среде разработки, а не только к фоновому агенту. Следите за интегрированными рабочими процессами, сочетающими интерактивное кодирование (Windsurf IDE) и автономное выполнение задач (Devin) в одном продукте.

### <a name="22-swe-agent-princeton"></a>2.2 Агент SWE (Принстон)

Академический агент, разработанный специально для решения проблем GitHub только на основе описания проблемы. Документ NeurIPS 2024, Princeton NLP Group и Стэнфорд.

| Атрибут | Подробности |
|-----------|---------|
| **GitHub** | [SWE-agent/SWE-agent](https://github.com/SWE-agent/SWE-agent) |
| **Звезды** | 19 300+ (май 2026 г.) |
| **Бумага** | НейрИПС 2024 |
| **Лицензия** | Массачусетский технологический институт |
| **Язык** | Питон (95%) |
| **Версия** | v1.1.0 (май 2025 г.) |
| **Сопровождающие** | Принстонская группа НЛП + Стэнфорд |

#### Что такое SWE-агент?

Конвейер агента, который принимает URL-адрес проблемы GitHub и модель, затем пытается воспроизвести ошибку, написать исправление и создать патч. В его архитектуре используется уровень интерфейса агент-компьютер (ACI), который абстрагирует терминал, редактирование файлов и выполнение тестов в согласованный набор команд независимо от базовой среды. Этот дизайн ACI является основным научным вкладом: он показывает, что производительность агента сильно коррелирует с тем, насколько хорошо среда предоставляет информацию, а не только с необработанными возможностями модели.

Рецензируемая оценка NeurIPS 2024 не тестировала Claude 3.7 или модель открытого веса в основных результатах SWE-bench. На полном тестовом наборе SWE-стенда SWE-агент разрешил 12,47% проблем с GPT-4 Turbo и 10,46% с Claude 3 Opus. В таблице 1 указаны средние затраты на вывод API в размере 1,59 и 2,59 долларов США соответственно, усредненные только по успешно разрешенным экземплярам, ​​с ограничением в 4 доллара за запуск. Эти цифры описывают эталонную конфигурацию газеты на 2024 год, а не текущее состояние дел. Источник: [Yang et al., SWE-agent](https://proceedings.neurips.cc/paper_files/paper/2024/file/5a7c947568c1b1328ccc5230172e1e7c-Paper-Conference.pdf), PDF, стр. 5-6, таблица 1.

#### Когда выбирать SWE-агент

Преимущественно академическое и исследовательское использование. Если вы хотите проводить систематические оценки эффективности различных моделей при решении реальных проблем GitHub, SWE-агент является подходящим инструментом, поскольку он имеет инфраструктуру воспроизводимости (регистрация траектории, средства оценки, конфигурация YAML), которую пропускают производственные инструменты.

Облачная песочница Devin и улучшенное восстановление ошибок делают решение проблем с производственными пакетами более практичным. SWE-агент требует, чтобы вы настроили среду и обрабатывали сбои вручную.

Ценность исследования реальна: команды, создающие агентские системы, могут использовать данные о траекториях SWE-агента (сгенерированные в результате прогонов решения проблем) для точной настройки моделей. SWE-agent-LM-32b компании Nous Research (открытые веса, SoTA на SWE-Bench для открытых моделей) был обучен на траекториях, сгенерированных SWE-агентом.

```bash
pip install swe-agent

# Run on a GitHub issue
sweagent run \
  --agent.model.name=claude-sonnet-5-5 \
  --env.repo.github_url=https://github.com/org/repo \
  --problem_statement.github_url=https://github.com/org/repo/issues/123
```

**Billing:** Anthropic объявил о выделении отдельного программного кредита для `claude -p` и агента SDK с 15 июня 2026 г., а затем приостановил его. ### <a name="24-openhands-all-hands-ai"></a>2.4 OpenHands (ИИ всех рук)

Платформа автономного кодирования с открытым исходным кодом, ранее OpenDevin. Ближайший самостоятельный эквивалент Девина.

| Атрибут | Подробности |
|-----------|---------|
| **GitHub** | [OpenHands/OpenHands](https://github.com/OpenHands/OpenHands) |
| **Звезды** | 79 900+ (июль 2026 г.) |
| **Поддержка модели** | Claude, GPT, Gemini, модели с открытым весом |
| **Развертывание** | Самостоятельный хостинг (бесплатно) или OpenHands Cloud/Enterprise (платно) |
| **Выполнение** | Песочница |

#### Что такое ОпенХандс?

Агент планирования строит график зависимостей перед началом любой работы, а затем создает субагенты для ее выполнения: задачи без зависимостей (уровень 0) выполняются параллельно, и каждая задача уровня 1 запускается, как только разрешается ее конкретная зависимость, а не ждет завершения всего уровня 0. Затем агент интегратора объединяет полученные файлы, исправляет пути импорта, передает вызовы API к компонентам внешнего интерфейса и запускает полный набор тестов перед возвратом результата.

#### Когда выбирать OpenHands

OpenHands — это практический выбор, если вам нужен параллелизм графов зависимостей Devin без оплаты за каждую задачу или блокировки с закрытым исходным кодом. Самостоятельное размещение означает, что вы контролируете песочницу и маршрутизацию модели за счет самостоятельного запуска инфраструктуры.

Уровень управления (ограждения, бюджеты, внутренний рынок плагинов, полный контрольный журнал) находится за OpenHands Cloud/Enterprise.. Ядро с открытым исходным кодом предоставляет вам график выполнения и «песочницу», а не обеспечение соблюдения политики в масштабах всей организации. Если вашим приоритетом являются детерминированные шлюзы и отслеживаемость внутри команды, заложите бюджет на платный уровень или соедините OpenHands с уровнем внешней политики.

## Раздел 3: Мультиагентные платформы

Это не инструменты кодирования. Это библиотеки для создания с нуля пользовательских мультиагентных приложений: маркетинговых конвейеров, автоматизации исследований, обработки документов, ботов поддержки клиентов. Многоагентная оркестровка на основе ролей. Преобладающий выбор для команд, которые хотят определить агентов по должностным функциям (исследователь, писатель, редактор) и позволить им совместно работать над структурированными задачами.

| Атрибут | Подробности |
|-----------|---------|
| **GitHub** | [crewAIInc/crewAI](https://github.com/crewAIInc/crewAI) |
| **Звезды** | 52 300+ (май 2026 г.) |
| **Язык** | Питон (99%) |
| **Лицензия** | Массачусетский технологический институт |
| **Версия** | v1.14.5 (18 мая 2026 г.) |
| **Выполнения** | Сообщается о выполнении более 2 млрд задач агента |
| **Загрузки** | 27M+ |
| **Корпоративные клиенты** | 150+ |

#### Что такое CrewAI?

Вы определяете агентов с ролью, целью и предысторией («команда»). Вы определяете задачи и назначаете их агентам. CrewAI управляет маршрутизацией: последовательной (заканчивает A, затем начинается B), параллельной (A и B выполняются одновременно) или иерархической (агент-менеджер делегирует полномочия специалистам). Каждый агент может использовать инструменты, включая серверы MCP и веб-поиск. Поддерживаются несколько провайдеров LLM (Claude, GPT, Gemini, Ollama).

Он стоит особняком от LangChain (более старой структуры, с которой его часто сравнивают), поскольку вообще не зависит от LangChain. Автономная библиотека Python.

#### Когда использовать CrewAI

Правильный уровень абстракции для команд, которые могут описать свой рабочий процесс в человеческих ролях. Если вы можете сказать: «Мне нужен исследователь, который собирает информацию, писатель, который пишет черновики, и редактор, который дорабатывает», CrewAI возьмет на себя оркестровку и межагентское общение. Вы пишете определения агентов, а не код оркестрации.

Избегайте этого, если ваш рабочий процесс имеет сложное условное ветвление, требует надежного выполнения при сбоях или требует детального контроля над передачей состояния между агентами. LangGraph лучше справляется с такими случаями.

```python
from crewai import Agent, Task, Crew, Process

researcher = Agent(
    role="Technical Researcher",
    goal="Find accurate technical information",
    backstory="Expert at synthesizing documentation and research papers",
    llm="claude-sonnet-5-5"
)

writer = Agent(
    role="Technical Writer",
    goal="Write clear, accurate documentation",
    backstory="Experienced at translating technical concepts",
    llm="claude-sonnet-5-5"
)

task = Task(
    description="Research and document the new auth API endpoints",
    expected_output="Markdown documentation with examples",
    agent=writer,
    context=[research_task]  # researcher's output feeds writer
)

crew = Crew(agents=[researcher, writer], tasks=[task], process=Process.sequential)
result = crew.kickoff()
```

### 3.2 Лангграф

Оркестровка агентов на основе графов от LangChain. Низкий уровень, чем CrewAI, более гибкий, лучше подходит для сложных рабочих процессов с отслеживанием состояния.

| Атрибут | Подробности |
|-----------|---------|
| **GitHub** | [langchain-ai/langgraph](https://github.com/langchain-ai/langgraph) |
| **Звезды** | 33 100+ (май 2026 г.) |
| **Язык** | Python (99%) + доступна версия JS |
| **Лицензия** | Массачусетский технологический институт |
| **Версия** | v1.2.2 (26 мая 2026 г.) |
| **Пользователи производства** | Кларна, Реплит, Эластик |

#### Что такое Лангграф?

Платформа построения агентов, моделирующая рабочие процессы в виде ориентированных графов с узлами (шагами агента) и ребрами (переходами). Ключевыми примитивами являются состояние (типизированный словарь, который сохраняется во всех узлах), условные ребра (ветвление на основе состояния) и постоянство (контрольная точка, позволяющая возобновлять прерванный рабочий процесс с последней контрольной точки, а не с нуля). «Человек в цикле» — это первоклассный шаблон: вы можете приостановить выполнение на любом узле и дождаться решения человека, прежде чем продолжить.

LangGraph не объединяет агенты. Вы определяете логику рабочего процесса и подключаете любой LLM, который захотите. Платформа гарантирует, что переходы состояний предсказуемы, сбои можно устранить, а рабочий процесс можно отлаживать шаг за шагом.

#### Когда использовать LangGraph

Правильный инструмент, когда вашему агенту необходимо пережить сбои, выполнять разветвление в зависимости от условий выполнения или требуется одобрение человека в определенных точках принятия решений. Примеры: конвейер проверки кода, который передается человеку, когда агент обнаруживает изменение, связанное с безопасностью; рабочий процесс обработки данных, который проверяет точки после каждого дорогостоящего шага, чтобы перезапуски не приводили к повторной обработке завершенных этапов; многоэтапный исследовательский агент, который делает паузу для получения помощи от человека, когда сталкивается с неоднозначным исходным материалом.

Более крутая кривая обучения, чем у CrewAI. Оно того стоит, если сложность рабочего процесса оправдывает вложения.

```python
from langgraph.graph import StateGraph, END
from typing import TypedDict

class AgentState(TypedDict):
    messages: list
    task_complete: bool

graph = StateGraph(AgentState)
graph.add_node("agent", call_agent)
graph.add_node("tools", call_tools)
graph.add_conditional_edges("agent", should_continue, {"continue": "tools", "end": END})
graph.add_edge("tools", "agent")
graph.set_entry_point("agent")

app = graph.compile(checkpointer=MemorySaver())  # Durable execution
```

LangSmith (продукт наблюдения LangChain) изначально интегрируется для отладки и отслеживания запуска агентов.

Многоагентная платформа Microsoft, промежуточный переход от исходной библиотеки AutoGen (режим обслуживания с сентября 2025 г.) к Microsoft Agent Framework (MAF), которая объединяет AutoGen и семантическое ядро ​​в один SDK.

|-----------|---------|

| **Устаревший GitHub** | [microsoft/autogen](https://github.com/microsoft/autogen) (60 033 звезды по состоянию на 27 июля 2026 г., было 58 400, режим обслуживания с сентября 2025 г.) |

#### Что такое Microsoft Agent Framework?

MAF — это объединение AutoGen (Python, диалоговый мультиагент) и семантического ядра (C# + Python, абстракции вызова функций). Результатом является межплатформенная среда выполнения: агенты Python могут координировать свои действия с агентами .NET, при этом все они поддерживаются одним и тем же уровнем обмена сообщениями. Он реализует протокол A2A (агент-агент), вклад Microsoft в взаимодействие агентов, и поддерживает MCP.

Количество звезд AutoGen (60 033 по состоянию на 27 июля 2026 г.) отражает его историческую репутацию. AutoGen впервые разработал шаблон «разговорного агента», при котором агенты общаются друг с другом в структурированном цикле разговора. Этот шаблон по-прежнему является доминирующей ментальной моделью в рамках, даже несмотря на развитие реализации.

#### Когда использовать МАФ

Идеально подходит для команд экосистемы Microsoft: магазины .NET + Python, развертывания Azure, корпоративные среды, где семантическое ядро ​​уже установлено. История перекрестного выполнения реальна: агент Python может вызывать инструменты, реализованные как функции семантического ядра .NET.

Менее привлекательно для команд, не имеющих инвестиций в .NET. Если вы используете только Python, у CrewAI или LangGraph есть более крупные сообщества и больше учебных пособий.

### <a name="35-metagpt"></a>3.5 МетаGPT

Исходная структура «компании-разработчика программного обеспечения для искусственного интеллекта»: пять фиксированных ролей (менеджер продукта, архитектор, менеджер проекта, инженер, контроль качества), объединенных в конвейер, который превращает однострочный запрос в PRD, диаграммы и код. Исторически важное, в настоящее время бездействующее.

| Атрибут | Подробности |
|-----------|---------|
| **GitHub** | [FoundationAgents/MetaGPT](https://github.com/FoundationAgents/MetaGPT) |
| **Звезды** | 69 384 (июль 2026 г.) |
| **Язык** | Питон |
| **Лицензия** | Массачусетский технологический институт |
| **Последний выпуск** | v0.8.1 (22 апреля 2024 г.) |
| **Последний коммит** | январь 2026 г. |
| **Коммерческий продукт** | MGX (хостинг, запуск в феврале 2025 г.) |

#### Основная идея

Тезис MetaGPT умещается в одной строке из его статьи: `Code = SOP(Team)`. Закодируйте стандартную рабочую процедуру компании-разработчика программного обеспечения, назначьте каждый шаг роли, и конвейер создаст артефакты, которые создала бы настоящая команда. Каждая роль передает структурированный документ следующей. Исполняемый цикл обратной связи повторяет до трех раз, если код не запускается.

Эта структура получила устное признание на ICLR 2024 и большое количество последователей. Было доказано, что декомпозиция ролей плюс структурированная передача функций превосходят одного агента при выполнении задач по созданию новых объектов.

#### Прочтите даты, прежде чем принять его.

Количество звезд является ошибочным сигналом активности. Последний отмеченный выпуск — v0.8.1 от апреля 2024 года, а репозиторий не получал коммитов с января 2026 года. Внимание команды переключилось на MGX, размещенный коммерческий продукт. Обещанная версия v1.0 с открытым исходным кодом так и не вышла.

Относитесь к MetaGPT как к эталонной архитектуре, а не как к зависимости. Его модель структурированного артефакта между ролями заслуживает изучения и проявляется почти во всех последующих структурах, включая BMAD и Liza. Сам код вышел два года назад после своего последнего выпуска.

#### Где это останавливается

Доверие предполагается через соответствие процессам. Ничто не мешает агенту игнорировать СОП; система делает ставку на то, что будет соблюдена четко описанная процедура. Обработка ошибок основана на повторных попытках (тот же агент пытается еще раз), а не на структурной основе. Здесь нет восстановления после сбоя, границ ролей, установленных за пределами приглашения, и нет цикла проверки, в котором второй агент может отклонить работу первого агента.

#### Что это на самом деле делает

Слоган — «Управляйте работой, а не агентами». Symphony опрашивает трекер, отправляет агента по каждой проблеме в свое рабочее пространство и собирает доказательства того, что работа реальна: статус CI, отзывы о проверке PR, анализ сложности и видео с пошаговыми инструкциями. Инженер просматривает доказательства вместо того, чтобы наблюдать за тем, как печатает агент.

Модель распространения необычна: основная рекомендация репозитория — не «установить наш двоичный файл», а «передать [SPEC.md](https://github.com/openai/symphony/blob/main/SPEC.md) вашему любимому агенту кодирования, и пусть он создаст Symphony на выбранном вами языке». Версия Elixir представляет собой экспериментальную эталонную реализацию, построенную на BEAM/OTP для контроля и параллелизма. Спецификация – это продукт.

Symphony предполагает, что вы уже выполнили [harness-инжиниринг](https://openai.com/index/harness-engineering/) в своей кодовой базе: сделали репозиторий понятным для агентов с помощью тестов, документации и инструментов. Он позиционирует себя как шаг после этого.

#### Прочтите предупреждающую этикетку

README открывается жирным предупреждением о том, что это «скромная инженерная предварительная версия для тестирования в доверенных средах». Никакого отмеченного релиза не существует, и с 9 июня 2026 года в репозитории ничего не происходит. 26 265 звезд (27 июля 2026 г.) измеряют охват распространения OpenAI, а не готовность к производству.

#### Где это останавливается

Symphony намеренно узок: планировщик, бегун и читатель трекеров. Он не проверяет и не обеспечивает соблюдение. В спецификации прямо указано, что она «не требует единого утверждения, изолированной среды или политики подтверждения оператора», оставляя доверие тому, кто ее реализует. Агент самостоятельно сертифицирует свою работу; нет второго агента, который мог бы его отвергнуть. Эталонная реализация предназначена только для Codex.

Эта узость — это дизайнерский выбор, а не недосмотр. Если вам нужна диспетчеризация и изоляция рабочего пространства, Symphony — это чистая спецификация для копирования. Если вам нужен цикл проверки или шлюз слияния, вы создаете его самостоятельно.

### <a name="45-paperclip"></a>4.5 Скрепка

Организационная структура агентов. Скрепка моделирует корпоративный аппарат (роли, бюджеты, шлюзы утверждения, цепочки делегирования) и позволяет указать на него любую среду выполнения агента. Самый быстрорастущий проект на всей этой странице.

| Атрибут | Подробности |
|-----------|---------|
| **GitHub** | [paperclipai/paperclip](https://github.com/paperclipai/paperclip) |
| **Звезды** | 74 900 (27 июля 2026 г.), 13 956 вилок |
| **Язык** | TypeScript (сервер Node.js + пользовательский интерфейс React) |
| **Лицензия** | Массачусетский технологический институт |
| **Created** | 2 марта 2026 г. |
| **Последний выпуск** | v2026.707.0 (7 июля 2026 г.) |
| **Работает с** | Гермес Agent/OpenClaw, Claude Code, Codex, Курсор, Bash, HTTP |

#### Что это на самом деле делает

README точно формулирует это: «Если OpenClaw — сотрудник, то Paperclip — компания». Вы определяете цель, нанимаете команду (генеральный директор, технический директор, инженеры, маркетологи, каждый из которых поддерживается той средой выполнения, которая вам нравится), устанавливаете бюджеты и осуществляете мониторинг с панели управления. Похоже на диспетчер задач. Ниже приведены организационные схемы, ограничения бюджета, правила управления и отслеживание затрат на каждого агента, задачу и цель.

Независимые от времени выполнения по своей конструкции, резюмированные в их собственной фразе: «если он может получать пульс, его нанимают». Именно это делает его интересным рядом с Claude Code, а не в конкуренции с ним. Claude Code становится одним из сотрудников.

#### Почему тяга имеет значение

75 тысяч звезд и 14 тысяч вилок (27 июля 2026 г.) примерно за четыре месяца, выпуски будут выходить еженедельно. Что бы вы ни думали о повествовании о «компании с нулевым участием людей», его внедрение реально, и проект поддерживается. Вокруг него уже сформировалась экосистема плагинов ([awesome-paperclip](https://github.com/gsxdsm/awesome-paperclip), шаблоны компании-мастера, адаптер Hermes от Nous Research).

#### Где это останавливается

Доверие к скрепке носит организационный, а не поведенческий характер. Он определяет, кто может действовать и сколько они могут тратить, с автоматической приостановкой бюджета и контрольными журналами только для добавления. Он не определяет, как выполняется работа внутри сеанса агента. В их собственных документах прямо говорится, что это не инструмент проверки кода. Ничто здесь не мешает агенту модифицировать тест, чтобы пройти неработающий код; это другой уровень проблемы, решаемый шаблонами управления [spec-first](../workflows/spec-first.md).

Другой домен тоже. Paperclip ориентирована на бизнес-операции в целом, а не на разработку программного обеспечения конкретно. Если ваша цель — поставка кода, абстракция организационной диаграммы может оказаться более аппаратной, чем требуется для работы.

### <a name="46-cli-agent-orchestrator-cao-aws-labs"></a>4.6 Оркестратор агента CLI (CAO, лаборатории AWS)

Агент супервизора, который делегирует полномочия рабочим агентам, каждый из которых представляет собой реальный процесс CLI в своем собственном сеансе tmux, координируемый через MCP. Примечателен по причине, не имеющей ничего общего с его возможностями: это единственный оркестратор в этой категории с оправданным фактором шины.

| Атрибут | Подробности |
|-----------|---------|
| **GitHub** | [awslabs/cli-agent-orchestrator](https://github.com/awslabs/cli-agent-orchestrator) |
| **Звезды** | 954 (27 июля 2026 г.), 184 форка, 73 открытых выпуска (в июле 2026 г. было 893/172/71) |
| **Язык** | Python 3.10+, распространяется на PyPI как `cli-agent-orchestrator`. |
| **Лицензия** | Apache-2.0 |
| **Created** | 29 июля 2025 г. |
| **Последний выпуск** | v2.3.0 (12 июля 2026 г.) |
| **Авторы** | 41, лучший участник с 20% коммитов |
| **Работает с** | Claude Code, Киро CLI, Codex CLI, Антигравитация CLI, Агент Гермеса, Кими CLI, GitHub Copilot CLI, OpenCode, Курсор CLI |

#### Что это на самом деле делает

Один агент-супервизор запускает, отправляет сообщения и координирует несколько рабочих процессов с помощью трех примитивов MCP: `handoff` (синхронный, ожидает завершения), `assign` (асинхронный, запустить и забыть) и `send_message` (доставка входящих сообщений между агентами). Каждый агент запускается как полный процесс CLI в изолированном сеансе tmux, что является наиболее важным проектным решением: поскольку он управляет реальным двоичным файлом, а не оберткой API, собственные функции сохраняются, включая субагенты Claude Code, специальные агенты Kiro и аутентификацию провайдера.

Отсюда следуют два последствия, которые не могут предложить большинство организаторов. Вы можете `tmux attach` обратиться к любому работающему работнику и управлять им в середине задачи, вместо того, чтобы ждать завершения субагента и надеяться. И вы можете смешивать поставщиков внутри одного сеанса, привязывая профиль к данному CLI через интерфейс агента, чтобы супервизор Kiro мог управлять работниками Claude Code.

Вокруг этого ядра находятся запланированные потоки (автономные запуски в стиле cron), встроенный веб-интерфейс, сервер `cao-ops-mcp`, который позволяет агенту создавать и контролировать сеансы CAO из собственного цикла чата, постоянная межсессионная память через `memory_store` и `memory_recall`, а также ограничения инструментов для каждого агента, объявленные как `role` плюс `allowedTools` в профиле, преобразованные в встроенные правила каждого провайдера, где они существуют.

#### Почему он вообще здесь указан

В июле 2026 года анализ рынка восьми мультиагентных оркестраторов с открытым исходным кодом, проверенных на соответствие GitHub API, а не README проекта, выявил семь, у которых один участник несет от 95% до 100% коммитов. Исключением было CAO: 41 вкладчик и самый крупный вкладчик, владеющий 20%.

Сравнение, которое должно запомниться вам: Mission Control ([builderz-labs/mission-control](https://github.com/builderz-labs/mission-control), MIT) имеет 5862 звезды по состоянию на 27 июля 2026 г. (было 5763), что в 6,1 раза больше, чем у CAO, и один человек является автором 78% его коммитов. Сортировка этого рынка по звездам приводит к выбору почти совершенно неправильного инструмента. Позиция данного руководства относительно количества звезд в качестве доверенного лица принятия изложена в [Section 5](#the-model-lock-in-question) и в [`docs/resource-evaluations/README.md`](../../docs/resource-evaluations/README.md); CAO против Mission Control — самая наглядная иллюстрация этого в дикой природе.

#### Где это останавливается

САО отвечает за координацию и ничего больше. У него нет собственных шлюзов качества, и он честен в этом: может ли агент объявить «готово» для сломанного кода, полностью зависит от того, что базовый CLI запускает внутри своего рабочего дерева. Ограничения инструментов ограничивают то, какие инструменты может вызывать агент, а не корректность его вывода. Ответьте на вопрос 1 из контрольного списка по управлению [](../workflows/agentic-software-factories.md#4-five-governance-questions-before-you-adopt-anything) самостоятельно, в своем CI, поскольку CAO не ответит на него за вас.

Изоляция осуществляется на уровне процесса, а не на уровне системы. tmux разделяет контексты и предоставляет реальный доступ PTY; это не песочница. Агенты наследуют среду, включая секреты и конфигурации. `cao-server` усилен специально для локального хоста (проверка заголовка хоста на предмет повторной привязки DNS, WebSocket PTY, отказывающийся от соединений без обратной связи), что сообщает вам предполагаемое развертывание: ваш компьютер, а не общий хост.

По состоянию на июль 2026 года не существует ни одного опубликованного тематического исследования с измеренными результатами, что ставит его в такое же доказательное положение, как и любую коммерческую платформу в этой категории. Поддержка AWS Labs означает непрерывность обслуживания, а не проверенные производственные результаты.

### <a name="48-liza"></a>4.8 Лиза

Liza — это многоагентная плоскость управления с применением кода для работы по кодированию. Он запускает CLI поставщика в качестве рабочих, назначает каждую задачу паре doer/reviewer, изолирует их ветви в рабочих деревьях git и сохраняет состояние координации вне контекста модели.

| Атрибут | Подробности |
|-----------|---------|
| **GitHub** | [liza-mas/liza](https://github.com/liza-mas/liza) |
| **Звезды** | 363 (28.08.2026), 49 вилок |
| **Лицензия** | Apache-2.0 |
| **Язык** | Go-супервизоры, утилиты поддержки Python |
| **Последний выпуск** | [v0.8.0](https://github.com/liza-mas/liza/releases/tag/v0.8.0), 2026-06-03 |
| **Каталог адаптеров** | Claude Code, Codex, OpenCode, Кими, Gemini, Квен, Мистраль, Девин, Курсор; Gemini и Mistral отключены в закрепленном каталоге |
| **Моментальный снимок доказательства** | [`a22c123`](https://github.com/liza-mas/liza/commit/a22c12381c5d884d2586a48aaaa517bca184f9cf), 2026-08-27 |

#### Что обеспечивает кодекс

Модель надзора [Лизы](https://github.com/liza-mas/liza/blob/a22c12381c5d884d2586a48aaaa517bca184f9cf/specs/architecture/supervision-model.md) отделяет семантическую работу от детерминированного управления жизненным циклом. Агенты предлагают переходы задач; Руководители Go проверяют право собственности, состояние, аренду, рассматривают вердикты и право на слияние. Доска YAML выдерживает потерю контекста модели, а поколения аренды изолируют устаревшие рабочие процессы после восстановления. Каждый исполнитель работает в изолированном рабочем дереве, и отдельный рецензент может отклонить заявку до того, как руководитель разрешит интеграцию.

Это делает Лизу полезным примером объединения двух слоев. Его путь `liza init` устанавливает ресурсы репозитория, такие как поведенческие контракты, навыки, настройки и ограждения. Режим MAS добавляет оркестратор над выбранной средой выполнения. Каталог поставщиков [](https://github.com/liza-mas/liza/blob/a22c12381c5d884d2586a48aaaa517bca184f9cf/provider-catalog.yaml) подтверждает, что Claude Code, Codex и другие CLI по-прежнему владеют своими внутренними циклами инструментов.

Проверенный коммит содержал 296 тестовых файлов Go и соответствовал заданиям Ubuntu и macOS CI проекта. В ходе этой проверки пакет не выполнялся локально, поскольку Go был недоступен на хосте проверки. Восходящая CI является полезным свидетельством обслуживания, но она не определяет качество задач, успешность восстановления под производственной нагрузкой или безопасность от ненадежного репозитория.

#### Где это останавливается

Границей изоляции Лизы является git, а не операционная система. Некоторые адаптеры поставщиков поддерживают широкие режимы утверждения, включая `--dangerously-skip-permissions` OpenCode и `--permission-mode dangerous` Devin. Агенты по-прежнему наследуют любую файловую систему, среду, учетные данные и доступ к сети, которые получает базовый процесс. Перед автоматическим использованием поместите песочницу ОС или контейнера и учетные данные с ограниченной областью действия под Liza.

Проект также публикует необычайно откровенный журнал [по архитектурным проблемам](https://github.com/liza-mas/liza/blob/a22c12381c5d884d2586a48aaaa517bca184f9cf/specs/architecture/architectural-issues.md). Он фиксирует использование одного оркестратора для семантической интерпретации, одного супервизора в качестве контроля правильности, неполную перекрестную проверку, пробелы в обратной связи по качеству спецификации и контекстное давление со стороны поведенческого контракта. Эти ограничения делают Liza подходящей для изолированного пилотного проекта с 8–12 билетами, а не для производственной зависимости по умолчанию, основанной только на количестве функций.

Читайте Liza как систему циклов и граф, специфичный для предметной области. Замороженная конфигурация конвейера [](https://github.com/liza-mas/liza/blob/a22c12381c5d884d2586a48aaaa517bca184f9cf/internal/embedded/pipeline.yaml) определяет стабильный организационный граф: роли, пары ролей, словари состояний, кворумы и переходы. Задачи и зависимости времени выполнения формируют изменяющийся график работы. Модель выполняет семантическую работу внутри узлов; детерминированный код Go проверяет части протокола перехода. Liza не является общей средой выполнения графа, поскольку ее тип перехода намеренно узкий, а ее узловые программы привязаны к жизненному циклу кодирования.

Граница ответственности важнее метки графика. Незаконные переходы, устаревшие претензии и неудовлетворенные кворумы механически отклоняются. Достаточность плана или правильность исправления по-прежнему зависит от доказательств и мнения рецензента. Закрепленный реестр явно определяет неизмеренную точность рецензента, последующие решения по кросс-парной декомпозиции, разнообразие поставщиков, которое является предпочтительным, а не гарантированным, и контрольные точки, выполняемые человеком, которые ограничивают пропускную способность. Оценивайте правильность рабочего процесса и правильность задачи отдельно. См. протокол тестирования [Agent Evaluation](../roles/agent-evaluation.md#evaluate-judgment-allocation-and-reviewer-independence).

В настоящее время существует один независимый отчет практикующего специалиста. В статье [Ippon Ипполита Дюрикса](https://blog.ippon.fr/2026/04/29/premier-rex-multi-agent-liza/) описывается небольшой запуск каталога Spring Boot, Vue.js и PostgreSQL: примерно 30 задач в течение 5 автоматических спринтов, 35 вердиктов проверки, 3 исправленных и повторно отправленных отказа и от 3 до 4 часов человеческого времени. Автор также сообщает о массовом потреблении токенов, необходимости проверки человеком этапов планирования и отсутствии проверки между поставщиками. Это полезное практическое свидетельство реального пользователя, но не производственный тест: проект был намеренно простым, цифры сообщаются самими пользователями, и никаких сопоставимых базовых показателей уровня артефактов не публикуется.

Мейнтейнер Liza также публикует отдельный проект [bash-policy](https://github.com/liza-mas/bash-policy). Он разбирает полезные данные составной оболочки на командные единицы, оценивает политику проекта и выдает решения `allow`, `manual` или `deny`. В проверенном репозитории не было ни помеченного релиза, ни свидетельств внедрения, поэтому рассматривайте его как проверяемый политический эксперимент, а не как зрелую зависимость безопасности. Его границы по-прежнему полезны: политика команд может ограничивать и проверять то, что агент запрашивает, но она не обеспечивает изоляцию файловой системы, учетных данных, процессов или сети. Соедините его с собственным механизмом политики среды выполнения и песочницей на уровне ОС.

### <a name="49-multica"></a>4.9 Мультика

Multica — это плоскость управления, ориентированная на решение проблем, для людей и агентов по кодированию. Он хранит рабочие области, проблемы, чат, конфигурацию агента, расписания и историю запусков в одном приложении, а затем делегирует выполнение существующим интерфейсам командной строки агента кодирования. Claude Code, Codex, Cursor, OpenCode и другие инструменты по-прежнему имеют свои внутренние циклы моделей и инструментов.

| **Лицензия** | [Multica License](https://github.com/multica-ai/multica/blob/7a438bd5b8bf39afd54259a7eb0971390e50a8ef/LICENSE): текст Apache 2.0 плюс условия хостинга, внедрения, брендинга и атрибуции |

#### Что это на самом деле делает

Назначение задачи, прямой чат, упоминание или запланированный автопилот создает запуск в очереди сервера. Демон на подключенном компьютере утверждает, что запускается, подготавливает рабочий каталог или рабочее дерево git, вызывает настроенный локальный CLI и передает потоки прогресса, активности инструмента, ошибок, использования токенов и конечного результата обратно в проблему.

```text
issue / chat / mention / Autopilot
              |
              v
Multica server + PostgreSQL
              |
       queued run over WebSocket
              |
              v
daemon on a connected computer
              |
      worktree + local agent CLI
              |
              v
progress, logs, cost, result -> server timeline
```

Режим развертывания меняется там, где работает уровень координации, а не в этом разделении выполнения:

| Режим | Уровень координации | Уровень исполнения |
|---|---|---|
| Мультика Облако | Multica размещает веб-приложение API и базу данных. | На вашем компьютере или облачном компьютере запущен демон, репозиторий, учетные данные и интерфейс командной строки агента. |
| Self-hosted | Вы запускаете веб-приложение API и PostgreSQL с помощью Docker Compose или Helm. | На одном или нескольких подключенных компьютерах запускаются интерфейсы командной строки демона и агента. |

Если демон находится в автономном режиме, новые запуски остаются в очереди. Запуски, которые уже выполнялись, могут завершиться неудачей и получить право на повторную попытку; демон перерегистрирует среду выполнения и пытается восстановиться после возвращения. Это делает Multica больше, чем просто визуальный запуск сеанса, оставляя при этом рассуждение о задачах и выполнение инструментов выбранному CLI.

#### Граница данных и безопасности

Локальные репозитории и учетные данные инструмента не загружаются автоматически полностью. Сервер сохраняет проблемы, комментарии, конфигурацию агента, контекст запуска, записи выполнения и результаты. Значения агента `custom_env` и конфигурация MCP хранятся на стороне сервера и передаются в среду выполнения, поэтому локальное выполнение не означает, что каждый секрет или артефакт задачи остается на исполняющей машине.

Документированная модель безопасности [](https://github.com/multica-ai/multica/blob/7a438bd5b8bf39afd54259a7eb0971390e50a8ef/apps/docs/content/docs/security-model.mdx) делает учетную запись операционной системы, на которой запущен демон, эффективной границей. Runs может читать и записывать все, что может получить эта учетная запись, использовать ее учетные данные и получать доступ к сети. Проверенные пути по умолчанию запускают Claude Code с `bypassPermissions` и Codex с `danger-full-access`, за исключением случаев, когда применяется документированное согласие на использование песочницы Windows Codex. Перед автоматическим выполнением используйте выделенную учетную запись ОС, контейнер или виртуальную машину с ограниченной областью действия Git и облачными учетными данными.

Состояние `in_review` записывает статус рабочего процесса внутри Multica. Он не настраивает защиту ветвей и не заменяет правила проверки и слияния хоста Git. Агенты могут использовать учетные данные, доступные на исполняющей машине, для отправки ветвей или открытия запросов на извлечение, поэтому политика репозитория остается точкой применения.

#### Где это останавливается

Проверка исходного кода охватывала закрепленный коммит, документацию, пути демона, адаптеры агентов, запросы к базе данных, лицензию и успешный восходящий CI для этого коммита. Приложение не было запущено, и реальный запуск агента не выполнялся. Это устанавливает архитектуру и заявленные средства управления, а не сквозную надежность, качество задач, восстановление под нагрузкой или защиту от враждебного репозитория.

Репозиторий описывает себя как открытый исходный код, но его лицензия добавляет ограничения помимо Apache 2.0. Назовите это доступным по источнику, если юридическая проверка не установит более узкий вывод об использовании. Команда, оценивающая Multica, должна протестировать точную облачную или локальную топологию с непроизводственными учетными данными, защитой ветвей, одним восстанавливаемым репозиторием и отработанным сценарием отключения демона.

### <a name="the-model-lock-in-question"></a>Вопрос о привязке модели

Самый проясняющий вопрос при выборе между Claude Code, Codex, CLI, Hermes, Aider и Goose: должен ли инструмент работать только с одним поставщиком моделей или с несколькими?

Если вы привержены Claude и экосистеме Anthropic (подписка, подпрограммы, агент SDK, инструменты CLAUDE.md), Claude Code — однозначно правильный выбор. Интеграция является встроенной, а скорость работы функций Anthropic высока.

Если вам нужна гибкость модели (локальные модели для конфиденциального кода, более дешевые модели для рутинных задач, специальные модели для сравнительного анализа), Hermes Agent обрабатывает самый широкий диапазон с максимальной автоматизацией. Aider и Goose — более простые альтернативы, занимающие меньше места.

Если ваша команда использует OpenAI в первую очередь и уже платит за ChatGPT Pro, Codex CLI не требует никаких дополнительных затрат.

### Компромисс между автономией и контролем

Более высокая автономия означает, что агент может выполнить больше работы без вашего наблюдения, но также означает больше возможностей отклониться от выполнения неоднозначных задач. Правильный уровень автономности зависит от того, насколько хорошо определены ваши задачи, а не от того, какой инструмент «более мощный».

Безголовый Claude Code (`claude -p`) и SWE-агент дают вам контролируемую автономию: вы ставите задачу, агент запускается, вы просматриваете выходные данные. Devin дает вам максимальную автономию благодаря облачной песочнице: агент имеет полную среду Linux и может выполнять действия, которые вы не ожидали. Перед слиянием требуется больше мощности, больше проверок.

Интерактивные агенты (терминал Claude Code, Hermes, Aider, Goose) дают вам контроль в режиме реального времени. Вы наблюдаете, как агент думает, перенаправляете его, когда что-то идет не так, и одобряете деструктивные действия. Для исследовательской работы, когда требования меняются в середине сессии, интерактивный режим работает быстрее, чем автономный, несмотря на то, что он кажется более ручным.

Безагентный подход является противоположным примером рассмотрения автономности или количества кандидатов как показателя качества. В оценке FSE 2025 использовался ограниченный трехэтапный рабочий процесс с GPT-4o на SWE-bench Lite, и было решено 96 из 300 проблем, или 32%, при средней заявленной стоимости вывода 0,70 доллара США за проблему. Производительность восстановления стабилизировалась примерно на 40 патчах-кандидатах. Результат получен на основе одного эталонного показателя с ценами API 2024 года и не включает тестовую инфраструктуру и человеческий анализ, поэтому это не прогноз производства. Он поддерживает тестирование ограниченного рабочего процесса локализации, восстановления и проверки перед добавлением дополнительных циклов или кандидатов агента. Источник: [Xia и др., Демистификация агентов разработки программного обеспечения на основе LLM](https://lingming.cs.illinois.edu/publications/fse2025.pdf), DOI [10.1145/3715754](https://doi.org/10.1145/3715754), PDF, стр. 10–15, таблица 1 и рисунок 6.
