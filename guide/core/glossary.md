# Глоссарий

Определения терминов, используемых в этом руководстве. Концепции уровня модели (токены, температура, RAG) см. в глоссарии платформы [Anthropic](https://platform.claude.com/docs/en/about-claude/glossary).

Для практических сравнений см. Концептуальные границы [AI](./ai-concept-boundaries.md): контекст против памяти, модель против системы, рабочий процесс против агента, инструменты против MCP, инструкции против средств управления выполнением, оценка против производственных доказательств, а также архитектура модели, класс размера, модальность и метки задач. Он включает семь сценариев с исправлениями, выборочно адаптированных из Lexigraph с указанием авторства.

---

## A

### Команды агентов

Несколько независимых сеансов Claude Code, координируемых руководителем группы, с общим списком задач и одноранговым обменом сообщениями. В отличие от субагентов, которые запускаются в рамках одного сеанса, у каждого из товарищей по команде есть собственное контекстное окно, и вы можете напрямую взаимодействовать с любым из них. Это экспериментальная функция; для включения требуется `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`. См. [§4 Агенты](../ultimate-guide.md#4-agents).

### Агентический цикл

Цикл Claude работает для каждой задачи: собрать контекст, выполнить действие, проверить результаты, повторять до тех пор, пока не будет выполнено. Каждое использование инструмента возвращает информацию, которая определяет следующий шаг. Большинство точек расширения (хуки, навыки, MCP) включаются в определенные фазы этого цикла. См. [§1. Как работает Claude Code](../ultimate-guide.md#1-how-claude-code-works).

### Агент-компьютерный интерфейс

Команды, наблюдения, формат обратной связи и правила взаимодействия, посредством которых модель действует на компьютере. Лучший интерфейс может улучшить агента без изменения модели. [SWE-agent](https://arxiv.org/abs/2405.15793) использует этот термин для обозначения команд и обратной связи, ориентированных на репозиторий. Интерфейс — это один из компонентов среды выполнения, а не только его визуальный интерфейс.

### Автоматическая память

Примечания Claude пишет для себя на основе ваших исправлений и предпочтений, которые хранятся в репозитории git под `~/.claude/projects/`. Первые 200 строк или 25 КБ `MEMORY.md` загружаются при запуске сеанса. Все рабочие деревья одного и того же репозитория используют один каталог автоматической памяти. См. [§3 Память](../ultimate-guide.md#3-configuration--memory).

### Автоматический режим

Режим разрешений, в котором отдельная модель классификатора проверяет каждое действие в фоновом режиме, а не показывает запросы на одобрение. Классификатор блокирует расширение области действия, ненадежную инфраструктуру и попытки быстрого внедрения. Он никогда не видит результатов работы инструмента, что делает его невосприимчивым к введенным инструкциям. Это предварительный обзор исследования. См. [§3 Режимы разрешений](../ultimate-guide.md#3-configuration--memory).

## B

### Голый режим

Флаг запуска (`--bare`), который пропускает автоматическое обнаружение перехватчиков, навыков, плагинов, серверов MCP, автоматической памяти и CLAUDE.md. Вступают в силу только те флаги, которые вы передаете явно. Рекомендуется для вызовов CI и сценариев, где требуется одинаковое поведение на всех компьютерах. Доступно с версии 2.1.81. См. [§9. Режим Headless/Non-interactive](../ultimate-guide.md#9-advanced-features).

### Комплексные навыки

В состав Claude Code входят сборники сценариев на основе подсказок, такие как `/batch`, `/code-review`, `/debug` и `/loop`. В отличие от встроенных команд (которые выполняют фиксированную логику), связанные навыки дают Claude подробную подсказку и позволяют ему координировать работу. Они могут создавать агентов, читать файлы и адаптироваться к вашей кодовой базе. См. [§5 Навыки](../ultimate-guide.md#5-skills).

## C

### Канал

Сервер MCP, который передает события в ваш текущий сеанс, чтобы Claude мог реагировать на события, происходящие, пока вы находитесь вдали от терминала. Каналы могут быть двусторонними: Claude считывает входящее событие и отвечает через тот же канал. Telegram, Discord и iMessage включены в предварительную версию исследования. См. [§8 MCP](../ultimate-guide.md#8-mcp).

### Контрольно-пропускной пункт

Точка восстановления создается при каждом отправленном вами запросе. Claude Code делает снимки файлов перед каждым редактированием, поэтому вы можете вернуть код, диалог или и то, и другое в более раннее состояние. Нажмите `Esc` дважды или запустите `/rewind` для восстановления. Контрольные точки являются локальными для сеанса, отделены от git и не отслеживают изменения, внесенные с помощью инструмента Bash. См. [§9. Контрольная точка](../ultimate-guide.md#9-advanced-features).

### Каталог `.claude`

Каталог, в котором Claude Code считывает конфигурацию проекта: настройки, перехватчики, навыки, субагенты, правила и автоматическую память. В корне проекта находится `.claude/`; ваши настройки по умолчанию на уровне пользователя находятся по адресу `~/.claude/`. См. [§3 Конфигурация](../ultimate-guide.md#3-configuration--memory).

### CLAUDE.md

Файл уценки постоянных инструкций, который вы пишете для Claude, загружаемый в начале каждого сеанса как сообщение пользователя после системного приглашения. Поместите сюда соглашения проекта, примечания по архитектуре и правила поведения. CLAUDE.md выдерживает сжатие и после этого заново считывается с диска. См. [§3.1 Файлы памяти](../ultimate-guide.md#31-memory-files-claudemd).

### Уплотнение

Автоматическое обобщение вашего разговора, когда контекстное окно приближается к своему пределу. Сначала очищаются выходные данные старых инструментов, а затем суммируется диалог. CLAUDE.md и автоматическая память выдерживают сжатие и перезагрузку с диска; инструкции, данные только в разговоре, могут быть потеряны. Запустите `/compact` для запуска вручную. См. [§2 Контекстное окно](../ultimate-guide.md#2-core-concepts).

## D

### Отправлять

Маршрутизатор задач, инициируемый телефоном, который создает сеанс Claude Code в приложении для настольного компьютера, когда вы отправляете задачу кодирования из мобильного приложения Claude. Ваше приглашение автоматически направляется к нужному инструменту. Доступно в планах Pro и Max. См. [§9 Функции рабочего стола](../ultimate-guide.md#9-advanced-features).

## E

### Уровень усилий

Настройка, которая контролирует, какую часть бюджета адаптивного мышления Claude использует за ход. Более высокие усилия означают больше жетонов мышления и более глубокие рассуждения; меньшее усилие быстрее и дешевле. Поддерживается в Opus 4.6+ и Sonnet 4.6+. Навыки могут переопределять уровень усилий сеанса в своей основной теме. См. [§2.5 Выбор модели](../ultimate-guide.md#25-model-selection--thinking-guide).

### <a name="extended-thinking"></a>Расширенное мышление

Наглядные пошаговые рассуждения, которые модель выполняет перед ответом. Вы можете ограничить количество жетонов мышления с помощью `MAX_THINKING_TOKENS` или отрегулировать уровень усилий. Мышление отображается в терминале серым курсивом. См. [§2.5 Выбор модели](../ultimate-guide.md#25-model-selection--thinking-guide).

## G

### Графовая инженерия

Проектирование рабочего процесса агента в виде явного исполняемого графа с версионным состоянием, узлами, ребрами, условиями маршрутизации, соединениями, контрольными точками и поведением восстановления. Граф может содержать циклы, но эти два термина не являются синонимами: цикл описывает повторяющуюся обратную связь, а граф описывает топологию, которая определяет работу и состояние маршрутов. Этикетка скорее появляется, чем стандартизируется. См. [Разработка циклов и графов](./loop-graph-engineering.md).

## H

### <a name="agent-harness"></a>Агентская обвязка

Среда выполнения модели, которая выполняет цикл агента: она собирает контекст, предоставляет инструменты, применяет разрешения, сохраняет или восстанавливает состояние и передает результаты инструментов обратно в модель. Claude Code — это среда выполнения; Claude — это модель, на которой он работает. Не путайте его с обвязкой репозитория, которая представляет собой уровень инструкций, настройки, состояния и проверки для конкретного проекта. См. [Проектирование проводки агента](./agent-harness.md), [Проектирование проводки агента](../ecosystem/agent-harness-landscape.md)и [§9.25 Проектирование проводки репозитория](../ultimate-guide.md#925-harness-engineering).

### Оценочный комплект

Повторяемая установка, которая запускает агент или модель для выполнения определенных задач и записывает результаты, затраты, трассировки или оценки. Оценочный комплект измеряет систему; ему не требуется владеть циклом интерактивных инструментов системы или работать с репозиторием. Инструменты SWE-bench — это средства оценки, а SWE-агент — это среда выполнения кода, которую можно оценить с их помощью. См. [Оценка агента](../roles/agent-evaluation.md).

### Пара шлейки-модель

Точная комбинация модели, среды выполнения, конфигурации, набора инструментов, среды репозитория и бюджета, используемого для запуска. Оцените эту пару как единое целое: замена ремня может изменить точность, стоимость и режимы отказов, даже если модель остается неподвижной. [Эффект каркаса](https://arxiv.org/abs/2607.22585) предоставляет контролируемые доказательства этого эффекта на двух моделях и трех системах кодирования. См. [Проектирование проводки агента](./agent-harness.md#the-core-claim) и [Программа проводки агента](../ecosystem/agent-harness-landscape.md).

### Возможность использования

Параметр рабочей оценки того, насколько надежно модель следует конкретному оборудованию в условиях реалистичного давления: необходимые проверки, границы политик, протокол восстановления, переходы между состояниями и правила эскалации. Это не стандартизированный скаляр или внутреннее свойство модели. Сообщайте о наблюдаемых показателях и режимах отказов для конкретной пары «модель-привязь» вместо публикации единого универсального показателя. См. [Оценка распределения решений и независимость рецензента](../roles/agent-evaluation.md#evaluate-judgment-allocation-and-reviewer-independence).

### Оптимизатор жгута

Система внешнего цикла, которая предлагает изменения в целевой системе, оценивает возможные версии и сохраняет или отклоняет эти изменения по определенным метрикам. Его цель поиска может включать в себя подсказки, правила контекста, инструменты, поток управления, проверку или политику памяти. Оптимизатор жгутов не заменяет оцениваемый им цикл времени выполнения. См. [«Оптимизаторы обвязок» и «Мета-обвязки»](./agent-harness.md#11-harness-optimizers-and-meta-harnesses).

### Хук

Определяемый пользователем обработчик, который выполняется автоматически в определенный момент жизненного цикла Claude Code, например, перед запуском инструмента, после редактирования файла или при запуске сеанса. Конфигурация перехватчика имеет три уровня: событие перехвата (какая точка жизненного цикла), сопоставитель (какие события его запускают) и обработчик перехвата (что выполняется). Обработчиками могут быть команда оболочки, конечная точка HTTP, инструмент MCP, приглашение LLM или субагент. Хуки детерминированы: они срабатывают в фиксированных точках жизненного цикла, а не по усмотрению модели. См. [§7 Хуки](../ultimate-guide.md#7-hooks).

## J

### Распределение решений

Явное распределение решений между людьми, моделями, детерминированными проверками, механизмами политики и внешними органами власти. Он отвечает на вопрос, кто устанавливает планку качества, какие доказательства допустимы, кто решает, что доказательств достаточно, и кто обрабатывает исключения. Автоматизация выполнения может перенести человеческое решение на разработку цикла, политику, эскалацию или утверждение выпуска, не устраняя его. См. [. Явное определение решения](./loop-graph-engineering.md#5-allocate-judgment-explicitly).

## L

### Петлевая инженерия

Разработка процесса повторяющейся обратной связи, который находит или получает работу, вызывает агента, наблюдает за результатами, проверяет прогресс и выбирает следующее действие до тех пор, пока не сработает правило остановки. Этот термин представляет собой полезный практический словарь, а не формальный стандарт. Цикл может быть закодирован внутри графа и ограничен связкой. См. [Разработка циклов и графов](./loop-graph-engineering.md).

## M

### Управляемые настройки

Файл настроек, применяемый на уровне всей организации ИТ-специалистами или DevOps, расположенный по пути на уровне ОС за пределами `~/.claude`. Пользователи не могут переопределить или исключить управляемые настройки. Используйте это для политик безопасности, требований соответствия или стандартизированных инструментов для всего парка машин. См. [§3.3 Настройки](../ultimate-guide.md#33-settings--permissions).

### Meta-harness

Перегруженный термин, имеющий два текущих значения. В исследованиях оптимизаторов это система, основанная на одном или нескольких целевых жгутах, которая генерирует или модифицирует возможные жгуты, проводит оценки и использует результаты для направления следующего шага оптимизации. [Meta-Harness](https://arxiv.org/abs/2603.28052) и [Agentic Harness Engineering](https://arxiv.org/abs/2604.25850) — текущие примеры препринтов. Некоторые продукты используют *meta-harness* для общего клиента, который распределяет задачи по существующим средам выполнения. В этом руководстве эта вторая роль классифицируется как оркестратор или плоскость управления, если только система не изменяет и не оценивает саму систему. См. [Проектирование жгутов агентов](./agent-harness.md#0-four-layers-four-responsibilities).

### MCP (Model Context Protocol)

Открытый стандарт для подключения инструментов искусственного интеллекта к внешним источникам данных и сервисам. Серверы MCP предоставляют Claude новые инструменты для Slack, Jira, баз данных, браузеров и сотен других интеграций. Подключите серверы через `/mcp` или добавив их в `.mcp.json`. См. [§8 MCP](../ultimate-guide.md#8-mcp).

### MCP поиск инструмента

Механизм сохранения контекста, который откладывает схемы инструментов MCP до тех пор, пока они не понадобятся. При запуске загружаются только имена инструментов; Claude извлекает полную схему по требованию, когда решает использовать конкретный инструмент. Это удерживает простаивающие серверы MCP от потребления контекста. См. [§8 MCP](../ultimate-guide.md#8-mcp).

## N

### Неинтерактивный режим

Режим, который выполняет одно приглашение и завершается без диалогового сеанса, вызывается с помощью `-p` или `--print`. Используется для CI, сценариев и конвейеров. Флаг `--bare` расширяет возможности автоматизации с чистого листа. Ранее назывался «безголовый режим». См. [§9 Неинтерактивный режим](../ultimate-guide.md#9-advanced-features).

---

## O

### Оркестратор

Система, которая координирует прогоны, рабочие пространства, очереди, бюджеты, передачу обслуживания или утверждения людьми между одним или несколькими агентами. Оркестратор может вызывать отдельную среду выполнения, не владея самим циклом модель-инструмент-наблюдение. См. [Оркестраторы: продукты выше среды выполнения](../ecosystem/agent-harness-landscape.md#orchestrators-products-above-the-runtime).

### Стиль вывода

Конфигурация, которая изменяет системное приглашение Claude для изменения поведения, тона или формата ответа для всего сеанса, в отличие от CLAUDE.md (который доставляется в виде пользовательского сообщения). Встроенные стили «Проактивный», «Краткий», «Пояснительный» и «Обучение» сохраняют инструкции по разработке программного обеспечения по умолчанию; пользовательский стиль отбрасывает их, если его заголовок не устанавливает `keep-coding-instructions: true`. Значение по умолчанию означает, что стиль не выбран. См. [§9.7 Стили вывода](../ultimate-guide.md#97-output-styles).

## P

### Режим разрешений

Базовое поведение утверждения для сеанса. Доступные режимы: `default`, `acceptEdits`, `plan`, `auto`, `dontAsk` и `bypassPermissions`. Циклически используйте `Shift+Tab` в CLI или используйте переключатель режима в VS Code, Desktop и claude.ai. См. [§3.3 Настройки](../ultimate-guide.md#33-settings--permissions).

### Правило разрешения

Запись настроек, которая разрешает, запрашивает или запрещает вызов инструмента на основе имени инструмента и шаблона аргументов. Правила оцениваются в порядке «запретить, затем спросить, затем разрешить», поэтому побеждает первое совпадение. Правила разрешений — это детальные элементы управления, расположенные поверх более широкого режима разрешений. См. [§3.3 Настройки](../ultimate-guide.md#33-settings--permissions).

### <a name="plan-mode"></a>Режим планирования

Режим разрешений, в котором Claude исследует и предлагает изменения без редактирования исходных файлов. Он может читать, искать и запускать команды исследования, а затем представляет план на утверждение, прежде чем прикасаться к чему-либо. Войдите в режим планирования с помощью `/plan` или нажав `Shift+Tab`. См. [§3.3 Настройки](../ultimate-guide.md#33-settings--permissions).

### Плагин

Пакет навыков, перехватчиков, субагентов и серверов MCP, упакованных как один устанавливаемый модуль. Навыки плагинов имеют пространство имен `plugin-name:skill-name`, поэтому несколько плагинов сосуществуют без конфликтов. Распространяйте плагины между командами через торговую площадку. См. [§5 Навыки](../ultimate-guide.md#5-skills).

### Доверие к проекту

Диалоговое окно, которое принимает каталог до того, как Claude Code загрузит его конфигурацию. Принятие сохраняется для каждого каталога проекта, за исключением вашего домашнего каталога (где доверие предоставляется только для каждого сеанса). Доверительные ворота обеспечивают автоматическую установку плагинов торговой площадки и выполнение определенных проектом перехватчиков. См. [§3 Конфигурация](../ultimate-guide.md#3-configuration--memory).

### Быстрая инъекция

Враждебные инструкции, встроенные в файл, веб-страницу или инструмент, приводят к попытке перенаправить Claude на действия, которые вы никогда не запрашивали. Защита Claude Code включает систему разрешений, черные списки команд и проверку доверия. В автоматическом режиме добавляется классификатор на стороне сервера, который никогда не видит результаты инструмента, поэтому введенный текст не может повлиять на его решения об утверждении. См. [§10 Безопасность](../ultimate-guide.md#10-security).

## R

### Репозиторий

Уровень, специфичный для проекта, который обеспечивает повторяемость запуска агента внутри репозитория: инструкции, настройка среды, устойчивое состояние, тестовые команды, шлюзы проверки и соглашения о восстановлении. Он заземляет и проверяет среду выполнения, но не заменяет цикл модель-инструмент среды выполнения. См. [§9.25 «Инжиниринг репозитория».](../ultimate-guide.md#925-harness-engineering) и [Четыре уровня, четыре обязанности](./agent-harness.md#0-four-layers-four-responsibilities).

### <a name="remote-control"></a>Пульт дистанционного управления

Способ продолжить локальный сеанс Claude Code с телефона или браузера через claude.ai. Ваш код остается на вашем компьютере; только пользовательский интерфейс является удаленным. Отличается от веб-версии Claude Code, которая работает в облачной песочнице. См. [§9.22 «Пульт дистанционного управления»](../ultimate-guide.md#922-remote-control-mobile-access).

### Правила

Модульные файлы инструкций в `.claude/rules/`, которые загружаются вместе с CLAUDE.md. Правило может быть ограничено путем с помощью заголовка YAML `paths:`, поэтому оно загружается только тогда, когда Claude читает соответствующий файл, сохраняя контекст до тех пор, пока он не станет актуальным. См. [§3.1 Файлы памяти](../ultimate-guide.md#31-memory-files-claudemd).

## S

### Песочница

Файловая система на уровне ОС и сетевая изоляция для инструмента Bash. Команды выполняются внутри границ, которые вы определяете заранее, поэтому Claude может свободно работать внутри них без запросов на одобрение каждой команды. Песочница — это отдельный уровень от правил разрешений. См. [§10 Безопасность](../ultimate-guide.md#10-security).

### Эффект каркаса

Изменение результата, использования токена и режима отказа, вызванное окружающим каркасом агента или ремнями безопасности, пока модель остается фиксированной. В одном контролируемом исследовании кодирования выбор средств управления изменил использование токенов для каждой решенной задачи до 40 раз, в то время как разница в скорости прохождения оставалась между 0 и 8 процентными пунктами и в большинстве случаев не была статистически значимой. Относитесь к этому как к свидетельству ограниченного эксперимента, а не как к универсальному рейтингу. См. [Эффект каркаса](https://arxiv.org/abs/2607.22585).

### Сессия

Разговор, привязанный к вашему текущему каталогу, с собственным независимым контекстным окном. Сеансы можно возобновлять с помощью `claude -c`, разветвлять с помощью `--fork-session` или запускать параллельно на всех терминалах. Стенограмма каждого сеанса хранится под именем `~/.claude/projects/`. См. [§1. Как работает Claude Code](../ultimate-guide.md#1-how-claude-code-works).

### Слои настроек

Иерархия Claude Code считывает конфигурацию в порядке приоритета от высшего к низшему: управляемая политика, аргументы командной строки, локальные настройки в `.claude/settings.local.json`, настройки проекта в `.claude/settings.json`, затем пользовательские настройки в `~/.claude/settings.json`. Массивы объединяются между слоями; скаляры на более высоком уровне переопределяют более низкие. См. [§3.3 Настройки](../ultimate-guide.md#33-settings--permissions).

### Навык

Файл `SKILL.md`, содержащий инструкции, знания или рабочий процесс, который Claude добавляет в свой набор инструментов. Вызовите напрямую с помощью `/skill-name`. Навыки соответствуют открытому стандарту «Навыки агента»; Claude Code расширяет его за счет управления вызовами и выполнения субагента. Навыки являются рекомендуемой преемницей пользовательских команд: файлы `.claude/commands/` продолжают работать, но `.claude/skills/` является предпочтительным расположением. См. [§5 Навыки](../ultimate-guide.md#5-skills).

### Субагент

Специализированный ИИ-помощник, работающий в собственном контекстном окне с настраиваемой системной подсказкой, доступом к определенным инструментам и независимыми разрешениями. Он работает над делегированной задачей и возвращает сводку в основной диалог. В отличие от групп агентов (где каждый агент представляет собой полностью независимый сеанс), субагенты работают внутри родительского сеанса и отчитываются перед ним. См. [§4 Агенты](../ultimate-guide.md#4-agents).

### Поверхность

Из любого места, где вы получаете доступ к Claude Code: CLI, VS Code, JetBrains, Desktop или claude.ai. На всех поверхностях используется один и тот же движок, поэтому ваш CLAUDE.md, настройки и навыки работают на них одинаково. Slack и расширение Chrome — это интеграции, которые подключаются к поверхности, а не к самим поверхностям.

## T

### Телепортироваться

Команда (`/teleport`), которая подключает облачный сеанс Claude Code к вашему локальному терминалу. Claude извлекает ветку, загружает историю разговоров и возобновляет работу с последнего состояния веб-сеанса. Обратное направление — `--remote`, которое отправляет локальную задачу для запуска в Интернете. См. [§9.16 Сеансовая телепортация](../ultimate-guide.md#916-session-teleportation).

### Инструмент

Действие, которое может выполнить Claude: прочитать файл, отредактировать код, запустить команду оболочки, выполнить поиск в Интернете, создать субагент. Инструменты — это то, что делает Claude Code агентом. Без них Claude сможет ответить только текстом. Каждое использование инструмента возвращает результат, который информирует Claude о следующем решении в агентном цикле. См. [§1. Как работает Claude Code](../ultimate-guide.md#1-how-claude-code-works).

### Повернуть

Один полный ответ от Claude в течение сеанса. Ход начинается, когда вы отправляете сообщение, и заканчивается, когда Claude заканчивает отвечать, с любым количеством вызовов инструментов между ними. Остановить стрельбу крюками в конце каждого хода. См. [§7 Хуки](../ultimate-guide.md#7-hooks).

## V

### Цикл проверки

Шаблон сеанса, в котором вы даете Claude проверку, которую он может выполнить (набор тестов, сборку или сравнение снимков экрана), и Claude выполняет итерацию до тех пор, пока проверка не пройдет, а не останавливается после одной попытки. Цикл проверки является необходимым условием для `/goal`, автоматических запусков и динамических рабочих процессов: без него единственным сигналом о завершении работы агента является сам агент. См. [§9 Дополнительные функции](../ultimate-guide.md#9-advanced-features).

## W

### <a name="worktree-isolation"></a>Изоляция рабочего дерева

Режим изоляции, который запускает Claude в отдельном рабочем дереве git под `.claude/worktrees/`, включается с помощью флага `-w` или `isolation: worktree` в конфигурации субагента. Изменения остаются в отдельной ветке и каталоге, поэтому параллельные агенты не могут перезаписывать файлы друг друга. См. [§4 Агенты](../ultimate-guide.md#4-agents).
