# Кредиты и внешнее вдохновение

В этом руководстве описаны шаблоны сообщества Claude Code. Некоторые разделы напрямую вдохновлены репозиториями с открытым исходным кодом, сообщениями в блогах или общественными инженерными работами. На этой странице сведения об авторстве собраны в одном месте.

## Команда инженеров Packmind

**Repo**: [github.com/packmind/packmind](https://github.com/PackmindHub/packmind)
**Автор**: Седрик Тейтон (технический директор Packmind)
**License**: Apache 2.0

Packmind поддерживает рабочую конфигурацию Claude Code в своем репозитории с открытым исходным кодом. Несколько паттернов, описанных в этом руководстве, были вдохновлены их настройкой `.claude/`:

### Шаблон 1: справочный файл MCP

**Раздел руководства**: [Документирование MCP для Claude](../ecosystem/mcp-servers-ecosystem.md#documenting-an-mcp-for-claude-the-reference-file-pattern)
**Источник**: `.claude/skills/datadog-analysis/references/datadog_mcp.md`

Файл `references/<mcp-name>.md`, читаемый навыком перед любым вызовом MCP. Содержит ошибки синтаксиса запросов, необходимые комбинации параметров, рабочие примеры и правила исключения шума, специфичные для одного сервера MCP.

### Модель 2: Скептически настроенный рецензент субагент

**Раздел руководства**: [Шаблон: Скептический рецензент, субагент](../ultimate-guide.md#pattern-skeptical-reviewer-sub-agent)
**Источник**: `.claude/skills/playbook-audit/references/report-agent.md`

Четвертый агент в многоагентном конвейере аудита, задача которого — отклонять ложные срабатывания первых трех агентов. Работает с явными критериями ложноположительных результатов и требует доказательств от обоих артефактов, прежде чем сохранять какие-либо результаты.

### Модель 3: Совместное внедрение истины

**Раздел руководства**: [Шаблоны проектирования навыков](./skill-design-patterns.md#shared-ground-truth-injection)
**Источник**: `.claude/skills/doc-audit/SKILL.md`

Оркестратор вычисляет общую фактическую основу (структуру навигации, команды CLI, список файлов) один раз, а затем вводит один и тот же блок во все параллельные запросы субагента. Предотвращает повторное обнаружение одними и теми же фактами каждым субагентом независимо друг от друга.

### Шаблон 4. Предварительно отфильтрованные ссылки по путям к началу страницы.

**Раздел руководства**: [Шаблоны проектирования навыков](./skill-design-patterns.md#pre-filtered-references-via-frontmatter-paths)
**Источник**: `.claude/skills/qa-review/SKILL.md`

Оркестратор считывает файлы правил, анализирует шаблоны шаблонов заголовка `paths:`, сопоставляет их с измененными файлами и передает каждому агенту проверки только применимые правила. Прогрессивное раскрытие информации применяется к стандартам, а не только к документации.

### Шаблон 5: триада передачи обслуживания с семантикой слияния

**Раздел руководства**: [Шаблон передачи сеанса](../ultimate-guide.md#session-handoff-pattern) и шаблоны на `examples/commands/handoff/`
**Источник**: `.claude/commands/create-handoff.md`, `resume-handoff.md`, `update-handoff.md`

Протокол из трех команд для обеспечения непрерывности сеанса: `create-handoff` инициализирует структурированный документ, `update-handoff` применяет правила слияния для конкретного раздела (только добавление для рабочего журнала, замена для статуса), а `resume-handoff` загружает последний документ в контекст.

### Шаблон 6: Шаблон рецепта с контрольными точками проверки контекста

**Раздел руководства**: [Шаблоны проектирования навыков](./skill-design-patterns.md#recipe-template-and-context-validation-checkpoints) и шаблон на `examples/commands/recipe-template.md`
**Source**: повторяющийся шаблон в командных файлах Packmind.

Структура шаблона команды, в которой в разделе «Проверки проверки контекста» перечислены предварительные условия, которые Claude должен проверить перед выполнением шагов рецепта. Уменьшает количество ошибок, вызванных отсутствием контекста или неправильной средой.

## Packmind контекстный оценщик

**Автор**: Команда инженеров Packmind
**Лицензия**: MIT

### Схема 7. Ведение журнала подсказок во время выполнения

**Раздел руководства**: [Шаблоны проектирования навыков](./skill-design-patterns.md#runtime-prompt-logging)
**Источник**: `src/shared/evaluation/runtime-prompt-logger.ts`

### Схема 8: Адаптивный режим unified/parallel

**Раздел руководства**: [Шаблоны проектирования навыков](./skill-design-patterns.md#adaptive-unifiedparallel-mode)
**Источник**: `src/shared/evaluation/runner.ts` (`canUseUnifiedMode()`)

Пороговое переключение токена между унифицированной оценкой одного агента (обнаружение нескольких файлов) и параллельными независимыми агентами для каждого файла. Порог по умолчанию: 100 000 токенов.
