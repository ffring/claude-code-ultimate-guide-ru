# Справочник по встроенным инструментам

Claude Code поставляется с набором встроенных инструментов, которые он использует для чтения, изменения и выполнения действий в вашей среде. Вы не устанавливаете и не настраиваете их; они всегда присутствуют.

Имена инструментов — это точные строки, которые вы используете в правилах разрешений (`allow`/`deny`), субагентах `tools` и `disallowedTools`, полях перехвата `matcher` и флагах CLI `--allowedTools`/`--disallowedTools`. Чтобы добавить пользовательские инструменты, подключите сервер [MCP](../ecosystem/mcp-servers-ecosystem.md). Чтобы создать многократно используемые рабочие процессы, управляемые подсказками, напишите [skill](../../examples/skills/); они запускаются с помощью существующего инструмента `Skill`, а не добавляют новую запись инструмента. [Использование компьютера](./computer-use.md) — это отдельный встроенный сервер MCP с границей разрешений рабочего стола macOS.

## Форматы правил разрешений

Имена инструментов появляются в правилах разрешений с необязательным спецификатором:

| Формат правила | Применяется к | Чему оно соответствует |
|-------------|------------|-----------------|
| `Bash(npm run *)` | `Bash`, `Monitor` | Команды оболочки от prefix/glob |
| `PowerShell(Get-ChildItem *)` | `PowerShell` | PowerShell команды |
| `Read(~/secrets/**)` | `Read`, `Grep`, `Glob`, `LSP` | Пути к файлам |
| `Edit(/src/**)` | `Edit`, `Write`, `NotebookEdit` | Пути к файлам |
| `Skill(deploy *)` | `Skill` | Префикс названия навыка |
| `Agent(Explore)` | `Agent` | Название типа субагента |
| `WebFetch(domain:example.com)` | `WebFetch` | Доменное имя |
| `WebSearch` | `WebSearch` | Нет спецификатора; разрешить или запретить весь инструмент |

Правило разрешения `Edit(...)` также предоставляет доступ на чтение к тому же пути, поэтому вам не требуется соответствующее правило `Read(...)` рядом с ним.

Полный синтаксис, включая формы префикса пути (`//`, `~/`, `/`, `./`) и семантику подстановочных знаков Bash, см. в разделе Синтаксис правила [Permission в settings-reference.md](./settings-reference.md#permission-rule-syntax).

## Поведение каждого инструмента

### Баш

Каждая команда выполняется в отдельном процессе. Изменения рабочего каталога, сделанные с помощью `cd`, переносятся на последующие вызовы Bash в основном сеансе (но не в субагентах), пока цель остается внутри каталога проекта или пути `--add-dir`. Переменные среды, установленные с помощью `export`, не сохраняются между командами. Используйте `CLAUDE_ENV_FILE` или `SessionStart` для распространения состояния окружения.

Тайм-аут по умолчанию составляет 2 минуты; Claude может запрашивать до 10 минут на команду. По умолчанию вывод ограничен 30 000 символов (настраивается через `BASH_MAX_OUTPUT_LENGTH`, максимум 150 000). Когда команда превышает ограничение, полный вывод сохраняется в файл в каталоге сеанса, а Claude получает путь плюс краткий предварительный просмотр.

Для длительных процессов Claude устанавливает `run_in_background: true` для запуска в качестве фоновой задачи. Просматривайте и останавливайте фоновые задачи с помощью `/tasks`.

### Редактировать

Выполняет точную замену строки. `old_string` должен выглядеть точно так, как написано (посимвольно, включая пробелы), и должен появляться только один раз. Если оно встречается более одного раза, укажите более длинную строку с достаточным окружающим контекстом, чтобы зафиксировать одно вхождение, или используйте `replace_all: true`. Claude должен был прочитать файл в текущем диалоге перед редактированием, и с момента чтения файл не должен был измениться на диске.

### Глоб

Находит файлы по шаблону имени с поддержкой рекурсивного сопоставления `**`. Результаты отсортированы по времени модификации, максимум 100 файлов. Glob по умолчанию не учитывает `.gitignore` (в отличие от Grep, который это делает).

### Греп

Ищет содержимое файла с помощью ripgrep. Шаблоны соответствуют синтаксису регулярных выражений ripgrep, который отличается от POSIX grep. Метасимволы, такие как `{` и `}`, необходимо экранировать (например, `interface\{\}`, чтобы найти `interface{}` в Go). Grep уважает `.gitignore` и пропускает файлы gitignored; передайте путь напрямую для поиска файла gitignored. Три режима вывода: `files_with_matches` (по умолчанию, только пути), `content` (сопоставление строк с номерами строк), `count` (счетчик совпадений для каждого файла).

### ЛСП

Неактивно, пока вы не установите плагин анализа кода для вашего языка. После каждого редактирования файла он автоматически сообщает об ошибках типа и предупреждениях. Также может вызываться напрямую, чтобы перейти к определениям, найти ссылки, составить список символов, отследить иерархию вызовов и получить информацию о типе в определенной позиции.

### <a name="monitor-v2198"></a>Монитор (v2.1.98+)

Позволяет Claude наблюдать за чем-то в фоновом режиме и реагировать на изменения. Claude пишет сценарий наблюдения, запускает его в фоновом режиме и получает каждую выходную строку по мере ее поступления. Полезно для отслеживания журналов, опроса статуса CI, наблюдения за изменениями файлов в каталоге или отслеживания длительно выполняемых сценариев. Использует те же правила разрешений, что и Bash. Недоступно в Amazon Bedrock, Google Vertex AI или Microsoft Foundry, а также недоступно, если установлен `DISABLE_TELEMETRY` или `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`.

Источник команд принимает `timeout_ms` и `persistent`; остановите активный монитор с помощью `TaskStop`. Начиная с версии 2.1.195, монитор может вместо этого использовать собственный источник WebSocket: `ws.url` плюс дополнительный `ws.protocols`. `command` и `ws` являются взаимоисключающими. Текстовые фреймы становятся событиями; двоичные кадры становятся заполнителем; кадр размером более 1 МБ или закрытый сокет останавливают работу монитора. URL-адрес должен быть ASCII `ws://` или `wss://`, без учетных данных и пробелов. Мониторы WebSocket требуют собственного одобрения и отказываются от частных, локальных мест назначения и мест назначения метаданных.

Событие не является авторизацией. Рассматривайте текст из любого источника как ненадежные данные, а не как команду оболочки или разрешение. См. [Monitor, Каналы и безопасное делегирование в Codex](../workflows/monitor-event-delegation.md) для получения информации о границе GitHub-to-WebSocket и рабочем процессе Codex с наименьшими привилегиями.

```text
# Ask Claude to set up a monitor like this:
"Tail /var/log/app.log and alert me when you see any ERROR line."
"Watch CI on PR #42 and tell me when it passes or fails."
```

### БлокнотПравить

Изменяет блокнот Jupyter по одной ячейке с помощью `cell_id`. Три режима: `replace` (перезаписать исходную ячейку, по умолчанию), `insert` (добавить новую ячейку после целевой), `delete` (удалить целевую ячейку). Не выполняет замену строк в записной книжке, как это делает Edit в простых файлах.

### PowerShell

Изначально доступно на Windows; зарегистрируйтесь на Linux/macOS через `CLAUDE_CODE_USE_POWERSHELL_TOOL=1` (требуется `pwsh` на `PATH`). Claude Code порождает PowerShell с `-ExecutionPolicy Bypass` только на уровне процесса, поэтому корпоративные блокировки `MachinePolicy` или `UserPolicy` по-прежнему применяются. Подробные сведения о настройке см. в разделе [PowerShell Native Tool](../ultimate-guide.md#powershell-native-tool).

### Читать

Возвращает содержимое файла с номерами строк. Обрабатывает изображения (PNG и JPG, возвращаемые как визуальное содержимое), PDF-файлы (короткие файлы целиком; PDF-файлы объемом более 10 страниц считываются в диапазонах до 20 страниц с параметром `pages`) и блокноты Jupyter (все ячейки с выходными данными). Когда чтение всего файла превышает лимит токена, Read возвращает первую страницу с уведомлением и смещением, необходимым для дальнейшего чтения.

### WebFetch

Принимает URL-адрес и запрос на извлечение. Получает страницу, преобразует HTML в Markdown и запускает запрос на извлечение содержимого, используя небольшую быструю модель. Claude получает ответ этой модели, а не необработанную страницу. Это делает WebFetch с потерями по замыслу. Приглашение к извлечению определяет, что достигнет Claude. URL-адреса HTTP автоматически обновляются до HTTPS. Ответы кэшируются на 15 минут. Когда URL-адрес перенаправляется на другой хост, WebFetch возвращает текстовый результат с указанием обоих URL-адресов, а не после перенаправления; Claude выполняет второй вызов нового URL-адреса. Для необработанной необработанной страницы используйте `curl` через Bash.

### Веб-поиск

Запускает запрос и возвращает заголовки результатов и URL-адреса. Он не извлекает страницы результатов; Claude обращается к WebFetch, чтобы прочитать найденную страницу. Может выполнять до 8 внутренних поисков за один вызов для внутреннего уточнения результатов.

### Писать

Создает новый файл или перезаписывает существующий. Если целевой путь уже существует, Claude должен прочитать его хотя бы один раз в текущем диалоге, прежде чем перезаписать. Для частичных изменений Claude использует Edit, а не Write.

### <a name="workflow-dynamic-workflows-v21154"></a>Рабочий процесс (динамические рабочие процессы, v2.1.154+)

Запускает сценарий JavaScript, который управляет множеством субагентов в фоновом режиме и возвращает один консолидированный результат. Claude использует ключевое слово `ultracode` (переименованное в `workflow` в версии 2.1.160, критическое изменение) для запуска многоагентного разветвления. Контролируйте текущие рабочие процессы с помощью `/workflows`. Требуется явное согласие пользователя: Claude не запускает рабочий процесс, пока его не спросят.

Сам сценарий оркестратора потребляет ноль токенов. Вся стоимость токенов поступает от вызовов `agent()`. Сценарии рабочих процессов используют четыре примитива: `agent()` порождает отдельные субагенты; `parallel()` одновременно запускает пакет и ждет всех (барьер); `pipeline()` распределяет предметы по этапам без глобального барьера между этапами; `phase()` обновляет метку прогресса пользовательского интерфейса. Экспорт `meta` в верхней части файла объявляет имя рабочего процесса и заголовки этапов.

Сценарии рабочих процессов сохраняют прогресс по мере выполнения: прерванное задание возобновляется с последней завершенной единицы, а не начинается заново. Чтобы это работало, оркестратор должен быть детерминированным: API-интерфейсы `Date.now()`, `Math.random()` и Node.js недоступны внутри оркестратора. Передавайте временные метки и начальные значения через глобальный `args`.

Полное описание примитивов, поведенческие гарантии и общие шаблоны (состязательная проверка, цикл до высыхания, судейские комиссии) см. в разделе [Динамические рабочие процессы](../workflows/dynamic-workflows.md).

## Продвинутые инструменты: как их активировать

### `/loop` и ScheduleWakeup

Команда `/loop [interval] [prompt]` запускает запрос с повторяющимся интервалом. Опустите интервал, чтобы позволить Claude двигаться самостоятельно; после каждой итерации он вызывает `ScheduleWakeup`, чтобы решить, когда сработает следующая (от 1 минуты до 1 часа). Ожидаемое пробуждение отображается в `session_crons` во входном сигнале Stop. Отмените с помощью Esc или Ctrl+C.

```text
/loop 5m /ci-status        # check CI every 5 minutes
/loop /monitor-deploys     # self-paced monitoring loop
```

### Запланированные задачи: CronCreate/CronList/CronDelete.

Эти инструменты планируют подсказки в рамках текущего сеанса. Задачи ограничиваются сеансом и восстанавливаются на `--resume` или `--continue`, если срок действия еще не истек. Используйте `CronList`, чтобы просмотреть активные задачи, `CronDelete`, чтобы отменить одну по идентификатору. Вы взаимодействуете с ними, прося Claude что-то запланировать:

```text
"Remind me to run the test suite in 30 minutes."
"Schedule a deploy check every hour until I cancel it."
```

### Удаленные процедуры: RemoteTrigger и /schedule.

`RemoteTrigger` поддерживает команду `/schedule` и создает подпрограммы на claude.ai. Подпрограммы выполняются вне текущего сеанса по расписанию, через API или по событиям GitHub. Требуется план Pro, Max, Team или Enterprise; недоступно в Bedrock, Vertex AI или Foundry. См. [Routines](../ultimate-guide.md#routines-cloud-automation) для полного руководства по функциям.

### Push-уведомления: PushNotification

Claude вызывает `PushNotification` для отправки уведомления на рабочий стол, а когда удаленное управление подключено с включенной функцией «Нажимать, когда Claude решит», — нажимает на телефон. Полезно для длительных задач, требующих отстранения. Доставка осуществляется через инфраструктуру, размещенную на Anthropic, поэтому она недоступна на Bedrock, Vertex AI или Foundry. См. [Пульт дистанционного управления](../ultimate-guide.md#remote-control).

### Команды агентов: TeamCreate/TeamDelete/SendMessage

Экспериментальная функция `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`. `TeamCreate` порождает команду названных товарищей по команде; `SendMessage` отправляет сообщение товарищу по команде или возобновляет работу остановленного субагента по его идентификатору агента; `TeamDelete` распускает команду. См. специальное руководство [Agent Teams](../workflows/agent-teams.md) для настройки, шаблонов и примеров.

### <a name="cross-session-messaging-listagents--sendmessage"></a>Межсессионный обмен сообщениями: ListAgents/SendMessage

В отличие от команд агентов, описанных выше: это обмен сообщениями между сеансами, которые никогда не создавались друг другом, каждый из которых уже работает независимо, на одном компьютере или доступен через вашу учетную запись. `ListAgents` (`/list-agents`, псевдоним `/peers`) перечисляет каждый доступный сеанс с его именем; два Claude Code одновременные локальные сеансы видят друг друга автоматически, настройка не требуется. `SendMessage({to: "session-name"})` доставляет текст в собственный диалог целевого сеанса под именем отправителя; принимающий сеанс отвечает таким же образом, отслеживание идентификатора не требуется. Сообщение от однорангового узла никогда не имеет полномочий: оно не может утвердить запрос разрешения или изменить конфигурацию от имени принимающего сеанса, а собственные правила разрешений принимающего сеанса по-прежнему применяются ко всему, что он запрашивает. Требуется версия 2.1.224+ (macOS/Linux/WSL2) или v2.1.234+ (родной Windows). Начиная с версии 2.1.248, обмен сообщениями на одном компьютере также работает на Bedrock. Claude Платформа на AWS, платформа агентов Google Cloud, Foundry и с отключенной функцией получения флагов функций; сеансы за пределами этого компьютера по-прежнему требуют входа в систему на claude.ai и удаленного управления. См. посвященный [Руководство по межсессионному обмену сообщениями](../workflows/cross-session-messaging.md) для механики открытий, `crossSessionInbound`/`isolatePeerMachines` меры безопасности, защита от коррелированного дрейфа и схемы координации.

### Задачи API: TaskCreate через TaskStop

Современная система управления задачами (v2.1.16+, по умолчанию начиная с v2.1.142). Полный набор инструментов:

- `TaskCreate`: добавить задачу
- `TaskList`: список всех задач (обзор состояния; не содержит полной информации).
- `TaskGet`: получить полную информацию об одной задаче.
- `TaskUpdate`: изменить статус, зависимости или детали; также удаляет
- `TaskStop`: убить запущенную фоновую задачу по идентификатору

`TodoWrite` — устаревшая альтернатива; в версии 2.1.142 он был отключен по умолчанию. Вместо этого установите `CLAUDE_CODE_ENABLE_TASKS=0`, чтобы снова включить его. Информацию о шаблонах и межсессионном сохранении см. в разделе [«Задачи API»](../ultimate-guide.md#tasks-api).

## Доступность провайдера

Некоторые инструменты доступны только тогда, когда Claude Code подключается через собственную инфраструктуру Anthropic:

| Инструмент | Недоступно на |
|------|-----------------|
| `Monitor` | Amazon Bedrock, Google Vertex AI, Microsoft Foundry |
| `PushNotification` | Amazon Bedrock, Google Vertex AI, Microsoft Foundry |
| `ScheduleWakeup` | Amazon Bedrock, Google Vertex AI, Microsoft Foundry |
| `RemoteTrigger` | Amazon Bedrock, Google Vertex AI, Microsoft Foundry |
| `WebSearch` | Коренная порода Амазонки (не обнажена) |

`Workflow` (ключевое слово `ultracode`) имеет различия в поведении у разных поставщиков; проверьте примечания к выпуску на предмет текущего состояния.
