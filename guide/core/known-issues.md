# Известные проблемы и критические ошибки

В этом документе отслеживаются проверенные критические проблемы, затрагивающие пользователей Claude Code, на основе отчетов сообщества и официальных сообщений.

> **Последнее обновление**: 23 апреля 2026 г.
> **Источник**: Проблемы [GitHub](https://github.com/anthropics/claude-code/issues) + [Anthropic Официальные сообщения](https://www.anthropic.com/engineering)

См. также: [Claude Code Releases](claude-code-releases.md), чтобы узнать историю версий, лежащих в основе этих проблем, и [Правила безопасности производства](../security/production-safety.md), чтобы узнать о мерах, снижающих риск возникновения связанных инцидентов в производстве.

## 🚨 Активные критические проблемы

### 0. Оперативные ошибки кэша: скрытое увеличение затрат (март 2026 г. – настоящее время).

**Серьезность**: 🔴 **HIGH – ВЛИЯНИЕ НА СТОИМОСТЬ**
**Status**: ⚠️ ЧАСТИЧНО ИСПРАВЛЕНО (Ошибка 3 и ошибка 2 все еще активны, начиная с версии 2.1.88)
**Проблема**: [#40524](https://github.com/anthropics/claude-code/issues/40524)
**Первое сообщение**: март 2026 г.
**Затронутые версии**: v2.1.69+ (ошибки 2 и 3), v2.1.36+ автономный двоичный файл (ошибка 1)

#### Проблема

Три независимые ошибки нарушают кэширование подсказок Anthropic на основе префиксов, что приводит к списанию средств в `cache_creation`.
(полная стоимость токена) вместо `cache_read` (со скидкой). Измеренное влияние на стоимость зависит от модели использования:

- **Ошибка 3 (заголовок атрибуции)**: увеличение в 2–5 раз системного запроса с токенами ~12 тыс. за начало сеанса и за вызов субагента.
- **Ошибка 2 активна (резюме + 10+ навыков)**: перестроение 87-118 тыс. токенов для каждого резюме; сеансы с 3-4 возобновлениями измерены при коэффициенте чтения кэша **4,3-34,6%** (против 95-99% в работоспособном состоянии), что соответствует стоимости **10-20x за ход** в худших сеансах
- **Комбинированный эффект**: улучшение коэффициента попадания в кеш с 48% до 99,98%, подтвержденное применением обходных решений (измерение сообщества, CC#40524)

> **Basis**: Подтверждено в результате обратного проектирования сообщества (CC#40524), анализа исходного кода
> утечка исходной карты npm и независимый анализ JSONL сеанса (ArkNill, апрель 2026 г.). Anthropic отправлен
> частичное исправление в версии 2.1.88 (байты схемы инструмента). Ошибки 2 и 3 остаются не исправленными.

#### Ошибка 2: Полная перестройка кеша при --resume / --continue (v2.1.69+), ВЫСОКОЕ ВОЗДЕЙСТВИЕ

**Основная причина**: модуль записи JSONL сеанса удаляет записи вложений `deferred_tools_delta` перед
запись на диск. На `--resume` эти записи исчезли, поэтому уровень отложенных инструментов не имеет предшествующих
историю анонсов и повторно анонсирует все инструменты с нуля. Это смещает каждую позицию сообщения в
восстановленный диалог, полностью нарушая префикс кэша уровня сообщений.

**Конкретные доказательства** (из анализа JSONL сеанса сообщества, сеансы с 14 навыками):

| Вход | cache_read | cache_creation | Событие |
|-------|-----------|----------------|-------|
| 102 | 84,164 | 174 | Обычный поворот |
| 103 | 0 | 87,176 | **Резюме: полный ребилд** |
| 105 | 87,176 | 561 | Восстановлено |
| 166 | 115,989 | 221 | Обычный поворот |
| 167 | 0 | 118,523 | **Резюме: полный ребилд** |

Каждое резюме = 87-118 тыс. токенов, перестроенных как `cache_creation` вместо `cache_read`. 3-4 резюме на
сессия = 300-400 тыс. токенов с предотвратимой стоимостью. Ударные весы с количеством инструментов skills/deferred:
пользователи с навыками более 10 (обычно в настройках платформы) видят полный коэффициент кэширования 0% в каждом резюме.

**Обходное решение**: Избегайте `--resume` и `--continue` до тех пор, пока не будет выпущено исправление. Начать новые сеансы.
Вариант понижения версии: `npm install -g @anthropic-ai/claude-code@2.1.68` (последняя версия перед регрессом).
Anthropic отслеживает это внутренне (в исходной телеметрии упоминается как `inc-4747`).

**Инженерное исправление**: сохраняются записи `deferred_tools_delta` и `mcp_instructions_delta` при
написание сеанса JSONL, чтобы резюме могло правильно вычислить дельту вместо того, чтобы повторно объявлять обо всем.

#### Ошибка 3: заголовок атрибуции (влияние от низкого до среднего, версия 2.1.69+).

**Основная причина**: Claude Code вставляет заголовок счета в качестве **первого блока** системного приглашения
каждый запрос API. Этот заголовок содержит 3-значный хэш, полученный из символов вашего первого
пользовательское сообщение, что делает его уникальным для каждого сеанса, каждого субагента и каждого бокового запроса. Поскольку кеш Anthropic
основан на префиксе, этот уникальный первый блок вызывает холодный пропуск системного приглашения с токенами ~ 12 000 каждый раз.
Начало сеанса и вызов субагента.

**Nuance** (по словам Джмариански, оригинального аналитика RE): система подсказывает холодный промах для каждого сеанса.
«незначительное влияние» на практике, поскольку системное приглашение невелико по сравнению с общим контекстом сеанса.
Ошибка возобновления (Ошибка 2) имеет более высокую измеримую цену для активных пользователей.

**Эмпирические измерения**: коэффициент попадания в кэш 48% → 99,98% с обходным решением, но это отражает совокупность
влияние с другими факторами кэша; изолированное воздействие ошибки 3 может быть меньшим.

**Обходное решение** (применить немедленно, низкий риск):
```json
// ~/.claude/settings.json
{
  "env": {
    "CLAUDE_CODE_ATTRIBUTION_HEADER": "false"
  }
}
```
Допустимые значения: `"false"`, `"0"`, `"no"`, `"off"`. Перезапуск не требуется.

#### Ошибка 1: замена строки Sentinel (автономный двоичный файл версии 2.1.36+, крайний случай)

**Корневая причина**: собственный стек HTTP Bun заменяет заполнитель `cch=00000` в теле запроса.
после сериализации. Если именно эта строка появляется в содержимом вашего сообщения (например, из CLAUDE.md
где обсуждается эта ошибка), возможно, он заменен не в том месте.

**Обходное решение**: Не вставляйте `cch=00000` буквально в CLAUDE.md или файлы конфигурации.
Примечание: это влияет только на автономный двоичный файл, а не на установку npm/npx.

#### Инструмент аудита

Запустите `/check-cache-bugs` (установите из каталога [examples/commands](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/examples/commands/check-cache-bugs.md)), чтобы проверить вашу установку на наличие всех трех ошибок примерно за 20 секунд.

> **Лучшая практика**: запускайте в самом начале нового сеанса или однократно через `claude -p "$(cat .claude/commands/check-cache-bugs.md)"`, чтобы избежать загрязнения текущего контекста сеанса строками `cch=` (потенциальный триггер ошибки 1).

#### Мониторинг состояния кэша

Чтобы проверить работоспособность ваших сеансов, используйте официальную переменную среды `ANTHROPIC_BASE_URL` для маршрутизации через прозрачный локальный прокси и регистрируйте `cache_creation_input_tokens`/`cache_read_input_tokens` из ответов API:

```json
// ~/.claude/settings.json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://localhost:8080"
  }
}
```

Запустите сквозной прокси-сервер на порту 8080, который считывает, но не изменяет requests/responses, анализируя объект `usage` из каждого ответа. **Здоровые сеансы** показывают коэффициент чтения кэша > 80%; **затронутые сеансы** показывают <40%.

Альтернативно, проверьте файлы JSONL сеанса непосредственно в `~/.claude/projects/` и найдите `cache_creation_input_tokens` и `cache_read_input_tokens` по очереди.

Инструменты сообщества для мониторинга:
- Ранее указанный репозиторий `cc-diag` недоступен. Используйте описанный выше метод проверки JSONL.
- [`claude-code-router`](https://github.com/musistudio/claude-code-router): прозрачный прокси с логированием

Патч сообщества (применяет исправления как ошибок 1, так и ошибок 2):
- [`cc-cache-fix`](https://github.com/Rangizingo/cc-cache-fix): разработанный сообществом патч + набор инструментов для тестирования.

#### Официальный ответ

Частичное исправление в версии 2.1.88 (байты схемы инструмента). Ошибки 2 и 3 подтверждены, все еще активны.

### 1. Ошибка автоматического создания GitHub в неправильном репозитории (декабрь 2025 г. – настоящее время).

**Серьезность**: 🔴 **КРИТИЧЕСКИЙ - SECURITY/PRIVACY РИСК**
**Статус**: ⚠️ АКТИВЕН (по состоянию на 28 января 2026 г.)
**Проблема**: [#13797](https://github.com/anthropics/claude-code/issues/13797)
**Первое сообщение**: 12 декабря 2025 г.
**Затронутые версии**: v2.0.65+

#### Проблема

Claude Code **систематически создает проблемы GitHub в общедоступном репозитории `anthropics/claude-code`** вместо частного репозитория пользователя, даже при работе в локальном каталоге репозитория git.

#### Влияние

**HIGH - PRIVACY/SECURITY**: как минимум **17+ подтвержденных случаев**, когда пользователи случайно раскрывают конфиденциальную информацию в общедоступном репозитории:

- Схемы базы данных
- Учетные данные API и сведения о конфигурации
- Архитектура инфраструктуры
- Дорожные карты частных проектов
- Конфигурации безопасности

#### Симптомы

- Проблема, созданная с неожиданным флагом `--repo anthropics/claude-code`
- Детали частного проекта появляются в общедоступных выпусках anthropics/claude-code.
- Нет запроса на подтверждение перед созданием проблемы в публичном репозитории
- Происходит, когда Claude просит «создать проблему» в локальном репозитории git.

#### Примеры случайных творений

Недавние подтвержденные случаи (январь 2026 г.):
- [#20792](https://github.com/anthropics/claude-code/issues/20792): «Удалено — создано в неправильном репозитории»
- [#16483](https://github.com/anthropics/claude-code/issues/16483), [#16476](https://github.com/anthropics/claude-code/issues/16476): «Claude ОТКРЫВАЕТ ПРОБЛЕМЫ ПО НЕПРАВИЛЬНОМУ РЕПО»
- [#17899](https://github.com/anthropics/claude-code/issues/17899): «Claude Code внезапно решил создать проблему в репозитории кода Claude»
- [#16464](https://github.com/anthropics/claude-code/issues/16464): «[Ошибочное сообщение] Пожалуйста, удалите»

Полный список: [Найти «неправильный репозиторий» ИЛИ «удалить это»](https://github.com/anthropics/claude-code/issues?q=is%3Aissue+%22wrong+repo%22+OR+%22delete+this%22)

#### Первопричина (гипотеза)

Claude Code может сбить с толку:
- **Законный отзыв** о самом Claude Code → `anthropics/claude-code` (правильный)
- **Проблемы пользовательского проекта** → Текущий репозиторий (должен быть по умолчанию)

Похоже, что инструмент жестко запрограммировал `anthropics/claude-code` или отдал ему слишком высокий приоритет в качестве цели по умолчанию.

#### Обходные пути

**🛡️ ПРЕЖДЕ ЧЕМ создавать любую задачу GitHub через Claude Code:**

1. **Всегда проверяйте целевой репозиторий**:
   ```bash
   # Check current repo
   git remote -v
   ```

2. **Явно указать репозиторий**:
   ```bash
   gh issue create --repo YOUR_USERNAME/YOUR_REPO --title "..." --body "..."
   ```

3. **Просмотрите команду** перед выполнением:
   - Найдите флаг `--repo anthropics/claude-code`.
   - Если присутствует и неверен, прервите и укажите правильный репозиторий.

4. **Использовать одобрение вручную** для всех команд `gh` в настройках Claude

5. **Никогда не включайте конфиденциальную информацию** в подсказки по созданию задач, пока ошибка не будет исправлена.

#### Если вы затронуты

Если вы случайно создали проблему, раскрывающую конфиденциальную информацию:

1. **Немедленно обратитесь в службу поддержки GitHub**, чтобы запросить удаление проблемы (а не просто закрытие).
2. **Поменяйте все открытые учетные данные** (ключи API, пароли, токены)
3. **Сообщите Anthropic** по электронной почте безопасности [](mailto:security@anthropic.com), если важна безопасность
4. **Проверьте утечку данных.**: Отслеживайте использование открытой информации.

#### Официальный ответ

По состоянию на 28 января 2026 г.: **Проблема остается открытой**, официального исправления не объявлено.

**Tracking**: [Issue #13797](https://github.com/anthropics/claude-code/issues/13797) (открыт с 12 декабря 2025 г.)

### <a name="2-excessive-token-consumption-jan-2026---present"></a>2. Чрезмерное потребление токенов (январь 2026 г. – настоящее время)

**Серьезность**: 🟠 **HIGH – ВЛИЯНИЕ НА СТОИМОСТЬ**
**Status**: ⚠️ СООБЩЕНО (Anthropic проводит расследование)
**Проблема**: [#16856](https://github.com/anthropics/claude-code/issues/16856)
**Первое сообщение**: 8 января 2026 г.
**Затронутые версии**: v2.1.1+ (сообщается), может повлиять на более ранние версии

#### Проблема

Несколько пользователей сообщают о более быстром потреблении токенов **4x+** по сравнению с предыдущими версиями, что приводит к:
- Ограничения по ставкам достигаются гораздо быстрее, чем обычно
- Те же рабочие процессы, потребляющие значительно больше токенов
- Неожиданное увеличение затрат

#### Симптомы

Из выпуска № 16856:
> «Начиная с сегодняшнего утра с обновлением до CC 2.1.1 — использование просто смехотворно. Я работаю над одними и теми же проектами месяцами, по одним и тем же процедурам, в одно и то же время. Но сегодня лимит в 5 часов достигает 4+ раз быстрее!»

Общие отчеты:
- Недельные лимиты исчерпаны за 1-2 дня (обычно 5-7 дней)
- Сеансы достигают 90% контекста после 2-3 сообщений
- Расход токенов в 4–20 раз для идентичных операций

#### Контекст

**Срок действия бонуса за использование в праздничные дни**: 25–31 декабря 2025 г. Anthropic удвоил лимит использования в качестве праздничного подарка. Когда 1 января 2026 года ограничения вернулись к норме, пользователи почувствовали «снижение емкости».

Однако отчеты **сохраняются и после этого времени (**), что указывает на потенциальную основную проблему.

#### Anthropic ответ

Из [The Register](https://www.theregister.com/2026/01/05/claude_devs_usage_limits/) (5 января 2026 г.):
> «Anthropic заявил, что «серьезно относится ко всем таким отчетам, но не выявил никаких недостатков, связанных с использованием токенов», и указал, что исключил ошибки в своем стеке выводов».

**Status**: **Официально не подтверждено как ошибка** Anthropic по состоянию на 28 января 2026 г.

#### Обходные пути

Пока Anthropic исследует:

1. **Активно отслеживать использование токенов**:
   ```
   /context
   ```
   Регулярно проверяйте используемые токены в зависимости от их емкости.

2. **Использовать более короткие сеансы**:
   - Перезапуск сеансов при достижении контекста 50-60%.
   - Разбивайте сложные задачи на несколько сеансов

3. **Отключить автосжатие** (может помочь):
   ```bash
   claude config set autoCompaction false
   ```

4. **Уменьшите количество инструментов MCP**, если они не нужны:
   - Обзор `~/.claude.json` (поле `"mcpServers"`)
   - Отключить неиспользуемые серверы

5. **Используйте субагенты** для изолированных задач:
   - Субагенты имеют отдельные контекстные окна.
   - Используйте инструмент «Задачи» для сложных операций

6. **Отслеживайте свою модель использования**:
   - Сравните обновления версий before/after
   - Задокументируйте необычные всплески

## ✅ Решены исторические проблемы

### <a name="triple-harness-incident-effort-thinking-tokens-verbosity-mar-apr-2026"></a>Инцидент с тройным ремнями безопасности: усилие, маркеры мышления, многословие (март-апрель 2026 г.)

**Серьезность**: 🔴 **HIGH**
**Status**: ✅ **RESOLVED** (все три проблемы решены к 20 апреля 2026 г.)
**Хронология**: 4 марта — 20 апреля 2026 г.

#### Проблема

Три независимых изменения жгута проводов и системных подсказок ухудшили качество продукции Claude Code за шестинедельный период. Ни одна из них не была регрессией на уровне модели; все они находились на уровне жгута Claude Code. Anthropic API, используемый напрямую (без ремня Claude Code), не был затронут.

#### Инцидент 1: усилие по умолчанию от высокого до среднего (4 марта, отменено 7 апреля)

**Trigger**: из-за длительной задержки в режиме высоких усилий пользовательский интерфейс выглядел зависающим в некоторых сеансах.
**Change**: Anthropic изменил усилие рассуждения по умолчанию с `high` на `medium` для Sonnet 4.6 и Opus 4.6.
**Impact**: Пользователи, которые не установили `/effort high` вручную, молча получили рассуждения среднего качества. Внутренний индикатор по-прежнему показывал «высокий уровень», маскируя регресс более месяца.
**Affected**: Sonnet 4.6, Opus 4.6.
**Resolution**: отменено 7 апреля. Значения по умолчанию на тот момент: xhigh для Opus 4.7, high для других поддерживаемых моделей. В текущей версии Opus 5.5 по умолчанию установлен средний уровень; см. выбор модели [](../ultimate-guide.md#effort-levels). Вместе с ним поставляются правильные итерации пользовательского интерфейса (мыслящие счетчики, более понятный UX `/effort`).

#### Инцидент 2: жетоны мышления очищаются за ход после простоя (26 марта, исправлено 10 апреля).

**Trigger**: Anthropic внес изменение в токены ясного мышления один раз, когда сеанс бездействовал более часа (чтобы уменьшить задержку и затраты на кэш при возобновлении).
**Bug**: из-за дефекта кода очистка срабатывала на каждом последующем ходу до конца сеанса, а не только один раз при возобновлении.
**Impact**: Сеансы стали забывчивыми и повторяющимися, при этом Claude постепенно терял контекст на протяжении всего возобновленного разговора.
**Affected**: Sonnet 4.6, Opus 4.6.
**Resolution**: ошибка исправлена ​​10 апреля 2026 г. (v2.1.101). Основная причина по мнению Бориса Черного (команда CC): большие простаивающие сеансы приводили к полным промахам в кэше (более 900 тыс. токенов), что приводило к значительному увеличению стоимости токенов для пользователей Pro при возобновлении работы.

#### Инцидент 3: Инструкция по подсказке системы многословия (16 апреля, отменено 20 апреля)

**Trigger**: Anthropic добавил инструкцию системной подсказки, чтобы уменьшить многословие ответа.
**Impact**: В сочетании с другими изменениями, активными в то время, качество кодирования заметно упало.
**Affected**: Sonnet 4.6, Opus 4.6, Opus 4.7.
**Resolution**: отменено 20 апреля. Четыре дня воздействия, самое быстрое разрешение из трех инцидентов.

#### Влияние сообщества

- Широко распространенные сообщения о снижении качества на Reddit, HN, X/Twitter (март – апрель 2026 г.)
- Отмены среди подписчиков Pro и Max
- Сотрудники Anthropic (включая Бориса Черного) первоначально ответили в комментариях, не признавая системных проблем.
- В день раскрытия ветка HN достигла 250+ комментариев

#### Anthropic ответ

**Официальное обновление**: [Обновление последних отчетов о качестве Claude Code](https://www.anthropic.com/engineering/april-23-postmortem) (23 апреля 2026 г.)

Ключевые обязательства на этой должности:
- Сброс лимитов использования для всех подписчиков (23 апреля)
- Большая часть внутреннего персонала будет использовать именно общедоступную сборку (а не сборку для функционального тестирования).
- В разделе «Вперед» обещано улучшение методов оценки и развертывания.

Ключевая цитата Бориса Черного (комментарий HN):
> «Мы согласны и потратим следующие несколько недель на увеличение наших инвестиций в полировку, качество и надежность».

**Resolution**: все три проблемы решены в период с 7 по 20 апреля 2026 г.

### <a name="model-quality-degradation-aug-sep-2025"></a>Ухудшение качества модели (август – сентябрь 2025 г.)

**Серьезность**: 🔴 **КРИТИЧЕСКИЙ**
**Status**: ✅ **RESOLVED** (середина сентября 2025 г.)
**Хронология**: 25 августа — начало сентября 2025 г.

#### Проблема

Пользователи сообщили, что Claude Code производит:
- Результаты хуже, чем в предыдущих версиях
- Синтаксические ошибки неожиданно
- Неожиданные вставки символов (текст Thai/Chinese в ответах на английском языке)
- Невыполненные базовые задачи
- Неправильные правки кода

#### Первопричина

Anthropic выявил **три ошибки инфраструктуры** (не деградация модели):

1. **Неправильная маршрутизация трафика**: ~30% запросов Claude Code перенаправляются на сервер неправильного типа → ухудшенные ответы
2. **Повреждение вывода**: неправильная конфигурация, развернутая 25 августа, привела к ошибкам генерации токенов.
3. **XLA: Неправильная компиляция TPU**: оптимизация производительности вызвала скрытую ошибку компилятора, влияющую на выбор токена

#### Влияние сообщества

- **Кампания массовой отмены** (август – сентябрь 2025 г.)
- Теории сообщества: преднамеренная деградация модели (квантование) для снижения затрат
- Настроения на Reddit резко упали

#### Anthropic ответ

**Официальное вскрытие**: [Вскрытие трех последних выпусков](https://www.anthropic.com/engineering/a-postmortem-of-three-recent-issues) (17 сентября 2025 г.)

Ключевая цитата:
> «Мы никогда не снижаем качество модели из-за спроса, времени суток или нагрузки на сервер. Проблемы, о которых сообщили наши пользователи, были связаны только с ошибками инфраструктуры».

**Resolution**: все ошибки исправлены к середине сентября 2025 года.

## <a name="-llm-day-to-day-performance-variance"></a>🔄 LLM ежедневные колебания производительности

**Type**: ожидаемое поведение (не ошибка).
**Серьезность**: 🟡 **LOW - ОСВЕДОМЛЕННОСТЬ**
**Status**: свойственный выводу LLM, не специфичный для какой-либо версии.

### Что это такое

Качество вывода Claude может заметно различаться от сеанса к сеансу, даже при одинаковых подсказках и чистом контекстном окне. Это отличается от деградации окна контекста, которая происходит в течение сеанса по мере заполнения контекста. Здесь проблема заключается в различиях между свежими сеансами.

Пользователи иногда сообщают о более коротких ответах, более консервативных предложениях или неожиданных отказах в задачах, которые накануне работали нормально. Это может выглядеть как понижение модели, но это не так.

### Коренные причины

**Вероятностный вывод**: Температура выше 0 означает, что каждый вывод недетерминирован. Два запуска одного и того же приглашения создадут разные последовательности токенов. Это фундаментально для того, как работают языковые модели.

**Цифровые значения, зависящие от партии**: Даже при температуре 0 выходные данные могут различаться для одинаковых запросов. В глоссарии [Anthropic](https://platform.claude.com/docs/en/about-claude/glossary) отмечается, что температура 0 не является полностью детерминированной. [Thinking Machines](https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/) анализирует стеки вывода с открытым исходным кодом и многое из этого связывает с ядрами, которые не являются пакетно-инвариантными: результат запроса зависит от того, сколько других запросов обрабатывается с ним, и нагрузка на сервер меняет это. Anthropic не документирует причину Claude и не документирует публично внутреннюю архитектуру Claude, поэтому это руководство не связывает отклонения с конкретной конструкцией.

**Различия в инфраструктуре**: В производственной среде запросы поступают на разные серверы с разными уровнями нагрузки, поколениями оборудования и температурными состояниями. Эти факторы влияют на числовую точность арифметических операций с плавающей запятой во время вывода, создавая тонкие, но реальные различия в результатах.

**Контекстная чувствительность**: Даже при использовании `/clear` накапливаются небольшие различия между сеансами. Системное приглашение, список инструментов и инициализация сеанса незначительно влияют на первые результаты модели.

### Наблюдаемые сигналы

| Сигнал | Что ты видишь | Что это значит |
|--------|-------------|---------------|
| Длина ответа | Короче, менее подробно, чем обычно | Другой путь генерации (выборка образцов или числовые различия при температуре 0) был более консервативным. |
| Отказы | Пограничные случаи, которые обычно работают, получают отказ | Другая калибровка безопасности в этом пробеге |
| Стиль кода | Более многословный или более минимальный, чем ожидалось | Различные маркеры на ранних этапах ответа (из выборки или числовых различий) сформировали остальную часть ответа. |
| Креативность | Более консервативные, менее изобретательные предложения | Не потеря возможностей, а результат отклонения |
| Многословие | Больше предостережений и отказов от ответственности, чем обычно | Нормальное отклонение вероятностей токенов |

### Что это НЕ

- **Не является понижением версии модели.**: версии Anthropic намеренно моделируют и документируют изменения. Ежедневные отклонения происходят в пределах одной и той же версии модели.
- **Это не ошибка, о которой следует сообщать.**: Такое поведение ожидаемо и описано в литературе по LLM. Это присуще вероятностному выводу.
- **Не постоянный**: Следующий сеанс, скорее всего, будет вести себя иначе. «Плохой» результат не означает долгосрочных изменений.
- **Не ухудшение контекстного окна**: Это явление внутри сеанса, вызванное накоплением токенов. Это разница между сессиями при новом старте.

> Инцидент, произошедший в августе-сентябре 2025 года ([см. «Решенные проблемы» выше](#model-quality-degradation-aug-sep-2025)), был исключением: Anthropic подтвердил реальные ошибки инфраструктуры, приводящие к систематической деградации. Настоящая систематическая деградация встречается редко, и Anthropic исследует ее. Обычная разница между сессиями — это нечто иное.

### Стратегии смягчения последствий

**Ограничить подсказку.**: более конкретные подсказки уменьшают пространство вывода и делают отклонения менее заметными. «Напишите функцию, которая выполняет X, Y, Z, возвращает тип T, обрабатывает крайний случай E» дает более последовательные результаты, чем «напишите мне что-нибудь для обработки X».

**Свежий контекст перед важной работой**: запускайте `/clear` перед выполнением важной задачи. Накопленный сеансовый шум от предыдущих исследовательских работ может исказить последующие результаты даже в рамках одного и того же сеанса.

**Переформулируйте и повторите попытку.**: Если результат не соответствует вашим ожиданиям, попробуйте тот же запрос с другим кадрированием. Вторая формулировка часто использует другой путь генерации и дает лучший результат.

**Сравнить с заведомо исправным приглашением**: Если у вас есть приглашение из предыдущего сеанса, которое дало отличный результат, используйте его в качестве справочного материала. Если сегодняшняя версия этого запроса постоянно выдает заметно худшие результаты, это требует более тщательного расследования (и, возможно, проблемы GitHub, если она воспроизводится).

**Калибровка ожиданий по типу задачи**: Детерминированные задачи (регулярные выражения, простые преобразования, четко определенные алгоритмы) демонстрируют меньшую дисперсию, чем творческие задачи или задачи, требующие принятия решений. Используйте Claude Code для первого с высокой надежностью; во втором случае включите этапы проверки в свой рабочий процесс.
