## Полный цикл (глубокое погружение)

Каждое взаимодействие с Claude Code следует следующей последовательности:

```
┌──────────────────────────────────────────────────────────────┐
│ 1. YOU PROMPT                                                │
│    "Fix the bug in auth.js on line 45"                      │
└────────────────────┬─────────────────────────────────────────┘
                     │
                     ▼
┌──────────────────────────────────────────────────────────────┐
│ 2. CLAUDE READS                                              │
│    - Reads auth.js (full file)                              │
│    - Reads related files (auth-test.js, config.js, etc)     │
│    - Understands the error context                          │
│    - Analyzes call sites where auth.js is used              │
└────────────────────┬─────────────────────────────────────────┘
                     │
                     ▼
┌──────────────────────────────────────────────────────────────┐
│ 3. CLAUDE ANALYZES                                           │
│    - Identifies the root cause                              │
│    - Considers side effects                                 │
│    - Plans minimal changes                                  │
│    - Checks for tests                                       │
└────────────────────┬─────────────────────────────────────────┘
                     │
                     ▼
┌──────────────────────────────────────────────────────────────┐
│ 4. CLAUDE DECIDES                                            │
│    Does the change need tests? → Suggest test updates       │
│    Is the change safe? → Proceed or ask for confirmation    │
│    Should multiple files change? → Show full scope           │
└────────────────────┬─────────────────────────────────────────┘
                     │
                     ▼
┌──────────────────────────────────────────────────────────────┐
│ 5. CLAUDE PROPOSES                                           │
│    Shows you:                                               │
│    - Description of changes                                 │
│    - diff view (what's changing)                            │
│    - Reasoning                                              │
└────────────────────┬─────────────────────────────────────────┘
                     │
                     ▼
┌──────────────────────────────────────────────────────────────┐
│ 6. YOU REVIEW                                                │
│    - Read the diff carefully                                │
│    - Ask questions if unclear                               │
│    - Accept or reject the changes                           │
└────────────────────┬─────────────────────────────────────────┘
                     │
                     ▼
┌──────────────────────────────────────────────────────────────┐
│ 7. CHANGES APPLIED                                           │
│    - Files updated on disk                                  │
│    - You can now test/run the code                          │
│    - Next iteration begins                                  │
└──────────────────────────────────────────────────────────────┘
```

## Как Claude читает ваш проект

Claude не читает всё. Это **Умный прицел**.

### Пример: вы спрашиваете: «Исправьте ошибку входа в систему».

Claude будет:

1. **Найдите «логин»** в своей кодовой базе.
2. **Найти auth.js, login.js, auth-controller.js**
3. **Сначала прочтите эти файлы** (полное содержимое)
4. **Найти вызывающих абонентов** (что вызывает эти файлы?)
5. **Читать тесты** (если они существуют)
6. **Найти связанную конфигурацию** (переменные среды, константы)

Claude **не будет** читать:
- node_modules (исключается автоматически)
- История .git (слишком много данных)
- Каждый файл в проекте (слишком медленно)
- Вся ваша кодовая база, если это не актуально

### Совет профессионала

Будьте конкретны в отношении объема:
- ❌ «Исправить ошибки» → Claude должен угадать, какие файлы
- ✅ «Исправьте ошибку входа в auth.js в строке 45» → Claude читает именно то, что важно.

## Контекст: Ключевая концепция

**Context** — это то, какую часть вашего разговора запоминает Claude. Это конечно (~200 тыс. токенов).

### Что использует контекст?

```
Your prompt:           50 tokens
Claude's response:     500 tokens
File reads:            2000 tokens per file
Previous messages:     accumulated tokens
```

### Измеритель контекста

```bash
/status
```

Shows:
```
Context: 67%
```

Это означает:
- 0–50 %: осталось много места, работайте свободно.
- 50–70 %: используется наполовину, будьте внимательны.
- 70-90%: Нажимаем `/compact`.
- 90%+: критично, надо почистить

### `/compact` – ваш предохранительный клапан

Когда контекст достигнет 70%+, используйте:

```bash
/compact
```

This:
1. Обобщает предыдущий разговор
2. Удаляет старые сообщения
3. Освобождает ~40% контекста.
4. Позволяет вам работать в одном сеансе

Вы можете сжимать несколько раз за один сеанс.

## Режимы: обычный, план, размышление.

Claude Code имеет три режима взаимодействия.

### Обычный режим (по умолчанию)

Claude вносит изменения сразу после анализа. Используйте для:
- Простые исправления ошибок
- Небольшие дополнения к функциям
- Рефакторинг небольших разделов

**Flow**: Спросить → Анализировать (1–2 секунды) → Предложить → Применить

### Режим планирования (`/plan`)

Claude первым думает, предлагает план, ждет одобрения, прежде чем вносить изменения. Используйте для:
- Комплексные функции
- Рискованные изменения
- Общесистемные рефакторинги
- Когда вы не уверены в подходе

**Flow**: Спросить → Подумать → Предложить план → Вы одобряете → Анализировать → Применить

**Example**:
```bash
/plan
Refactor the authentication system to use JWT instead of sessions
```

Claude предлагает вам пошаговый план для ознакомления.

### Режим мышления (`/think`)

Claude демонстрирует расширенное рассуждение, шаг за шагом обдумывая проблему. Используйте для:
- Понимание сложных ошибок
- Архитектурные решения
- Анализ безопасности
- Оптимизация производительности

**Flow**: Спросить → Расширенное рассуждение → Анализ → Предложение.

## Структурирование эффективных запросов

### Структура: ЧТО, ГДЕ, КАК, ПРОВЕРИТЬ

Хорошие запросы следуют следующему шаблону:

| Часть | Цель | Пример |
|------|---------|---------|
| **Что** | Цель | «Исправить ошибку с нулевым указателем» |
| **WHERE** | Область применения | "в `src/auth/login.js` в строке 45" |
| **Как** | Ограничения | "без изменения подписи API" |
| **Проверить** | Ожидаемый результат | «Все существующие тесты должны пройти» |

### Пример хорошего запроса

```
Fix the bug where login fails for emails with + symbols
WHERE: src/controllers/auth.js, line 78 (email validation regex)
HOW: Update the regex to allow + in emails, but keep existing validation otherwise
VERIFY: Existing tests in tests/auth.test.js should pass
```

### Пример плохого запроса

```
Fix the bugs
```

Claude должен задавать уточняющие вопросы вместо того, чтобы решать немедленно.

## Контекст сеанса

**session** — это ваш текущий разговор с Claude.

### Факты сессии

- Запускается при запуске `claude`
- Завершается при выходе или запуске `/clear`.
- Не сохраняется по умолчанию
- Ограничено одним проектом
- Можно управлять с помощью `/rewind` (вернуться на N шагов назад)

### Сеансы контрольных точек

Чтобы сохранить сеанс (необязательно):
```bash
/checkpoint save "fixed login, added tests"
```

Позже восстановлю:
```bash
/checkpoint load "fixed login, added tests"
```

## <a name="exercise-the-complete-loop"></a>Упражнение: Полный цикл.

### Задача: Создать простую служебную функцию.

1. **Спросите с помощью WHAT/WHERE/HOW/VERIFY:**

```
Create a utility function to validate email addresses
WHERE: in src/utils/validators.js
HOW: export as validateEmail(email), return boolean, handle edge cases
VERIFY: Write tests in tests/validators.test.js
```

2. **Claude анализирует:**
   - Находит src/utils/
   - Читает существующие валидаторы
   - Проверяет структуру каталогов тестов
   - Предлагает решение

3. **Просмотр различий:**
   - Проверьте сигнатуру функции
   - Проверьте логику проверки
   - Просмотрите тестовые примеры

4. **Примите или повторите:**
   ```
   Looks good, but make the regex more permissive for + symbols
   ```

5. **Claude обновляет** и вы просматриваете еще раз

6. **Done:** У вас есть проверенная, работающая функция

## Ключевые выводы

✓ Каждый запрос следует: прочитать → проанализировать → решить → предложить → применить

✓ Будьте конкретны (WHAT/WHERE/HOW/VERIFY), чтобы быстрее получить результаты.

✓ Контекст ограничен, следите за своим процентом и `/compact` на уровне 70%+

✓ `/plan` для рискованных изменений, нормальный режим для безопасных

✓ Сеансы временные, используйте `/checkpoint`, чтобы сохранить важную работу.
