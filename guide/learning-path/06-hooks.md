# Модуль 06: Хуки и события

**Время:** 1 час | **Сложность:** Средний уровень

**Предыдущий:** [Модуль 05: Навыки и автоматизация](05-skills.md)

## Цель

Добавьте один хук Claude Code, который принимает решение об инструменте на основе структурированного ввода, не закрывается при неправильном вводе и может быть протестирован без запуска интерактивного сеанса.

Хуки Claude Code не являются хуками Git. Перехватчики Git реагируют на действия репозитория, такие как `pre-commit`. Хуки Claude Code реагируют на жизненный цикл Claude Code и события инструмента, такие как `PreToolUse`, `PostToolUse` и `SessionStart`.

## Что вы узнаете

- где Claude Code считывает конфигурацию ловушки;
- как сопоставители выбирают вызовы инструментов;
- что командный перехватчик получает на стандартном вводе;
- как перехватчик `PreToolUse` разрешает или запрещает вызов;
- какие коды выхода доказывают и что не доказывают;
- как протестировать сценарий принятия решения с фиксированными фикстурами.

Для получения полной матрицы событий используйте Справочник событий [Hooks](../core/hooks-events-reference.md). Anthropic поддерживает авторитетную документацию [hooks](https://code.claude.com/docs/en/hooks).

## Граница крюка

Командный хук — это локальная программа, запускаемая Claude Code. Он получает один объект JSON на стандартный ввод. Поля зависят от события. Для `PreToolUse` полезными полями являются `tool_name`, `tool_input` и `tool_use_id`.

Сопоставитель для фильтров событий инструмента на `tool_name`:

```text
Claude proposes Write or Edit
             |
             v
PreToolUse matcher selects the hook
             |
             v
Hook reads JSON and returns deny or no decision
             |
             v
Claude Code applies the decision
```

Держите решение узким. Политика пути может решить, будет ли предлагаемая запись файла предназначаться для защищенного местоположения. Он не может доказать, что полученная программа безопасна или правильна.

## Зарегистрируйте хук `PreToolUse`

Хуки проекта принадлежат `.claude/settings.json`. Следующая запись запускает одну команду Python для вызовов `Write` и `Edit`:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "python3",
            "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/protect-paths.py"],
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

`settings.json` — поддерживаемый файл конфигурации в этом примере. Вариант `settings.yaml` не является частью настоящего контракта.

## Создайте сценарий принятия решения

Сохраните этот файл как `.claude/hooks/protect-paths.py`:

```python
#!/usr/bin/env python3
import json
import sys
from pathlib import PurePosixPath


def decide(value: str, reason: str) -> None:
    print(json.dumps({
        "hookSpecificOutput": {
            "hookEventName": "PreToolUse",
            "permissionDecision": value,
            "permissionDecisionReason": reason,
        }
    }))


try:
    payload = json.load(sys.stdin)
except (json.JSONDecodeError, UnicodeDecodeError):
    decide("deny", "Hook input was not valid JSON.")
    raise SystemExit(0)

if payload.get("tool_name") not in {"Write", "Edit"}:
    decide("deny", "Unexpected tool for this matcher.")
    raise SystemExit(0)

file_path = payload.get("tool_input", {}).get("file_path")
if not isinstance(file_path, str) or not file_path.strip():
    decide("deny", "Write or Edit input did not contain a file_path.")
    raise SystemExit(0)

path = PurePosixPath(file_path.replace("\\", "/"))
protected = (
    ".git" in path.parts
    or path.name == ".env"
    or path.name.startswith(".env.")
    or path.suffix in {".key", ".pem"}
)

if protected:
    decide("deny", f"Protected path: {file_path}")
else:
    raise SystemExit(0)
```

Этот пример возвращает структурированное решение только в том случае, если он отклоняет вызов. Код выхода `0` без вывода оставляет обычный поток разрешений Claude Code на месте; он не дает разрешения. Неверный или неполный ввод отклонен, поскольку сценарий не может установить безопасный путь.

## Протестируйте три светильника

Запустите сценарий принятия решения напрямую:

```bash
printf '%s\n' '{"tool_name":"Write","tool_input":{"file_path":"src/app.py"}}' \
  | python3 .claude/hooks/protect-paths.py

printf '%s\n' '{"tool_name":"Edit","tool_input":{"file_path":".env"}}' \
  | python3 .claude/hooks/protect-paths.py

printf '%s\n' '{bad json' \
  | python3 .claude/hooks/protect-paths.py
```

Ожидаемые решения:

| приспособление | Ожидаемый результат | Причина |
| --- | --- | --- |
| `src/app.py` | Выход `0`, нет вывода | Путь находится за пределами защищенного набора, поэтому продолжается обычный поток разрешений. |
| `.env` | `deny` | Политика явно называет путь |
| искаженный JSON | `deny` | Хук не может проверить запрос |

Эти тесты фиксации проверяют локальный контракт ввода и вывода сценария. Они не проверяют, что настройки проекта были загружены Claude Code. Подтвердите загрузку среды выполнения отдельно, попытавшись выполнить безопасную запись и защищенную запись в проекте одноразового приспособления.

## <a name="exit-codes"></a>Коды выхода

Коды выхода зависят от событий:

- код выхода `0` означает, что команда перехвата завершена; Затем Claude Code анализирует любой поддерживаемый вывод JSON;
- код выхода `2` блокирует события, поддерживающие блокировку, включая `PreToolUse`, и отправляет стандартную ошибку обратно в Claude;
- другие ненулевые коды выхода обычно сообщают об ошибке неблокирующего перехвата;
- `WorktreeCreate` является исключением, поскольку любой ненулевой выход не может быть создан;
- некоторые события игнорируют коды выхода или вместо этого используют структурированное решение JSON.

Не импортируйте соглашения Unix вслепую. Код выхода `1` не блокирует вызов `PreToolUse`. Ссылка [event](../core/hooks-events-reference.md#exit-code-2-behavior-per-event) записывает поведение каждого поддерживаемого события.

## Правила безопасного проектирования

- Держите сопоставитель таким же узким, как и политика.
- Явно анализируйте входные данные и отклоняйте неизвестные формы, когда от них зависит безопасность.
- Избегайте сетевых вызовов в блокирующей перехватчике.
- Не допускайте попадания секретов в выходные данные перехватчиков и журналы отладки.
- Предпочитайте проверку только для чтения, а не скрытую мутацию файла.
- Установите тайм-аут.
- Тест пройден, отклонен и некорректно сформирован.
- Запишите, какое поведение во время выполнения осталось непроверенным.

Хуки выполняют локальный код с разрешениями процесса Claude Code. Просмотрите общий хук, прежде чем включать его. Информацию о рисках моделирования угроз и запуска запуска см. в статьях [Security Hardening](../security/security-hardening.md#16-startup-hooks-code-execution-before-your-first-prompt) и [Production Safety](../security/production-safety.md).

## <a name="exercise-create-a-validation-hook"></a>Упражнение: создайте хук проверки

1. Добавьте регистрацию `PreToolUse` в `.claude/settings.json` в одноразовом проекте.
2. Сохраните сценарий принятия решения по адресу `.claude/hooks/protect-paths.py`.
3. Запустите три прибора и сохраните их выходы JSON.
4. Запустите Claude Code в проекте приспособления.
5. Запросите запись на `src/app.py` и подтвердите, что решение позволяет это.
6. Запросите запись на `.env` и подтвердите, что решение отклоняет это.
7. Запишите версию Claude Code, путь к настройкам, команду, результат и непроверенную область действия.

Упражнение считается завершенным, когда три прямых прибора соответствуют таблице, а два одноразовых датчика времени выполнения соответствуют заявленным решениям. Если загрузка во время выполнения не проверялась, запишите ее как `UNKNOWN`, а не делайте выводы из прямых тестов сценария.

## Вы готовы, когда

- вы можете отличить хуки Claude Code от хуков Git;
- вы можете назвать событие и средство сопоставления, используемые вашим хуком;
- ваш хук читает JSON со стандартного ввода;
- неверный ввод имеет явный результат;
- вы знаете, что код выхода `1` не блокирует `PreToolUse`;
- ваше доказательство отделяет тесты сценариев от загрузки среды выполнения Claude Code.
