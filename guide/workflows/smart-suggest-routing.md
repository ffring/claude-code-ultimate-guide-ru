# <a name="smart-suggest-routing-regex--bm25-skill-hints"></a>Маршрутизация Smart-Suggest: подсказки по навыкам Regex + BM25

Хуки `UserPromptSubmit` могут добавлять консультативный контекст перед тем, как модель обработает приглашение. Regex работает для фиксированных правил применения. Okapi BM25 работает с вариантами естественного языка, подкрепленными проверенным корпусом навыков.

Работоспособная реализация в `examples/hooks/bm25-routing/` поддерживает Claude Code и Codex. Рекомендуемое развертывание Codex — это один глобальный хук, который учитывает навыки проекта и пользователя из рабочего каталога каждого приглашения.

## Выберите правильный двигатель

| Ситуация | регулярное выражение | БМ25 |
|---|---:|---:|
| Фиксированная команда или фраза политики | Сильный | Слабый |
| Правоприменение перед действием | Сильный | Не подходит |
| Двуязычные вариации естественного языка | хрупкий | Сильный с корпусом |
| Новый навык с менее чем восемью положительными эффектами | Возможно ручное правило | Только нативное соответствие |
| Широкий смысл с контрастными примерами | Большой набор правил | Сильный после оценки |

Regex и BM25 могут подключаться к `UserPromptSubmit`, но они решают разные проблемы. Напоминание о регулярном выражении может потребовать проверки журнала изменений. Подсказка BM25 может определить вероятный навык проверки или обнаружения хранилища. Также не следует автоматически одобрять или автоматически запускать разрушительные действия.

## Codex архитектура

Codex объединяет соответствующие перехватчики из глобальной конфигурации и конфигурации проекта. Таким образом, установка одного и того же обработчика BM25 на обоих уровнях может привести к появлению дублированного контекста. Используйте один глобальный обработчик на настроенной рабочей станции:

```text
prompt + cwd
    |
    v
~/.codex/hooks/skill-router/bm25-suggest.js
    |
    +-- <cwd>/.agents/skills up to <git-root>/.agents/skills
    +-- ~/.agents/skills
    +-- ~/.codex/skills
    +-- /etc/codex/skills when readable
    +-- SKILL_ROUTER_EXTRA_ROOTS
    +-- external corpus overlays
    |
    v
user-owned cache keyed by repo, relative cwd, and resolved roots
    |
    v
one bounded additionalContext, or silent output
```

Ближайший навык проекта затеняет корневой или глобальный навык проекта с тем же именем `name`. Это имеет значение в монорепозиториях, где вложенный каталог `.agents/skills` может намеренно переопределить более широкое определение.

Навыки без калиброванного корпуса имеют маркировку `native-only`. Codex по-прежнему может выбрать их из описания, или пользователь может вызвать их явно с помощью `$skill-name`.

## <a name="claude-code-architecture"></a>Claude Code архитектура

Эту же среду выполнения можно установить в режиме проекта с помощью `SKILL_ROUTER_HOST=claude`. Обнаружение и калибровка остаются прежними. Изменяется только синтаксис явной подсказки с Codex `$skill-name` на Claude Code `/skill-name`.

Сохраняйте перехватчики регулярных выражений, специфичные для проекта, такие как `smart-suggest.sh`, если они кодируют отдельные правила применения. Не дублируйте сам обработчик BM25 на активных уровнях конфигурации Codex.

## Формат корпуса

Соседний корпус принадлежит `<skill>/evals/scenarios.json`:

```json
{
  "skill": "debug-db",
  "positive": [
    "my Prisma client reports connection refused",
    "connexion à la base de données impossible",
    "the database pool is exhausted"
  ],
  "negative": [
    "optimize this slow SQL query",
    "add an index to the users table",
    "export a database backup"
  ]
}
```

Значение `skill` должно соответствовать активному имени `SKILL.md` и `^[a-z0-9][a-z0-9:_-]{0,127}$`. Для калибровки требуется не менее восьми положительных и двух отрицательных подсказок. На практике используйте 12 или более разнообразных положительных и как минимум пять близких отрицательных значений.

Негативам нужен общий словарный запас с позитивами. Несвязанные негативы искусственно упрощают задачу и устанавливают небезопасный порог. Среда выполнения также оценивает контрастные отрицательные примеры и налагает вето на кандидата, если его самое сильное отрицательное соответствие по крайней мере так же сильно, как и его положительное совпадение.

Используйте внешнее наложение, если каталог навыков имеет строгий файловый контракт. `SKILL_ROUTER_OVERLAY_ROOTS` указывает на один или несколько каталогов, содержащих файлы корпуса JSON. Наложение игнорируется, если его `skill` в данный момент не преобразуется в активный навык.

## Границы обнаружения и безопасности

Маршрутизатор анализирует только `name` и `description` из первых 64 КиБ каждого `SKILL.md`. Он отклоняет неверные имена и файлы сценариев, предназначенные для неактивных или несовпадающих навыков.

Символические ссылки навыков преобразуются в их реальный путь. Цель принимается только тогда, когда она находится внутри обнаруженного или явно разрешенного корня навыка. Выдаваемая подсказка включает в себя точный разрешенный путь `SKILL.md`, который дает модели проверяемую цель.

Приоритет детерминирован:

1. ближайший `.agents/skills` предок `cwd`;
2. корень репозитория `.agents/skills`;
3. `~/.agents/skills`;
4. `~/.codex/skills`;
5. `/etc/codex/skills`;
6. явные дополнительные корни.

## Индекс и калибровка

Автор гола использует Okapi BM25 с `K1 = 1.2` и `B = 0.3`. Он не реализует BM25+, поскольку здесь нет дельта-члена. Форма IDF:

```text
IDF(t) = log(1 + (N - n + 0.5) / (n + 0.5))
```

Позитивные и контрастирующие отрицательные документы имеют одно и то же терминологическое пространство IDF. Положительные и отрицательные оценки для каждого навыка являются максимальными по сравнению с примерами соответствия этого навыка. Максимум избегает отдавать предпочтение навыкам только потому, что в их корпусе больше подсказок.

Калибровка с исключением одного выбирает порог, который максимизирует F-бету с квадратом бета, равным четырем. Статус использует простую F1:

| Статус | Значение | Поведение во время выполнения |
|---|---|---|
| `ok` | Калибровка F1 составляет не менее 0,60, и оценка перекрестных навыков пройдена. | Имеет право на BM25 |
| `conflict` | Порог существует, но F1 ниже 0,60. | Никогда не предлагал |
| `excluded` | Менее восьми положительных или двух отрицательных | Никогда не предлагал |
| `native-only` | Активный навык не имеет принятого корпуса | Только нативное соответствие |

Оригинальный маршрутизатор фильтровал только `excluded`, что позволяло использовать навыки `conflict`. Текущая среда выполнения требует ровно `status: ok`, конечного порога, соответствия перекрестным навыкам, активного разрешенного навыка и отсутствия более сильного контрастного отрицательного соответствия. Объединенный набор, отвечающий критериям, должен достичь глобального уровня F1 0,70. Корпуса проектов более низкого качества остаются `native-only`; наложение, прошедшее независимое ограничение, остается защищенным, пока набор проектов обрезается.

## Поведение кэша

Каждая разрешенная область получает отдельный ключ кэша на основе корня репозитория, относительного `cwd`, разрешенных корней навыков и версии алгоритма. Это предотвращает совместное использование несовместимого индекса двумя вложенными рабочими пространствами монорепозитория.

Отпечаток сборки включает в себя нормализованные пути, размер, время модификации, хэш контента SHA-256 и версию алгоритма для каждого активного `SKILL.md` и корпуса. Быстрый «горячий путь» проверяет отпечаток статистики по известным источникам и путям просмотра, что позволяет обнаружить обычные добавления, изменения и удаления без повторного чтения сотен файлов. Каждые 60 секунд отдельная глубокая проверка пересчитывает хэши контента. Это также фиксирует необычное редактирование одинакового размера, время модификации которого было восстановлено вручную.

У одного строителя есть замок `O_EXCL` с 30-секундным TTL. Файлы кэша записываются во временные файлы и переименовываются атомарно. Во время перестроения в текущем приглашении используется последний действительный индекс. Без действительного индекса перехватчик завершает работу автоматически и планирует сборку в фоновом режиме.

В текущем репозитории не записывается файл времени запроса. Глобальный установщик устанавливает каталог данных, принадлежащий пользователю. Дополнительные журналы содержат только метаданные маршрутизации, а не необработанный текст подсказки.

## Выходной контракт

Адаптер Codex выдает:

```json
{
  "hookSpecificOutput": {
    "hookEventName": "UserPromptSubmit",
    "additionalContext": "Skill routing candidates:\n- $agentic-project-finder (/absolute/path/SKILL.md)\nUse only if the intent matches."
  }
}
```

Адаптер Claude использует `/agentic-project-finder`. Маршрутизатор выдает не более трех кандидатов и 500 символов. Он не отображает процент достоверности, поскольку `score / sum(top scores)` не является калиброванной вероятностью. Обычные предложения не имеют `systemMessage`.

Обычное отрицание остается маршрутизируемым. Например, `analyse ce dépôt sans modifier les fichiers` по-прежнему может выбрать навык проверки. Явные отказы, такие как `ne suggère aucune skill`, останавливают маршрутизацию. Существующее активное упоминание `$skill` для Codex или `/skill` для Claude также останавливает маршрутизатор, чтобы избежать лишних советов.

## Установка

Предварительный просмотр глобальной установки Codex:

```bash
cd examples/hooks/bm25-routing
node install.js --host codex --scope user --dry-run
```

В предварительном просмотре без записи перечислены изменения источника, места назначения, контрольной суммы и перехватчика. Подавайте заявку только после проверки:

```bash
node install.js --host codex --scope user --apply
```

Программа установки сохраняет существующие обработчики, добавляет один обработчик `UserPromptSubmit` и создает резервную копию с отметкой времени. Повторение идентичной установки недопустимо.

Откройте `/hooks` в Codex после установки. Неуправляемые перехватчики требуют явного рассмотрения и доверия. Копия файла сама по себе не делает новый обработчик активным.

Для установки автономного проекта на машине без глобального обработчика:

```bash
node install.js \
  --host codex \
  --scope project \
  --project-root /absolute/path/to/repo \
  --dry-run
```

Сгенерированный хук проекта по-прежнему записывает кеши в каталог пользователя. Не активируйте одновременно проектный и глобальный обработчики Codex BM25.

## <a name="evaluation"></a>Оценка

Примеры обучения не должны служить доказательством принятия. Сохраните отдельный набор подсказок с ожидаемыми и запрещенными навыками:

```json
{
  "prompt": "find repositories implementing shared agent memory",
  "expected": ["agentic-project-finder"],
  "forbidden": ["critique-plan"]
}
```

Запустите строгий оценщик:

```bash
SKILL_ROUTER_CWD=/absolute/path/to/repo \
node routing/eval.js \
  --acceptance test/acceptance-prompts.json \
  --strict
```

Включенные ворота требуют точности не менее 0,80, F1 не менее 0,70 и отсутствия запрещенных попаданий. Расширяйте охват одного проверенного навыка за раз. Не создавайте производственные сценарии автоматически на основе описаний.

## Виды отказов для проверки

- отсутствующий, усеченный или недействительный кэш возвращается автоматически;
- имена проекта и глобальные повторяющиеся имена разрешаются в путь к проекту;
- Названия `conflict`, `excluded` и неактивных навыков никогда не появляются;
- добавление, редактирование или удаление корпуса делает недействительной только соответствующую область действия;
- две одновременные перестройки производят одну запись;
- дополнительные журналы не содержат текста подсказки;
- Перед развертыванием проходит 30 или более положительных, отрицательных и явных запросов на вызов;
- Задержка теплого подключения остается ниже 75 мс в p95 на целевой машине.

Используйте `routing/benchmark.js --iterations 1000 --cwd <repo>` для шлюза задержки теплого пути. Он измеряет загрузку кэша, проверки недействительности статистики, токенизацию, оценку, фильтрацию и построение выходных данных в одном процессе, исключая однократный запуск узла.

Полные работоспособные тесты используют встроенный инструмент запуска тестов Node:

```bash
node --test examples/hooks/bm25-routing/test/*.test.js
```
