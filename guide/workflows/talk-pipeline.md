# Процесс подготовки доклада: от идеи к слайдам с помощью ИИ

> **Confidence**: Уровень 2, проверен в реальных условиях на реальных конференциях (DevWithAI, Лион, 2026 г.).

Превратите необработанную статью, стенограмму или заметки в полноценное выступление на конференции, включая готовую для Кими подсказку для слайдов, созданных искусственным интеллектом. Шесть этапов, два режима, одна контрольная точка с участием человека.

## <a name="tldr"></a>ТЛ;ДР

```
Source Material (article / transcript / notes)
        │
        ▼
[Stage 1] EXTRACT ─────────────── {slug}-summary.md
        │
        ├──────────────────────────────────────┐
        │                                      │
        ▼ (--rex only)                         ▼
[Stage 2] RESEARCH               [Stage 3] CONCEPTS
  git-archaeology.md              concepts.md
  changelog-analysis.md           concepts-enriched.md
  timeline.md                         │
        │                             │
        └──────────────┬──────────────┘
                       │
                       ▼
              [Stage 4] POSITION
                angles.md
                titre.md
                descriptions.md
                feedback-draft.md
                       │
                  [CHECKPOINT]
             User selects angle + title
                       │
                       ▼
              [Stage 5] SCRIPT
                pitch.md
                slides.md
                kimi-prompt.md ──► Copy-paste into Kimi.com
                       │
                       ▼
             [Stage 6] REVISION
              revision-sheets.md
```

Два режима: **REX** (обсуждение с реальными доказательствами: история git, метрики) и **Concept** (idea/thesis-based, пропускает этап 2).

## <a name="when-to-use"></a>Когда использовать

Этот конвейер подходит, когда вам нужно подготовиться к разговору и либо:

- **A REX сообщает**: вы что-то создали, отправили, имеете реальные показатели и хотите превратить это в структурированное выступление на конференции.
- **A концепция для разработки**: у вас есть статья, заметки или идеи, которые вы хотите превратить в структурированную презентацию.

Подходящие форматы:
- Выступления на конференции (20-45 мин)
- Презентации на встречах (15–30 минут)
- Внутренние технические переговоры
- Открытие мастерских

Не подходит для: обновлений слайдов для повторяющихся встреч, коротких кратких докладов продолжительностью менее 10 минут или ситуаций, когда у вас нет материала для работы.

## <a name="prerequisites"></a>Предварительные условия

**Required**:
- Claude Code с установленными навыками (см. [examples/skills/talk-pipeline/](../../examples/skills/talk-pipeline/))
- Исходный материал: статья `.mdx`, расшифровка `.md`, примечания или микс.
- Метаданные разговора: ярлык, название мероприятия, дата, продолжительность, описание аудитории.

**Только для режима REX**:
- Доступ к репозиторию git, который вы хотите проанализировать.
- Необязательно: путь `CHANGELOG.md`, если он отличается от корня репо.

**Для поколения слайдов Кими (выход этапа 5)**:
- Бесплатная учетная запись на [kimi.com](https://kimi.com) (API не требуется, просто скопируйте и вставьте)

**Необязательно, но рекомендуется**:
- Каталог `talks/` в корне вашего проекта для выходных файлов.
- Для обратной связи доступны 1–2 доверенных партнера (этап 4).

| `{slug}-timeline.md` | 2 | ✓ | — |
| `{slug}-concepts.md` | 3 | ✓ | ✓ |


## <a name="stage-by-stage-guide"></a>Поэтапное руководство

### Этап 1: Извлечение

**Что он делает**: Читает исходный материал и составляет структурированное резюме: сюжетная линия, ключевые показатели, основные темы, пробелы.

| | |
|--|--|
| **Ввод** | Исходный файл + метаданные (слаг, событие, дата, продолжительность, аудитория, режим) |
| **Вывод** | `{slug}-summary.md` |
| **Использованные инструменты** | Читайте, пишите, задавайте вопросы пользователю |
| **Mode** | РЕКС + Концепция |

**Основные правила**:
- Автоматически определяет тип источника (REX или Concept) на основе сигналов (даты, показатели, «Я отправил» или «Я думаю»)
- Извлекает каждую измеримую метрику из ее источника, без придуманных чисел.
- Явно отмечает пробелы, а не скрывает их

**Invocation**:
```
/talk-stage1-extract
```

Или через оркестратор:
```
/talk-pipeline --stage=extract --slug=my-talk --event="Conf 2026" --date=2026-06-15 --duration=30 --audience="senior devs"
```

**Просмотр перед тем, как перейти к**:
- Повествование арки последовательное (не общее: «этот разговор об ИИ…»)
- Все показатели имеют явный источник
- Пробелы перечислены (даже если «нет серьезных пробелов»)
- Определение типа правильное (REX/Концепт/Гибрид)

---

### Этап 2: Исследование (только в режиме REX)

**Что он делает**: Археология Git: извлекает метрики скорости, перекрестные ссылки CHANGELOG, строит фактическую временную шкалу, проверенную git (не оценено).

| | |
|--|--|
| **Ввод** | `{slug}-summary.md` + путь репо |
| **Вывод** | `git-archaeology.md`, `changelog-analysis.md`, `timeline.md` |
| **Использованные инструменты** | Bash (команды git только для чтения), Чтение, Запись |
| **Mode** | Только REX (**автоматически пропускается в концептуальном режиме**) |

**Основные правила**:
- Только команды git только для чтения, никогда не изменяют репозиторий.
- Даты, не найденные в git, помечены как «непроверенные», никогда не оцениваются.
- Противоречия между источниками отмечаются, а не разрешаются молча

Используемые команды **Git** (только для чтения):
```bash
git log --pretty=format:"%Y-%m" | sort | uniq -c   # velocity by month
git shortlog -sn --no-merges                         # contributors
git tag --sort=version:refname                       # releases
git log --merges --oneline | wc -l                   # PRs merged
```

**Просмотр перед тем, как перейти к**:
- Временная шкала охватывает весь период от сводки
- Нет предполагаемых дат, все проверено
- Пики скорости имеют контекстные примечания.

---

### Этап 3: Концепции

**Что он делает**: Создает пронумерованный каталог всех понятий в материале. Каждая концепция получает оценку потенциала разговора (ВЫСОКИЙ/СРЕДНИЙ/НИЗКИЙ).

| | |
|--|--|
| **Ввод** | `{slug}-summary.md` + `{slug}-timeline.md` (необязательно) |
| **Вывод** | `{slug}-concepts.md`, `{slug}-concepts-enriched.md` (если доступно репо) |
| **Использованные инструменты** | Читай, пиши |
| **Mode** | РЕКС + Концепция |

**Критерии оценки**:
- **HIGH**: наглядный, нелогичный, с проверенными цифрами, действенный за 30 секунд.
- **MEDIUM**: полезно, но ожидаемо, отсутствуют доказательства или цифры.
- **LOW**: Слишком абстрактно, слишком подробно, сложно проиллюстрировать на слайде.

**Дисциплина подсчета очков**: Максимум 30% ВЫСОКИЙ, главное – проявлять избирательность.

**Просмотр перед тем, как перейти к**:
- Выявлено более 15 концепций (более 20 для REX с доступом к репо)
- Оценки калибруются (не все ВЫСОКИЕ, не все НИЗКИЕ)
- Каждое понятие имеет конкретное описание в 1-2 предложениях.

---

### Этап 4: Позиция + ЧЕКПОИНТ

**Что он делает**: Создает стратегические точки зрения, заголовки, описания и черновой вариант для отзывов коллег. Затем **останавливается и ждет** вашего выбора ракурса и названия.

| | |
|--|--|
| **Ввод** | `{slug}-summary.md` + `{slug}-concepts.md` + ограничения событий |
| **Вывод** | `angles.md`, `titre.md`, `descriptions.md`, `feedback-draft.md` |
| **Использованные инструменты** | Читайте, пишите, задавайте вопросы пользователю |
| **Mode** | РЕКС + Концепция |

**Что генерируется**:
- **3-4 ракурса**: каждый со своими силами, слабостями, соответствием аудитории, вердиктом (оценка /5)
- **Рекомендация**: один четкий выбор со структурированным обоснованием
- **3-5 названий** на каждый ракурс
- **Краткое описание** (~100 слов абстрактного) + **длинное описание** (~250 слов CFP)
- **Черновик обратной связи**: готовое к отправке сообщение для одноранговой проверки (3 формата: Slack DM, электронная почта, сообщение в LinkedIn)

Отображение **CHECKPOINT** (обязательно перед этапом 5):

```
---
CHECKPOINT : Choix angle + titre

J'ai généré 4 fichiers :
- talks/{YYYY}-{slug}-angles.md    → {n} angles analysés
- talks/{YYYY}-{slug}-titre.md     → {n} options de titre
- talks/{YYYY}-{slug}-descriptions.md
- talks/{YYYY}-{slug}-feedback-draft.md

Avant de lancer le script (Stage 5), j'ai besoin de ton choix :

1. Quel angle tu retiens ? (recommandé : Angle {X} — {nom})
2. Quel titre tu préfères ? (recommandé : "{titre}")

Tu peux aussi modifier, mixer, ou proposer quelque chose d'autre.
---
```

**Stage 5 не может запуститься без явного подтверждения пользователя.**

**Проверка перед подтверждением**:
- Вы прочитали черновик отзыва и при желании отправили его коллеге.
- Рекомендуемый угол может выдерживать всю продолжительность без повторений.
- Название конкретное (без жаргона и кликбейта).

---

### Этап 5: Сценарий

**Что он делает**: Составляет полный доклад в 5 актах с заметками докладчика, описанием слайдов и подсказкой Кими.

| | |
|--|--|
| **Ввод** | резюме + концепции + временная шкала (необязательно) + **подтвержденный ракурс + заголовок** |
| **Вывод** | `{slug}-pitch.md`, `{slug}-slides.md`, `{slug}-kimi-prompt.md` |
| **Использованные инструменты** | Читай, пиши |
| **Mode** | РЕКС + Концепция |

**Три результата**:

1. **`pitch.md`**: повествование в 5 актах с заметками докладчика, таймингом и ключевыми моментами. То, что вы говорите, а не то, что читаете со слайдов.

2. **`slides.md`**: Спецификация слайд-за-слайдом: заголовок, визуальное описание, основной текст (до 30 слов), примечания докладчика, продолжительность, номер акта. Готов передать дизайнеру или передать Кими.

3. **`kimi-prompt.md`**: Полная подсказка для [kimi.com](https://kimi.com). Включает систему дизайна, цветовую палитру, типографику, полное содержимое слайдов и заполнители для скриншотов. Копипаст готов.

**Правило «1 идея на слайд»**: Если для описания слайда требуется знак «и», разделите его.

**Просмотр перед тем, как перейти к**:
- Проверка времени: общая сумма ≤ продолжительность + буфер 10 %.
- Заметки докладчика читаются естественным образом вслух (проверьте это)
- В приглашении Кими не осталось незаполненных `{PLACEHOLDER}`

---

### Этап 6: Пересмотр

**Что он делает**: Создает листы исправлений во время и после выступления: быстрая навигация по действиям, таблица основных концепций, шпаргалка вопросов и ответов, глоссарий.

| | |
|--|--|
| **Ввод** | `pitch.md` + `slides.md` + `concepts.md` |
| **Вывод** | `{slug}-revision-sheets.md` |
| **Использованные инструменты** | Читай, пиши |
| **Mode** | РЕКС + Концепция |

**Что находится в списках изменений**:
- **Navigation** с якорными ссылками по действиям
- **Разбивка по действиям**: ключевые понятия + показатели + анекдоты + возможные вопросы и ответы
- **Главная таблица**: концепция → определение из 1–2 предложений → URL-адрес для публикации
- Шпаргалка **Q&A**: 6-10 возможных вопросов с короткими ответами (на произнесение ≤20 секунд)
- **Блок метрики**: все цифры в одном месте
- **Внешние ресурсы**: ссылки, упомянутые в докладе
- **Глоссарий**: технические термины, максимум 10 слов каждый.

**Purpose**: Кто-то задает вопрос → найдите раздел → поделитесь URL-адресом за 5 секунд.

## <a name="the-kimi-handoff"></a>Передача Кими

На этапе 5 генерируется `{slug}-kimi-prompt.md`, полное приглашение для [kimi.com](https://kimi.com).

**Что с этим делать**:
1. Откройте сгенерированный файл
2. Убедитесь, что `{PLACEHOLDER}` не осталось (найдите файл)
3. Перейдите на [kimi.com](https://kimi.com) (бесплатная учетная запись, API не требуется)
4. Начать новый разговор
5. Скопируйте и вставьте всю подсказку
6. Кими создает презентацию (PowerPoint или PDF)

**Итерируемся с Кими**:
- После первого поколения просмотрите слайды, соответствующие вашей спецификации `slides.md`.
- Добавьте последующие сообщения для отдельных корректировок: «Слайд 7: увеличьте число, удалите маркированный список».
- Для снимков экрана: замените заполнители `SCREENSHOT AREA` вручную после экспорта.

**Система проектирования**, встроенная в шаблон:
- Темная тема (фон #0a0a0a)
- Оранжевый акцент (#f97316) для ключевых номеров и призывов к действию.
- Inter/SF Профессиональная типографика
- Максимум 30 слов на слайде, цифры в качестве героев.
- Коэффициент контрастности WCAG AA (безопасен для проектора)

**Почему Кими?** На момент написания статьи Кими создает более качественные презентации на конференциях с подробными подсказками, чем большинство альтернатив. Шаблон настроен Кими, но система дизайна и структура слайдов работают с любым инструментом презентации AI.

## <a name="human-in-the-loop-checkpoints"></a>Контрольно-пропускные пункты с участием человека

Трубопровод имеет два контрольно-пропускных пункта:

### Контрольная точка 1: сбор метаданных этапа 1

Если метаданные разговора (ссылка, событие, дата, продолжительность, аудитория, режим) не предоставлены заранее, этап 1 использует `AskUserQuestion` для их сбора перед продолжением. Это позволяет избежать создания сводки, которую вы могли бы отбросить.

### Контрольная точка 2 (Этап 4): Выбор ракурса + названия (обязательно)

Это критически важные ворота трубопровода. Этап 5 не может начаться без явного человеческого выбора.

**Почему это важно**: Ракурс и название определяют все, что следует за ним: пятиактную структуру, на которой вырисовываются концепции, быстрый тон Кими. Автоматический выбор здесь приведет к общему разговору. Это единственное решение, которое должно быть вашим.

**Что делать на КПП**:
1. Прочтите `angles.md` и не пропускайте: рекомендация может не соответствовать вашему контексту.
2. При необходимости отправьте `feedback-draft.md` доверенному узлу (занимает 10 минут, экономит 2 часа доработок)
3. Ответьте по своему выбору (это может быть рекомендация, изменение или что-то совершенно другое).

## <a name="adapting-the-pipeline"></a>Адаптация конвейера

### Блестящая беседа (10-15 мин)

- Сохраните этапы 1, 3, 4, 5, но пропустите этап 2 даже в режиме REX.
- На этапе 3: ограничьтесь 8-10 концепциями (безжалостно фильтруйте только до ВЫСОКОГО уровня)
- На этапе 4: создайте максимум 2 угла.
- На этапе 5: целевые ~8–10 слайдов, ~2 min/slide.
- Пропустить этап 6 (не требуется для короткого формата)

### 45-минутный разговор

- Полный конвейер, все этапы
- На этапе 3: нацельтесь на 25–35 концепций (достаточно для выполнения 5 серьезных действий)
- На этапе 5: 20–25 слайдов, допускается 3 средних значения min/slide.
- 6 этап становится критическим (вопрос-ответ длится 10-15 мин)

### Мастер-класс (90+ мин)

- Запустите трубопровод до этапа 4
- На этапе 5: замените slides.md спецификацией деятельности (упражнения, время, секционные группы).
- Раздел с подсказками Кими становится необязательным (менее актуален для материалов семинара)

### Нет доступного репозитория git (REX без кода)

- Используйте режим `--rex`, если у вас есть метрики из других источников (аналитика, информационные панели, отчеты об инцидентах).
- На этапе 2: замените команды git сбором данных из этих источников вручную.
- Будьте строже в отношении источников: «непроверенные» показатели не выдерживают разговоров

## <a name="common-pitfalls"></a>Распространенные ловушки

### Метрики без источников

Этап 1 извлекает метрики, но не проверяет их. Этап 2 проверяет. Если вы находитесь в концептуальном режиме, любая метрика, которую вы упоминаете в выступлении, должна быть явно указана в вашем резюме или удалена. Зрители спрашивают: «Откуда взялось это число?» и «Я посмотрел» — это не ответ.

### Перегруженные слайды

Подсказка Кими требует 30 слов на слайд, но pitch.md, который вы пишете на этапе 5, может перейти к маркированным спискам. Проверьте правило «1 идея на слайд»: если вам нужно «и» для описания содержимого слайда, разделите его.

### Пропуск контрольной точки

Проведение этапа 5 без подтвержденного ракурса + заголовка дает технически правильный сценарий неправильного выступления. Рекомендация этапа 4 — это хорошая отправная точка, а не окончательный ответ: важны знания вашей аудитории.

### Отправка черновика отзыва слишком поздно

Черновой вариант отзыва создается на этапе 4, еще до создания сценария. Это сделано намеренно: обратная связь от коллег на этапе angle/title полезна. Отзывы о готовом сценарии чаще всего вызывают сожаление.

### Общие заметки докладчика

Заметки докладчика в `pitch.md` должны читаться как естественная речь. Если вы поймаете себя на том, что пишете: «На этом слайде мы обсуждаем…», перепишите это так, как вы на самом деле сказали бы аудитории. Подсказка Кими копирует эти заметки, поэтому они должны быть диалоговыми.

## <a name="design-patterns-showcased"></a>Представлены шаблоны проектирования

Этот конвейер интересен с точки зрения Claude Code, поскольку он демонстрирует несколько продвинутых шаблонов в одной связной системе.

### Цепочка навыков с файловым состоянием

Каждый этап записывает файлы, которые читает следующий этап. Состояние сохраняется между вызовами навыков через файловую систему без какой-либо связи в памяти. Вы можете запустить этап 3 через неделю после этапа 2, не теряя контекста.

```
Stage 1 → writes {slug}-summary.md
Stage 2 → reads {slug}-summary.md → writes 3 new files
Stage 3 → reads summary + timeline → writes 2 new files
...
```

### Область действия разрешений инструмента

Этап 2 — единственный этап, на котором требуется Bash (для команд git). Все остальные этапы доступны только для чтения и записи. Это сделано намеренно: минимальная занимаемая площадь на каждом этапе означает меньшую вероятность ошибок.

```yaml
# Stage 2 only
allowed-tools:
  - Write
  - Read
  - Bash
```

### Ворота с участием человека

На этапе 4 `AskUserQuestion` используется для отображения CHECKPOINT как структурного требования, а не для удобства. Навык не перейдет на Стадию 5 без явного ответа человека. Это шаблон «Claude предлагает, человек решает».

### Передача управления от ИИ к ИИ

На этапе 5 генерируется запрос на использование второй системы искусственного интеллекта (Кими). Claude генерирует спецификацию, которую выполняет другой ИИ, а не слайды напрямую. Этот шаблон позволяет объединить сильные стороны: Claude для структурированного повествовательного рассуждения, Kimi для создания визуальной презентации.

```
Claude (Stage 5) → kimi-prompt.md → Kimi.com → slides.pptx
```

### Два режима выполнения с условным пропуском этапов

Флаг `--rex`/`--concept` определяет, какие этапы выполняются. Этап 2 автоматически пропускается в концептуальном режиме. Оркестратор (`/talk-pipeline`) управляет маршрутизацией: отдельные навыки этапа не зависят от режима.
