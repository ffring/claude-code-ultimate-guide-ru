## 🎯 Рабочие процессы разработки

### [Плановая разработка](./plan-driven.md)

Структурируйте сложные задачи с режимом планирования перед выполнением.

**Когда использовать**: многоэтапные функции, архитектурные изменения, неуверенность в подходе

### [ZВклады с открытым исходным кодом с помощью AI](./ai-assisted-open-source-contributions.md)

Подготовьте вклад с воспроизведенной проблемой, объяснением автора, проверочными доказательствами и ответственностью за отзывы сопровождающих. Включает многоразовый пакет пожертвований.

**Когда использовать**: Claude Code помогает подготовить патч для сопровождающих другого проекта.

### [TDD с Claude](./tdd-with-claude.md)

Рабочий процесс разработки через тестирование: сначала напишите тесты, а потом реализуйте.

**Когда использовать**: критически важные функции, предотвращение регресса, дизайн API

### [Специальная разработка](./spec-first.md)

Пишите спецификации перед кодом для большей ясности требований.

**Когда использовать**: совместная работа в команде, сложные функции, проекты, ориентированные на документацию.

### <a name="iterative-refinement"></a>[Итеративное уточнение](./iterative-refinement.md)

Улучшайте код посредством нескольких циклов доработки.

**Когда использовать**: улучшение качества, оптимизация производительности, очистка кода.

### [Лучший из N: создать, выбрать и проверить](./best-of-n.md)

Сгенерируйте объявленный набор независимых кандидатов, оцените каждого кандидата по замороженному критерию, проверьте выбранный результат вне контекста его генерации и сохраните журнал проверки.

**Когда использовать**: несколько вероятных решений с существенными компромиссами и рецензент или исполняемая проверка, которая может их отличить.

**Ресурсы многократного использования**: [Лучший из N навыков](../../examples/skills/best-of-n/SKILL.md) и [TESTING.md доказательство](../../examples/claude-md/TESTING.md)

### [Скелетные проекты](./skeleton-projects.md) ⭐ НОВИНКА

Используйте существующие проверенные репозитории в качестве основы для новых проектов.

**Когда использовать**: запуск новых проектов, стандартизация командных моделей, быстрое создание прототипов на проверенных основах.

### [Инструкции для Team AI](./team-ai-instructions.md)

Масштабируйте CLAUDE.md с помощью команды, состоящей из нескольких разработчиков и различных инструментов, с помощью сборки модулей на основе профилей.

**Когда использовать**: команда разработчиков из 5+, несколько инструментов искусственного интеллекта (Claude Code + Cursor/Windsurf), смешанная ОС

### [Фрагменты журнала изменений](./changelog-fragments.md) ⭐ НОВИНКА

**Enforce документации по PR с помощью трехуровневой системы: правило CLAUDE.md + перехватчик UserPromptSubmit + шлюз CI**

Устраняет конфликты слияния на `CHANGELOG.md`, фиксирует контекст во время реализации и гарантирует, что миграция БД никогда не будет развертываться в автоматическом режиме. Включает многоразовый шаблон перехвата `UserPromptSubmit` для выполнения любого обязательного этапа рабочего процесса.

**Основные темы**:
- Правило рабочего процесса CLAUDE.md для автономного создания фрагментов
- Перехватчик `UserPromptSubmit` с трехуровневым приоритетом (принудительное исполнение, обнаружение, контекстный)
- Шаблон условного предложения: «при пиар-намерении без упоминания фрагмента»
- Применение CI с независимой проверкой миграции

### [Smart-Suggest Routing](./smart-suggest-routing.md) ⭐ НОВИНКА

**Двухмоторная система перехвата `UserPromptSubmit`: применение регулярных выражений + самокалибровка лексического подсчета BM25**

Вводит рекомендации по ранжированию навыков как `additionalContext`, поэтому Claude предлагает правильный навык, даже если формулировка никогда не ожидалась. BM25 обобщает примеры сценариев; уровень регулярных выражений обрабатывает шаблоны принудительного применения. Оба выполняются параллельно в каждом приглашении.

**Основные темы**:
- Таблица решений Regex и BM25 (когда выигрывает каждый движок)
- Формат корпуса: 10+ положительных + 3+ отрицательных сценария на каждый навык.
- `build-index.js`: калибровка с исключением одного, порог F-бета, статус `ok`/`excluded`/`conflict`
- Параллельное подключение двух хуков через settings.json
- Перестроение отдельного фонового индекса при изменении корпуса

### [RPI: Исследование → План → Реализация](./rpi.md) ⭐ НОВИНКА

**3-этапная разработка функций с явными воротами проверки между этапами**

Создавайте функции в три последовательных этапа: сначала исследуйте осуществимость, затем спланируйте реализацию, затем напишите код. На каждом этапе создается конкретный артефакт (RESEARCH.md → PLAN.md → код). Каждые ворота требуют явного GO перед началом следующей фазы.

**Когда использовать**: функции с неясной осуществимостью, работа более одного дня, неизвестная техническая территория или где-либо позднее обнаружение неверного предположения обходится дорого.

### [GitHub Actions Рабочие процессы](./github-actions.md) ⭐ НОВИНКА

**5 готовых к производству шаблонов для автоматизации PR-проверок, сортировки проблем и контроля качества**

Подключите Claude напрямую к вашему рабочему процессу GitHub через официальный `claude-code-action`. Два режима: интерактивный (упоминание `@claude`) и полностью автоматизированный (триггеры push/schedule).

**Основные темы**:
- Настройка через `/install-github-app` (30-секундное краткое руководство)
- Схема 1: PR-обзор по запросу через упоминание `@claude`
- Схема 2. Автоматический просмотр при каждом нажатии.
- Схема 3: сортировка проблем и маркировка
- Схема 4. Проверка конфиденциальных путей с точки зрения безопасности
- Схема 5: Плановая еженедельная проверка работоспособности репо
- Контроль затрат, параллелизм, безопасность форков

**Когда использовать**: Любая команда, которой нужна проверка кода на базе искусственного интеллекта без управления инфраструктурой.

### [Обзор кода для нескольких поставщиков](./multi-provider-code-review.md) ⭐ НОВИНКА

**Запустите Claude Code Action вместе с CodeRabbit и Greptile без тройного повторения результатов**

Неизбыточная архитектура для трех автоматических рецензентов на одном PR: Claude владеет глубоким семантическим обзором и шлюзом блокировки слияния, детерминированный инструмент владеет проверками перед слиянием PASS/FAIL, инструмент RAG владеет межфайловыми инвариантами. Охватывает сценарий CI Gate, пакетную обработку крупных запросов на обработку, дельта-проверку и дедупликацию между инструментами.

**Когда использовать**: Запуск более одного автоматического средства проверки кода и обнаружение одной и той же проблемы, о которой сообщалось трижды, или желание, чтобы результаты Claude фактически блокировали слияние, а не просто комментировали.

### [Переключение когнитивного режима](./gstack-workflow.md) ⭐ НОВИНКА

Переключайтесь между ролями специалистов на протяжении всего цикла разработки: стратегические ворота продукта, проверка архитектуры, параноидальная проверка кода, автоматический выпуск, контроль качества встроенного браузера и ретроспектива.

**Когда использовать**: циклы поставки, в которых требуется четкое разделение между направлением разработки продукта, тщательностью разработки, проверкой и выпуском, а не одним общим помощником, управляющим всеми этапами.

## Мультиагентный и расширенный

### [Динамические рабочие процессы](./dynamic-workflows.md) ⭐ НОВИНКА

Сценарии JavaScript, которые координируют работу десятков и сотен субагентов с детерминированным потоком управления, параллельным разветвлением и автоматическим возобновлением работы при прерывании.

**Когда использовать**: многоэтапная распараллеливаемая работа, длительные задания, задачи, требующие передачи структурированных данных между этапами, или любая ситуация, когда один агент достигает ограничений контекста.

**Основные темы**:
- Примитивная ссылка: `agent()`, `parallel()`, `pipeline()`, `phase()`, `log()`, `budget`.
- `pipeline()` против `parallel()` с данными тестирования (разница в задержке в 3 раза, разница в токенах в 2 раза)
- Результаты, структурированные по схеме, на разных этапах
- 5 именованных шаблонов: состязательная проверка, цикл до высыхания, судейские комиссии, мультимодальная проверка, план-выполнение-проверка
- Поведенческие гарантии: ограничения детерминизма, resume/caching, ограничения параллелизма.

Отслеживание многосессионных задач с помощью TodoWrite, задач API и сохранение контекста между сеансами.

**Когда использовать**: длительные задачи, охватывающие несколько сеансов, координация команды, сложные очереди.

### [Межсессионный обмен сообщениями](./cross-session-messaging.md) ⭐ НОВИНКА

`ListAgents` и `SendMessage`: как независимые, уже работающие сеансы Claude Code обнаруживают и отправляют сообщения друг другу на одном компьютере или через вашу учетную запись без участия человека, передающего контекст между терминалами.

**Когда использовать**: координационные сеансы, которые вы начали и управляете самостоятельно (параллельные рабочие деревья, сеансы для каждой роли, передача функций между компьютерами), в отличие от команд агентов (ведущий сеанс создает и контролирует своих собственных товарищей по команде)

**Основные темы**:
- Обнаружение `ListAgents`: субагенты, товарищи по команде, локальные узлы, облако, удаленное управление.
- Доставка сокетов на одной машине и маршрутизация удаленного управления между компьютерами
- Модель безопасности: `crossSessionInbound`, `isolatePeerMachines`, почему сообщение однорангового узла никогда не имеет авторитета
- Временная шкала версий и ограничения (ограничение размера сообщения, пакетное регулирование)
