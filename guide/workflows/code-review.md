# <a name="code-review"></a>Обзор кода

> **Доступность**: общедоступно с 15 октября 2026 г. (предварительная исследовательская версия от 9 марта 2026 г.). Только планы Team и Enterprise в репозиториях GitHub (включая GitHub Enterprise Server и GitHub Enterprise Cloud с резидентностью данных). Недоступно с нулевым сохранением данных, конфигурацией HIPAA или ключами шифрования, управляемыми клиентом (CMEK). Факты на этой странице были сверены с официальной документацией по проверке кода [](https://code.claude.com/docs/en/code-review) от 27 октября 2026 г.

Функция проверки кода Claude Code запускает многоагентную проверку запросов на извлечение GitHub. Несколько агентов проверяют различия в контексте окружающего кода, каждый ищет разные классы проблем (логические ошибки, уязвимости безопасности, неработающие крайние случаи), после чего выполняется этап проверки, который фильтрует ложные срабатывания.

Результаты публикуются в виде встроенных PR-комментариев к соответствующим строкам, помеченных по серьезности, со сводкой в ​​тексте обзора и проверочным прогоном под названием **Claude Code Review**. Рецензии никогда не одобряют и не блокируют PR, а проверка никогда не завершается неудачей, поэтому существующие рабочие процессы проверки остаются неизменными.

Проверка кода — это управляемый вариант. В любом плане вы также можете запустить [`/code-review`](https://code.claude.com/docs/en/code-review-local) локально, запустить ультраобзор из Claude Code или запустить Claude в своем собственном CI.

## <a name="how-it-works"></a>Как это работает

1. **Find**: несколько агентов параллельно проверяют разницу и окружающий код в инфраструктуре Anthropic.
2. **Verify**: этап проверки проверяет результаты кандидатов на соответствие коду и удаляет ложные срабатывания.
3. **Rank**: остальные результаты дедуплицируются и ранжируются по серьезности.
4. **Post**: встроенные комментарии, сводка и проверка **Claude Code Review** отображаются в PR.

При проверке считываются различия и окружающий код, не создавая и не запуская их, а доступ к репозиторию доступен только для чтения: при этом не выполняются фиксации. Anthropic сообщил в GA, что большинство обзоров заканчиваются через 6–10 минут, что примерно в три раза быстрее, чем примерно 20 минут предварительного просмотра (объявление[GA](https://claude.com/resources/articles/code-review-is-now-generally-available)). Считайте это цифрой поставщика, а не гарантией.

### Уровни обзора

Владелец устанавливает один уровень по умолчанию для организации и может переопределить его для каждого репозитория:

| Уровень | Trade-off |
|-------|-----------|
| **Быстрый** | Более легкий пас. Самый быстрый, самая низкая стоимость |
| **Стандарт** | Сбалансированная глубина, скорость и стоимость. По умолчанию |
| **Deep** | Самый тщательный проход. Самый медленный, самая высокая стоимость |

Code Review сам выбирает модели; в настройках администратора нет выбора модели. Уровень – контроль тщательности.

### Уровни серьезности

| Маркер | Серьезность | Значение |
|:-------|:---------|:--------|
| 🔴 | Важный | Ошибка, которую следует исправить перед объединением |
| 🟡 | Нит | Небольшая проблема, которую стоит исправить, но не блокировать. |
| 🟣 | Pre-existing | Ошибка в кодовой базе, не упомянутая в этом PR. |

Когда в обзоре были записаны обоснования, в выводе был свернут раздел **«Почему это было отмечено»**, объясняющий, почему Claude отметил это и как он подтвердил проблему.

## <a name="setup"></a>Настройка

**Owner** организации Claude включает проверку кода в настройках **Admin > Claude Code** ([claude.ai/admin-settings/claude-code](https://claude.ai/admin-settings/claude-code#code-review)). Обзоры выполняются на инфраструктуре Anthropic, поэтому файлы рабочих процессов не добавляются в репозитории.

Требуемый доступ:

- Роль владельца в организации Claude для каждого шага на странице администратора.
- Владелец организации GitHub, чтобы установить приложение Claude GitHub и связать его с организацией Claude.
- Доступ на запись к каждому добавляемому вами репозиторию из учетной записи GitHub, подключенной к Claude.

Steps:

1. Нажмите переключатель **Разрешить проверку кода**.
2. Подключите свою учетную запись GitHub (сначала выберите экземпляр GitHub Enterprise Server, если применимо)
3. Установите приложение Claude GitHub в организации GitHub и выберите репозитории, к которым оно может получить доступ. Набор разрешений приложения шире, чем используется в обзоре, поскольку он используется совместно с другими функциями Claude, такими как [GitHub Actions](./github-actions.md).
4. Выберите репозитории, затем нажмите **Продолжить**.
5. Нажмите **Finish** в диалоговом окне **Проверка кода настроена**. Закрытие другим способом оставляет **Allow code review** отключенным.
6. Откройте нечерновой тестовый PR и убедитесь, что появился контрольный прогон **Claude Code Review**.

### Установить время запуска отзывов

Каждый репозиторий имеет свой собственный параметр **Reviewruns**:

| Вариант | Когда он работает | Профиль затрат |
|--------|-------------|--------------|
| **Однажды после создания PR** | Когда запрос на заявку открывается, повторно открывается или помечается как готовый к рассмотрению | Самый низкий автоматический вариант |
| **После каждого нажатия** | При каждом отправке в ветку PR автоматически разрешаются темы, когда помеченные проблемы исправляются. | Самый высокий (умножается на количество push-уведомлений) |
| **Руководство (@claude review)** | Только по команде комментария | Контролируемый |

Репозиторий, добавленный из диалогового окна **Добавить репозиторий**. **начинается с После каждого нажатия**, самый дорогой вариант. Измените его сразу после настройки, если хотите меньше отзывов. Автоматические проверки пропускают черновые PR и PR из вилок независимо от настроек.

Владелец также может охватить всю организацию github.com из своей строки в таблице **Repositories**, которая требует ежемесячного лимита расходов и применяет выбранную опцию к каждому репозиторию там, включая добавленные позже.

## Комментировать команды

Опубликуйте команду как новый PR-комментарий верхнего уровня, в одной строке в начале комментария. Вам необходимо разрешение на запись, обслуживание или администрирование репозитория; Комментарии ботов не запускают обзоры.

| Команда | Эффект |
|---------|--------|
| `@claude review` или `@claude review once` | Начинает один обзор всего PR, **без** с подпиской на будущие пуши |
| `@claude review always` | Начинает обзор и подписывает PR на push-триггерные обзоры. |
| `@claude review stop` (также `off`, `pause`) | Завершает подписку без запуска или отмены обзора. |

Перед обновлением в июле 2026 года `@claude review` подписался на PR на push-обзоры. Теперь используйте `@claude review always` для такого поведения. В репозитории, установленном на **, после каждого нажатия**комментарий не может остановить рецензирование; Вместо этого преобразуйте PR в черновик.

Команда комментариев работает с черновиками и PR с форков, которые автоматические рецензии пропускают. Для разветвления требуется доступ на запись к базовому репозиторию. Если проверка последнего коммита уже выполняется, новый запрос не запускает второй.

Если репозиторий также запускает [Claude Code GitHub Action](./github-actions.md) с триггерной фразой `@claude` по умолчанию, `@claude review` также запускает действие. Установите вход `trigger_phrase` действия на другую фразу, чтобы разделить их.

### Повторные проверки и сохранение результатов

Обзор, который начинается после обновления, фокусируется на том, что изменилось со времени последнего обзора, и публикует меньше ошибок и ранее существовавших выводов; орган проверки указывает, сколько из них он не учел. Комментарий `@claude review` для полного повторного обзора.

После отправки, в результате которой добавленные и удаленные строки остаются без изменений (пустая фиксация, чистое слияние базовой ветки или чистое перебазирование), Code Review может сохранить более ранний результат вместо запуска проверки. Заголовок прогона проверки начинается с **Проверка кода пропущена** (важные выводы все еще открыты) или **Проверка кода не повторена** (ранее важные выводы все еще открыты).

### Создайте слияние из собственного CI

Проверка завершается нейтрально, а не неудачно. Чтобы выполнить слияние, прочитайте значения серьезности, которыми заканчивается текст сведений о выполнении проверки, а также HTML-комментарий, например `<!-- bughunter-severity: {"nit":1,"normal":2,"pre_existing":0} -->`, где `normal` учитывает важные выводы. Пропущенная строка означает отсутствие вердикта или отсутствие результатов. Официальная процедура [](https://code.claude.com/docs/en/code-review-pull-requests#read-the-result-from-a-script) дает командам `gh api` и `jq` и проверке заголовка выполняться в первую очередь.

## <a name="configure-reviews"></a>Настройка отзывов

Два файла управляют флагами Claude. Оба являются дополнительными к проверкам правильности по умолчанию.

### CLAUDE.md

Claude читает все файлы `CLAUDE.md` в вашей иерархии каталогов. Вновь выявленные нарушения помечаются как выводы уровня nit. Двунаправленный: если PR делает заявление `CLAUDE.md` устаревшим, Claude отмечает, что документы также нуждаются в обновлении.

Используйте `CLAUDE.md` для получения инструкций, которые также применимы к интерактивным сеансам Claude Code.

### REVIEW.md

Добавьте `REVIEW.md` в корневой каталог **репозитория**, чтобы использовать правила только для просмотра. Обнаруживается автоматически, настройка не требуется. Проверка кода считывает его из базовой ветки или ветки по умолчанию, а не из собственных изменений PR, поэтому PR не может ослабить свои собственные правила проверки.

```markdown
# Code Review Guidelines

## Always check
- New API endpoints have corresponding integration tests
- Database migrations are backward-compatible
- Error messages don't leak internal details to users

## Style
- Prefer early returns over nested conditionals
- Use structured logging, not f-string interpolation in log calls

## Skip
- Generated files under `src/gen/`
- Formatting-only changes in `*.lock` files
- Migration files in `db/migrations/`
```

Используйте `REVIEW.md` для правил, которые загромождают `CLAUDE.md` для общих сессий (соглашения о линтере, списки пропусков, шаблоны, специфичные для команды).

## <a name="pricing"></a>Цены

Счет за проверку кода взимается за использование токенов посредством кредитов за использование, **, отдельно от включенного в ваш план использования**, и выставляется организации, а не разработчику, который открыл или запросил проверку. Затраты отображаются в счете Anthropic, даже если организация использует Amazon Bedrock, платформу агентов Google Cloud или Microsoft Foundry для других функций Claude Code ([затраты и использование](https://code.claude.com/docs/en/code-review-costs)).

- Нет фиксированной цены за проверку: стоимость зависит от уровня проверки, размера изменения, сложности окружающего кода и количества потенциальных проблем, которые необходимо проверить. Статья поддержки [](https://support.claude.com/en/articles/14233555-set-up-code-review-for-claude-code) дает **в среднем 15-25 долларов за обзор**
- «После каждого нажатия» стоимость умножается на количество запросов, и это начальная настройка для новых репозиториев.
- Ежемесячный лимит расходов: **Настройки организации > Использование**, для службы проверки Claude Code.
- Средняя стоимость обзора на репозиторий: столбец **Average Cost** таблицы **Repositories** в **Настройки администратора > Claude Code**; показатели аналитики оцениваются по прейскурантной цене и могут отличаться от указанной в счете-фактуре.
- Продвижение предприятий в GA: соответствующие критериям Claude корпоративные организации могут претендовать на сумму не менее 10 000 долларов США в виде кредитов Code Review до 15 января 2027 года; Срок действия кредитов истекает через 30 дней после запроса (условия[в объявлении GA](https://claude.com/resources/articles/code-review-is-now-generally-available))

## Обзор информирует о политике принятия

Опубликованный отзыв является свидетельством квалификации, а не разрешением на слияние. Подтвердите проверенную версию, фактическое выполнение и охватываемый объем, затем примените необходимые проверки репозитория и авторизованный процесс принятия решений. При подведении итогов сохраняйте неразрешенные выводы и разногласия. Рабочий процесс [с несколькими поставщиками](./multi-provider-code-review.md#blocking-merge-the-ci-gate) охватывает эти границы и локальный контроль; он не определяет поведение управляемой службы во время выполнения.

## <a name="known-limitations"></a>Известные ограничения

- Только для команд и предприятий, без доступа к Free/Pro
- Недоступно с нулевым сохранением данных, конфигурацией HIPAA (не подпадающей под действие BAA Anthropic) или ключами шифрования, управляемыми клиентом.
- GitHub только для управляемой службы (GitLab поддерживается посредством интеграции CI/CD, а не этой функции)
- Обзоры не запускаются в локальных средах и не создают и не выполняют ваш код.
- Автоматические обзоры пропускают черновики и PR из форков; запросите их с помощью команды комментария
- Внутренняя статистика Anthropic из предварительной версии: ~7,5 проблем найдено на PR >1000 строк, <1% ложных срабатываний (самооценка, независимая проверка)
