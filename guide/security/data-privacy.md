# Конфиденциальность данных Claude Code: что не освещается в официальных документах

На странице конфиденциальности Anthropic указаны уровни хранения (Потребитель 5 лет, ZDR 0 дней и т. д.). Это полезная информация, но она не охватывает риски, характерные для Claude Code как локального инструмента CLI. В этом руководстве основное внимание уделяется этим: шести векторам воздействия на данные, которые существуют, поскольку Claude Code работает с доступом к файловой системе, порождает подпроцессы и вызывает серверы MCP, а также способы блокировки каждого из них.

> **Краткая справка**: Уровни хранения Anthropic приведены в таблице ниже. Полную официальную политику можно найти по адресу [claude.ai/settings/data-privacy-controls](https://claude.ai/settings/data-privacy-controls).

## <a name="tldr---retention-summary"></a>TL;DR – сводка по хранению

| Конфигурация | Срок хранения | Обучение | Как включить |
|---------------|------------------|----------|---------------|
| **Потребитель (по умолчанию)** | 5 лет | Да | (состояние по умолчанию) |
| **Потребитель (отказ)** | 30 дней | Нет | [claude.ai/settings](https://claude.ai/settings/data-privacy-controls) |
| **Команда / Предприятие / API** | 30 дней | Нет (по умолчанию) | Используйте план Team, Enterprise или ключи API. |
| **ZDR (нулевое сохранение данных)** | 0 дней на стороне сервера | Нет | Соответствующе настроенные клавиши API. |

**Немедленное действие**: [Отключите использование обучающих данных](https://claude.ai/settings/data-privacy-controls), чтобы сократить срок хранения с 5 лет до 30 дней.

## <a name="1-understanding-the-data-flow"></a>1. Понимание потока данных

### <a name="what-leaves-your-machine"></a>Что оставляет ваша машина

Когда вы используете Claude Code, в Anthropic отправляются следующие данные:

```
┌─────────────────────────────────────────────────────────────┐
│                    YOUR LOCAL MACHINE                       │
├─────────────────────────────────────────────────────────────┤
│  • Prompts you type                                         │
│  • Files Claude reads (including .env if not excluded!)     │
│  • MCP server results (SQL queries, API responses)          │
│  • Bash command outputs                                     │
│  • Error messages and stack traces                          │
└───────────┬──────────────────┬──────────────┬───────────────┘
            │                  │              │
            ▼ HTTPS/TLS       ▼ HTTPS        ▼ HTTPS
┌───────────────────┐ ┌──────────────┐ ┌─────────────────────┐
│   ANTHROPIC API   │ │   STATSIG    │ │       SENTRY        │
├───────────────────┤ ├──────────────┤ ├─────────────────────┤
│ • Your prompts    │ │ • Latency,   │ │ • Error logs        │
│ • Model responses │ │   reliability│ │ • No code or        │
│ • Retention per   │ │ • No code or │ │   file paths        │
│   your tier       │ │   file paths │ │                     │
└───────────────────┘ └──────────────┘ └─────────────────────┘
                       (opt-out:        (opt-out:
                       DISABLE_         DISABLE_ERROR_
                       TELEMETRY=1)     REPORTING=1)
```

### Что это означает на практике

| Сценарий | Данные отправлены на Anthropic |
|----------|------------------------|
| Вы просите Claude прочитать `src/app.ts`. | Полное содержимое файла |
| Вы запускаете `git status` через Claude. | Вывод команды |
| MCP выполняет `SELECT * FROM users` | Результаты запроса с пользовательскими данными |
| Claude читает файл `.env` | API ключи, пароли, секреты |
| В вашем коде возникает ошибка | Полная трассировка стека с путями |

## <a name="2-known-risks"></a>2. Известные риски

### Риск 1. Автоматическое чтение файлов.

Claude Code читает файлы, чтобы понять контекст. По умолчанию сюда входят:

- Файлы `.env` и `.env.local` (ключи API, пароли)
- `credentials.json`, `secrets.yaml` (служебные аккаунты)
- Ключи SSH, если они находятся в области рабочей области.
- Строки подключения к базе данных

**Mitigation**: Настройте `excludePatterns` (см. раздел 4).

### <a name="risk-2-mcp-database-access"></a>Риск 2: доступ к базе данных MCP

При настройке серверов базы данных MCP (Neon, Supabase, PlanetScale):

```
Your Query: "Show me recent orders"
            ↓
MCP Executes: SELECT * FROM orders LIMIT 100
            ↓
Results Sent: 100 rows with customer names, emails, addresses
            ↓
Stored at Anthropic: According to your retention tier
```

**Митигация**: Никогда не подключайте рабочие базы данных. Используйте dev/staging с анонимизированными данными.

### Риск 3: вывод команды оболочки

Команды Bash и их вывод включены в контекст:

```bash
# This output goes to Anthropic:
$ env | grep API
OPENAI_API_KEY=sk-abc123...
STRIPE_SECRET_KEY=sk_live_...
```

**Mitigation**: используйте перехватчики для фильтрации конфиденциальных выходных данных команд.

### <a name="risk-4-the-bug-command-sends-everything-retained-5-years"></a>Риск 4: команда `/bug` отправляет все (хранится 5 лет).

Когда ты бежишь `/bug` в Claude Code, твой **полная история разговоров** (включая весь код, содержимое файлов и, возможно, секреты) отправляется на Anthropic для сортировки ошибок. Эти данные сохраняются в течение **5 лет**, независимо от настроек отказа от обучения.

Это не зависит от ваших настроек конфиденциальности: даже при отключенном обучении и 30-дневном хранении отчеты об ошибках подчиняются собственной политике 5-летнего хранения. Это различие имеет значение, поскольку `/bug` легко случайно активировать, а также потому, что срок его хранения длиннее, чем у любых других данных, отправляемых при обычном использовании Claude Code.

Что включается в отчет об ошибке: весь контекст вашего сеанса во время вызова `/bug`. Пути к файлам, содержимое файлов, прочитанное Claude во время сеанса, выходные данные команды bash, результаты сервера MCP и любые секреты, которые появлялись в любом из них. Перед отправкой не выполняется очистка или фильтрация.

**Проверьте, если вы уже отключили его:**

```bash
echo $DISABLE_BUG_COMMAND
```

Если пусто, команда активна. Чтобы отключить навсегда:

```bash
# Add to ~/.zshrc or ~/.bashrc
export DISABLE_BUG_COMMAND=1
```

Если вы работаете на нескольких машинах или делитесь точечными файлами через репозиторий, добавление этого в свой профиль — единственный способ сохранить его в разных средах. Переменные среды, установленные в `.claude/settings.json`, не сохраняются во всех сеансах оболочки.

### Риск 5: Задокументированные инциденты в сообществе

| Инцидент | Источник |
|----------|--------|
| Claude по умолчанию читает `.env` | Проблемы r/ClaudeAI, GitHub |
| Попытки DROP TABLE на плохо настроенном MCP | r/ClaudeAI |
| Учетные данные, предоставляемые через переменные среды | Проблемы с GitHub |
| Оперативное внедрение через вредоносные серверы MCP | r/programming |

### <a name="risk-6-claude-desktop-browser-integration-silent-native-messaging-host-installation"></a>Риск 6: Claude Интеграция браузера настольного компьютера: автоматическая установка собственного узла обмена сообщениями

Claude Desktop устанавливает собственные файлы манифеста хоста обмена сообщениями в каталоги `NativeMessagingHosts` браузера, чтобы включить функцию «Claude в Chrome». С апреля 2026 года это происходит без явного согласия пользователя.

**Что будет установлено:**

```
~/Library/Application Support/Google/Chrome/NativeMessagingHosts/
  com.anthropic.claude_browser_extension.json

/Applications/Claude.app/Contents/MacOS/
  claude_browser_native_host  (helper binary)
```

Claude Desktop записывает эти файлы в **Zвсе браузеры на базе Chromium, обнаруженные в системе** (Chrome, Brave, Edge, Arc, Vivaldi, Opera, Chromium), включая браузеры, не установленные на момент установки Claude Desktop. Отказ «Не спрашивать» в настройках Claude Desktop не предотвращает этого надежно ([GitHub #53864](https://github.com/anthropics/claude-code/issues/53864), апрель 2026 г.).

**Что на самом деле делает (и не делает) встроенный обмен сообщениями:**

Собственный обмен сообщениями — это стандартный механизм Chrome, используемый менеджерами паролей, VPN и многими другими законными приложениями. Собственный хост может получать только сообщения, отправленные расширением Chrome, которое явно предназначено для него. Он не может инициировать соединения с браузером, читать вкладки или получать незапрошенный доступ к данным браузера. Это архитектурно отличается от шпионского ПО.

Настоящая проблема заключается в **отказ от согласия**, а не сам механизм. Приложение, незаметно изменяющее каталоги приложений другого поставщика, нарушает принцип наименьшего неожиданности, независимо от намерений.

**Что проверить, если вы обеспокоены:**

```bash
# List all native messaging hosts installed for Chrome
ls ~/Library/Application\ Support/Google/Chrome/NativeMessagingHosts/

# Check if Anthropic's host is present
cat ~/Library/Application\ Support/Google/Chrome/NativeMessagingHosts/com.anthropic.claude_browser_extension.json

# Check other browsers
ls ~/Library/Application\ Support/BraveSoftware/Brave-Browser/NativeMessagingHosts/
ls ~/Library/Application\ Support/Microsoft\ Edge/NativeMessagingHosts/
```

**Чтобы удалить:**

```bash
# Remove from Chrome (repeat for each browser as needed)
rm ~/Library/Application\ Support/Google/Chrome/NativeMessagingHosts/com.anthropic.claude_browser_extension.json

# Restart Chrome after deletion
```

При удалении Claude Desktop удаляется вспомогательный двоичный файл, но в некоторых каталогах браузера могут остаться устаревшие файлы манифеста. Перезапустите затронутые браузеры после очистки.

**Конфликт с Claude Code:** Когда установлены как Claude Desktop, так и Claude Code CLI, расширение Chrome всегда привязывается к собственному хосту Claude Desktop, что делает инструменты Claude Code `claude-in-chrome` MCP недоступными. ([GitHub #51949](https://github.com/anthropics/claude-code/issues/51949)). Это известная ошибка, для решения которой по состоянию на апрель 2026 г. не существует другого решения, кроме удаления Claude Desktop.

**Mitigation:**

Если вы не используете функцию интеграции браузера, вы можете безопасно удалить файлы манифеста. Anthropic еще не предоставил официальный механизм отказа, который бы надежно предотвращал установку. Следите за обновлениями [GitHub #53864](https://github.com/anthropics/claude-code/issues/53864).

### <a name="risk-7-the-local-looking-network-client"></a>Риск 7: локальный сетевой клиент

A CLI или MCP Сервер может объявлять «нулевые зависимости, отсутствие регистрации, отсутствие телеметрии» и при этом отправлять все вводимые вами данные на сервер, который вы не контролируете. Эти три утверждения касаются *упаковка*, а не о *данные*. Тонкий HTTP клиент действительно не имеет никаких зависимостей, потому что он ничего не содержит.

Телль — это арифметика. Прежде чем что-либо устанавливать, сравните распакованный размер с заявленной функциональностью:

```bash
npm view <package> --json | grep -E '"unpackedSize"|"fileCount"|"dependencies"'
```

Пакет, рекламирующий 148 инструментов анализа размером 17 КБ в 3 файлах, не содержит 148 инструментов. Он передает вызов `fetch`. Реальные локальные реализации токенизаторов, сканеров или встроенных математических вычислений имеют минимальный размер, которого нет у сетевого клиента. Если числа не складываются, прочитайте исходный код, прежде чем запускать его; при таком размере это занимает минуты:

```bash
curl -sL $(npm view <package> dist.tarball) | tar -xzO package/index.js | head -50
```

Честные проекты часто прямо говорят об этом в комментарии к заголовку или README. Проблема в том, что маркетинговый текст и архитектура живут в разных местах, и только один из них попадает в публикацию в LinkedIn.

**Почему режим MCP категорически ухудшает ситуацию:**

В режиме CLI каждый вход выбирает человек. Это проблема дисциплины, и осторожная команда может жить с размещенным инструментом, просто никогда не вставляя в него ничего конфиденциального.

В режиме MCP агент выбирает входные данные, и агент получает вашу кодовую базу в контексте. Он передаст собственный исходный файл размещенному помощнику `count_tokens`, потому что это разумно сделать со счетчиком токенов. Никто не одобрил этот конкретный призыв, потому что никого не спрашивали. Собственная техника безопасности инструмента здесь не помогает: усиление защиты временных файлов и предупреждения о секретных параметрах защищают от утечек argv и локальных атак, а не от агента, самостоятельно решающего, что отправлять.

Это преобразует правило, которое команда может соблюдать («не вставлять данные о клиентах в этот инструмент»), в правило, которое она не может («не позволяйте агенту читать неправильный файл»). Для регулируемых данных, данных несовершеннолетних или источника клиента в соответствии с соглашением о неразглашении это дисквалифицируется независимо от того, насколько хорошо написан клиент.

**Проверка, которая имеет значение:**

Для любого размещенного сервера MCP спросите, существует ли вообще локальный путь выполнения. Если каждый вызов инструмента является сетевым вызовом, то добавление сервера в `.mcp.json` означает предоставление третьей стороне доступа на чтение ко всему, что ваш агент сочтет важным. «Нет регистрации» делает ситуацию скорее хуже, чем лучше: отсутствие учетной записи означает отсутствие соглашения об обработке данных, отсутствие именованного субобработчика и отсутствие политики хранения, на которую вы можете указать во время аудита.

## <a name="3-protective-measures"></a>3. Защитные меры

### Немедленные действия

#### <a name="31-configure-file-exclusions"></a>3.1 Настройка исключений файлов

В `.claude/settings.json` используйте `permissions.deny`, чтобы заблокировать доступ к конфиденциальным файлам:

```json
{
  "permissions": {
    "deny": [
      "Read(./.env*)",
      "Edit(./.env*)",
      "Write(./.env*)",
      "Bash(cat .env*)",
      "Bash(head .env*)",
      "Read(./secrets/**)",
      "Read(./**/credentials*)",
      "Read(./**/*.pem)",
      "Read(./**/*.key)",
      "Read(./**/service-account*.json)"
    ]
  }
}
```

> **Note**: старые настройки `excludePatterns` и `ignorePatterns` устарели в октябре 2025 года. Вместо них используйте `permissions.deny`.

> **Предупреждение**: `permissions.deny` имеет известные ограничения [](./security-hardening.md#known-limitations-of-permissionsdeny). Для обеспечения глубокоэшелонированной защиты используйте средства безопасности и управление внешними секретами.

#### 3.2 Используйте хуки безопасности

Создайте `.claude/hooks/PreToolUse.sh`:

```bash
#!/bin/bash
INPUT=$(cat)
TOOL_NAME=$(echo "$INPUT" | jq -r '.tool.name')

if [[ "$TOOL_NAME" == "Read" ]]; then
    FILE_PATH=$(echo "$INPUT" | jq -r '.tool.input.file_path')

    # Block reading sensitive files
    if [[ "$FILE_PATH" =~ \.env|credentials|secrets|\.pem|\.key ]]; then
        echo "BLOCKED: Attempted to read sensitive file: $FILE_PATH" >&2
        exit 2  # Block the operation
    fi
fi
```

#### <a name="33-opt-out-of-telemetry-and-error-reporting"></a>3.3 Отказ от телеметрии и отчетов об ошибках

Claude Code подключается к сторонним сервисам для получения операционных показателей (Statsig) и регистрации ошибок (Sentry). Они не включают ваш код или пути к файлам, но вы можете полностью их отключить:

| Переменная | Что это отключает |
|----------|-----------------|
| `DISABLE_TELEMETRY=1` | Операционные метрики Statsig (задержка, надежность, шаблоны использования) |
| `DISABLE_ERROR_REPORTING=1` | Журнал ошибок Sentry |
| `DISABLE_BUG_COMMAND=1` | Команда `/bug` (предотвращает отправку полной истории разговоров) |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` | Весь второстепенный сетевой трафик одновременно |
| `CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY=1` | Опросы качества сеанса (примечание: опросы отправляют только ваш числовой рейтинг, а не расшифровку) |

Добавьте их в свой профиль оболочки для постоянного эффекта:

```bash
# In ~/.zshrc or ~/.bashrc
export DISABLE_TELEMETRY=1
export DISABLE_ERROR_REPORTING=1
export DISABLE_BUG_COMMAND=1
```

> **Note**: при использовании поставщиков Bedrock, Vertex или Foundry весь второстепенный трафик (телеметрия, отчеты об ошибках, команды ошибок, опросы) отключен по умолчанию.

### Лучшие практики MCP

| Правило | Обоснование |
|------|-----------|
| **Никогда не подключайте производственные базы данных** | Все результаты запроса отправляются на Anthropic. |
| **Использовать пользователей базы данных только для чтения** | Предотвращает несчастные случаи DROP/DELETE/UPDATE |
| **Анонимизировать данные разработки** | Снижает риск раскрытия личной информации |
| **Создание минимальных наборов тестовых данных** | Меньше данных = меньше риска |
| **Аудит источников сервера MCP** | Сторонние MCP могут иметь уязвимости |

### <a name="reversible-tokenization-at-the-model-boundary"></a>Обратимая токенизация на границе модели

Шлюз конфиденциальности может заменять распознанные значения заполнителями перед запросом модели и восстанавливать их локально, когда инструменту требуется исходное значение. Например, синтетическая цель `10.42.1.5` может стать `IP_PRIVATE_001` в видимом для модели результате инструмента. Локальное сопоставление остается чувствительным, поскольку оно может обратить преобразование вспять.

Покрытие зависит от детектора, входного формата и пути интеграции. Фильтр, который маскирует назначение учетных данных в виде обычного текста, может пропустить одно и то же значение внутри объекта JSON. Обработка ошибок также имеет значение: возврат исходных полезных данных после исключения очистки предоставляет эти полезные данные следующему потребителю. Перехватчик запуска с отказоустойчивым закрытием не устанавливает, что каждый последующий результат инструмента не закрывается с ошибкой.

Исследование [DarkMoon и сравнение Strix](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/guide/security/agentic-pentesting.md) объясняют эти границы. Рассматривайте обратимую токенизацию как снижение риска. Чтобы оценить конкретный запуск, проверьте фактические исходящие запросы модели с синтетическими канареечными значениями, включая выходные данные инструмента, повторные попытки и пути ошибок. Сами по себе журналы токенизации не определяют, что пересекло границу поставщика.

### Для команд

| Среда | Рекомендация |
|-------------|----------------|
| **Разработка** | Отказ + исключения + анонимные данные |
| **Простановка** | Рассмотрите Enterprise API при работе с реальными данными. |
| **Производство** | НИКОГДА не подключайте Claude Code напрямую. |

## 4. Сравнение с другими инструментами

| Особенность | Claude Code + MCP | Курсор | GitHub Copilot |
|---------|-------------------|--------|----------------|
| Объем данных отправлен | Полные результаты SQL, файлы | Фрагменты кода | Фрагменты кода |
| Доступ к производственной базе данных | Да (через MCP) | Ограниченный | Не предназначен для |

**Ключевое отличие**: MCP создает уникальную поверхность атаки, поскольку серверы MCP представляют собой отдельные процессы с независимым доступом network/filesystem.

## <a name="5-enterprise-considerations"></a>5. Факторы предпринимательства

### <a name="when-to-use-enterprise-api-zdr"></a>Когда использовать корпоративный API (ZDR)

- Обработка личных данных (имена, электронные письма, адреса)
- Регулируемые отрасли (HIPAA, GDPR, PCI-DSS)
- Обработка данных клиента
- Государственные контракты
- Финансовые услуги

### Контрольный список оценки

- [ ] В вашей организации существует политика классификации данных.
- [ ] Уровень API соответствует требованиям конфиденциальности данных.
- [ ] Команда обучена управлению конфиденциальностью
- [ ] План реагирования на инциденты, связанные с потенциальным раскрытием данных
- [ ] Обзор Legal/compliance завершен

---

### <a name="test-access-continuity-as-well-as-data-location"></a>Проверьте непрерывность доступа, а также местоположение данных.

Глава [IFTTD о суверенитете](https://bilan.ifttd.io/apprentissage-4/?niveau=2) отличает местоположение хостинга от возможности доступа к данным при необходимости. Относитесь к этому как к операционному вопросу: локально хранимый экспорт может по-прежнему зависеть от удаленного поставщика удостоверений, недоступных ключей, проприетарного формата или внешней службы. Само по себе местонахождение данных не обеспечивает непрерывности или соблюдения законодательства.

Запустите детализации с синтетическими данными и одноразовой средой. Аутентификация инвентаря, доступ к модели, формат экспорта, расшифровка и зависимости инструментов. Имитируйте недоступность выбранного поставщика без изменения производственного доступа. Попытайтесь открыть экспортированные данные и выполнить одну репрезентативную задачу с помощью утвержденного резервного варианта. Запишите, что сработало, что ухудшилось, что потребовало недоступного провайдера и кому принадлежит восстановление.

Альтернативная конечная точка, использующая ту же модель, может диверсифицировать хостинг, не устраняя зависимость модели от поставщика. Прежде чем разрешить по-настоящему конфиденциальные данные, проверьте обработку данных и поведение задач в резервном режиме. Успешная тренировка устанавливает только проверенную задачу и сценарий отключения; не делайте из этого общего суверенитета.

### <a name="quick-audit-checklist"></a>Контрольный список для быстрого аудита

Запустите эти проверки сегодня. Каждый занимает менее двух минут.

**1. Отказ от обучения**
Перейдите к [claude.ai/settings/data-privacy-controls](https://claude.ai/settings/data-privacy-controls) и убедитесь, что параметр «Разрешить обучение модели в ваших разговорах» отключен. Если он включен, ваши данные хранятся 5 лет и используются для обучения.

**2. Команда `/bug` отключена**

```bash
echo $DISABLE_BUG_COMMAND
# Should print: 1
# If empty: add "export DISABLE_BUG_COMMAND=1" to your ~/.zshrc
```

**3. Файлы `.env` заблокированы**
Проверьте свой `.claude/settings.json`: он должен содержать как минимум `"Read(./.env*)"` в `permissions.deny`. Если файл еще не существует, Claude может прочитать ваш `.env` прямо сейчас.

**4. Наличие собственного хоста обмена сообщениями (macOS)**

```bash
ls ~/Library/Application\ Support/Google/Chrome/NativeMessagingHosts/ 2>/dev/null | grep anthropic
# Nothing should appear if you don't use Claude Desktop
```

**5. Инвентаризация сервера MCP**
Откройте `~/.claude/claude.json` (или `.mcp.json` в корне вашего проекта) и перечислите все настроенные серверы MCP. Для каждого сервера базы данных убедитесь, что он указывает на строку подключения для разработки или промежуточного подключения, а не на рабочую среду.

**6. Окружение телеметрии vars**

```bash
echo $DISABLE_TELEMETRY
echo $DISABLE_ERROR_REPORTING
# Both should print: 1
```

**7. Воздействие команды оболочки**
Запустите `env | grep -iE 'key|secret|token|pass'`, чтобы увидеть, какие переменные среды установлены в данный момент. Все, что здесь появляется, будет видно Claude, если он выполнит команду bash в этом сеансе оболочки.
