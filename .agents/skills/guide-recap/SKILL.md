# Обзор руководства

Создавайте контент для социальных сетей на основе записей CHANGELOG.md. По умолчанию выдает 8 выходных данных (4 формата x 2 языка).

## <a name="when-to-use"></a>Когда использовать

- После запуска `/release` для создания социальных объявлений
- Еженедельно для подведения итогов нескольких выпусков
- Прежде чем публиковать сообщения в LinkedIn, Twitter/X, новостной рассылке или Slack

## Использование

```
/guide-recap latest              # Latest released version
/guide-recap v3.20.5             # Specific version
/guide-recap week                # Current week (Monday to today)
/guide-recap week 2026-01-27     # Specific week (Monday to Sunday)
```

### Флаги

| Флаг | Эффект | По умолчанию |
|------|--------|---------|
| `--interactive` | Режим руководства: выберите ракурс, аудиторию, выделение | Выкл. (автоматический черновик) |
| `--format=X` | Единый формат: `linkedin`, `twitter`, `newsletter`, `slack`. | Все 4 формата |
| `--lang=X` | Один язык: `fr`, `en`. | Оба FR + EN |
| `--save` | Сохранить вывод в `claudedocs/social-posts/` | Только отображение |
| `--force` | Генерировать даже если только записи обслуживания | Пропустить низкий балл |

## Рабочий процесс (7 шагов)

### Шаг 1. Анализ входных данных

Разберите `$ARGUMENTS`, чтобы определить режим:

| Вход | Режим | Цель |
|-------|------|--------|
| `latest` | Одиночная версия | Первый `## [X.Y.Z]` после `[Unreleased]` |
| `vX.Y.Z` или `X.Y.Z` | Одиночная версия | Точное совпадение версий |
| `week` | Недельный диапазон | Понедельник текущей недели -> сегодня |
| `week YYYY-MM-DD` | Недельный диапазон | В тот понедельник -> в следующее воскресенье |

Если аргумент отсутствует или недействителен, отобразите использование и выйдите.

### Шаг 2. Извлечение записей CHANGELOG

Прочтите `CHANGELOG.md` из корня проекта.

**Одна версия:**
1. Найдите строку, соответствующую `## [{version}]`
2. Извлеките весь контент до следующей строки `## [`.
3. Разбор разделов `### Added`, `### Changed`, `### Fixed`

**Недельный диапазон:**
1. Соберите все записи `## [X.Y.Z] - YYYY-MM-DD`, дата которых попадает в диапазон.
2. Разобрать все разделы из всех совпадающих версий

**Ошибка: версия не найдена** -> Список последних 5 версий, предложите `latest`.
**Ошибка: на неделе нет записей.** -> Показать дату последнего выпуска, предложить эту версию.

### Шаг 3. Категоризация записей

Для каждой записи верхнего уровня (маркер первого уровня под `###`) назначьте категорию:

| Категория | Масса | Обнаружение |
|----------|--------|-----------|
| `NEW_CONTENT` | 3 | Новые файлы, новые разделы, новые диаграммы, новые вопросы викторины. |
| `GROWTH_METRIC` | 2 | Рост количества строк, изменение количества позиций |
| `RESEARCH` | 1 | Оценка ресурсов, интеграция внешних источников |
| `FIX` | 1 | Под `### Fixed` исправления |
| `MAINTENANCE` | 0 | Обновления README, синхронизация значков, синхронизация лендинга, обновления счетчика |

Подробные правила классификации см. в `references/changelog-parsing-rules.md`.

### Шаг 4. Преобразование в пользовательскую ценность

Примените сопоставления из `references/content-transformation.md`:

- Технический язык -> польза для пользователя
- Извлечение конкретных цифр
- Кредитные названные источники
- Записи, связанные с кластером

Проверьте соответствие контрольному списку `references/tone-guidelines.md` DO/DON'T.

### Шаг 4b: Интерактивный режим (только --interactive)

Если установлен флаг `--interactive`, вставьте между шагами 4 и 5:

1. Отображение основных моментов кандидата с оценками:
   ```
   Highlights (by score):
   [14] 4 new ASCII diagrams (16 -> 20)     [NEW_CONTENT]
   [ 9] 30 new quiz questions (227 -> 257)   [NEW_CONTENT]
   [ 6] Docker sandbox isolation guide        [NEW_CONTENT]
   [ 1] README updated                        [MAINTENANCE]
   ```

2. Угол запроса:
   - Авто (наивысшая оценка = хук)
   - Пользователь выбирает конкретную запись в качестве хука
   - Пользовательский угол (пользователь предоставляет тему)

3. Спросите целевую аудиторию:
   - `devs` (техническая глубина)
   - `tech-leads` (фокус удара)
   - `general` (доступный язык)
   - `all` (по умолчанию, сбалансированный)

4. Спросите основной момент:
   - Авто (высший балл)
   - Пользователь выбирает из списка

5. Подтвердите выбор и перейдите к шагу 5.

### Шаг 5: Оцените и выберите

Подсчитайте балл для каждой записи:

```
score = (category_weight * 3)
      + (has_number * 2)
      + (named_source * 1)
      + (new_file * 1)
      + (min(impact_files, 3))
      + (breaking * 2)
```

Выберите 3-4 записи с наибольшим количеством очков. Наивысший балл = хук.

**Если все оценки < 3**: Вывод: «Для этой версии не рекомендуется использовать социальный контент. В любом случае используйте `--force` для создания». и выйти (если только `--force`).

### Шаг 6: Создайте контент

Для каждого запрошенного формата (по умолчанию: все 4) и языка (по умолчанию: оба):

1. Прочтите соответствующий шаблон от `assets/`.
2. Заполните поля шаблона, используя оцененные и преобразованные записи.
3. Примените контрольный список качества tone-guidelines.md

**Links:**

| Формат | Цель ссылки |
|--------|-------------|
| LinkedIn | URL целевого сайта |
| Твиттер | URL-адрес репозитория GitHub |
| Информационный бюллетень | Оба (посадка + GitHub) |
| Слабый | URL-адрес репозитория GitHub |

**URLs:**
- Посадка: `https://florianbruniaux.github.io/Codex-ultimate-guide-landing/`
- GitHub: `https://github.com/FlorianBruniaux/Codex-ultimate-guide`

### Шаг 7: Вывод

Отобразите каждое сгенерированное сообщение в изолированном блоке кода, помеченном по формату и языку:

```
## LinkedIn (FR)

```text
[content]
`` `

## LinkedIn (EN)

```text
[content]
`` `

## Twitter/X (FR)

```text
[content]
`` `

...
```

Если флаг `--save`: запишите все выходные данные в `claudedocs/social-posts/YYYY-MM-DD-vX.Y.Z.md` (для версии) или `claudedocs/social-posts/YYYY-MM-DD-week.md` (для недели). Создайте каталог `claudedocs/social-posts/`, если он не существует.

## Обработка ошибок

| Ошибка | Ответ |
|-------|----------|
| Нет аргументов | Блок использования дисплея |
| Неверный аргумент | Отобразить блок использования с примерами |
| Версия не найдена | Перечислите 5 последних версий, предложите `latest` |
| Неделя не имеет записей | Показать дату последнего выпуска, предложить версию |
| Все записи ТЕХНИЧЕСКОЕ ОБСЛУЖИВАНИЕ (оценка 0) | «Не рекомендуется использовать социальный контент. Используйте `--force` для переопределения». |
| CHANGELOG.md не найден | «CHANGELOG.md не найден в корне проекта». |

## Справочные файлы

- `references/tone-guidelines.md` - правила DO/DON'T, бюджет смайлов, языковой регистр
- `references/changelog-parsing-rules.md` — формат CHANGELOG, извлечение, алгоритм оценки
- `references/content-transformation.md` — Технический -> сопоставления пользовательских значений (30+)
- `assets/linkedin-template.md` — ~1300 символов, хук + маркеры + призыв к действию + хэштеги.
- `assets/twitter-template.md` — 280 символов в одной цепочке или ветке из 2–3 твитов.
- `assets/newsletter-template.md` - ~500 слов, структурированные разделы
- `assets/slack-template.md` — компактный, богатый смайлами формат Slack.
- `examples/version-output.md` — Полный пример вывода для версии 3.20.5
- `examples/week-output.md` — полный пример вывода за неделю 27 января 2026 г.

## <a name="tips"></a>Советы

- Запустите `/guide-recap latest` сразу после `/release`, чтобы подготовить публикации в социальных сетях.
- Используйте `--interactive` первые несколько раз, чтобы понять подсчет очков.
- Используйте `--format=linkedin --lang=fr`, когда вам нужен только один конкретный вывод.
- Выходы `--save` игнорируются в соответствии с соглашением `claudedocs/`.
- Просмотрите и персонализируйте перед публикацией (это черновики, а не окончательная версия)
