# ИЗМЕНЕНИЯ Правила разбора

Как извлечь и классифицировать записи из `CHANGELOG.md` для создания социального контента.

## Формат журнала изменений

Проект следует за [. Сохраняйте журнал изменений](https://keepachangelog.com/en/1.0.0/).

```
## [Unreleased]

## [X.Y.Z] - YYYY-MM-DD

### Added
- **Title**: Description
  - Sub-detail 1
  - Sub-detail 2

### Changed
- **Title**: Description

### Fixed
- **Title**: Description

---
(horizontal rule separates grouped entries within same version)
```

## Методы извлечения

### По версии (`/guide-recap v3.20.5`)

1. Читать CHANGELOG.md
2. Найдите строку, соответствующую `## [3.20.5]`
3. Извлеките все до следующей строки `## [`.
4. Разобрать все разделы `### Added/Changed/Fixed`

### Последний (`/guide-recap latest`)

1. Читать CHANGELOG.md
2. Пропустить `## [Unreleased]`
3. Извлеките первый блок `## [X.Y.Z]` (= последняя выпущенная версия)

### По неделям (`/guide-recap week` или `/guide-recap week 2026-01-27`)

1. Определите диапазон дат:
   - `week` без даты: понедельник текущей недели -> сегодня.
   - `week YYYY-MM-DD`: В тот понедельник -> в следующее воскресенье.
2. Читать CHANGELOG.md
3. Соберите все записи `## [X.Y.Z] - YYYY-MM-DD`, дата которых попадает в диапазон.
4. Объединить все записи по версиям

## Структура входа

Каждая пуля верхнего уровня под `### Added/Changed/Fixed` — это одна **entry**. Разобрать:

| Поле | Источник | Пример |
|-------|--------|---------|
| `title` | Жирный текст после `- **` | `Visual Reference` |
| `description` | Текст после `:` или `--` в той же строке. | `4 new high-value ASCII diagrams (16 -> 20 total)` |
| `sub_items` | Маркеры с отступом ниже | Список линий детализации |
| `section` | Родительский заголовок `###` | `Added`, `Changed`, `Fixed` |
| `files` | Filenames/paths в описании | `guide/ultimate-guide.md`, `machine-readable/reference.yaml` |
| `source` | URL-адреса или именованные ссылки | `Pat Cullen's Final Review Gist` |
| `metrics` | Цифры в описании | `227 -> 257`, `+522 lines`, `4 new` |
| `score` | Оценочная оценка, если присутствует | `Score: 4/5` |

## Классификация категорий

Каждая запись получает ровно одну категорию с весом:

| Категория | Масса | Шаблон |
|----------|--------|---------|
| `NEW_CONTENT` | 3 | Новые разделы руководства, новые файлы, новые диаграммы, новые вопросы викторины. |
| `GROWTH_METRIC` | 2 | Увеличение количества строк, количество шаблонов, изменение количества викторин |
| `RESEARCH` | 1 | Оценка ресурсов, интеграция внешних источников |
| `FIX` | 1 | Исправления ошибок, исправления, повышение точности |
| `MAINTENANCE` | 0 | Обновления README, обновления значков, синхронизация счетчиков, синхронизация посадок |

### Правила классификации

1. Если запись создает новый файл `.md` или новый раздел -> `NEW_CONTENT`
2. Если запись содержит `-> ` с цифрами (ростом) -> `GROWTH_METRIC`
3. Если запись ссылается на внешний источник с оценочной оценкой -> `RESEARCH`
4. Если запись находится под `### Fixed` -> `FIX`
5. Если запись обновляет только счетчики, значки или синхронизацию -> `MAINTENANCE`
6. Если запись имеет подпункты с существенным содержанием -> повысьте уровень на один уровень.
7. В случае двусмысленности отдавайте предпочтение более высокой весовой категории.

### Примеры

```
"4 new ASCII diagrams (16 -> 20)"           -> NEW_CONTENT (new diagrams)
"30 New Quiz Questions (227 -> 257)"        -> NEW_CONTENT (new questions)
"Quiz badge updated (227 -> 257)"           -> MAINTENANCE (badge sync)
"Guide line count: 15,771 -> 16,293"        -> GROWTH_METRIC (growth)
"Score: 4/5 - Docker Sandboxes"             -> RESEARCH (evaluation)
"Fixed 14 -> 15 categories in landing"      -> FIX (correction)
"README.md: Added Visual Reference to table" -> MAINTENANCE (nav update)
```

## Алгоритм подсчета очков

Для каждой записи вычислите:

```
score = (category_weight * 3)
      + (has_number * 2)
      + (named_source * 1)
      + (new_file * 1)
      + (min(impact_files, 3))
      + (breaking * 2)
```

| Фактор | Ценить | Обнаружение |
|--------|-------|-----------|
| `category_weight` | 0-3 | Из таблицы категорий выше |
| `has_number` | 0 или 1 | Запись содержит числовое изменение (`N -> M`, `+N lines`, `N new`) |
| `named_source` | 0 или 1 | Запись указывает на человека или внешний источник. |
| `new_file` | 0 или 1 | В записи упоминается создание нового файла (`NEW`, новый `.md`). |
| `impact_files` | 0-3 | Количество упомянутых отдельных файлов (не более 3) |
| `breaking` | 0 или 1 | Запись под номером `### Breaking` или упоминает критическое изменение. |

### Интерпретация очков

| Счет | Действие |
|-------|--------|
| 10+ | Подсветка свинца (линия хука) |
| 6-9 | Второстепенный момент (пункт списка) |
| 3-5 | Включите, если позволяет место |
| 0-2 | Пропустить (шум технического обслуживания) |

Выберите 3-4 записи с наибольшим количеством очков. Если все оценки < 3, отметьте «Контент из социальных сетей не рекомендуется».

## Правила суммирования недель

При генерации на неделю с несколькими версиями:

1. Оценка всех записей во всех версиях в диапазоне дат.
2. Удаление дубликатов: если одна и та же тема появляется в нескольких версиях, сохраните ту, которая получила наивысший балл.
3. Вывод префиксной недели с количеством версий: `X releases this week`
4. Используйте диапазон дат в заголовке, а не отдельные номера версий.
