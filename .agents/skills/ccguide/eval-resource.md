# Оценочный ресурс

Значение ресурса (URL-адрес или копия текста) для определения актуальности для кабеля guide/projet.

## Обнаружение входа

Навык принимает два типа ввода через `$ARGUMENTS`:

1. **URL** : Начало по `http://` или `https://`.
2. **Texte copyé** : Весь дополнительный контент (уценка, текстовое сообщение, примечания)

## Инструкции

### Этап 0: определение типа ввода

```
SI $ARGUMENTS commence par "http://" ou "https://" :
  → input_type = "url"
  → source_url = $ARGUMENTS
SINON :
  → input_type = "text"
  → content = $ARGUMENTS
  → source_url = null
```

### Этап 1: выборка и суммирование

**Si URL:**
Утилизатор `WebFetch` по URL-адресу:
- Дополнительный основной контент
- Идентификатор очков (максимум 3–5)
- Обратите внимание на тип содержания (учебник, ссылка, блог, стенограмма видео и т. д.)

**Копия текста:**
Направление анализатора содержимого:
- Идентификатор очков (максимум 3–5)
- Noter le type de contenu (примечания для персонала, резюме, документация и т. д.)
- Идентификатор цитируемых источников в тексте (для дополнительной проверки фактов)

### Этап 2: Проверка контекста

**Определите кабель guide/projet:**

1. Если в проекте есть `machine-readable/reference.yaml` → пользователь, указанный в документации
2. Если в проекте есть `CLAUDE.md` → анализатор структуры документа
3. Если вы находитесь в контексте → потребитель к пользователю:
   ```
   Quel guide/projet cible pour cette évaluation?
   1. Claude Code Ultimate Guide (si disponible)
   2. Documentation du projet actuel
   3. Autre (préciser)
   ```

**Анализатор контекста:**
- Актуальная структура guide/projet
- Существующие разделы
- потенциальные пробелы

### Этап 3: Анализ пробелов

Используйте `grepai_search` с дополнительными концепциями:
- Трувер, если это документальное дежавю
- Идентификатор похожих разделов
- Repérer les manques

### Этап 4: Вывод

Создайте структуру взаимопонимания ci-dessous.

### Этап 5: Вызов (Автокритика)

Используйте инструмент `Task` с `subagent_type: technical-writer` для:
- Претендент на решение об актуальности
- Идентификатор, который может быть найден
- Предлагающий меры по улучшению плана интеграции

Подскажите для агента:
```
Critique cette évaluation de ressource pour le Claude Code Ultimate Guide:

[Coller le rapport généré à l'étape 4]

Challenge:
1. Le score est-il justifié ? Arguments pour un score +1 ou -1 ?
2. Y a-t-il des aspects de la ressource non mentionnés ?
3. Les recommandations d'intégration sont-elles les meilleures ?
4. Quels risques si on n'intègre PAS cette ressource ?

Sois brutal et direct.
```

### Этап 6: Проверка фактов (проверка)

**OBLIGATOIRE перед финализатором.**

**Si URL:**
1. **Отправьте исходный код**: WebFetch по новому URL-адресу для подтверждения подтверждения
2. **Проверка stats/citations**:
   - Упоминание Chaque chiffre (%, x fois и т. д.) → проверка того, что есть в статье
   - Атрибуция Чака (авторская, антреприза, этюд) → проверка точности
   - Дата Chaque → верификатор (внимание: дата в 2026 г., в 2024 г.!)

**Копия текста:**
1. **Идентификатор проверяемых претензий**: статистика, контрольные показатели, атрибуция, даты
2. **Utiliser Perplexity** (`mcp__perplexity__perplexity_search`) для проверки большей претензии
3. **Перейдите к исходным кодам**: Не пропустите один исходный код

**Во всех случаях:**
3. **Если вам нужен второй источник**: Требование к пользователю:
   ```
   ⚠️ Stats non vérifiables:
   - "[stat X]" - source citée: [Y]

   Voulez-vous une recherche Perplexity approfondie?
   ```
4. **Исправление взаимопонимания** с проверенной информацией

**Контрольный список для проверки фактов:**
- [ ] Автор/роль верна?
- [ ] Дату публикации исправить?
- [ ] Статистика приведена в статье?
- [ ] Идентифицированные второстепенные источники?
- [ ] Aucune галлюцинация де шифр?
