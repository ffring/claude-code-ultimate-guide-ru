# Сервер MCP — идеи будущего

Отслежены идеи, которые не попали в текущий выпуск. Сложность реализации варьируется; все они технически осуществимы с учетом существующих данных.

---

## Инструменты

### `get_quiz(topic?, count?)`

Интерактивная викторина от `machine-readable/questions.json` (274 вопроса, уже используются лендингом).

- `topic` (необязательная строка): фильтрация по теме (например, «хуки», «агенты», «mcp»).
- `count` (необязательное число, по умолчанию 5, максимум 20): количество возвращаемых вопросов.
- Возвращает вопросы с вариантами, правильным ответом и объяснением.
- Полезно для изучения рабочих процессов проверки, адаптации и обучения.

**Data**: `machine-readable/questions.json` — на данный момент не входит в комплект поставки; потребуется объединение или выборка GitHub.

---

### `get_methodology(name)`

Пошаговые рабочие процессы для TDD, SDD, BDD из `guide/core/methodologies.md`.

- `name` (строка): `tdd | sdd | bdd | all`
- Возвращает шаги рабочего процесса, время его использования и примеры команд.
- Полезно для агентов, занимающихся разработкой через тестирование или проектированием на основе спецификаций.

**Data**: `guide/core/methodologies.md` — извлекается по требованию (уже в инфраструктуре чтения разделов).

---

### `get_workflow(name)`

Пошаговые рабочие процессы из каталога `guide/workflows/`.

- `name` (строка): частичное совпадение имени (например, «проверка кода», «рефакторинг», «отладка»).
- Возвращает рабочий процесс с шагами, триггерами и примерами подсказок.
- Может перечислять доступные рабочие процессы, если имя не указано.

**Data**: `guide/workflows/*.md` — извлекается по требованию.

## <a name="resources"></a>Ресурсы

### `claude-code-guide://diff`

Показывает, что изменилось между включенной индексной версией YAML и активной версией GitHub.

- Загрузите живой `machine-readable/reference.yaml` с GitHub
- Отличия от встроенной версии (количество записей, новые ключи, измененные значения)
- Помогает пользователям узнать, когда пакет устарел по сравнению с руководством.

**Complexity**: Средний — требуется асинхронный обработчик ресурсов + структурированное сравнение.

## Промпты

### `security-review`

Специальная подсказка рабочего процесса аудита безопасности с использованием базы данных угроз.

- Проводит модель через: проверка CVE → проверка авторов → проверка навыков → проверка методов.
- Возвращает структурированный отчет о состоянии безопасности.
- Повторно использует инструменты `list_threats` и `get_threat` внутри компании.

**Dependency**: требуются инструменты `threats.ts` (уже реализованы в версии 1.1.0).

## Примечания

- Все идеи используют данные, уже находящиеся в репозитории — новые источники данных не нужны.
- `get_quiz` требует наличия `questions.json` (в настоящее время нет в пакете npm)
- `get_methodology` и `get_workflow` не требуют больших усилий, поскольку программа чтения разделов уже обрабатывает произвольную выборку файлов.
