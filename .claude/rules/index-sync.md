# Индексная синхронизация

Когда `guide/` получает страницу, раздел, именованную концепцию или именованный инструмент, машиночитаемый индекс должен узнать об этом за тот же проход. Индекс передается на сервер MCP и палитру Cmd+K целевого сайта, поэтому контент, который никто не индексирует, — это контент, который никто не может найти.

## Что обновить

| Файл | Когда | Как |
|------|------|-----|
| `machine-readable/reference.yaml` | Всегда | Ключ `deep_dive`, указывающий на `path#anchor`. Предпочитайте якоря `path:LINE`, которые смещаются каждый раз, когда строки вставляются выше. |
| `mcp-server/content/reference.yaml` | Всегда | Ручное копирование. Сценария повторной синхронизации не существует, и раньше он был изменен. |
| `llms-full.txt` | Только структура уровня руководства | Новая область верхнего уровня, а не каждый раздел. |
| `llms.txt`, `machine-readable/llms.txt` | Изменения в списке покрытия | Сохраняйте два байта идентичными. |

## Проверить

```bash
python3 scripts/check-index-coverage.py --check   # every guide file reachable
python3 scripts/validate-reference-yaml.py --ci   # anchors resolve, paths exist
```

Оба работают в CI (`.github/workflows/index-integrity.yml`). Ворота покрытия равны нулю, поэтому сборка нового неиндексированного файла невозможна.

Ключ `deep_dive`, который добавляется, переименовывается или удаляется, также нуждается в `pnpm build:search` в целевом репозитории, иначе палитра поиска продолжит обслуживать старую запись.

## Правоприменение

Хук `Stop` `.claude/hooks/index-sync-reminder.sh` сообщает в конце хода, когда `guide/` изменился, а индексный файл не изменился. Он предупреждает, но никогда не блокирует: ход может законно завершиться в середине редактирования, а хук, который накладывает вето, отключается.
