# Аудит покрытия викторины: предложите новые вопросы на основе недавних изменений

Цель: прочитать, что недавно изменилось в руководстве и в самом Claude Code, сделать перекрестные ссылки на живую викторину и предложить новые вопросы по всему, что еще не освещено. Это рабочий процесс **, предназначенный только для предложений**: никогда не добавляйте автоматически вопросы в викторину без проверки человеком.

## Источники для чтения

1. `CHANGELOG.md` в этом репозитории — раздел `[Unreleased]` плюс последние 5–10 выпущенных записей, чтобы увидеть, какой контент руководства изменился или был добавлен недавно.
2. `machine-readable/reference.yaml` — индекс topic/section руководства (ключи `deep_dive`), чтобы узнать, что и где документировано.
3. `machine-readable/claude-code-releases.yaml` — собственная история версий Claude Code (`latest`, `releases[]`, `breaking_summary`, `milestones`). Сосредоточьтесь на самых последних 10-15 версиях.
4. `guide/core/claude-code-releases.md` — удобочитаемая версия, полезная для полного контекста конкретной версии.

Схема файла вопроса (вступление + тело):
```yaml
---
id: NN-NNN            # category-two-digit, question three-digit
category_id: N         # 1-16
difficulty: junior|intermediate|senior|power
profiles: [junior, senior, power, pm]   # subset
correct: a|b|c|d
options:
  a: "..."
  b: "..."
  c: "..."
  d: "..."
doc_reference:
  file: guide/....md   # must exist under the guide repo root
  section: "..."
  anchor: '#...'       # optional
official_doc: https://...   # optional
---

Question text here

---

Explanation text here
```

**YAML gotcha**: любая опция или значение поля, содержащее двоеточие (`: `), ДОЛЖНО быть заключено в двойные кавычки, иначе не удастся проанализировать вступительную часть (это дважды нарушило сборку во время последнего аудита викторины, см. `claudedocs/quiz-audit-2026-07-08/` об инциденте).

## Что делать

Если `$ARGUMENTS` называет идентификатор категории или пул, охватить анализ пробелов только этой категорией. Если `$ARGUMENTS` пуст или `all`, охватить каждую категорию.

Для каждой категории в объеме:

1. Прочтите текст `question` каждого существующего вопроса и `doc_reference` в каталоге этой категории (только идентификатор + вопрос, пропустите объяснения, чтобы сэкономить), чтобы узнать, что уже рассмотрено.
2. Перекрестная ссылка на:
   - Любая запись `[Unreleased]` или недавняя запись `CHANGELOG.md`, описывающая дополнение к руководству, имеющее отношение к теме этой категории.
   - Любая запись `claude-code-releases.yaml` (последние версии), описывающая новую функцию Claude Code, флаг, изменение по умолчанию или поведение, относящееся к этой категории, по которой не существует вопросов.
   - Любой ключ `reference.yaml` `deep_dive` для этой темы, в связанном разделе руководства которого нет соответствующего вопроса.
3. Составьте по 2–5 НОВЫХ вопросов для каждой категории, которые заполняют реальный пробел (а не перефразирование существующего вопроса). Каждый должен:
   - Будьте нетривиальны (тесты understanding/application, а не пустяки).
   - Имейте ровно 4 правдоподобных варианта с одним проверяемым правильным ответом (перед завершением проверьте цитируемый раздел руководства).
   - Процитируйте настоящий `doc_reference` (файл, который действительно существует в репозитории руководства, раздел, который фактически поддерживает ответ).
   - Отдавайте приоритет недавним (последние 2-3 выпуска) изменениям Claude Code и недавно добавленным разделам руководства над старым, уже стабильным контентом.
4. Однострочное обоснование каждого вопроса: какой пробел он заполняет и почему именно сейчас (например, «v2.1.202 добавил X, ни один вопрос пока не закрывает это»).

## Выход

Напишите предложения в `claudedocs/quiz-coverage-audit-{today's date}/proposals-new-questions.md`, сгруппированные по категориям, в формате готовых к вставке блоков вопросов + вопросов + объяснений, соответствующих приведенной выше схеме, каждый со своим обоснованием. Не трогайте файлы под `claude-code-ultimate-guide-landing/`. Ничего не совершайте и не нажимайте.

В конце напечатайте краткое описание: просмотренные категории, найденные пробелы, вопросы, предложенные по каждой категории, а также любую категорию, в которой CHANGELOG/releases упоминает что-то важное, но вы не были достаточно уверены, чтобы составить вопрос (назовите тему, а не угадывайте).
