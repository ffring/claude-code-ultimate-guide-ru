# Серия технических документов Claude Code

Русские версии доступны в [каталоге технических статей](ru/), [каталоге карточек](recap-cards/ru/) и [шпаргалке в PDF](ru/cheatsheet.pdf).

## Создание EPUB

Технические документы изначально поддерживают формат EPUB3 через Quarto. Никаких дополнительных зависимостей: `format: epub` уже настроен во фронтальной части каждого `.qmd`.

### Создать отдельный EPUB

```bash
cd whitepapers/fr
quarto render 00-introduction-serie.qmd --to epub
# → produit 00-introduction-serie.epub dans le répertoire courant
```

### Создать все файлы EPUB (пакетный скрипт)

```bash
cd whitepapers
./render-epub.sh all      # FR + EN
./render-epub.sh fr       # Français seulement
./render-epub.sh en       # English only
```

EPUB генерируются в `whitepapers/epub-output/{fr,en}/`.

### стиль EPUB

Файл `whitepapers/epub-styles.css` применяет палитру Bold Guy ко всем файлам EPUB:
- Палитра: `#1a1207` (основной), `#d4520a` (ярко-оранжевый акцент), `#f5f0eb` (бежевый фон)
- Выноски Quarto (`callout-note`, `callout-tip`, `callout-warning`, `callout-important`) в собственном стиле.
- Блоки кода с акцентом на левой границе
- Столы Зебра
- Изображение на обложке: `_extensions/whitepaper/assets/claude-code-ai-logo.jpg`

## Создать новый технический документ

### 1. Создайте исходный файл

```bash
touch whitepapers/01-methodologies.qmd
```

### 2. Добавьте заставку YAML.

```yaml
---
title: "Titre du Whitepaper"
subtitle: "Sous-titre explicatif"
author: "Votre Nom"
date: 2026-01-15
date-format: "MMMM YYYY"
version: "1.0"
series: "Claude Code Ultimate Guide"
format:
  whitepaper-typst:
    toc: true
    toc-depth: 2
    section-numbering: "1.1"
  html:
    toc: true
    theme: cosmo
lang: fr
---

# Premier Chapitre

Contenu ici...
```

### 3. Создайте PDF-файл

```bash
quarto render 01-methodologies.qmd
```

## Распространенные проблемы и решения

### 🔴 Неработающие вложенные блоки кода.

**Symptom**: Диаграммы ASCII выходят из блока кода, содержимое отображается как обычный текст.

**Cause**: Блок кода ````markdown` содержит вложенный блок кода (например: ` ```bash`). Quarto interprète le ` ``` `, внутренний, а также закрывающий внешний блок.

**Решение**: Используйте 4 обратных кавычки для внешнего блока:

````markdown
## Exemple correct

````markdown
# Contenu markdown

```bash
echo "Ce code bash est DANS le markdown"
```

Fin du contenu.
````
````

**Détection automatique** :

```bash
# Trouver les code blocks imbriqués problématiques
awk '
/^```markdown$/ { in_md=1; start=NR }
in_md && /```[a-z]/ { print FILENAME":"NR": nested code at line "start }
/^```$/ && in_md { in_md=0 }
' *.qmd
```

### 🔴 Diagrammes ASCII mal rendus

**Symptôme** : Les caractères `├`, `└`, `│`, `─` s'affichent mal ou sont coupés.

**Causes possibles** :

1. **Code block cassé** (voir ci-dessus)
2. **Largeur excessive** - Le diagramme dépasse la largeur de page

**Solution largeur** : Réduire la largeur du diagramme ou utiliser des caractères ASCII simples :

```
# Au lieu de (Unicode)
├── fichier.txt
└── autre/

# Utiliser (ASCII simple)
+-- fichier.txt
`-- autre/
```

### 🟡 Tableaux rendus comme code

**Symptôme** : Un tableau Markdown s'affiche avec fond gris comme un code block.

**Cause** : Décalage des code blocks - un ` ``` ` superflu quelque part avant.

**Diagnostic** :

```bash
# Lister tous les délimiteurs de code
grep -n '^```' fichier.qmd

# Vérifier qu'ils sont par paires (nombre pair)
grep -c '^```' fichier.qmd
```

### 🟡 Page de couverture - logo non trouvé

**Erreur** : `cannot read file outside of project root`

**Solution** : Le logo doit être dans le répertoire du projet Typst :

```bash
# Copier le logo dans l'extension
cp ../assets/logo.jpg _extensions/whitepaper/assets/

# Dans le template, utiliser le chemin relatif au .qmd
image("_extensions/whitepaper/assets/logo.jpg", width: 3.5cm)
```

### 🟢 Régénérer tous les PDFs

```bash
cd whitepapers
for f in *.qmd; do
  echo "Rendering $f..."
  quarto render "$f" 2>&1 | grep -E "(Output created|error)"
done
```

### 🟢 Vérifier la cohérence des code blocks

```bash
# Script de validation complet
for f in *.qmd; do
  opens=$(grep -c '^```' "$f")
  if [ $((opens % 2)) -ne 0 ]; then
    echo "⚠️  $f: nombre impair de \`\`\` ($opens)"
  fi
done
```
