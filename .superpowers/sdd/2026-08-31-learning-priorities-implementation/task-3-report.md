# Отчет по задаче 3: исполняемый прототип схемы обучения

## Доставленный

Серия реализации на `codex/priority-learning`:

1. `23be055`: первоначальный прототип пути обучения без зависимостей.
2. `a491b3c`: исправление независимой проверки для проверки состояния, сбоя атомарного сохранения, стороннего вызова, сопоставления дорожек и границы валидатора.
3. `8e251e5`: эксклюзивный параллельный `init`, пересмотренное отображение самооценки и точная граница `quick_validate.py`.

Принадлежащие файлы зафиксированы:

- `examples/skills/learning-path/SKILL.md`
- `examples/skills/learning-path/README.md`
- `examples/skills/learning-path/assets/path.yaml`
- `examples/skills/learning-path/scripts/progress.py`
- `examples/skills/learning-path/tests/test_progress.py`

Навык предоставляет четыре направления: «Новичок», «Практик», «Производство» и «Сопровождающий». Определения семи модулей указывают на существующие страницы руководства по траектории обучения и заголовки их упражнений. `path.yaml` использует синтаксис JSON, допустимое подмножество YAML, поэтому стандартная библиотека Python может анализировать его без PyYAML.

Состояние сохраняется в целевом проекте по адресу `.claude/learning/claude-code-guide-progress.json`. Механизм создает профиль, не перезаписывая существующий файл состояния, атомарно сохраняет JSON через временный файл в том же каталоге и `os.replace`, отклоняет поврежденный JSON или недопустимую форму состояния, обеспечивает выполнение предварительных условий и требует непустое свидетельство для завершения.

Даты пересмотра — это ровно J+1, J+3, J+7, J+14, J+30, J+60 и J+90. CLI предоставляет команды `init`, `status`, `next`, `complete` и `due`.

## Доказательства в первую очередь

Первоначальный целенаправленный тестовый запуск не удался, поскольку `scripts/progress.py` не существовало. Неудачная ошибка для этого файла была `FileNotFoundError`. Затем была добавлена ​​реализация, чтобы удовлетворить требованиям тестов.

Целенаправленный набор тестов после реализации:

```text
python3 -m unittest -v examples/skills/learning-path/tests/test_progress.py

Ran 11 tests in 0.029s
OK
```

Охватываемое поведение:

1. Новый профиль новичка записывает состояние за пределами установленного навыка.
2. Атомное сохранение оставляет действительным полный JSON и отсутствие временного файла.
3. Внедренный сбой `os.replace` оставляет старые байты состояния нетронутыми и удаляет временный файл.
4. Неполные предварительные условия блокируют завершение.
5. Пустые доказательства блокируют завершение.
6. Выбор следующего модуля возвращает первый разблокированный модуль.
7. Планирование проверки возвращает семь необходимых дат.
8. Поврежденное состояние JSON не закрывается.
9. Логические значения версии, неизвестные дорожки, неизвестные модули и модули за пределами выбранной дорожки не закрываются.
10. `status`, `next`, `due` и `complete` отклоняют поврежденное состояние перед выполнением.
11. Шестнадцать одновременных попыток `init` дают ровно один успешный профиль и пятнадцать отклоненных попыток.

## Исправление независимой проверки

- `_validate_state` теперь получает доверенный `path_data`. Он требует, чтобы `version` был действительным целым числом, распознает только определенные дорожки и принимает только известные модули, принадлежащие выбранной дорожке. Он также отклоняет запись о завершении, для которой отсутствуют предварительные условия.
- Каждая команда чтения состояния CLI загружает и проверяет состояние по `path_data` перед выбором, планированием, завершением работы или отчетом о ней.
- Команды навыков теперь выполняются через `${CLAUDE_SKILL_DIR}/scripts/progress.py` с `--root "$PWD"` перед подкомандой. Поэтому они нацелены на сторонний проект учащегося, а не на получение данного руководства.
- Сопоставление самооценки изначально сделало программу Maintenanceer доступной только для управления; окончательное исправление полностью удаляет его из результатов оценки.
- В формулировке теперь говорится, что для завершения требуется непустая доказательная запись. Это больше не означает, что произвольные доказательства могут быть признаны неполными.
- Первоначальное примечание валидатора заменяется ниже точной границей проверки фронтальной информации `quick_validate.py`.

## Исправление окончательной проверки

- `init` больше не проверяет существующую цель перед записью. Он записывает и синхронизирует временный файл в том же каталоге, а затем публикует его с помощью `os.link`. Этот примитив успешен ровно для одного претендента и никогда не перезаписывает существующую цель. Каждый проигравший соперник удаляет только свой временный файл.
- Параллельный тест запускает шестнадцать вызывающих абонентов у барьера и проверяет одного победителя, пятнадцать отклоненных вызовов и читаемое конечное состояние.
- Карта самооценки теперь содержит только уровни «Начинающий», «Средний» и «Продвинутый». Программа сопровождающего документируется отдельно как выбор вручную для целей совместного управления.
- Граница проверки теперь называет фактическое поведение `quick_validate.py`: она импортирует PyYAML перед анализом заголовка `SKILL.md`. В системном Python отсутствует PyYAML, и он вызывает `ModuleNotFoundError`, но доступный Python pyenv успешно запускает этот валидатор.

## Граница и забота

Прототип намеренно записывает доказательства завершения, но не оценивает качество доказательств и не отмечает проверки как завершенные. Причитающиеся отзывы остаются видимыми после истечения их даты. Человеческая или будущая логика продукта должна решить, был ли обзор выполнен по существу. Прототип не выполнял никаких сетевых операций, установки пакетов, редактирования руководства, обновления навигации, обновления каталога, обновления журнала изменений, изменения версии или внешней записи.
